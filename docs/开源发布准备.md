# 开源发布准备（Apache-2.0）

> 这份文档记录"把这个仓库公开到 GitHub"这件事**具体做了什么、为什么这么做、哪些没做**。
> 它不是宣传稿：合规缺口、未验证项、以及"开放后仍需人工完成的三步"都写在下面。

---

## 1. 许可证：为什么选 Apache-2.0

| 候选 | 为什么不选 / 选 |
|---|---|
| MIT | 最短最宽，但**没有显式的专利授权**与"贡献者专利报复"条款。本项目要跟 Node/DSH 生态里的 npm 包互操作，Apache-2.0 的专利条款对下游更清楚 |
| GPL-3.0 | 会传染到使用者的整套部署；一个"接自家 QQ 的桥接"没有必须 copyleft 的理由，反而挡住别人用 |
| **Apache-2.0** ✅ | 明确专利授权 + 允许商用/闭源二次开发 + 要求保留 `NOTICE` 与变更声明，与项目里已有的 MIT 依赖（`ws`、Node）兼容 |

落地文件：

- `LICENSE` —— Apache-2.0 全文（逐字，未改）
- `NOTICE` —— 版权行 + "第三方组件见 THIRD-PARTY.md"
- `THIRD-PARTY.md` —— 逐条列出第三方组件、版本、许可证、出处、**以及合规缺口**

### 2.1 发布前修补：把"跳过"和"通过"分开

开源前把 62 套拿**放开 spawn** 的会话重跑了一遍（此前一直在受限沙箱里跑），当场 17 项红 ——
这是本项目第一次知道 `verify-onebot` / `verify-mcp` / `verify-live` 里到底有没有问题：

1. **真产品问题（已修）**：隐私闸的「生物特征」判据认**裸词**（连类别名 `生物特征` 都算），
   于是**我们自己的提示词**（"不要记隐私：…生物特征（指纹/人脸/声纹）"）被判成含隐私，
   输出侧把**整条回复吞掉**。真机上"指纹锁坏了怎么办"这类正常回答同样会被吞。
   已收紧为只认**数据形态**，并在 `verify-privacy` 里留下正例 3 条 / 反例 3 条锚点。
2. **两套套件自身陈旧（已修，16 项）**：它们**从没真跑过**（受限沙箱整份跳过 ⇒ `exit 0` ⇒
   链条显示"全绿"），于是与实现慢慢脱节 —— 分片时序、投递终检门删段标题、来源标注里的 `#id`、
   `qq_api` 从黑名单改白名单后的措辞。

完整记录见 `docs/0.2.7-release-notes.md` §5。**给开源读者的一句话**：本仓库的测试链条在
受限沙箱里会**打印"跳过"并仍然退出 0** —— 那是设计上的诚实（不假装通过），但**不等于通过**，
要复现"全绿"必须在正常 Windows 会话里跑。

## 3. 真机标识 → 占位号码

原则：**只换数字，不换语义**。文档里"真机取证"的结论、行数、字节数、时间戳全部保持原样，
只有号码本身变了 —— 这样历史记录仍然可读、可复算，同时不再公开任何真实账号。

| 占位号码 | 是谁 |
|---|---|
| `200000001` | 机器人自己的 QQ（OneBot `uin`） |
| `100000001` | 使用者（管理员） |
| `100000002` | 群里的一位成员 |
| `700000001` / `700000002` | 两个群号 |

⚠️ **映射表本身不公开**（真机号码 → 占位的对应关系只存在本地 `packages/qq-bridge/cache/scrub-ids.mjs`，
而 `cache/` 在 `.gitignore` 里）。写进仓库等于换个地方公开真号码。

**替换脚本**：`packages/qq-bridge/cache/scrub-ids.mjs`（本地工具，不入库）。
两个细节是有意的：

- 按 **latin1 字节**替换，不是 utf8 字符串 —— 目标是纯 ASCII 数字，字节级替换不会破坏
  任何非 UTF-8 内容（仓库里 `snowluma-log.mjs` 的注释就含 GBK 乱码样本），也保证"没命中的字节一个都不改"。
- 带 NUL 的二进制文件整体跳过（唯一命中者是 `assets/icon.ico`，与号码无关）。

**唯一的例外**：`_release/` 里的旧发布包里还有真号码，但那些文件既不进索引也不进新历史（见 §4）。

## 4. 发布包改走 GitHub Releases + 历史重写

**为什么**：`_release/` 曾经入过库，代价被低估了：

1. 每个版本的包都进历史 → `.git` 涨到 **354.8 MB**（`git count-objects -vH` 的 `size-pack` 165.77 MiB）；
2. `vendor/node/node.exe`（85.6 MB）走 **Git LFS** → 仓库里存的只是 **133 字节指针**。
   别人 clone 后若没装 git-lfs，拿到的是一个"看起来正常"的假文件，发布包**跑不起来**，
   而报错完全指不到这里；
3. GitHub 仓库本来就不该承担二进制分发。

**怎么做**（在**本地克隆**里做，开发仓库不动）：

```bash
git clone --local <原仓库> InteractBot-public
cd InteractBot-public
# ① 把 _release/ 从**所有提交**里删掉（index-filter：只改索引，不检出树，快）
git filter-branch --force --index-filter \
  "git rm -r --cached --ignore-unmatch _release" \
  --prune-empty --tag-name-filter cat -- --all
# ② 再把**历史里**的真机号码换成占位号码（tree-filter：逐棵树检出再改内容）
git filter-branch --force --tree-filter \
  "node <本地>/scrub-ids-tree.mjs" \
  --prune-empty --tag-name-filter cat -- --all
# ③ 清 refs/original + reflog 并 gc，否则旧对象还留着、体积降不下来
git for-each-ref --format='%(refname)' refs/original | while read r; do git update-ref -d "$r"; done
rm -rf .git/refs/original && git reflog expire --expire=now --all && git gc --prune=now --aggressive
```

> 没有用 `git filter-repo`（本机没有 Python 环境，`pip` 不可用），所以走 git 自带能力。
> 两遍是刻意的：先删大目录（便宜），再改内容（贵，71 个提交逐棵树过一遍）。
> 替换脚本按 **latin1 字节**改，只认纯 ASCII 数字，因此不会破坏任何非 UTF-8 内容。

## 5. 实测数据

- 移出索引：`_release/` **143 个文件**
- 号码替换：**67 个文件 / 346 处**（`git diff --shortstat`）
- 界面重建：`dist/assets/index-CA9aNFKi.js` + `index-CTydWB1O.css`，`ui-build.json.sourceHash = cbd76f19ea36…`
- 测试链：**62 套，放开 spawn 的会话里退出码 0**（这是本项目第一次连 `verify-onebot` /
  `verify-mcp` / `verify-live` 都真跑的完整链条；修补前后的 17 项红见 §2.1）
- 历史重写后 `.git` 体积与验证结果：见 §5.1（实测，不是估计）

### 5.1 历史重写实测（在本地克隆里做过一遍）

| 指标 | 重写前 | 重写后 |
|---|---|---|
| `.git` 目录 | 356.2 MB | **4.2 MB** |
| `git count-objects -vH` 的 `size-pack` | 165.77 MiB | **4.10 MiB** |
| 提交数（`--all`） | 71 | **69** |
| `git log --all -- _release` | 13 个提交 | **0** |
| `git rev-list --objects --all` 里的 `_release` 对象 | 143+ | **0** |
| `git log --all -S <真机号码>`（5 个号码逐个查） | 命中 | **全部 0** |
| `git rev-parse HEAD^{tree}` | `4d278734b378121c7fdd51522c9cabcd9cbbbd21` | **同上（逐字节一致）** |

- **提交数 71 → 69**：有 2 个提交**只动 `_release/`**（发布包入库那类），删掉该目录后它们变成空提交，
  被 `--prune-empty` 剪掉。源码提交一个没少。
- **HEAD 树哈希前后一致**：重写只影响历史，**不动当前内容** —— 这也是"重写没错"最硬的一条证据
  （若它变了，说明脚本误改了某个文件）。
- `.git` 从 356 MB 掉到 4.2 MB，说明那 350 MB 几乎全是发布包与它的 LFS 对象。
- ⚠️ **开发仓库（`project_InteractBot`）保持原样**：重写不可逆，所以只在副本里做，
  推 GitHub 也从副本推（见 §7）。开发仓库留着完整历史，自己继续用。
- **发布包也扫过一遍**：重打后的 `_release/InteractBot-0.2.7-win-x64/`（147 个文本文件）
  真机号码**零命中** —— 那个 zip 是要公开下载的，不能只清仓库不管包。

## 6. 没做的 / 未验证的（如实列）

1. **重写后的历史没有在别的机器上 clone 验证过**（本地 `git fsck` / 树哈希 / `-S` 三样都过了，
   但没有第二台机器做一次真实 clone）。推之前建议先 `git clone` 到自己另一个目录跑一次 `npm test`。
2. **发布包里没有随附 Node.js 的 `LICENSE`**（再分发合规缺口）。原因与补法写在 `THIRD-PARTY.md`。
   尝试过联网取官方 `LICENSE`，但这台机器**没有出口网络**（DNS 都解析不了），所以没取到。
3. **没有配 CI**。62 个套件目前只能在开发机上手动 `npm test`；公开后建议加一条
   "PR 上跑离线套件"的工作流（不需要 QQ、不需要 DSH、不需要网络）。
   ⚠️ 若真加 CI，注意 `verify-onebot` / `verify-mcp` / `verify-live` 在**受限环境里会跳过并退出 0**
   （见 §2.1）—— CI 上要么给足权限真跑，要么**显式承认它们没跑**，别让绿色骗人。
4. **没有 `.github/` 下的 ISSUE 模板 / CODE_OF_CONDUCT**。
5. **`reference/` 里两份上游原件的许可证状态未确认**（上游没写许可证）。已在
   `THIRD-PARTY.md` 里声明，并写明"原作者若不同意可要求移除"。
6. **第二台干净机器上的"发布包能否跑起来"仍未验证** —— 这一条从 0.2.7 打包时就挂着，
   与开源无关，但公开时值得一起做掉。

## 7. 开放之后的三步（人工，必须做）

> 下面三条里，第 1、3 条只能由你在浏览器/账号里做；第 2 条的仓库已在本机备好（见 §5.1）。

1. 在 GitHub 建**空仓库**（不要勾 README / .gitignore / License —— 勾了首次 push 会打架）。
   仓库名建议 `InteractBot`，可见性先 **Private**（确认没问题再改 Public）。
2. 从那个**重写过历史的克隆**里 push（**不要**从开发仓库推，否则真机号码与发布包历史又回去了）：

   ```bash
   cd packages/qq-bridge/cache/InteractBot-public     # 本机已有的那份（cache/ 已忽略，不会入库）
   git remote add origin https://github.com/<你的账号>/InteractBot.git
   git push -u origin main
   git push --tags                                    # 目前没有 tag，这条是为将来留的
   ```

   推之前建议先自查一次（三条命令，输出应当分别是 0 / 空 / 空）：

   ```bash
   git log --all --oneline -- _release | wc -l        # 0
   git log --all -S 100000001 --oneline | wc -l      # 0（真机号码在历史里也搜不到）
   git status --short                                 # 空
   ```
3. 在 **Releases** 里新建 `v0.2.7`：

   - Tag：`v0.2.7`（指向 main 的最新提交）
   - 标题：`0.2.7 —— 视频识别接线 + 三处静默失效清理`
   - 附件：`_release/InteractBot-0.2.7-win-x64.zip`（33.5 MB，本机已重打：修复后的源码 + 冒烟 45/45）
   - 正文：直接抄 `docs/0.2.7-release-notes.md`（含 §5 那段"跳过被当成通过"的交代）
   - Topics 建议：`qq-bot` `onebot` `deepseek` `dsh` `chatbot` `windows`

   之后把仓库从 Private 改成 Public（或先 Private 跑几天）。

## 8. 以后提交时的约定

- **不要再把真机号码写进任何受跟踪文件**（日志片段、截图文本、`PROJECT.json` 的取证描述都算）。
  需要引用时直接用占位号码。
- 发布产物继续走 Releases；`_release/` 保持被忽略。
- 提交信息与文档里的"为什么"照旧写清楚 —— 这个仓库的价值一半在代码，一半在这些取舍记录里。
