## 1. 一句话

**服务器里的玩家可以随时和后端的小鲸鱼说话；服务器出问题时它报告且只报告一次，并尝试一次重启；
重启失败就向管理员求助并等指令。** 另外它现在能**问出一台服务器的情况**（人数 / TPS / 连通），
**管理员可以从三个入口下控制台指令**（op 级别），而且这一切**不需要任何服务端插件或模组**。

## 2. 需求与验收：六条行为，逐条对上

设计契约 §1 定的六条（左边是需求原话，右边是**实际落点**）：

| # | 需求 | 本版怎么落的 |
|---|---|---|
| 1 | 玩家在服务器内聊天 → 小鲸鱼在后端收到 → 决定要不要回 | **读桥接自己拉起的那个服务端的控制台日志**（P2 已经把它的 stdout 重定向到 `runtime/servers/<id>.console.log`）⇒ **零服务端代码**。设计契约原本假定"需要服务端侧代码"，这一版证明**不需要**（§4.1） |
| 2 | 服务器出问题 → 在选定聊天报告**恰好一次** | 三层保证：**状态机只在跃迁时产出事件** + `claimEventFire` 事件级去重 + 冷却（默认 5 分钟）。播报目标走 `resolveScheduleTarget`（fail-closed） |
| 3 | 报告后**尝试一次重启**（不是重试循环） | `restart.mjs`：`canRestart` 依次查「只有 down 才允许 / 归属证据 / 次数上限 / 在等指令 / 冷却」；`maxAttempts` 默认 1，**成功一次后计数归零** |
| 4 | 重启失败 → **向管理员求助并等指令** | `waitingForAdmin` 落盘；`--supervise retry` / `abandon` 是**人**才能给的指令 |
| 5 | 进服要求绑定 UUID ↔ QQid，提醒一次；未绑定者不能聊天 | 进服提醒（**只给本人**、每次进服最多一次）+ `\mc bind` 取码 + 群里提交即绑定；未绑定者说话**不进模型**（零成本） |
| 6 | 群友**可以问出服务器内的情况** | 普通用户（只读）就能问：模型调只读的 RCON 命令（`list` / `forge tps`），或用「服务器」页签的「主动检测」 |

### 2.1 两条**没有**照设计契约做的地方（如实记）

1. **"选定聊天"落成了"事件型任务"，不是一个新的播报开关。**
   契约 §4 设想"从白名单里选一个群"专门收报告；实际落法是复用定时任务那套：
   任务定义里 `trigger.kind === 'server'` + `trigger.events: ['down','up']`，
   而**是否自动播报由 `announce` 决定，默认 `manual`（不播报）**。
   理由写在 `#onServerEvent` 的注释里，是一条安全问题：
   > 一台服务器 down 就自动播报到群里，等于把"服务端的一部分事实"交给了**任何能让它掉线的人**
   > —— 重启一下、打崩它，群里就会响。

   ☆ 但 **"尝试一次重启"不受 `announce` 影响**：让服务器活过来是**处置**，告诉群是**播报**，
   两件事分开（`announce: manual` 只影响后者）。
2. **"事件型任务"与"定时任务"共用一套台账**（`runtime/schedule/<id>.json`），
   不是两个模块。好处是"恰好一次"那套认领/台账/错过记录**只写了一份**。

### 2.2 这一版最贵的一条教训：**接线级的缺陷，纯函数断言一条都抓不到**

任务页签四条接口在**真实运行时**全部抛 `ReferenceError: listScheduleTasks is not defined`
（使用者原话：「我在拓展中开启了定时任务功能，但是标签页中显示未开启且读不到定时任务」）。
根因：`--schedule` 那个 CLI 段里用 `const { listTasks: listScheduleTasks, … } = await import(...)`
造了一批**块级局部别名**，而 `main()` 另一处的路由对象照着抄了这些名字。

**为什么 81 套测试全绿**：`verify-api-h13.mjs` 与 `verify-apitest.mjs` **各自造了一份路由对象**
（各自 import 一份 `schedule.mjs`）⇒ 它们测的是**副本**，而那份真实接线**从来没有被跑过一次**。
（与更早那次「任务段从未注入过」是同一类缺陷。）

**修法**：新增 `mocks/verify-route-scope.mjs`（14 项）——
极简词法扫描 `src/index.mjs`，找到 `createApiHandler({…})` 那个对象字面量，
把里面**调用位置的名字**与**全大写常量**逐个对照作用域（模块级 ∪ `main()` 同层声明 ∪ 字面量内声明）。
它**是可证伪的**：有 6 条正/负对照（含"事故的真实形状"必须被抓到）+ 一条反向对照
（把那批别名从作用域里拿掉必须变红）。实测：去掉顶部 import ⇒ 它报出那 10 个缺失的名字。

**同一次还修掉**：「扩展页开了定时任务，但东西不跑」——`bridge.syncScheduleRunner()` +
`onToggled` 回调 + `schedule.hot = true` + 接口回带 `runnerRunning`，
让**界面上的开关与真实运行状态对齐**（`runnerRunning` 是"定时器挂上了没有"的活证据）。

## 3. 定时任务（P1 + P5）

**为什么这是这一版的地基**：在此之前桥接是**纯镜像** —— 只回答刚收到的那条消息。
所以「8 点叫我一声」「提醒某某人吃饭」这类**无人开口**的需求一处都落不下去。

### 3.1 "恰好一次"落成两条不变量

| 不变量 | 怎么做到的 |
|---|---|
| **每条提醒只会发一次**（说两遍比漏一遍更糟） | 触发点是**算出来的**（不是等一个心跳），且**落盘台账在调模型之前**认领（`claimed → sending → delivered/failed/empty`） |
| **不许静默** | 认领了但没发出去的，启动时**大声报出来**（投递账本同款纪律：**不自动重发** —— 崩溃可能发生在"已发出但没标上"那一瞬间，自动重发会产生重复） |

### 3.2 迟到与错过（两条都有明确口径）

- **迟到 ≤2 分钟**：照常发，并在正文里**如实说"晚了"**（不假装准时）。
- **超过就记进错过台账**，**下次对话里提一句** —— 补发一条 3 小时前的"该吃药了"比不说更糟。
- 这两条都有断言；口径写在 `schedule.mjs` 的 `dueAt` / `lateToleranceMs`。

### 3.3 谁能建、能发给谁

- **只能由管理员建**；**目标必须是"来过消息的会话"**（`resolveScheduleTarget` 是 fail-closed：
  不往陌生号码发消息）。
- 默认**关**（`schedule.enabled`）—— 它是唯一一个**不用谁开口就往外发消息**的能力。
- 控制台「定时任务」页签：看任务 / 建改删 / 看**下次什么时候响** / 看**上一次实际发出去的原文** /
  看**错过台账**。⚠️ 界面产物要 `npm run build` 之后才在浏览器里出现。

## 4. 服务器监测（P2）

### 4.1 为什么不需要服务端插件（本版最重要的一条"白拿"）

P2 把服务端的 **stdout/stderr 重定向**进 `runtime/servers/<id>.console.log`，
P3 直接**读那个文件**当事件源 ⇒ 游戏内聊天、玩家进出、控制台输出全都是现成的。
代价是一条**必须如实告知**的限制：**只有本程序拉起的服务端才有那个文件**。
别人手动起的服读不到任何东西 —— 那不是故障，是这条路的设计边界
（要覆盖它就得去尾随服务端自己的 `logs/latest.log`，而那正是 P2 刻意避开的）。

### 4.2 判据（先定义清楚，否则是猜）

- **默认只把「连不上」算 down**：连续 `failThreshold` 次（默认 2）才判定，防网络抖动误报。
- `rules` 里的 TPS / 人数阈值**只产出异常报告，不触发重启** —— 「TPS 低就重启」是赌博。
- `tpsCommand` **留空 = 不问**（不是"问了没拿到"）：TPS 不是通用命令，猜一个只会把"我猜错了"
  显示成"服务器有问题"。填了只解析最稳的那段（`Mean TPS:`），多维度取**最小值**，
  认不出仍留 `null` —— **绝不猜成 0**（否则 `minTps` 会立刻误报）。
- **同一个异常只报一次**：异常键里带**指标名**而不是数值；异常消失才清键（否则"第二次低 TPS"永远没人知道）。

### 4.3 控制台日志**不是** UTF-8（真机取证）

真机实测：`say 夹具-测试消息` 落进 `forge1.console.log` 的字节是 **GBK**，不是 UTF-8
（Windows 中文版 JVM 默认 `file.encoding=GBK`，而 P2 把 stdout 原样重定向进那个文件）。
⇒ **任何按 UTF-8 读它的代码在真机上一个中文字都读不出来**。
解码层因此是「UTF-8 严格解不过才回退 GBK」，**反向也有一条断言**（正常 UTF-8 中文不许被错解成乱码）。
夹具里的中文是**真 GBK 字节**，且有一条断言逐字节核对我们的编码与真机一致。

方言语种覆盖（`mocks/fixtures/chat-dialects.mjs`）：Forge 真机逐字 / `[Not Secure]` 前缀 /
中文（GBK）/ 中文玩家名 / 原版 / Paper 线程名 / Fabric 圆括号记录器 /
噪音（含 **`[Rcon]` 自话不许被当成玩家聊天** —— 否则会形成自环）/ 正文含 `<` 与 `]: `
（第一版「取最后一个 `]: `」会切成半句）。

### 4.4 「正在启动」是一个**独立状态**（使用者要求）

模组服冷启动 **18~60 秒**（首次能到 1~2 分钟），而判 down 要连续失败 N 次 ⇒
**还在加载时就会被判成 down**。危害不只是"显示错了"：

> `down` 是**唯一允许触发重启**的那一类 ⇒ 可能"再拉一个"，
> 而**两个 JVM 同时打开同一个世界目录 = 存档损坏（不可逆）**。

所以新增 `starting`（🟡）与 `up`/`down` 并列，判据只有一处（`evaluateStarting`），
监测循环与界面共用同一份，避免"监测说在启动、界面说 down"那种两处措辞分叉。
★ 这一笔的**根因没有复现**：使用者报的是"重启桥接后服务器也重启了"，我们**没有**找到那次的具体触发链，
只按"这个状态缺失会导致什么"把缺口补上 —— 这一条如实记在这里，别当成"修好了某个已知根因"。

### 4.5 启动接管（`servers[].manageOnStart`，默认关）

桥接启动时按**这个顺序**办三件事，顺序本身就是纪律：

1. **端口活着 + 归属是我** ⇒ **接管**（只挂监测，不上手）；
2. **端口活着但归属不是我** ⇒ **只报告**（绝不"先杀再起"去抢 —— 那可能是在杀别人的服务端）；
3. **端口不通** ⇒ 按 `startExe`/`startCommand` 拉起来，并**等端口真的开放**才算起来。

### 4.6 真机才暴露的三个缺陷（都修在这一版）

| 现象 | 根因 |
|---|---|
| RCON 认证一直失败 | 判据写错了：按包里的 `type` 判，而**应当按 `id`** 判（真机协议行为） |
| 归属永远判不出来 | 只看 `startCommand` 拼出来的形状；`startExe`+`startArgs` 那条路没被识别（**四处**都要认这个形状） |
| `--supervise start` **谎报成功** | 第一版打印 `launch()` 的结果就收工 ⇒ 「✅ 已拉起」只意味着"进程创建成功"。实测：紧接着 `--supervise status` 看到的是「⛔ 没在跑」（那次 Forge 要 18 秒才 `Done`）。现在**等端口真的开放**才算成功，等不到就如实说没起来并指路控制台输出 |

### 4.7 界面（第 9 个页签：服务器）

- 状态卡：🟢/🔴/🟡 + 连续失败次数 + 上次采样的人话 + 归属证据（pid / 启动时刻 / 谁起的）。
- **「主动检测」按钮**：真连一次并跑只读命令。★★ 它**不喂状态机**（不累加"连续失败"）——
  点几次都不会把一台好好的服务器"点成 down"。
- **「实时后台」折叠栏**：读控制台日志的**最新输出**，按**字节偏移**读（文件可能在写一半、
  也可能被轮转/截断；按行读会截断半行，而偏移指向不存在的位置会让"控制台永远不再更新"）。
  回带 `encoding` 字段如实告诉你是 `gbk` 还是 `utf8`。
- **条目增删改**：改完**即时生效**（后端重建监测循环，不必重启桥接、不断 QQ、不打断在跑的回合）。
  ★★ 保存是**按字段合并**的 —— 见 §8.1/§8.3 的事故。

## 5. 重启编排（P4）

**这一块是"唯一会改变机器状态"的动作**，所以每一条纪律都是为了**不把事情弄得更糟**。

### 5.1 归属：`pid@进程启动时刻`

- 只有"归属是**我**"才允许动手；判据是 `pid` + 进程启动时刻落在**我们自己写的归属档**里。
- ★★ **推荐 `startExe` + `startArgs`（不走 shell）**：走 shell 时拿到的是 `cmd.exe` 的 pid，
  它起完 java 就自己退出 ⇒ 归属档里那个 pid 立刻变成"已死的进程" ⇒ 归属永远判成"不是我起的"
  ⇒ **重启能力永远不可用**（实测抓到的硬伤）。
- ★ 「从哪跑」决定服务端能不能活：**在 agent/沙箱会话里拉起的进程会随那条命令一起被回收**
  （实测：服务端起完就被杀，日志戛然而止、一行停机记录都没有）。∴ 推荐
  `supervise-server.bat start --id <id>` 在**使用者自己的终端**里跑，判据是服务端日志尾部
  （优雅停服有完整收尾 `All dimensions are saved`）。

### 5.2 流程与纪律

```
优雅停服（RCON stop）→ 等端口释放 → 拉起 → 等端口开放   ← 四步都成功才算"重启成功"
```

- **冷却**（默认 10 分钟）+ **同一次故障最多尝试一次**（默认 `maxAttempts: 1`）。
- **成功一次后计数归零**（是"每次故障最多一次"，不是"一辈子一次"）。
- 任何一步没做到都**如实说**：停服失败就跳过"等端口释放"这一步并说明多半是它已经崩了；
  等不到端口就说没起来并指路控制台输出。

### 5.3 人怎么介入

```bash
node src/index.mjs --supervise status  [--id <id>]   # 归属 / pid / "能不能重启"
node src/index.mjs --supervise retry   --id <id>     # 管理员说"再试一次"
node src/index.mjs --supervise abandon --id <id>     # 放弃：别再自动动它
```

`stop` / `retry` / `abandon` 都会改状态，所以**必须显式带 `--id`**（或配置里只有一台时自动选它）——
**不许"猜一台"**。

## 6. 完整控制台（RCON = op 级别）

### 6.1 三条入口，一处硬闸

| 入口 | 怎么用 | 谁 |
|---|---|---|
| **本机网页** | 「服务器」页签的输入框（`POST /api/servers/command`） | 能碰到这台机器的人 |
| **QQ（本地指令）** | 管理员在群里发 `\mc [id] <命令>` ⇒ 桥接**本地拦截执行，不经模型** | 只认管理员 |
| **QQ（模型那条路）** | 模型调 `mc_command` 工具 | 读本轮授权文件，非管理员一律拒绝 |
| **游戏内** | 绑定到**管理员 QQ** 的玩家在服里叫它 | 同上（那一轮用的就是那个 QQ 的会话） |

开关是 `servers[].commandFromQQ`，**默认关**。
★ 它管的是**所有"让 bot 去动服务端"的入口**；与「游戏内对话」（`gameChat`）的分工是**另一个维度**：
`gameChat` 决定**听不听**游戏里的人说话（只有对白），这个决定**动不动**服务端（op）。
∴ 游戏内的管理员要查 TPS，**两个都得开**。

### 6.2 授权文件与它的**真实上限**（不写清等于骗后来的人）

判据是桥接在准入判定那一步算出来的 `tier`，写成工作区里的一份**明文授权文件**
（MCP 子进程与桥接主进程只能靠文件通信）。∴ 必须写明：

> ① **授权文件是明文放在工作区里的，模型自己也能读写** ⇒ 模型**可以伪造**它。
> 这条路**不是"密码学意义上的硬墙"**，而是"比提示词强得多的一道关卡"：
> 它挡得住**外部陌生人**，**挡不住模型主动恶意伪造**。
> ② 粒度是**会话**，不是"这一次调用属于哪个回合"（MCP 协议层没有后者）。
> ③ 过期（10 分钟）是给"回合崩了没删掉"兜底的，不是权限时长。

两条**已知并接受**的代价：`op` 可提权 ⇒ 命令白名单**事实上失效**（能 op 一个玩家，白名单就没意义了）；
**管理员 QQ 被盗 = 服务器 op 被劫持**（本机网页那个终端没有这个问题，因为它要求能碰到这台机器）。

### 6.3 为什么"控制台"不能做成看起来精确的终端

真机实测：RCON 的应答**常常是空的** —— `list` / `forge tps` 有回显，而 `time set day` 这类不回话
（结果只进服务端日志）。∴ 「命令成功」**不能**用"有回显"来判，且接口与界面都**如实标注**
「输出不保证只属于这一条命令」。把假终端做成看起来精确的样子才是危险的。

## 7. 游戏内对话（P3）

### 7.1 事件源与绑定流程（**两次改口径**，两次都是使用者实测推翻的）

```
玩家进服（未绑定）        → ★ 一进服就收到**只给他本人**的提醒（每次进服最多一次）
玩家在**游戏里**说 \mc bind → 生成 6 位码（**与他的 UUID 挂在一起**，5 分钟、一次性），只发给他本人
玩家在**群里直接发** \mc bind <码>（**不用 @ 我**）→ 桥接本地拦截 ⇒ **当场绑定**
                          → 群里回一句 + **立刻在游戏里通知他本人**（抢绑藏不住）
已绑定的玩家在游戏里叫它   → 命中唤醒词（默认 小鲸鱼 / 小鱼）⇒ 模型 ⇒ 回复发到**公屏**
```

口径变化（都记在 `bindings.mjs` 的注释里）：

| 版本 | 流程 | 为什么改 |
|---|---|---|
| 设计契约 §5.1 | 群里 `/绑定` 取码 → 群里提交 | 「码 = 资格」，归属只能等下一次游戏内发言去**猜** |
| 第一次改 | **码在游戏里生成**、与那个 UUID 挂在一起 | 提交上去就是确定的映射，没有"资格"这一步、没有歧义 |
| 第二次改 | 形状从 `//mc bind` 改成 **`\mc bind`（反斜杠）** | **实测**：以 `/` 开头的输入会被服务端当命令，而那句 "Unknown command" **不写进任何日志** ⇒ 我们看不到。`\` 在游戏里只是普通字符 ⇒ 那句话以**聊天**发出 ⇒ 进日志 |

★ 代码里 `\mc bind` / `/mc bind` / `//mc bind` / 裸 `mc bind` **都还认**（零代价的兜底，
将来真装了服务端插件就能用），但**对外只说 `\mc bind`** —— 一次只教一个形状。
⚠️ 后来做措辞收口时把这一条推到了全仓：**所有指令一律写反斜杠**（见 §9.1）。

### 7.2 两条回应通道 + 公屏样式（使用者要求）

| 内容 | 通道 | 为什么 |
|---|---|---|
| 未绑定提醒 · 绑定码 · 绑定成功通知 | `tellraw <玩家>` **只给本人** | 未绑定状态与码本身都是个人信息 |
| 小鲸鱼的正常回复 | **`tellraw @a`** 公屏 | 使用者要求：「每条发言都要在前面加上 `<小鲸鱼>`，**不要高亮**，模仿正常玩家」 |

- `say` 渲染出来是 `[Server] …` 且带服务端配色 ⇒ **一眼就看出不是玩家**，所以弃用。
- **代价如实记**：`tellraw` **不写控制台日志**（`say` 会写）⇒ 它说过什么由**桥接日志**记
  （`[game-chat] 说（公屏）：…`），代价是"实时后台"里不会再出现它自己的发言。
- **`§` 会被剥掉**（连着后面的格式字母一起）：它是原版格式逃生码，写在 `text` 组件里
  **客户端仍会渲染**（`§c` 变红、`§k` 变乱码）⇒ 留着就等于让模型能给自己的话上色。
  只剥 `§` 会留下一个游离的 `c`（第一版就是这样，被断言抓到）。

### 7.3 两道门：**能不能说话** vs **有多大权限**

| | 门是什么 | 不通过时 |
|---|---|---|
| **能不能在游戏里说话** | **绑定**（`runtime/bindings.json` 里那条映射） | 未绑定：进服提醒一次 + 他说话时**不进模型**（零成本） |
| **说话的人有多大权限** | **管理员表**（`roster.tierOfSpeaker`） | 非管理员一律 `USER`（**只读**，动不了任何东西） |

★ 上一版把 **QQ 的私聊白名单**也当成一道门 ⇒ 玩家好不容易绑上了，却因为那个 QQ 不在
`dmAllowlist` 里而**在游戏里说不上话**。那不是使用者要的：**绑定本身已经要求**"人在服里 +
在某个已允许的群里"，所以它就是合适的门。⚠️ 但**权限一分不让**。

### 7.4 未绑定者的行为（硬要求）

使用者的口径是：「由于**不能确定每次玩家都在跟小鲸鱼说话**，只有进入服务器时进行提醒」。
∴ 提醒**只在进服那一刻**发（那次才知道"他刚来"），他之后说什么都**不进模型、也不回话**。
**一个窄得多的例外**：他**明确叫了名字**（命中唤醒词）时补发一次提醒 ——
那种情况我们**确定**他在跟小鲸鱼说话，而沉默会让他以为机器人坏了。
（它还解决"桥接启动时他已经在服里了 ⇒ 拿不到进服事件"这个洞。）

### 7.5 控制台里它是**单独一个窗口**（使用者要求）

`chatKey` 与**展示键**是两件事：

| | 用哪个键 | 为什么 |
|---|---|---|
| **会话 / 记忆 / 串行锁 / 去重 / 权限** | `private:<绑定的QQ>` | 让"他在游戏里说的话"与"他在 QQ 里说的话"落进**同一段记忆** —— 那正是绑定要买到的东西 |
| **控制台预览开哪个窗口** | `game:<服务器id>` | 单独一个「游戏内对话 · 主服」窗口，**不混进**那个人的 QQ 私聊 |

窗口里三样都要显示：**玩家说的**（说话人用**游戏里的名字**，同时留 QQ 号）、
**它回公屏的话**、**只发给本人的那些话**（记成 `→ 玩家：正文` —— 点对点与公屏的区别要看得出来）。
那个窗口里的"搜历史"是**真的能搜到**的（游戏内消息也进语料库，`/api/corpus/search` 放行 `kind=game`）。

### 7.6 ★★★ 两条"通道串味"缺陷（同一版里被发现并修掉）

**A. 「先应一声」被发进了 QQ 私聊。**
游戏内那一轮在**会话**上用 `private:<绑定的QQ>`（上表第 1 行的理由），
于是 `#runTurn` 里任何 `#safeSend(kind, peerId, …)` 都会**打到那个人的 QQ 私聊里** ——
而「先应一声」（长回合的垫场白）正是这么发的。

真机证据（可复查，`logs/bridge.log`）：

```
07:08:31 [bridge] 回合仍在进行，先发一条：稍等，正在调用工具（private:100000001）
07:09:12 [bridge] 回合仍在进行，先发一条：正在喊小虾米们起来干活（private:100000001）
07:09:40 [game-chat] 说（公屏）：…          ← 同一分钟他正在**游戏里**说话
```

修法两条：
1. **游戏通道整条跳过「先应一声」**（使用者要求）—— 它只剩公屏一条路，而一句"我在想"的垫场白
   印到**全服公屏**上是纯噪音。抑制是**按通道**的，不是把功能关了（QQ 私聊/群里照旧发，
   有**对照组**断言盯着）。
2. 其余系统提示走 `#speakerNotice(kind, peerId, text, deliverTo)`：**通道是游戏 ⇒ `tellraw <玩家>`**，
   否则才走 QQ。覆盖了 `#runTurn` 里另外两处同形状的发送（交不上 DSH、回合超时）。
   ★ 先例：投递失败那条早就这么做了（`#deliverToGame` 失败时不用 `#safeSend` 去 QQ 解释 ——
   那会把"游戏里没收到"变成"QQ 里收到一条莫名其妙的私聊"）。

**工程教训一句话：`kind`/`peerId` 是"会话身份"，不是"投递通道"。**
游戏内那条通道**借用**了 QQ 的会话身份，所以任何"发给这个会话"的调用都可能投错屏幕。
新增任何提示之前先问一句：**它该出现在哪块屏幕上？**

**B. 游戏内管理员查 TPS 被 bot 推回给使用者。**（这个问题**两个方向都错过一次**）

使用者问：「为什么我在游戏内要求bot检测TPS无法执行，在游戏外却可以」。日志三行摆在一起就清楚了：

```
07:31:07 [game-chat] 唤醒（keyword:小鲸鱼）「YoCerin」→ 按 QQ 100000001 跑一轮
07:31:07 🎛️ [servers] 已给这一轮写控制台授权（private:100000001·admin）   ← 授权是写了的
07:31:32 [game-chat] 说（公屏）：… 公屏这条通道我没有控制台权限，你自己在服务端控制台敲…  ← 它照着错话念
07:32:06 [dsh] [mcp-qq] tools/call mc_command {"command":"forge tps","kind":"private",…}  ← 同会话、QQ 里问就真去查了
```

差别**不在权限**（两边同一条会话键、同一个授权文件），而在**提示词**：

| | 我写的 | 实际表现 |
|---|---|---|
| 第一版 | 什么都不说 | 模型自己编出「那个「允许从 QQ 下指令」的开关没开」——对站在游戏里的玩家毫无用处 |
| 第二版 | 一句无条件的「游戏内这条通道**没有**控制台权限」 | **那是假的**（桥接明明已经给管理员那一轮写了授权）⇒ 它把自己的活推回给使用者 |

**最终修法**：`#onGameChat` 的来源标注**按说话人的 tier 分三支**（判据只用桥接自己算出来的事实）：

| 这一轮的说话人 | 提示词怎么说 |
|---|---|
| **管理员** + 至少一台服开了 `commandFromQQ` | **你能用** —— 要查 TPS/人数就**直接调 `mc_command`**，并把 `kind='private'` / `peerId=<那个QQ>` / `serverId` **给全**；**别让他自己去控制台敲** |
| **管理员** + 一台都没开 | 如实说"开关没开"，并指路**本机网页控制台的服务器页签**（他是管理员，那开关就是给他用的） |
| **非管理员** | 拿不到授权（桥接只给管理员写授权文件）⇒ 说"这条要管理员"，**不要**让他去打开任何开关 |

三支都提醒：**结果会进公屏**，所以挑着说（人数/TPS 可以；op 名单、白名单、封禁、IP 别提）。

## 8. 四个真机缺陷（这一版最值钱的部分）

四个都是**"不报错但会害人"**的形状，前三个是同一个病根的不同实例。

### 8.1 保存一次服务器条目，RCON 密码就没了

**现象**：控制台突然说「⚠️ 没配 RCON 密码」，而使用者明明填过。

**真机证据**（可复查，两条合起来才定性）：

- `config.json.bak`（02:48）里 `servers[0].password` 是 **5 个字符**；
- `config.json`（14:02）里是**空串**，而同一次写入把 `gameChat` 从"压根没有这个键"变成了 `true`
  —— 那是**同一次表单保存**的两半（他当时正是在勾「游戏内对话」）；
- `.bak` 只由 `POST /api/config` 写，而改后那份的 mtime 不是它 ⇒ 14:02 那次走的是 `/api/servers/save`。

**根因**（三段，每段单看都合理）：

1. 界面表单**从不回显密码**（后端只给 `passwordSet` 布尔），所以保存时**不带 `password` 字段**
   —— `ServerForm.tsx` 的注释写的就是「留空 = 不改」；
2. 后端是 `list[idx] = norm`（**整条替换**）；
3. `normalizeServerEntry` 把缺掉的 `password` 补成 `''`。

⇒ **每点一次保存就丢一次密码，而且不报任何错**：界面没有任何异常，只是控制台开始说"没配密码"，
看起来像配置没保存，**不像密码被删**。∴ 「留空 = 不改」那句话在修之前是**假的**（界面在说谎）。

**修法**：`resolveServerPassword` —— **空串/缺省 = 保留原值、非空 = 覆盖、`null` = 显式清除**
（与 `dsh.apiKey` 那条语义完全一致），两条保存路径都走它，且**按 `id` 配对、不按下标**
（下标在删过一台之后会错位 ⇒ 会把 A 的密码贴到 B 上，那比丢掉更难查）。
界面另加了一个**显式的清除入口**（「清除已保存的密码」勾选框，默认不勾、勾上就禁用并清空输入框、
回执说清代价）—— 因为"删除"这条语义只能由 `null` 表达，**界面上必须有地方可点**。

### 8.2 `GET /api/config` 把 RCON 密码明文发给浏览器

同一个病的**反方向**：密码住在**数组元素**里，上不了 `SECRET_FIELDS` 那张"固定路径"的表
⇒ `redactConfig` 漏了它。RCON 是 **op 级别**的通道，性质和 token 一样，
而界面上明明写着"永不回显已有密码"。

★★ **这两件事必须一起改**：先补脱敏，就必然出现"回传时缺字段"；那时若 `mergeConfigPatch`
不做逐条复原，**修了泄露反而开始丢密码**。这也是为什么两条修在同一次提交里。

### 8.3 `commandFromQQ` 被保存静默关掉

**现象**：使用者说「bot反馈允许从QQ下指令的开关没开，但是我应该是打开的才对」。

**根因**：`ServerForm` 里**压根没有**这个勾选框，而后端是**整条替换**
⇒ 他每点一次保存就被重置成 `false`，**界面上没有任何地方能看出来**；
他只能照 bot 说的去手改 `config.json`，手改完下次保存又被抹掉。

**修法**（这次修的是**病根**，不只是这一个字段）：

- 保存改成**按字段合并**：`normalizeServer({ ...prevEntry, ...incoming })` ——
  **提交什么就改什么，没提交的保持原样**（与 `mergeConfigPatch` 同一条纪律）。
  ★ **显式**送 `false` / 空串仍然生效（那是用户在勾选框里真的取消了勾）。
  ⚠️ 而 `''` 这个值有双语义：对 `password` 是"不改"，对别的字段是"清空" ——
  **新加一个密钥类字段时先想清楚它属于哪一种**。
- 快照与 `/api/servers` 白名单放行 `commandFromQQ`（界面才能显示它）；
- `ServerForm` 加勾选框、`ServerTab` 卡片上显示状态，并把**两条路的分工**写在勾选框下面。

**同一次还会被静默重置的字段**（全都"手改能配、界面一保存就没了"）：
`failThreshold` / `logEncoding` / `startWaitMs` / `rules` / `shell` / `startArgs`。
其中 `startArgs` 还有一个独立实例：界面**无条件**送 `[]`，而那个框**不回填**已有参数
⇒ 「打开表单 → 直接点保存」就把真实的 `@user_jvm_args.txt nogui` 清空了
（改成"留空 = 不改"，并如实标注"界面上清不掉，要清得改 config.json"）。

### 8.4 顺带修掉的两个"守卫撒谎"事件

- `verify-api-h13.mjs` 里手写的 `normalizeServer` 桩只保留 **7 个字段**，
  恰好把 `commandFromQQ` 等全丢了 ⇒ "合并"这条断言**假红**（看起来像产品代码的 bug，其实是桩在说谎）。
  改成用实现里那一份 `normalizeServerEntry` —— "二次实现迟早分叉"，这次分叉的是测试。
- `verify-bindings.mjs` 有一条断言把**真机 UUID 的前 8 位**写成了字面量
  ⇒ 脱敏把它换成占位值之后**假红**。改成"由那个常量推出来的前 8 位"，不再写死。

## 9. 其它改动

### 9.1 措辞收口：对外只有 `\mc`，群里不用 @

使用者实测反馈两处：「小鱼提醒绑定的教程中依然在说要@小鲸鱼，实际上不用，直接输入即可；
`/mc say` 指令依旧是正斜杠而不是反斜杠，检测其他指令有没有类似情况」。

- **@ 一直是多余的**：绑定通道的插入点在唤醒判定**之前**（谁也不会为了一串码去 @ 它），
  教人 @ 会让玩家以为不 @ 就没反应 ⇒ 三处文案（游戏内进服提醒、群里指路、私聊指路）
  都**明说"不用 @ 我"**，且**不许出现 `@小鲸鱼`**。
- **全仓扫了一遍 `/mc` → `\mc`**（文档、提示、示例、注释）。**只保留两类** `/mc`：
  说明"代码里这几个形状也认"的兜底清单，以及解释"为什么 `/` 会被当命令"的段落。
- ★ 断言落在三处：`verify-bindings`（进服提醒**通篇不许出现 `/mc`**、必须明说"不用 @ 我"）、
  `verify-api`（界面文案）、`verify-release-hygiene`（**出厂模板**里的说明文字）。

### 9.2 出厂模板也漏了（打包核对时抓到的）

发布包里的 `config.json` 是组装脚本从 **`config.example.json`** 复制出来的，
而那份模板的 `_commandFromQQ说明` 还写着「**两条路**都受它控制」（漏了游戏内那条）。
⇒ 等于给所有人发一份错文档。已修，并加了一条**发布卫生断言**：
模板说明**必须**点到三条入口、必须写着「听不听 vs 动不动」、且**不许**再出现"与游戏内无关"这类错话。

**教训**：改了语义要按"**用户能读到的每一份副本**"清点 —— `config.example.json` 是其中最容易漏的一份。

### 9.3 版本戳：从"四处靠自觉"变成"五处逐个断言"

打包时发现 `mcp-skills-server.mjs` 的 `SERVER_INFO.version` 还是 **`0.3.0alpha`**，
而它的注释里原本写着"本文件靠自觉保持一致，不是被断言钉住的" —— 这就是"第二个副本迟早分叉"的活例子

### 9.6 bot 的会话在 DSH 侧栏里是「未分组」——不是我们的 bug，但可以归到一个工作区下

使用者问：「bot 调用的对话全部是未分类，能否把这些对话放到同一个工作区之下」。
查清了机制（都有源码出处）：

- DSH Desktop 的会话侧栏**按工作区分组**：一个会话属于某个工作区，当且仅当它的 id 出现在那个
  工作区记录的 `sessionIds` 里；其余的进「未分组 / Ungrouped」
  （`@deepseek-ai/dsh-client-ui-workspace` 的 `groupByWorkspace()`：**只认 `workspace.sessionIds`，
  不做按路径的自动收编**）。
- 而桥接走 **SDK 那条路**：`dsh --profile sdk` 的 `agents.create()` 只传 `meta: { cwd }`，
  **没有任何工作区参数**（`@deepseek-ai/dsh-sdk-jsonrpc-server/lib/index.js` 的 `createSession()`）。

⇒ bot 的会话**必然**落进未分组，**这不是我们的 bug，也不是配置能改的**
（SDK 的 `initialize` 只收 cwd / provider / model / reasoningEffort / maxTokens）。
能改的只有 DSH 那份注册表 `<DSH_HOME>/storages/workspace.json`。

∴ 这一版加了一个 **dev-only 工具** `tools/link-dsh-workspace.mjs`（**默认干跑**）：
确保存在一个以 bot 工作区为路径的工作区，然后把 **header 里 cwd 与它一致**的会话挂进去 ——
判据与 DSH 自己 `attachSession()` 的校验**逐条对齐**（header 必须有 cwd、必须解析得到、
必须是目录、必须**等于**工作区路径）。写之前**备份**，且**要求 DSH Desktop 关着**
（那份注册表在它内存里也有一份，开着改会被覆盖；查不出在不在跑就**不写**，fail-closed）。

实测（真机）：**141 个会话**全部符合条件、0 个已在里面 ⇒ 一次就能全挂上。

★ 它有测试 `mocks/verify-link-dsh-workspace.mjs`（29 项，**已接进测试链**，链上 82 → **83 套**）：
拿**假 DSH_HOME**把**真写那条路**跑一遍 —— 因为**它动的是别的应用的数据**，
写坏了的后果是"使用者的 DSH 侧栏出问题"，那是最不该靠"看着像对的"交付的一类改动。
★ 两条纪律：只碰临时目录（不摸真机的 `%APPDATA%`）；**不 spawn 子进程**（直接 import 导出的函数，
顺带逼着工具把逻辑与 CLI 外壳分开 —— 受限沙箱里 spawn 带管道是 EPERM）。

⚠️ **不是一劳永逸**：DSH 的 SDK 路线不带工作区，所以**新会话仍会落进未分组**，
攒多了再跑一次即可。想彻底解决得 DSH 那边在 SDK 握手里支持 `workspaceId`（本版没做，
因为那是改上游契约，不是我们这个包能决定的）。

### 9.7 服务端那两个文件也能在编辑栏里改（`server.properties` + `eula.txt`）

使用者两条原话：「**开服时显示 `enable-rcon=false`，能否在桥接的编辑栏直接修改**」、
「**在编辑页面改了游戏端口也不能实际生效，并且不能自动同意 Eula**」。

**根因是同一件事：两边的配置各说各话，而界面只改了其中一边。**

| 配对 | 我们这份（`config.json`） | 它那份（服务端目录） |
|---|---|---|
| 游戏端口 | `servers[].port`（**我们往哪儿连**） | `server-port`（**它监听哪儿**） |
| RCON | `servers[].rconPort` / `servers[].password` | `rcon.port` / `rcon.password` |
| 启动许可 | —— | `eula.txt` 的 `eula=true`（**没有它服务端直接拒绝启动**） |

那一列右边的东西**只在服务端启动时被读进内存**，所以：

- 只改左边 ⇒ **改了等于没改**（使用者遇到的正是这个）；
- 只改右边 ⇒ **要重启服务端才生效**，而且会踢掉在线的人；
- `eula=false` ⇒ 控制台只留一句 `You need to agree to the EULA in order to run the server.
  Go to eula.txt for more info.`，**使用者不知道该点哪里**（真机 `snowmemory` 的日志里就有这一句）。

**这一版落的做法**（编辑一台已有服务器时出现的那一块）：

- **托管的行只有四行**：`server-port` / `enable-rcon` / `rcon.port` / `rcon.password`，加上
  `eula.txt` 里的 `eula`。其余**逐字保留**（行级替换，**不是** parse→stringify —— 后者会丢注释）；
  缺的键追加到末尾；CRLF 文件改完仍是 CRLF；值本来就对 ⇒ **一个字节都不写**。
- **写前备份 + 写前重读**（乐观并发）：文件刚被别处改过就**拒绝写**，而不是盖掉。
- **写服务端那份的同时同步我们这份**（`syncToConfig`，默认开）—— **只改一半等于没修**。
- **路径只从归属档的 `cwd` 或 `servers[].cwd` 推**，找不到就如实说"不知道目录"，**不去盘上乱找**
  （找错文件 = 改了**别的服务器**的配置）。「这些目录都不存在」与「这个目录里没有
  `server.properties`」是**两句不同的话**。
- 界面上直接显示**哪几个布尔对不上**（`mismatch{port,rconPort,password}`）：游戏端口那一项还会
  点破"**这就是『改了游戏端口不生效』**"。
- ★★★ **保存主表单时若游戏端口变了，会主动回读一次**：真的还对不上就①如实说、
  ②把那一块的 `server-port` 框**替他填成刚输入的值**、③**不自动关窗**（还有一步要人做）。
  读不到文件时**什么都不说** —— 不凭空宣称一个没核实过的差异。
- ★★ **`eula.txt` 是"同意条款"的动作**：只有「同意 EULA（写 `eula=true`）」那个按钮会送
  `agreeEula`，**不放在"保存"里顺手做掉、不预勾**，旁边给出条款原文的链接。

**真机取证**（两台服各一个反例与正例）：

| 服 | 我们这份的 port | 文件里的 `server-port` | 结论 |
|---|---|---|---|
| `snowmemory` | 25566 | 25565 | ❌ **对不上 —— 使用者报的"改了不生效"就是它** |
| `forge1` | 25565 | 25565 | ✅ 一致；`eula.txt: eula=true` |

★ 两条实测澄清（写下来免得以后推断）：

1. **"跑着的时候改会被服务端覆盖"是句流传的话，至少在这台机器上不成立** —— 实测停止服务端
   之后 `server.properties` 的 mtime 没变（17:48 的文件 / 17:57 的停止日志）。
2. ⚠️ **边界**：`forge1` 的归属档里 `cwd` 是空的（`running.json` 被重写过）⇒ 它的路径**推不出来**，
   界面上如实说"先在「工作目录 cwd」里填上服务端根目录"。这不是缺陷，是"**不猜**"这条纪律的代价。

## 11. 已知边界 / 未决（如实列）

1. **控制台授权文件是明文、模型能伪造** —— 挡得住外部陌生人，**挡不住模型主动恶意伪造**。
   要堵它得让宿主把会话身份透传到 MCP 层（改宿主契约，本次没做）。
2. **游戏内没有"真·斜杠命令"** —— 现在靠"游戏内聊天形态"（`\mc bind`）。
   要真命令 / 推送式事件 / 第二因子，需要**单独的服务端插件或模组**：本版**刻意不写服务端代码**。
3. **只有本程序拉起的服务端才有控制台日志**（别人手动起的服读不到东西，日志里会有一行说明）。
4. **身份有一条"按名字回退"的路**（`lookupByName`）：它解决的场景是"桥接启动时玩家已经在服里"
   （拿不到登录行 → 拿不到 UUID）。**它的强度等于服务端对名字的认证**：
   `online-mode=true` 时没问题；**离线模式或前面挂了代理时**，"顶着管理员的名字进来"就能拿到
   那一轮的 op 级授权。真机当前是 `online-mode=true`（UUID 版本位是 4 = 正版随机 UUID）。
   ★ 要不要收紧（权限要求 UUID 必须来自服务端写的登录行、名字回退只用于提醒）**尚未决定**。
5. **两个 JVM 同写一个世界 = 存档损坏**。我们靠"端口活着就绝不重复拉起"躲开它，
   但那是纪律不是锁 —— 别在别处手动再起一个。
6. **`starting` 那笔的根因没有复现**（见 §4.4）：补的是缺失的状态，不是某个已定位的 bug。
7. **`mc_command` 的 `kind`/`peerId` 要模型自己给对**（已把三个参数在提示词里给全，但这是提示词层的约束）。
8. **RCON 的应答不保证只属于这一条命令**（真机实测：很多命令不回话）⇒ 控制台不能当精确终端用。
9. **定时任务的内容由模型现写** ⇒ 会花钱（一次调度一次模型调用）；**错过不补发**是刻意的。
10. **没有 CI**：84 套目前只能在开发机上手动 `npm test`。公开后建议加一条"PR 上跑离线套件"的工作流，
    ⚠️ 但要注意有些套件在受限环境里会**跳过并退出 0** —— CI 上要么给足权限真跑，要么**显式承认它们没跑**。
11. **没有 `.github/` 下的 ISSUE 模板 / CODE_OF_CONDUCT**。
12. **发布包没有在第二台干净机器上验证过**能否跑起来（这一条从 0.2.7 打包时就挂着）。
13. **语义唤醒那道判定仍可能误判"沉默"**（它只做减法，但减法也会做错）；`--wake` 有报告可查。
