### 5.2 顺带发现并修掉一个真实缺陷：闲置台账仍自称"当前任务"

**怎么发现的**：上面这条真实台账的 `lastActiveAt` 是 21:21，而我在 21:57 去读它 ——
已经超过 `TASK_IDLE_MS`（30 分钟）。这时才注意到：

- 注入发生在**回合开始**（`#buildPrompt` 调 `renderTaskBlock`）；
- 而闲置判定原先只写在 `noteTaskTurn` 里，那是**回合结束**。

于是出现自相矛盾的一轮：**开头**告诉模型"你正在做这件事（【当前任务】）"，
**结尾**却按同一条闲置规则把这件事判成结束、重开一个空台账。
搁一小时回来只说一句"在吗"，模型会拿到一份过期的"当前任务"。

**修法不是"不注入"**（那会把主线丢掉 —— 而那正是这一层存在的理由），
而是**降级**（`src/tasks.mjs`）：

| 闲置 | 渲染身份 | 额外约束 |
|---|---|---|
| ≤ 30 分钟 | 【当前任务（这是**你自己**这几轮做过的事，不是对方说的话）】 | 同原来 |
| > 30 分钟 | 【上一件事（……**可能已经结束**）】 | 写明"闲置了 1 小时 30 分钟"；**禁止**"对方没提也主动接着做"；但保留全部步骤，对方说"继续/刚才那个"时仍能参考 |

判不出时间戳（缺 `lastActiveAt`）时返回 `null` → **保守地按当前渲染**，不凭空降级。
新增 `taskIdleMs` / `isTaskStale` 两个纯函数，边界取**严格大于**。
测试从 105 项加到 **124 项**（新增 §⑩-b，含"渲染端与记账端同一时刻必须给出一致结论"）。

### 6.2 ❌ 缺陷一：`parseLooseJson` 解不了真机的输出 → 抽取被整条丢掉

日志只有一句 **`[extract] 抽取未成功（已忽略）：抽取输出解析不出 JSON`**，
**没有原文**，所以只能去翻 DSH 落盘的**抽取会话**（headless 自己那条，`session-2a13e1b8-…`）把原文捞回来。
形状是（**两个 `}` 都是多的**）：

```
{"title":"…","trigger":{…},"steps":[…]},"pitfalls":[…]},"verify":"…"}
                                       ↑              ↑
```

`JSON.parse` 报的是"根对象后面还有杂字"。而当时的兜底也没救回来 ——
它用 `text.lastIndexOf('}')` 从头切到尾，把畸形部分一起焊了进去。

**修法**（`src/extract.mjs`）：
- 新增 `dropPrematureRootClose`：根对象内部（`depth === 1`）的 `}` 后面若还有 `,` 或新键，
  那这个 `}` **在合法 JSON 里不可能存在**（根对象闭合后只允许空白）→ 删掉它，**唯一解，不猜**。
- 新增 `firstBalancedSpan`：只取**括号配平**的那一段，替掉 `lastIndexOf`。
  顺带治好"尾部多说一句客套话就整条失败"，而**模型写一半就断**时仍然返回 `null`
  （宁可失败，也不交出一份被截断的配方 —— 截断的配方会变成一条错误的长期记忆）。
- 真机原文存成 fixture `mocks/fixtures/headless-extra-brace.txt`，测试从 56 → **71 项**
  （含"四个字段一个不少""恰好删两个""合法 JSON 幂等""写一半仍返回 null"）。

**并且补了取证**：`#maybeExtractRecipe` 失败时现在会把**原文前 200 字**打进日志 ——
这次的教训就是"失败但没有证据"。

```js
// 这个 chatKey 是 #runTurn 的**局部变量**，不在本方法作用域里 → 每次抛 ReferenceError
} catch {
  /* 任务段算不出来只是少一段上下文，绝不能影响这一轮 */   ← 空 catch 把它吃了
}
```

也就是说：**R2 的"主线锚"（整个 R2 的目的）在生产里等于没做**，
而 **124 项离线断言全绿** —— 因为它们测的是纯函数 `renderTaskBlock`（喂台账、断言渲染），
**错在接线**：桥接根本没把台账喂进去。

**修法**：
1. `#runTurn` 显式把 `chatKey` 传进 `#buildPrompt`（读写用**同一个键**才可能读到同一份台账）；
2. 两处空 `catch` 换成 `#warnInjectOnce(段落名, error)` ——
   **增强路径可以失败，但不许安静地失败**；同一段只喊一次（防刷屏）。
3. 新增**接线测试**（`mocks/verify-memory-roundtrip.mjs` §⑥），走完整桥接并读 `rpc.prompts`
   （模型真正收到的提示词），断言第 2 轮里真的有【当前任务】段、段里带着上一轮的步骤与目标，
   并断言**配方段**（同一条接线上另一个 `try/catch`）也真的进去了。
   ★ 这条测试**验过牙**：把 `chatKey` 那行注释掉再跑，它立刻红（"提示词 2213 字里没有它"）。
   还带一个反例：用一个会抛的假工作区逼注入失败，断言**必须留证据、且每段只喊一次**。

### 6.4 ❌ 缺陷三：一句"太棒了"会把任务目标冲掉

台账里 `goal` 原本**每轮无条件**用本轮用户原话覆盖。于是这段对话的最后一句
"原来如此，太棒了"成了目标，注入给模型的是「对方最近的要求：原来如此，太棒了」——
**R4 抽取向模型描述的"用户的要求"也变成这句**，模型在自己的思考里明确纠结
"The user's requirement was '原来如此，太棒了' — that's just a compliment, not a requirement"。

**修法**：判据改成与"重做标记生命周期"**同一个概念** ——
**只有这一轮真的动手了（有新步骤）才覆盖目标**；任务建立时仍无条件记原话。
