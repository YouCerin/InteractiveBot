# 0.2.4 发布说明：自主发表情包

> **一句话**：机器人现在能从**你自己导入的表情库**里，按场景挑一张发出去 ——
> 判定全在本地（运行期**零模型调用**），发不发、发哪张都留了可回溯的理由。

这一版的主线只有一件事：**把"发表情包"从"一个不存在的承诺"做成真的**。
在此之前，仓库里只有一条 `[sticker:名字]` 的标记通道，而它的表情表默认是空的、
只能装 QQ 内置表情的 id（`markers.mjs:113`）。真正的表情包功能一直挂在
roadmap 的 M5' 上（`docs/0.2.1-memory-prompt-plan.md` §2b.8）。

---

## 1. 用户能看到的

### 两步用起来

```bash
cd packages/qq-bridge
node src/index.mjs --stickers --import "C:\我的表情包"   # ① 导入（离线、零成本）
node src/sticker-tag.mjs --apply                        # ② 打标签（离线、一次性）
node src/index.mjs --stickers                           # ③ 看状态：几张能用、为什么没发
```

### 三条触发路径

| 路径 | 说明 |
|---|---|
| **模型主动** | 回复里写 `[sticker:标签]`（标签由桥接按"库里真有货"现算后教给它） |
| **桥接自主补** | 模型没写，但正文像"在笑/无语/安慰" → 桥接补一张，挂在回复**最后一条**后面 |
| **只有表情** | 模型只写了标签、没有正文 → 单独发一条图（不会被"没有输出文字"的兜底顶掉） |

### 频率三档（默认 medium）

| 档 | 每 N 轮最多 1 次 | 同会话最小间隔 | 每轮上限 | 每群每日上限 |
|---|---|---|---|---|
| `low` | 3 轮 | 120 秒 | 1 | 30 |
| **`medium`（默认）** | **2 轮** | **30 秒** | **1** | **80** |
| `high` | 每轮 | 10 秒 | 2 | 200 |

### 新命令

```bash
node src/index.mjs --stickers                        # 库状态 + 各标签张数 + 最近 12 条决策
node src/index.mjs --stickers --import <目录|文件…>  # 导入（不写 --scope 就是**全局库**）
node src/index.mjs --stickers --export-tags [--apply] # 按标签整理成一份看得懂的目录（默认预演）
node src/index.mjs --stickers --prune [--apply]      # 清理"文件已不在"的僵尸条目（默认预演）
node src/sticker-tag.mjs [--apply] [--all] [--force] [--limit N] [--sample N]
```

**打标签有两条路，共用同一份引擎**（`src/sticker-tagging.mjs`）：

| 入口 | 说明 |
|---|---|
| 控制台「扩展 → 表情包」卡片上的**重新打标签**按钮（主入口） | 带预检（点之前就知道要调用模型几次）、二次确认、进度条、停止；跑完留结果摘要与失败清单 |
| 命令行 `node src/sticker-tag.mjs`（备用入口） | 界面打不开、或想抽检准确率（`--sample 30`）、只跑前几张（`--limit 20`）时用 |

★ 按钮点的是"**把库里所有图重打一遍**"；**人工改过的标签（`source:"manual"`）默认跳过**，
不会被模型覆盖（人改标签往往是因为模型打错了，覆盖它等于把人纠正过的错误再犯一遍；
要连它们一起打只能用命令行的 `--force` —— 刻意收窄，那是一个"把人工成果冲掉"的动作）。

**关于"图库放在哪、按标签整理后在哪"**：库本身**不是按标签存的**，而是
**内容寻址 + 按会话分目录**（`stickers/group-700000001/<哈希>.png`）—— 这套布局
是给机器用的（同一张图只存一份、跨群不串、去重天然成立）。所以人想看"按标签的
样子"要导出一份**视图**：`stickers-by-tag/<标签>/<中文标签>__<哈希>.png`，
待打标签的图单独落在 `_pending/`。导出**只读源库**、默认**复制**（`--link` 用符号
链接但要系统权限，建不成会如实告诉你回落了）。

## 2. 三条设计决定（以及为什么）

### ① 标签按「**回应动作**」分轴，**不按情绪**分轴

按情绪分（开心/难过/生气）会立刻撞上语义重叠：`无语 / 敷衍 / 嫌弃 / 摆烂`
在语感上互相咬，打标签的人（不管是小模型还是人）自己都分不清 ——
最后表现成机器人**随机发错图**。

改成按"这一轮回复在做什么动作"分轴之后，标签天然互斥、能直接对应"什么场景该发"。
22 个标签里 **19 个是表达类**（模型可主动 + 桥接可自主补），
**3 个是功能类**（`打招呼 / 晚安 / 任务完成`）—— 功能类**只有模型能挑**：
自主判定只看得到词面，判不了"这一轮到底算不算收工"，而 `task-done` 配在一句
"你可以再试一次"上就是明确的错。

### ② 判定**必须在宿主**，技能里只放清单与标签

`skills/sticker` 是一个技能（可整目录拷走），但它**没有工具、也没有决策钩子**。
这不是漏了，是边界：

* 判定要碰配额台账、隐私/投递闸门的**顺序**、拟人延迟、发送失败冷却
  —— 那些是宿主的状态机，而技能契约要求"不 import 宿主内部模块"；
* 判定必须是**可离线单测的纯函数**（`sticker-decision.mjs` 有 83 项断言），
  塞进技能目录等于让"发错图"这条最贵的失败路径离开宿主的测试覆盖面；
* **技能没有"自主插入"的钩子**（入口契约只有 `setup/available/promptSections/
  dispose/diagnose`）—— 这件事技能**做不到**。

∴ 规矩写进了 `docs/插件设计规范.md` §7：**功能是技能，判定必须在宿主**。

### ③ 四层漏斗，**每一层都是否决层**

```
0 能力（技能开 / 库里有可用图 / 文件真的在）
1 硬否决（报错·道歉·权限被拒·隐私·**对方认真求助**·正文过长）★ 不可配置
2 触发（模型写的标签优先；否则从正文抽态度 → **抽不出就不发**）
3 打分（低于阈值不发 —— 绝不为"用上这个功能"而凑一张）
4 配额（冷却 / 每 N 轮 / 每日上限 / 同图冷却）
```

**★ 顺序纪律**：自主补图是**先看正文说了什么，再选图**，而不是"想发图然后找个理由"。
反过来的话就会出现"模型回了一大段正经技术答案、末尾贴一张无语脸"。

**★ 硬否决为什么不做成配置项**：与隐私闸门同一个理由（`bridge.mjs` 的既有注释）——
做成开关就等于给了一个"把道歉场景变成发表情"的入口，而关掉之后没有任何提示。

## 3. 开发过程中**实测抓到**的问题（都修了，都留了断言）

这一版有六处是**跑出来才发现**的，不是设计时想到的 —— 按发现顺序列在这里，
因为它们的形状都是"看着像对的、其实会静默出事"：

| # | 症状 | 根因 | 现在怎么防 |
|---|---|---|---|
| 1 | 纯红与纯蓝两张**完全不同**的图被判成"近似重复"，其中一张被丢掉 | aHash 对**纯色图**退化成同一个值（每像素与自身均值比） | `isFlatFingerprint()`：纯色图（全 1/全 0 指纹）排除在近重复判据之外 || 2 | 普通正文「重启一下**就行**」被判定成"无语"，会自主发一张无语脸 | `行` 是 `deadpan` 的线索，而中文里"就行/银行/运行"到处都是 | `SAFE_SINGLE_CHAR_CUES` 白名单：裸单字线索必须显式登记才参与匹配 |
| 3 | 「运**行一下就**知道了」被判定成 dismiss（明明只是"你去跑一下就知道"） | `String.includes()` 在中文里天然会在句子中间命中 | 短线索要**左侧是句子边界**，且**句首或整条基本就是它** |
| 4 | **用文档里那个目录名建的库，运行期一张图都选不到** | 清单写 `chat-700000001`，而 `scopeDirName` 算出的是 `chat-group-700000001` | 换算规则改成"只做字符白名单"（`group:123` → `group-123`），并加断言钉住"用户给的 scope 与运行期 chatKey 同口径" |
| 5 | 判定为"不发"时**只有决策流水、没有日志** —— 而函数的注释写着"两条都留" | 只有异常路径调了 `skip()`，正常 skip 直接 return | 走同一条 `skip()`（并留断言：日志与流水都必须有） |
| 6 | 状态页在"有 3 张待定、0 张可用"时让你**重新导入**（而图已经在库里了） | 空库与"有图没标签"共用一个分支 | 分开说，并给出**对的**下一步（去打标签） |
| 7 | `--extensions` 给「表情包」打了一条假的"启用但一个工具都没有 —— 检查 registerTool" | 判据只看 `tools.length === 0`，而这个技能是**刻意不要工具**的 | 判据改成"**声明了却没注册**"（`declaredToolCount`）；第一次修还写错了字段名（`s.declaredTools` 卡片上根本没有），第二次才对 |
| 8 | 导出视图说"已清掉 3 个过期文件"，**磁盘上一个都没少** | `rmSync(p, { force: true })` 在 Windows 上**静默不删也不抛**（本项目第五次踩这个坑，前四次在 `memory-files` / `personas` / `recipes` / `tasks`） | 改用 `unlinkSync` + **删完 `existsSync` 复查**；没删掉的**如实报出来**（"没能删掉哪几个"），不再假装清干净 |
| 9 | 导出视图**重复导出会堆过期文件**（改了标签后旧位置那张还在） | 第一版导出只会往里写、从不清理 | 重跑导出先清掉自己生成的内容（只删带 `__` 的、以及 `_pending/` 里的图；**手工放的不动**），空目录一并删掉；并有断言钉住 |
| 10 | 同一标签下超过 3 张图时，**永远只有哈希最小的那张会被选中**（库里另外 9 张等于白导入） | 同标签图的分数完全一样，而原实现按文件名固定排序取第一 | 改成"先排序、**只保留最高分那一档、在其中随机取一张**"；随机源可注入，所以测试不会变成"有时过有时不过"。顺带回答"每条标签要多少图"：**3 张左右就够**，多的不再提升精度但也不会浪费 |
| 11 | ★★ **157 张真实 GIF 里 117 张（75%）被静默拒收** | 入库用的是 **2MB 统一上限** —— 对 PNG 合理，对动图完全不成立（动图几十帧堆起来，实测分布 `<1MB 12 / 1-2MB 28 / 2-5MB 109 / 5-10MB 8`） | 判据改成"**先看画面尺寸**（>2048 判为照片/长截图，原因里写出实际尺寸），**再看按格式分开的字节上限**"（动图 20MB、静态图 4MB）；新增 `readImageSize`（只读头部：PNG IHDR / GIF / WebP VP8 / JPEG SOF） |
| 12 | ★★ 文件名先验**一张都定不下来**（全是哈希名） | 落盘名是内容哈希，**"这张图是什么"在入库那刻就丢了** —— 而表情包的原始文件名常常自带语义（`蓝色大肥鱼_笑_….gif`） | 条目里记 `originName`（原始文件名）+ 新增**文件名先验**（零模型调用）：实测 157 张里 **98 张**靠文件名就能定下来，**省掉约六成模型调用** |
| 13 | ★★ 模型**明确点名**要的图被阈值静默拒掉 | 全局库的图只有 2 分（全局兜底 +0、主标签命中 +2），低于默认阈值 4 —— 而阈值本意是挡"**自主猜测**不够确定"，不是挡模型的明确请求 | 阈值对"模型点名且确实是该标签的图"**不参与判定**（配额仍然参与：模型不能绕过频率）；自主那条路照旧受阈值约束 |
| 14 | 文件名先验表里写了词表里**不存在**的标签（"鼓励"），那一族图被静默跳过 | `normalizeLabelId` 返回 null，命中即丢弃 | 加断言：先验表里每个标签都必须能在词表里落地；实测就是这条抓到的 |
| 15 | ★★ 我加的"发送上限 2MB"**把 155 张里的 115 张滤掉**，`tired / agree / slack` 等标签一张都发不出去 | 那是个**基于猜测的保守值**（"8MB 请求可能超时"），而**实测协议端不看体积**：5.07MB 的 GIF（base64 6.76MB）**453ms** 上传成功（`snowluma` 日志 `[Highway.Image] uploading 5319636 bytes … fast-upload hit`） | 默认改成 **50MB（≈不拦）**，只作兜底（防误导入的超大文件）；加断言钉住"默认值是宽松的" |
| 16 | 更早的误判：以为是"发送通道不行" | 实际上**从来没走到发送** —— 所有轮次都卡在判定层，日志里零次 `[sticker] 已发` | 现在有真实分档探针记录（0.39/1.46/2.49/5.07MB 全部 200 且协议端确认上传），base64 发图这条**以前标为"未验证"的边界**已经验证 |
| 17 | ★★ **识图对表情包基本没用**：同一批图连文件名都能一眼判对，模型却逐张判错 | 做了两个对照实验才定位：① 纯绿图问颜色 → 答「绿色」，**无图对照答「蓝色」** ⇒ 它**确实看到了图**；② 真实表情包逐张问 → `问号`判成"被萌到"、`一切都好`(OK 手势)判成"无语"、`加油`判成"无语"。所以不是链路问题、也不是额度问题（`completion=12` 秒回），是**这个模型认不出表情包的语义** | 识图结果与**文件名先验对照**，不一致的写 `disputed` + `originHint`；标注台加「只看识图与文件名冲突的」筛选项 —— 那是**最值得人看一眼**的一批，不必全库挨个过 |
| 18 | 短线索「2 字必须句首或占正文 ≥40%」把 `这也太绝了` 判漏了 | 那条规则是为了挡住 `运行一下就**知道了**`，但它对"**词组结尾**"形态的 2 字线索太严（`绝了` 明明在句尾） | 2 字线索只要**左侧是边界**就算命中（它们是绑定短语，歧义低）；3 字线索才要"句首或基本就是它" |
| 19 | `太累了` / `太绝了` / `太惨了吧` 全判漏 | 句末助词「了」按 `\p{L}` 算"词内字符"，加上左侧的「太」，两侧都被挡 | 新增 `TAIL_PARTICLES`（了/吧/呢/啊/呀/啦/嘛…）**只在右侧**算边界；同时给词表补 `太累`/`太绝了`/`太惨` 这类"太X"形态（**数据问题不该用逻辑绕**） |
| 20 | 学自同类实现的三条防错机制（`exclude` / 压制对 / 单字减半） | 我原来只有 `exclusive` 字段，而它**只写进提示词、代码里不生效** | ① `exclude`：出现即**整条作废**（防语义反转，如 `被怼≠挑衅`）；② `SUPPRESS_PAIRS`：近义标签同时命中只留更具体的（**保守**，同类实现踩过"压太宽"的坑）；③ `SINGLE_CHAR_SCORE = 0.5`（防"怼/逗/梗"压过"摆烂"） |
| 21 | 风险类内容**完全没有闸门** | 本项目最不能接受的是"账号被处置"，而发一张带脏话/擦边的图是最便宜的入口 | 新增第 23 个标签 `risky`（慎发）：打标签时让模型判 `risky: true`，**默认不进候选**（不是"分数低"）—— 打分可能因"本会话 +3"把它顶到第一，所以必须在**建候选那层**挡。放行要显式开 `skills.sticker.allowRisky`（默认关），拦下多少张**如实写日志** |

另外两处是**测试夹具**自己的问题，但同样值得记：
第一版 e2e 忘了给 mock 的 `selfId`（于是 @ 永远不成立、整套断言因为"压根没被唤醒"而失败）；
第二版两轮回复用了同一句话，被桥接的"内容完全相同就跳过"去重挡住 ——
**测的其实不是配额**。

## 6. 如实写出的边界（不装作没有）

1. **近重复检测只对 PNG 有效**：项目没有图像依赖，本机那个 ffmpeg 是 SnowLuma 的
   Electron 插件、不是可执行文件。JPEG/WebP/GIF 只按内容哈希去重，导入时会
   如实报出"这 N 张没做近重复检测"。
2. **纯色图之间不会互相去重**（aHash 的固有性质，见上表 #1）。
3. **跨群不借图**：`global/` 之外的图只给本会话用 —— 代价是新群攒够图之前可能
   一次都发不出来（那正是"低于阈值就不发"的取向）。
4. **聊天里收到的表情包不会自动入库**（第一版只做外部导入）：
   所以库里的每一张都是你审过的。
5. **打标签要花钱**（一次模型调用/张，用 `wake.judge.apiKey` 那把 key）；
   不想花钱就手改 `library.json` 里的 `primary` 字段。
6. **真机发图未验证**：`stickerBase64` 走的是 `base64://` 段（SnowLuma 文档
   确认支持该形状），但本机没有真 QQ 环境跑过完整链路 —— 这一条与
   `qq_send_image` 的既有说明同一状态（`docs/插件设计规范.md` §9.5）。
