# 0.2.8 发布说明：改名 + 发布前的两处真修补

> **一句话**：项目名从 `InteractBot` 换成 **`InteractiveRobot`（「小鲸鱼」QQ 交互式机器人）**
> —— 因为英文名 `qq-bridge` 在同一个生态里已被另一个项目占用；
> 顺手把开源前跑出来的两处真问题修掉（**隐私闸误判吞掉整条回复** + 两套"一直在跳过"的全链路套件）。

这一版**没有新功能**。它由两件事组成：一次改名，和一次"把一直没跑的测试真跑一遍"。

---

## 1. 改名（0.2.8）

### 1.1 三个名字，各管一件事

| 名字 | 是什么 | 这一版有没有变 |
|---|---|---|
| **`InteractiveRobot`** | 项目名（英文，GitHub 仓库名 / 发布包前缀 / NOTICE） | ✅ 从 `InteractBot` 改过来 |
| **「小鲸鱼」QQ 交互式机器人** | 项目名（中文，README 首行 / 界面标题 / 文档） | ✅ 新定 |
| **`小鲸鱼`** | **机器人自己的人设名**（提示词里那段人格，代码与配置里都用它） | ❌ 不动 |
| **`qq-bridge`** | **模块名**（`packages/qq-bridge`、`package.json` 的 `name`、MCP 服务名） | ❌ **刻意不改** |

**为什么模块名不改**：它描述的是"桥接"这个模块，而"机器人是谁"是另一回事。改它要动几十条路径、
文档引用与断言，收益只有观感 —— 而这一版已经有一次改名要验了，不该把两件事叠在一起。

**为什么要改**：`qq-bridge` 这个名字在同一个生态里**已经有人用了**
（[github.com/Derpyu520/qq-bridge](https://github.com/Derpyu520/qq-bridge)，描述与本项目几乎一样：
SnowLuma OneBot v11 ↔ DSH、social simulation、safe MCP tools、slang learning，278 星）。
本仓库此前**从未 push 过**（`git remote -v` 为空），所以对方不是从我们这儿 fork 的 ——
但两个几乎同名同描述的项目混在一起，对使用者没有好处。

### 1.2 用户能感知到的三处变化

| 位置 | 旧 | 新 |
|---|---|---|
| 发布包 | `InteractBot-<版本>-win-x64` | **`InteractiveRobot-<版本>-win-x64`** |
| 工作区里的项目简介副本 | `store/interactbot-intro.md` | **`store/project-intro.md`** |
| 控制台页面标题 | 「QQ 机器人控制台」 | **「小鲸鱼 · QQ 交互式机器人控制台」** |

**工作区那处会自己清理**：桥接每次启动都会重写这份副本，这一版起**顺手删掉旧名字的那份**
（`store/interactbot-intro.md`）。为什么要删：留着它不会报错，只会让模型可能读到**过期的**旧副本、
让使用者看到两个几乎同名的文件不知道哪个是活的。删它是安全的 —— 那文件**由桥接自己生成**，
不是用户内容（见 `src/project-doc.mjs` 的注释）。日志里会打印一行说明。

### 1.3 改名边界：**历史取证文档一字不动**

`InteractBot` 在仓库里还有 80+ 处，绝大多数在 `docs/0.2.x-*.md`、`docs/2026-*.md`、
`docs/rollback-*` 这类**历史取证记录**里。**这些一个字都没改** ——
它们记录的是"当时的真机输出、当时的命令、当时的包名"，改掉就不再是可以复算的证据。
代价是你会看到旧名字与旧包名，README 顶部因此专门写了一段"**曾用名 `InteractBot`**"。
（同一套纪律的另一面写在 `docs/开源发布准备.md`：证据要留，但**标识要脱敏**。）

## 2. 发布前的两处真修补

这一版最值钱的部分不是改名，而是**把"一直没真跑"的测试真跑了一遍**，当场抓到 17 项红。
逐条经过写在 `docs/0.2.7-release-notes.md` §5，这里只列结论：

### 2.1 隐私闸的「生物特征」判据认裸词 → **整条回复被吞**（产品问题）

原判据把**类别名本身**（`生物特征`）和裸词（`指纹`/`声纹`/`人脸识别`）都当隐私。后果：

- **我们自己的系统提示词**里有"不要记隐私：…生物特征（指纹/人脸/声纹）"这句话 → 提示词自己被判成含隐私；
- 输出侧一拦，发给对方的就是"这条我不方便发出来…"，**整条回复被吞掉**；
- 真机上更常见的撞法：有人问"指纹锁坏了怎么办"，模型正常回答里出现"指纹"两字 → 回答被吞。

这不是保护，是坏了：命中的是"**在聊这个话题**"，不是"在泄露某个人的数据"。
已按本项目原有的判据纪律（"要可核对的具体形状，不是空话"）收紧为只认**数据形态**：
`指纹数据/录入/模板/文件`、`声纹样本`、`虹膜图像`、`人脸·面部 + 识别数据/特征/照片库`、
`DNA 检测/样本/报告`、`基因检测`。
`verify-privacy.mjs` 里正例 3 条、反例 3 条（含**提示词里那一整句原文**）当锚点防止被改回去。

### 2.2 两套全链路套件"一直在跳过" → 第一次真跑就红（16 项）

`verify-onebot` / `verify-mcp` / `verify-live` 都要起带管道的子进程；受限沙箱里起不了，
于是它们按设计**整份跳过并退出 0**，而 `npm test` 用 `&&` 串联 ——
**"跳过"和"通过"在退出码上长得一模一样**，所以此前那句"全链 62 套全绿"里从来没包含它们。

真跑之后抓到的是套件自身陈旧（不是被测代码错）：分片时序（回显的提示词被切成 8~10 条，
而用例只等"收到第一条"就断言提示词尾部）、投递终检门会删 `【长期记忆】` 这类段标题
（拿"用户收到的那条"断言"提示词里有没有记忆段"必然假红）、0.2.7 给来源标注加的 `#id`
没进断言的字符类、`qq_api` 从黑名单改白名单后回绝话术变了而断言只认旧措辞。
