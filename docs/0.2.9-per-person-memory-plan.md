## 0. 一页结论

**要做三件，缺一不可：**

1. **按人档案层（L3）** —— `memory/members/<kind>_<peerId>/<QQ>.json`，**按会话隔离**。
2. **回合后抽取扩产出** —— 复用现成的 `src/extract.mjs`，把"一次调用只产配方"扩成"同时产出 `people` / `recipe` / `tried`"。
3. **相关性注入** —— 群聊只注入**当前发言人**那一份档案，独立条数上限。

**不做：**

- ⛔ 好感度（**D3 已决策整套删除，本文维持**，理由见 §8.1）。
- ⛔ 跨群身份库 / 自动跨群归并（§2.4 已否决，**本轮已确认维持**）。
- ⛔ 记忆强度浮点权重与衰减（**D9**；`mocks/verify-memory-usage.mjs` 里有断言禁止这类字段出现在账本里）。

**为什么这不是"重新设计"：** 0.2.1 方案书已经把这件事设计完并拍板（D1/D2b/D3/D4/D6 + §2.3 数据模型 + §2.4 存储布局），**只是一条都没落地**——`memory/members/` 不存在、`qq_memory_*` 四个工具全无实现、`extract.mjs` 只产配方（见 §1.2）。所以本文的实际工作是：**把原方案对齐到 0.2.8 的真实代码**，并补上原方案没写清的三件事（归属判定、落点的安全接线、可观测口径）。

## 2. 需求与非目标

### 2.1 需求（写成可验收的形式）

- **N-1**：群里连续对话 ≥ 20 轮后，磁盘上出现"关于某个具体群友"的条目，且**不依赖模型自愿提议**。
- **N-2**：模型**不需要知道对方 QQ 号**，也能把条目记到对的人名下。
- **N-3**：A 群积累的内容**不会**出现在 B 群的注入里（哪怕是同一个人）。
- **N-4**：提示词里能出现"这个人是谁、他关心什么"，且**有上限**、不挤爆上下文。
- **N-5**：任何一条档案条目都能回答"**谁、何时、哪条通道**写的"。
- **N-6**：档案**不会**因为定时整理而归零或丢字段。

### 2.2 非目标（明确不做）

- ⛔ 好感分 / 亲密度数值，以及它必然带来的门槛结算、冷静期、防刷分、管理端改分。
- ⛔ 跨群身份库、自动跨群归并（同一个人在不同群 = **两份**档案）。
- ⛔ 由档案驱动的外发行为（例如"主动私聊某人"）。
- ⛔ 让档案影响权限判定（权限永远只由 `roster` 按配置判）。

## 3. 目标架构

### 3.1 分层（只标本次新增/改动）

```
L0 原始层   logs/ + DSH session log                      （不改）
L-B 运行层  runtime/tasks · runtime/oplog · runtime/corpus （不改）
L1 全局层   MEMORY.md                                    （不改）
L2 会话层   memory/group-<群号>.md · private-<QQ>.md       （不改）
L3 成员层   memory/members/<kind>_<peerId>/<QQ>.json      ★ 本文新增
L4 归档层   memory/archive/<yyyy-mm>.md                   （已有规划，本文不涉及）
L5 审计层   memory/audit.jsonl                            ★ 加 person 维度
```

**为什么成员档是 JSON 而不是 `.md`**（沿用 0.2.1 §2.1 的理由，并补一条今天的新理由）：
它要装 `impressions` / `stats` / `domains` 这类**数组与对象**，用 markdown 存就得每次读回来做正则解析；而这个项目已经为"测试里二次实现解析"付过两次学费。**第二条**：`resolveMemoryPath` 是**只允许 `.md`** 的（`ALLOWED_EXT`），成员档走 `.md` 反而会被迫挤进"给模型读的自然语言条目"那一套里，语义会糊。

### 3.2 数据模型

`memory/members/<kind>_<peerId>/<QQ>.json`（例：`memory/members/group_700000001/100000001.json`）

```jsonc
{
  "userId": "100000001",
  "name": "无忘远霞",              // 最后一次核实的昵称（协议端核实，与 contacts.md 同源不同用途）
  "chatKey": "group:700000001",    // 冗余一份，便于单文件自查"我是谁的档案"
  "impressions": [                 // ≤8 条，给提示词用（0.2.1 原稿是 12，本文下调，理由见 §3.5）
    {
      "content": "在做 InteractiveBot，关心表情包与唤醒策略",
      "createdAt": 1790234219000,
      "source": "turn",            // keyword | turn | marker | admin —— 四条通道各自的标签
      "sentiment": "neutral",      // positive | neutral | negative —— 只是属性，D4：不驱动任何行为
      "atChatKey": "group:700000001" // ★ 与路径同值；写进条目是为了"整档搬走"时不丢来源
    }
  ],
  "stats": {                       // ★ 桥接确定性累加，与模型无关，永不由模型改写
    "messages": 412,
    "firstSeenAt": 1789271988269,
    "lastSeenAt": 1790234219000
  },
  "domains": {},                   // 二期（D2c）；本期**建字段不写值**，避免以后迁移
  "updatedAt": 1790234219000
}
```

**字段纪律：**

| 字段 | 谁写 | 上限 | 备注 |
|---|---|---|---|
| `impressions[]` | 抽取 / 关键词 / 标记 / 管理员 | **8** 条 | 超出走整理（淘汰最旧、最没被注入过的） |
| `impressions[].content` | 同上 | **120 字** | 超过**拒绝**并如实回报，**不静默截断** |
| `impressions[].sentiment` | 同上 | 三值 | 归一化失败 → `neutral`（不猜） |
| `stats` | **只有桥接** | — | 模型一个字节都碰不到 |
| `domains` | 二期 | — | 本期只建空对象 |
| `name` | 协议端核实的昵称 | 12 字 | 与 `contacts.md` 冲突时**以人工那份为准**（联系人表是主人显式维护的） |

> ⛔ **没有** `favor` / `score` / `affinity` / `level` / `weight` / `strength`（D3 + D9）。
> 建议在 `mocks/` 里加一条**与 `verify-memory-usage.mjs` 同形的断言**：成员档文件里出现这些键 → 测试变红。

### 3.3 归属判定：由代码裁定（D20）

**问题**：群里模型只知道昵称（"无忘远霞"），拿不到 QQ 号 —— 这个能力缺口早在 `docs/0.2.1-memory-diagnosis.md` 的 R2 里就记录过。让模型"填 QQ 号"必然导致幻觉与串人（把 A 的话记到 B 名下，而记忆会被注入之后每一轮）。

**方案**（三步，判据全在代码里）：

1. **桥接给编号**：抽取提示词里附一份**发言人清单**，编号来自真实身份，例如
   `#1 = 无忘远霞(100000001)`、`#2 = 抽奖非酋研究员(200000001)`。
   清单来源按优先级：本轮说话人 → 本会话近期语料（`corpus.messages` 里有 `user_id` 与 `sender_name`）。
2. **模型只许引用编号**：抽取结果的形状里，人一律写 `"who": "#1"` 或 `"who": "self"`（`self` = 机器人自己）。**不接受任何数字 QQ 号**（那是猜）。
3. **桥接做映射**：`#n → 本轮清单里的真实 user_id`。引用不存在的编号、或清单为空 ⇒ **丢弃该条并记一行日志**（不猜、不兜底到"当前发言人"）。

标记通道（`<<<MEMORY person …>>>`）同理：**只接受 `#n` / `self`**，模型写 QQ 号一律拒绝并在回执里说明。这与"写入权在桥接、判据在桥接"是同一条原则的延伸。

> ★ 顺带修 G4：`applyMemoryItems` 的 `senderId` 形参已经在传了，实现时把"当前发言人"作为 `#0`/默认归属即可——**不需要新增参数**。

### 3.4 写入通道矩阵（六条 → 各写哪一层）

> ⚠️ 下表是**原稿的设想**；实际落地时成员档改成了"跟人走的 `memory/people/<QQ>.md`"，
> 且新增了**情绪倾注**与**承诺**两条确定性通道（见 §11.1 / §11.2 / §11.11）。
> 两者都不写"印象"式的性格判断，只写**可执行的状态与需要**、以及**谁许了诺**。

| 通道 | 触发 | 依赖模型 | 能写成员档吗 | 走哪道闸门 |
|---|---|---|---|---|
| 关键词直写 | 用户说"记住 X" | ❌ 零成本 | ✅ 默认归属**当前发言人**（群里"记住"= 记他自己的事） | `screenEntry` |
| **情绪倾注**（0.2.9 落地） | 本地 cue 判定（状态 + 需要；含接纳/归属） | ❌ 零成本 | ✅ 固定写**当前发言人**的个人档 | `screenEntry` |
| **承诺**（0.2.9 落地） | 本地句式判定（双向） | ❌ 零成本 | ❌ 落**会话层**（群里 → 群文件，私聊 → 个人档） | `screenEntry` |
| **回合后抽取（本期新增产出）** | 每 5 轮一次，后台 | ✅ 一次小额调用 | ✅ 主要来源 | `screenEntry` + 归属映射 |
| 模型标记 | `<<<MEMORY person …>>>` | ✅（漏报率≈0） | ✅ 只接受 `#n`/`self` | `screenEntry` + 归属映射 |
| 管理员手段 | 控制台 / `--memory` | ❌ | ✅（可直接编辑/软删） | 人工；**覆盖前备份**，但**审计仍未做** |
| 整理 | 每小时 / 手动 | ❌ | ✅ **只能改 `impressions`** | 只做去重/淘汰，不改语义 |

**为什么必须有第 2 条**：G5 已经用两处独立证据证明"靠模型自愿"在真机上**一次都没成功过**（本机转录 0 次；参考项目 58 次运行同样 0 次）。原方案 §6 交汇点原本就写了"**一次调用同时产出** people/recipe/…"，本期只是把它做完，**不新造轮子**。

### 3.5 注入策略（严格按会话隔离，D21）

| 会话类型 | 注入哪些人 | 明确不注入 |
|---|---|---|
| 群聊 | **只有当前发言人**的档案（`memory/members/group_<本群>/<发言人>.json`） | 本群其它成员的档案（隐私面）；**其它群/私聊的同名档案**（串场） |
| 私聊 | 对方档案（与既有 `private-<QQ>.md` 互补，不合并） | 别人在群里留下的任何内容 |

**渲染**（与既有 `nickname` 段**合并成一节**，不要出现两段都在讲"这个人是谁"）：

```
【关于正在跟你说话的这个人】
他希望你叫他「管理员」（这条跟权限无关）。
· 在做 InteractiveBot，关心表情包与唤醒策略          ← impressions，≤8 条
· 他常来（累计发言 412 条，最后一次 3 小时前）        ← stats 渲染成一句人话
```

**预算**：每人 ≤8 条印象 + 1 行 stats。超出写"（另有 N 条未展开）"——**照既有风格如实说，不静默截断**。`INJECT_ENTRIES` 现在**没有字节预算**（D7 未落地），所以本期先给成员档一个**自己的**条数上限，字节预算作为前置项单独立项，不要顺手塞进本次改动。

**为什么 ≤8 而不是原稿的 12**：群会话实测已经到 114k 上下文（§1.3），而档案是**每轮都注入**的；8 条 × 120 字 ≈ 1000 字，是可接受的量级，12 条开始明显挤占。

### 3.6 落点与安全边界：必须同步改的 6 处 ★★

**这一节是防"静默失效"的关键。** 新增一个 `memory/` 下的子目录，会踩到项目历史上踩过的同一类坑（0.2.1 的 P3 就是它）：

| # | 必须改的地方 | 不改的后果 |
|---|---|---|
| 1 | `memory-store.mjs` 的 `verifyAndRestoreMemory`——它的 `dirs = ['', 'memory']` **不递归** | 成员档被绕过桥接改动后**既不回滚也不告警**（"记忆像是没生效"这类最难查的假信息） |
| 2 | `memory-store.mjs` 的 `listMemoryFiles()`（只扫根 + `memory/`） | 体检/控制台看不见档案 ⇒ "工具说没有、其实有" |
| 3 | `memory-inspect.mjs` 的注入预览 | 体检报告的②段与实际注入**分叉**（这是本项目最贵的一类假信息） |
| 4 | `memory-files.mjs` 的 `resolveMemoryPath` —— **只允许 `.md`** | 成员档**不能走它**；必须照 `recipes.mjs` 写自己的原子写 + 自己的路径校验，并保留同样四条底线：只相对路径、解析后再确认在工作区内、拒软链接、拒隐藏目录 |
| 5 | `memory-search.mjs` / `memoryPaths()` 的文件清单 | 搜索与"记忆体检"的覆盖面两边不一致（建议：**搜索包含档案，注入不包含全量**） |

## 4. 关键决策（本文新增，含"不这么做会怎样"）

| # | 决策 | 结论 | 理由 / 不这么做的后果 |
|---|---|---|---|
| **D20** | 归属判定 | 代码裁定，模型只说 `#n` | 群聊里模型拿不到 QQ 号；让它填 = 幻觉 + 串人，而串人的内容会被注入之后每一轮 |
| **D21** | 可见性 | **严格按会话隔离**（已拍板） | §2.4 三条理由仍成立：跨群归并要造跨群身份库；A 群内容进 B 群正是要防的串场 |
| **D22** | 存储 | JSON + 原子写，**不走** `resolveMemoryPath` | 它只允许 `.md`（`ALLOWED_EXT`）；硬塞成 `.md` 会把结构化数据逼回"正则解析"那条路 |
| **D23** | 关系感 | `sentiment` 标签 + 确定性 `stats`，**没有分数** | D3 已删除整套好感度；D9 禁止强度浮点；见 §8.1 |
| **D24** | 抽取通道 | 复用 `extract.mjs` 的一次性进程 | 新写第二条模型通路 = key 读取/超时/重试/失败兜底/计费口径各长一套，而其中每一样都出过错 |
| **D25** | 注入 | 只给当前发言人 + 独立上限 | 群会话已 114k 上下文；全群名单既是隐私面又是成本面 |
| **D26** | 整理 | 只改 `impressions` | QQagent 的实测事故：`replaceConsolidated` 重建成员对象 ⇒ **每次自动整理把所有人好感清零** |
| **D27** | 第三方评价 | ⚠️ **待拍板**（建议默认不记负面定性） | 群友可以拿"某某是小丑"喂给机器人，而它会被当成长期事实读回来。建议判据：① 只记**来源式**陈述（"据 X 说…"）；② 对**不在场**第三方的**负面**定性一律拒绝并写回执；③ 正面/中性也要求来源 |
| **D28** | 告警口径 | 零写入告警改成**按文件** | G7：会话级口径下，一条 `global` 就能让"本群档案冻住"永不告警 |
| **D29**（§11.11） | 接纳/归属 | 归入情绪通道，落 `need='stay'` → 「他希望你留在这里、继续和大家聊天」 | 用户点名的那类话**既不是倾诉也不是求助**，但它对行为有明确含义（继续待着、别缩回去）。判据分强弱档，弱档必须配正面词，否则「你在这里等我一下」会被当成接纳 |
| **D30**（§11.11） | 承诺落在**会话层**，且机器人那侧带 `sent` 门槛 | 群里的承诺 → `memory/groups/<群号>.md`；私聊 → 个人档；**只有消息真的发出去才记** | 承诺是"在这个会话里许的"，不是关于某人性格的长期事实（个人档不该被待办塞满）。而**被取代/超时那一轮用户从没看见那句话**，记下来就是自己骗自己的假记忆 |
| **D31**（§11.11） | 控制台覆盖前**先备份**（`memory/.backups/`） | 每次覆盖留一份被覆盖的原文 + 回报路径；备份失败**不阻断**写入但要如实回 `backupError` | 记忆整理**依赖人工修改**（规则版做不了语义合并），一次误存原本不可恢复 —— 真机已发生过一次（无审计、无备份、无回滚日志）。⚠️ 控制台写入的**审计仍未做** |
| **D32**（§11.12） | 未被唤醒的群消息**进上下文**（方案①） | 唤醒时注入「机器人上一条发言之后」的最近 ≤6 条（单条 ≤150 字），标注**不是对你说的** | 真机事故：群里一句没 @ 机器人的话紧接着"@机器人 你说呢"，模型手上只有三个字只能瞎猜。★ 代价如实写：这些消息会被送给模型 API（此前只有被唤醒的那几条会） |
| **D33**（§11.12） | 未唤醒的**倾诉**不直接记，改加一道**判定器闸门**（`memory.affect.prewake`，默认 `off`） | 三档：`off` / `shadow`（只写日志不落盘）/ `judge`；**判不出来一律不记** | 直接前移实测误记 4/5（"舍不得就别走呐"是对别人说的挽留），而个人档**跟人走**、记错了会跨群串场（D21）。默认 `off` 是因为这是使用者该自己拍板的取舍，不该由升级替他决定 |

**待拍板清单**（实施前需要你回答，本文不擅自定）：

1. **D27** 第三方评价的判据（上面给了一版建议）。
2. `habits`（用户习惯：语言/答复风格/活跃时段）**是否纳入本期**——0.2.1 §2.3 有它，但它是"关于这个人"里最容易写错、也最像画像的一类，建议放二期。

## 8. 明确不做的事

### 8.1 ⛔ 好感度系统（维持 D3）

**反对理由（前两条是硬的）：**

1. **你在 0.2.1 已经决策整套删除过**，原文："对一个**以功能性为主**的 AI，给群友打'好感分'没有意义——它不改变回答的正确性，却带来一整套台账/门槛/冷静期/防刷分/审计/管理端后门"。当时的成本估算：**约 600 行代码 + 一整套配置项 + 一组管理端交互 + 每 5 轮一次额外 LLM 调用**。
2. **结构性死穴**（`docs/0.2.1-memory-prompt-plan.md` §1.3 第 4 条，有外部项目实测）：参考项目的 `replaceConsolidated`（`memory.js:1172-1229`）会删全部成员文件重建；不做"按 userId 先快照、重建后贴回"，**每次自动整理都会把所有人好感清零**。根因是"把状态和档案放在同一个对象里"——只要引入一个会被整体重写的数值，这个坑就会重新长出来。
3. **它会被群友当玩具。** 真机转录里已经在玩"谁最毒舌""给我起个四字头衔"这类话题；一个能被感知的分数会立刻变成社交武器。而一旦它影响回复语气，就会出现"你对他比对我好"——这是**产品风险**，不是技术风险（技术上是能实现的）。
4. **不可解释 + 会静默改变行为**，正面撞上第 6/9 条（失败必须让人知道 / 不许安静地失败）。而且数值必然引出"要不要衰减"：衰减 → 违反 D9；不衰减 → 无限膨胀。

**如果最后仍然想要"关系会变"的感觉**，本仓库有一个已通过审查的合规先例可照抄 —— `src/recipes.mjs` 的置信度：

- 用**可观测量**算（成功/使用次数，拉普拉斯平滑 `(ok+1)/(used+2)`），**不是**情感判断；
- **只影响"要不要自动注入"**，永不参与权限、永不参与事实判定；
- **只降权不删**（60 天半衰期），过时的仍可检索；
- 低置信度**显式提醒**，而不是悄悄降权。

把同样形状用在人身上（互动轮数、被帮过几次、被纠正几次 → 只影响"要不要主动多说一句"），既拿到了动态，又不碰 D3 / D9 的任何一条红线。**唯一不要做的**是把它显示成一个跨人可比的分数。

### 8.2 ⛔ 跨群身份库 / 自动跨群归并
§2.4 已否决（本轮再次确认）：它要引入一个新子系统，而且与"不串场"的底线冲突。同一个人在不同群 = 两份档案；`contacts.md` 的昵称本来就是跨会话的，需要"叫法一致"时走它，不走档案。

### 8.3 ⛔ 记忆强度浮点权重与衰减
D9 + `verify-memory-usage.mjs` 的断言。档案的更新靠**去重/淘汰/软删归档**，不靠权重。

### 8.4 ⛔ 由档案驱动外发
"他好久没来了，主动戳一下"这类行为不在本期，也不在本项目"群聊不主动插嘴"的既有立场内。

## 11. 实施记录：落地结果与原稿的差异（2026-09-30）

**结论先说**：用户批准了**方案 A（关系记忆）**，并追加一条硬要求 ——
**"保证记忆记录真实有效，特别是在对面向机器人倾注情绪时需要记录"**。
落地时为了同时满足"三层结构更合逻辑"与这条要求，对原稿做了**一处结构性修订**。

### 11.1 与原稿的结构性差异：个人层改成"跟人走的 `.md` 层"

| | 本文原稿（§3.2） | 实际落地 |
|---|---|---|
| 个人层落点 | `memory/members/<kind>_<peerId>/<QQ>.json`（**按会话隔离**） | `memory/people/<QQ>.md`（**跟人走**：私聊 + 他发言的任何群） |
| 数据形状 | JSON（`impressions[]` / `stats` / `domains`） | `.md` 条目（复用既有 `appendEntry` / supersede / 快照 / 整合 / 使用账本 / 审计） |
| 情绪记录 | 独立的 `affect` 字段（状态机） | 一条**模板生成的条目**（时间状语 + 状态 + 需要） |
| 群聊层 | `memory/group-<群号>.md` | `memory/groups/<群号>.md`（含 `-slang.md`） |

**为什么改**（用户原话："优化记忆模块的格式，使之更加符合逻辑：全局、群聊、个人；
对个人的记忆应当在对应私聊中也有效"）：

1. **原稿的"按会话隔离"与这条要求直接冲突** —— 按会话隔离意味着"他在群里的档案"私聊读不到，
   而用户要的正是"私聊也有效"。
2. **`.md` 而不是 JSON**：个人层一旦"跟人走"，它就与既有那条"关于某人的自然语言条目"管线
   完全同构 —— 可以白拿 `appendEntry` 的去重/上限、H4 的更正标注、快照回滚、每小时整理、
   使用账本（H3 的"写了但从不注入"防线）、审计与体检。用 JSON 反而要**重写**这一整套，
   而那正是本项目为"二次实现迟早分叉"付过两次学费的地方。
   代价如实记录：**没有结构化的 `stats`**（"他常来，累计发言 412 条"这类话本期没做，二期）。
3. **三层判据变得可一句话说清**：**按"这条事在哪儿成立"分** —— 全局（对谁都成立）、
   群聊（只在这群成立）、个人（关于这个人本身）。
   由此推出一条**必须写进提示词的硬约束**：只有本群才知道的事**不许**写个人层，
   否则等于替当事人把它带到别的群去（串场）。

### 11.2 情绪倾注（用户追加的硬要求）怎么落的

原稿只把它当成"抽取产出的一个字段"，落地时发现**那样满足不了"必须记录"**：
本项目已两次实测证明靠模型自觉的漏报率接近 100%。所以改成了**第三条确定性通道**：

- `src/affect-cues.mjs`：本地规则判定（零模型调用、可离线测），输出 `state` + `need` 两个封闭值；
- `bridge.mjs#settleMemory`：命中即组条 → 走 `SCOPE.PERSON` → 落个人档。
  **不看 `complete`** —— 它取自用户那句话本身，与模型这轮跑没跑完无关
  （H1 三分类里"用户的话照常落盘"那一类）。

**"真实"这条要求落成了三道闸**（都有测试钉住）：

| 闸 | 拦的是什么 | 反例 |
|---|---|---|
| 转述排除 | 把别人的情绪记到他名下（一条会被永久注入的**假记忆**） | 「我朋友最近很累」 |
| 指物主语排除 | 把"那件事的状态"当成人 | 「这游戏崩溃了」「那服务器崩了」 |
| 弱词门槛 | 日常闲聊被写成情绪记录 | 「有点烦」单独出现 → 放过 |

**"有效"这条要求落成了两件事**：注入闭环（H3 记账，避免"写了但从不注入"）
+ 可观测（`[memory] 情绪倾注 → 记入个人档（原因）`、审计 `source: 'cue'`）。

**刻意没做的**（原稿 §8.1 维持）：好感分、情感强度、衰减。

### 11.11 接纳/归属、承诺、以及"改坏了怎么回去"（2026-09-30，用户追加）

**需求原话**：「记忆是我修改的，因为目前的记忆整理依赖人工修改；情感注入应当对
"没事，你在这里和我们聊天，大家都很高兴，这就是完美的时间线"这类话有反应，且作出承诺需要记录。」

这一轮是三件独立的事，起因是同一句话 —— 用户手改记忆（因为规则版整理做不了语义合并，
见 §11.8），所以 ① 判定器要覆盖"接纳"这类**非倾诉/非求助**的表达，② 承诺必须留痕，
③ 人工改的那条路必须留后路。

**① 接纳/归属（`need='stay'`）** —— `src/affect-cues.mjs`

| 判据 | 说明 |
|---|---|
| 强（单独命中即算） | `完美的时间线` / `别走` / `留下来` / `有你在(就)(真)好` / `你就是我们…` / `算我们…一员` / `我们(都)很喜欢你` |
| 弱（**必须**配正面词） | `你在这里` / `有你在` / `和我们聊` / `和你聊` / `你陪我们` + `高兴\|开心\|喜欢\|挺好\|真好\|欢迎\|完美\|不介意\|愿意` |
| 条目 | `他希望你留在这里、继续和大家聊天`（**不加**"细节他没说" —— 只有需要、没有状态时那句话显得莫名其妙） |

★ **两个只有真跑才看得见的坑**（都是测试变红抓出来的，不是设想）：
1. **正面词自己也要过否定闸** —— 「你在这里也**没人**高兴」被否定的是 `高兴`，
   只检查 `你在这里` 会漏掉整句；
2. **接纳判定必须写"没有**可用**状态"而不是"没有状态线索"** —— 用户那句原话末尾还带着
   「大家都**开心**了😉」，那是个**被拒的**第三方情绪线索。第一版写成 `!stateHit`，
   于是整句在下一道闸被判成"转述别人的事"，**最该记住的一句话恰好被别人的情绪挡住**。
   ⇒ 结论：被拒的线索本来就不参与结论，不该挡路。
   接纳信号与真实状态**可以同时存在**（「你在这里真好，不过我今天好累」），
   这时显式需要优先，没有显式需要则由接纳补上 `stay`，两种信号都不丢。

**② 承诺（`src/promises.mjs`，新文件）** —— 第三条不依赖模型的写入通道

| 判据 | 说明 |
|---|---|
| 硬话术 | `包在我身上\|交给我\|一言为定\|说话算数\|我保证\|我答应你\|我负责` —— **不要求后接内容**（"一言为定"本身就是全部内容） |
| 软句式 | 第一人称 + `会/一定/保证/答应/尽量/尽快/回头/等下/待会/明天/后天/今晚/马上/这就` + ≥2 字实质内容，并排除「我会**觉得**…」这类心理动词 |
| 时间+动作 | `TIME_RE` + 第一人称 + 动作（「我周四给你看结果」记；「我周三没空」不记） |
| 不许认 | 假设句（如果/要是/假如/有空/也许/可能）、转述第三方（「他说他明天会来」） |

- **双向**且**带来源**：条目是 `（我许的诺）…` / `（对方许的诺）…` ——
  否则「我明天帮你查那个仓库」是一条**无主的事实**；
- **落在会话层**（`SCOPE.FACT`，`source='promise'`）：承诺是"这个会话里发生的事"，
  不是关于某人性格的长期事实，个人档不该被待办塞满；
- ★★ **机器人那一侧的承诺只在消息真的发出去之后才记**（`#settleMemory` 的 `sent` 标志）——
  被取代/超时的那一轮用户**从没看见**那句话，记下来就是自己骗自己的假记忆。

**③ 控制台写入先备份** —— `src/memory-files.mjs`

起因是一次真机事故：`memory/groups/700000001.md` 被清空、`MEMORY.md` 同时少 79 字节，
