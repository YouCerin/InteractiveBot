# 0.2.5 更新日志（桌面壳：独立窗口 + 打包为 .exe）

> 这一版做三件事，外加一次旧资产清理。**三个目标都是用户直接提的**：
> ① 把整个 UI 移植到单独的界面，不再依赖拉起浏览器；
> ② 把项目的启动方式打包为 .exe 文件；
> ③ 为在本地启动独立 UI 提供方法（原来只能靠 `start.bat` 起网页端后台）。

---

## 1. 交付了什么

| 目标 | 落地形态 | 入口 |
|---|---|---|
| ① 独立界面 | Electron 38.8.6 壳（`desktop/`）：窗口 `loadURL('http://127.0.0.1:<端口>/')` —— 即**桥接自己伺服的那份 UI**，不是另做一份 | 发布包里双击 `app\InteractBot.exe` |
| ② 打包为 .exe | electron-builder **免安装目录版**；`InteractBot.exe` **200.5 MB**，PE 版本号 **0.2.5**（图标与版本号由 `signAndEditExecutable` 写进 PE 资源） | 同上 |
| ③ 本地启动独立 UI | 源码侧不必打包就能开窗口：`npm run desktop`；打 exe：`npm run desktop:pack`；首次 `cd desktop && npm install --ignore-scripts` + `npm run desktop:fetch` | `packages/qq-bridge/README.md` |

发布包：**202 个文件 / 约 413 MB**（`app/` 占 324 MB —— 这就是 Electron 运行时的代价；不带桌面壳时是 88.6 MB）。

**目标机器不需要装 Node、不需要联网**：Electron 运行时与包内 `vendor\node\node.exe` 都在包里，整目录拷走即用。

---

## 2. 关键设计（为什么这么做）

- **窗口里加载的是桥接伺服的那份 UI**（`http://127.0.0.1:<端口>/`），不是 `file://` 打开 `config-ui/dist`：
  否则"窗口里那份 UI"与"浏览器/导出那份"会变成两个真相，改一处忘一处。
- **壳不自己拼启动参数**：起后台只走 `node src/index.mjs --background`；「已经有一个桥接在运行」
  这句判据由 `src/index.mjs` **独家**负责，壳只负责把 `exit 1` + 那句话认成「直接连上去」而不是失败。
- **关窗口 = 收进托盘，机器人不下线**；真正退出只有托盘菜单的「退出并停止机器人」（会先 `POST /api/stop`）。
- **包根按证据找，不猜层数**：① 环境变量 `INTERACTBOT_PKG_ROOT`（若有人显式设）→
  ② 从 `app.getAppPath()`（打包后是 `app\resources\app`）逐级向上找「同时有 `config.example.json`
  与 `src/index.mjs`」的那一层 → ③ 找不到就返回链上**真实存在**的一层并**在日志里喊一声**。
- **没有 .bat 启动器**：0.2.5 的旧资产清理把那些中文名入口删了，所以「没有启动器也能定位包根」
  必须自己成立（由判据保证，而不是靠启动器设环境变量）。

## 3. 这次特意避开的坑（都是 0.2.4 的真实事故）

| 0.2.4 的事故 | 0.2.5 的对应做法 |
|---|---|
| 壳按 `app.isPackaged` 猜目录层数，而 **`asar: false` 时它是 `false`** ⇒ 打包分支根本没进，壳**静默**把 `app\` 当成了包根（读不到使用者的 `config.json`、日志写进 `app\logs\`） | 三级「看证据」判据 + `verify-desktop` **造出真实发布包布局**再断言（离线 155 项） |
| 132 项离线断言**没抓到**上面那个 bug —— 它们只验「参数怎么用」，没验「真实布局长什么样」 | 新增专测**真实目录形状**的那一节，并用**打包产物里那份 `lib.cjs`** 在真实发布包路径上复核 |
| 一句中文注释让 `.bat` 吞掉换行、断掉启动链；注释里一个裸 `>` 把**主入口截断成 0 字节** | `verify-text-encoding.mjs` ④ 与 `check-release-package.mjs` ①-d：`.bat/.cmd` 必须纯 ASCII，且**注释行不许出现重定向字符**。★ 0.2.4 那版"纯 ASCII"断言其实**一个文件都没扫过**（恒为绿）—— 现在两条判据都带**负对照** |
| `_release/` 滚出 5 个同名包 / 928 MB；"删不掉就换个名字绕开" | 产物目录带时间戳 + 尽力清旧 + **删不掉不算失败**（假失败会让人去改脚本）；新版本发布包**不入库** |
| 把 413 MB 发布包以**普通 blob** 提交进库（`.gitattributes` 声明了 LFS，但本机 filter-process 起不来） | `.gitignore` 新增 `/_release/InteractBot-0.2.5-*/`、`.build-desktop/`、`desktop/.npm-cache/`、`desktop/node_modules/` —— **只提交源码** |
| 改了壳，但包里的壳是旧的（UI 侧曾脱钩一次而 1100 项测试全绿） | `assemble-release.mjs` ④-b：包里壳代码与 `desktop/` 源码**逐字节比对**，不一致就拒绝组装 |

### 3.1 顺带挖出并修掉一个**发布包级**的老缺陷（这条不在原计划里）

**症状**：从发布包里双击 `app\InteractBot.exe`，窗口起来了，但**一直停在启动页**，90 秒后报"等桥接超时"。

**根因**（实测，不是推测）：`src/ui-status.mjs` 在**运行期** require `scripts/ui-build-stamp.cjs`，
而发布包的拷贝清单**从来只拷 `src/`、不拷 `scripts/`** ⇒ 包里的桥接一 import 就抛
`MODULE_NOT_FOUND`、**启动即死**。更糟的是：`respawnBridge` 用的是 `stdio:'ignore'`（detached），
所以**连 `logs/bridge.log` 都不会生成** —— 用户手里没有任何线索，桌面壳也只能干等。

**范围比想象的大**：`_release/InteractBot-0.2.0` 起**每一份包**都有这个缺陷（那些包同样有
`src/ui-status.mjs`、同样没有 `scripts/`）。它一直没被发现，是因为**从来没人从包里跑过桥接**
（开发机一直跑仓库里那份；0.2.4 那个 exe 也是连到你正在跑的仓库桥接上）。

**修法三件**：

1. 把 `scripts/ui-build-stamp.cjs` 加进拷贝清单（并在清单里写明：它是**运行期依赖**，不是可选构建脚本）；
2. `ui-status` 缺助手时**降级不崩**，如实报 `uncheckable` 并指名缺哪个文件 ——
   这是本仓库既有的纪律：**观测手段不许把主流程弄挂**（同 `memory-stats` 那条）；
3. `check-release-package.mjs` 新增 ①-e：扫包内 `src/`、`mcp/` 里 `join(PKG_ROOT, …)` 指到的**文件**，
   断言它真的在包里（66 个文件全过）。这条判据会**直接挡住**同类问题再次发生。

**顺带修掉一个假红**：发布包里没有 `config-ui/src`（只发 dist），重算源码哈希的输入是空的
（空串的哈希 `e3b0c442…`），于是界面新鲜度永远报 `stale`（"源码改过没重新构建"）——
**判不了却报成一个具体的结论**。现在多一个 `uncheckable` 态，说清"发布包本身只有成品，这一层判不了"。

**修完实测**：包内桥接能正常启动并写 `logs/bridge.log`，然后在空白配置下**如实报**
`❌ 无法启动 DSH：没找到 DSH` —— 那是设计如此（DSH 是运行环境、不随包分发），
但**它现在是一条看得见的日志**，而不是一次静默死亡。

**机器验证过的**

- `npm test` 全链**退出码 0**；其中 `verify-desktop` **155 项**（含真实发布包布局那一节）、
  `verify-text-encoding` 23 项（新增 `.bat` 两条规矩 + 负对照）、`verify-manifest` 37 项、
  `verify-legacy-assets` 16 项。
- 真实构建：`npm run desktop:pack` → exe 200.5 MB / PE 版本号 **0.2.5** / `asar: false` 生效 /
  `resources/app/` 里 5 个壳文件与源码**逐字节一致**。

  （打包时间 / Electron 版本 / 主进程哈希）。

**未验证的（不粉饰）**

- ★★ **桌面窗口的交互语义**：已经从**发布包**里双击 `app\InteractBot.exe` 起过两次真窗口
  （窗口标题「QQ 机器人控制台」、4 个 Electron 进程、`logs/desktop.log` 第一行是**正确的发布包根**
  而不是 `app\`、端口来自 `config.json` —— 0.2.4 恰恰就是这两处错的），随后窗口已关闭。
  **仍未验**：托盘图标、关窗口是否真的收进托盘（机器人不下线）、托盘菜单各项、
  「退出并停止机器人」是否真的把桥接停掉。
- **"壳自己把后台拉起来"只验到一半**：发起成功 + 后台确实能起来（把包内 `src/index.mjs` 直接跑，
  能看到它写 `logs/bridge.log` 并如实报错）✓；**没验到**新机器上第一次双击就一路亮绿灯 ——
  因为本机的空白发布包**找不到 DSH**（包里 `config.json` 是空白模板，需要填 `dsh.cliPath`/
  `dsh.searchPaths` 或设 `DSH_DESKTOP_APP`）。请按 `RELEASE.md` §6 的清单在真机上走一遍。
- exe **未签名** ⇒ Windows 显示「未知发布者」，可能被 SmartScreen 拦一次（预期内，不是缺陷）。
- 只在 **Windows x64** 上打过。
- 完整清单在 `PROJECT.json` 的 `verificationStatus.notVerified`。

## 5. 与 0.2.4 的关系

0.2.4 那条线（同样是"桌面程序 + 打 exe"）**曾被整体回退**。成因不是方案错，而是两件事叠在一起：

1. **已发出去的那个 exe 是修复前编的** —— 它把 `app\` 当成包根（从 `_release/…-0.2.4-win-x64.zip`
   里的 `app/logs/desktop.log` 可以逐字看到：`包根 …\app` + `读不到 config.json（ENOENT）—— 用默认端口 3410`），
   而修复只进了源码与后来那份 `-r4`；
2. 收尾期一串**静默**事故：主入口 `.bat` 被截成 0 字节、`_release/` 同名包失控（5 个 / 928 MB）、
   清理脚本"删到一半"把两份包削成半份。

本次重新落地时：壳**源码**沿用 0.2.4 那份（它的问题已在 `10052a5` 修好，且 `src/` 一侧**零改动** ——
实测 `git diff main backup/0.2.4 -- packages/qq-bridge/src` 为空）；exe **重新打过**（不复用 0.2.4
的二进制），版本号 0.2.5；上面第 3 节那些坑**逐条补了机器判据**。
