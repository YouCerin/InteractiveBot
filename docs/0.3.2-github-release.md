# 0.3.2 — 从对话机器人到 Minecraft 服务端运维

## 概述

0.3.2 将本项目的能力从 QQ 侧对话扩展到 Minecraft 服务端运维：服务器内的玩家可以直接与机器人对话；服务端异常时自动上报并尝试一次重启，失败则请求管理员介入。同时提供服务器状态查询（在线人数 / TPS / 连通性）与控制台指令下发（op 级权限）。上述功能均**不需要在服务端安装任何插件或模组**。

完整技术说明与决策记录见 [`docs/0.3.2-release-notes.md`](https://github.com/YouCerin/InteractiveBot/blob/main/docs/0.3.2-release-notes.md)。

## 新增能力

| 模块 | 说明 |
|---|---|
| 服务器监测 | 连续 N 次采样失败才判定 `down`，避免网络抖动误报。「正在启动」为独立状态（模组服冷启动 18–60 秒），避免加载期间被判为故障并触发重复拉起 |
| 启动接管 | 依据端口占用与进程归属决定：接管现有进程 / 仅上报 / 拉起并等待端口开放。判据为「端口未监听才拉起」，而非「归属不匹配即重启」 |
| 重启编排 | 归属判据为 `pid` 与进程启动时刻；流程为优雅停服（RCON `stop`）→ 等待端口释放 → 拉起 → 等待端口开放；含冷却与「单次故障最多尝试一次」，失败时如实上报 |
| 控制台（op 级） | 本机控制台、群内 `\mc [id] <命令>`（本地拦截执行，不经模型）、模型工具调用、游戏内管理员。开关 `servers[].commandFromQQ` 管控后三条，默认关闭；本机控制台不受该开关限制 |
| 游戏内对话 | 玩家在游戏内发送 `\mc bind` 获取绑定码，在群内发送 `\mc bind <码>` 完成绑定；已绑定玩家的消息进入模型，回复以 `tellraw @a` 广播并带固定前缀；未绑定玩家的消息不消耗模型调用 |
| 定时任务 | 支持定时主动发言；触发保证恰好一次（落盘台账在模型调用前完成认领） |

另新增控制台「任务」「服务器」两个页签。

## 修复

1. **保存服务器条目导致 RCON 密码丢失**：表单不回显密码，保存时不提交该字段，后端整条替换将其置空，且不产生任何报错。现按「留空 = 不修改 / 有值 = 覆盖 / 显式清除 = 删除」三种语义处理。
2. **`GET /api/config` 明文返回 RCON 密码**：密码位于 `servers[]` 数组元素内，未被固定路径的字段白名单覆盖。已修复，并与第 1 项同步处理。
3. **游戏内消息触发 QQ 私聊应答**：通道串扰。游戏内通道现不再发送中间应答。
4. **控制台修改游戏端口不生效**：编辑表单此前只修改本桥接配置，未修改服务端 `server-port`。现可直接编辑服务端的 `server.properties` 与 `eula.txt`（游戏端口、`enable-rcon`、`rcon.port`、`rcon.password`、EULA），写入前备份并重读校验，同时同步本桥接配置。
5. **RCON 密码遗失的恢复路径**：支持将服务端 `server.properties` 中的凭据复制到本桥接配置，无需重启服务端，且全程不显示密码内容。
6. **界面产物缺失时的提示不可用**：原先仅返回一行 JSON。现返回说明页面，包含所查找的绝对路径与两种修复方式；`--check` 亦会报告该项。

## 运行前置条件

1. 需预先安装 DeepSeek Harness 桌面版（本包不含）。安装后在控制台「高级」页填写路径，或使用自动查找（`start.bat --check` 会输出解析结果及其来源）。
2. QQ 协议端 SnowLuma 需自行下载（其许可证不允许随第三方分发包分发）。
3. 需要模型 API Key：在控制台「高级」页填写一次即可；已配置 DSH 桌面版凭据的可直接复用。
4. `config.json` 含明文密钥（模型 Key、SnowLuma token），请勿外发或提交至版本库。

## 升级（0.3.1 / 0.2.9 → 0.3.2）

1. 解压至新目录，可与旧版本并存。
2. 将旧目录的 `config.json` 复制过来（必须）；`workspace-qq/`、`logs/`、`cache/` 按需复制。本版仅新增配置项，缺失项使用默认值，旧配置可以直接沿用。
3. 停止旧桥接进程后再启动新版本（进程守卫会拒绝第二个实例）。
4. 执行 `start.bat --check` 确认环境。
5. Minecraft 相关功能默认全部关闭（`servers: []`，不产生任何网络请求）。启用方式：在控制台「服务器」页签新增条目，填写 `id` / `host` / `port` / `rconPort` / `password`、`cwd`（服务端根目录）与 `startExe`（推荐形式，不经 shell）；随后可在同一处开启 `enable-rcon`、设置游戏端口并同意 EULA。这些配置项写入服务端文件，需重启服务端后生效。

## 已知限制

1. 控制台授权文件为明文，可被模型伪造：能够防御外部访问者，无法防御模型主动伪造。彻底解决需要宿主层透传会话身份。
2. 游戏内未注册原生命令，使用聊天形式（`\mc bind`，反斜杠）；以 `/` 开头的输入会被服务端作为命令处理，且不写入控制台日志。实现原生命令、推送式事件或二次验证需要服务端插件或模组，本版不包含服务端代码。
3. 仅由本程序启动的服务端具备控制台日志；外部手动启动的服务端无法读取。
4. 存在按玩家名回退的身份判定路径，其强度等同于服务端对名称的认证；关闭正版验证时可通过改名冒用。
5. 服务器事件播报默认不自动执行（`announce: manual`）：自动播报会将服务端状态暴露给任何可导致其离线的人。自动重启不受该设置影响。
6. 发布包尚未在第二台独立设备上完成端到端验证。
7. 本项目使用第三方协议端登录个人 QQ，违反《QQ 用户协议》，账号可能被限制或封禁；相关的延迟与频率限制仅降低特征强度，不构成保证。
8. 本项目与 DeepSeek / DeepSeek Harness 及其权利人无隶属、赞助或背书关系。
