# 怎么校验它真的能记录记忆

> 起因为一句话提问：「如何校验他真的能记录记忆？」
>
> 这个问题的答案必须分成两半 —— **混起来就会得出"测试全绿 = 它一定会记住"的错误结论**。

---

## 0. 先把问题拆开（这一步比任何命令都重要）

"它真的能记住"其实是**两个独立的问题**：

| # | 问题 | 性质 | 怎么答 |
|---|---|---|---|
| ① | **机制通不通**：模型提议了，桥接会不会正确剥离、落盘、出回执、下一轮注入？ | 确定性 | 离线测试，一条命令 |
| ② | **这个模型会不会主动提议**？ | **概率性（模型行为）** | 只能从真实会话里观察，测试答不了 |

★ 为什么要拆：机制全绿**不代表**它会记住 —— 它完全可能一整轮都不写那条标记，
于是你说了十遍"记住"它一条都没记。反过来，机制断了但模型很爱提议，
你会看到标记被当正文发给对方（社死），或者它嘴上说记下了其实什么都没写。

---

## 1. 校验①：机制（离线、零费用、确定性）

```bash
cd packages/qq-bridge
node mocks/verify-memory-roundtrip.mjs     # ★ 全链路：提议 → 落盘 → 剥离 → 回执 → 下一轮注入
node mocks/verify-memory-store.mjs         # 存储层：分档、内容过滤、篡改回滚
```

`verify-memory-roundtrip.mjs` 是**为这个问题专门加的那一环**。
`verify-memory-store.mjs` 早就存在，但它测的是存储层（给了 items 能不能落盘），
**不经过 Bridge** —— 所以链路上任何一环断了它都发现不了：

```
模型在回复里写标记 → 桥接解析 → 剥离标记 → 落盘 → 写回执
  → 下一轮把回执与记忆注入提示词 → 模型看到"记上了没有"
```

而这条链路上每一环断了**都不会报错**：

| 断在哪 | 表现 | 为什么难查 |
|---|---|---|
| 没剥离 | 对方在 QQ 里看到一整行 `<<<MEMORY fact …>>>` | 不报错，只是社死 |
| 没落盘 | 机器人说"记下了"，实际什么都没记 | **最难查的一种** |
| 没回执 | 模型**不知道**自己没记上 → 继续骗人 | 表现为"它答应了又忘" |
| 不注入 | 记了等于没记 | 表现为"它怎么不记得" |

这套测试用**桩 rpc**（回复内容由测试指定，包括那条标记），所以"模型会不会提议"
这个人品问题被排除掉，测的是**机制**；而**文件系统是真的**（临时目录），
落盘、回执、注入都真的发生。

它覆盖：全链路正例 / 记不上时必须有"没记下"回执 / 分档不串场（群事不写全局、
别的群看不到）/ 绕过桥接改记忆会被回滚 / 关掉开关就一个字都不写。

---

## 2. 校验①的**运行时**那一半：它此刻到底记着什么

测试答不了"这台机器现在记着什么"。用体检工具（**只读**，机器人跑着也能执行）：

```bash
node src/index.mjs --memory            # 默认：列文件 + 按会话预览注入什么
node src/index.mjs --memory --full     # 注入内容整段打出来
node src/index.mjs --memory --json     # 给脚本/界面用
node src/index.mjs --memory --inject private:100000001 --inject group:700000001
```

它回答四个问题：

1. **记忆文件里真的有什么** —— 每个文件的条数、字节数、最后写入时间、最后一条；
2. **下一轮会注入什么** —— 按会话列出（与桥接**同一份逻辑**算，不另写一套估算）；
3. **待消费的回执** —— 看到「没记下」就是在说：那条被拒了，机器人若说"记住了"就是骗人；
4. **快照一致性** —— 与快照不一致 = 有人/模型绕过桥接改了它，下次读记忆会被回滚。

★ 它会**主动报出"存在但不会被注入"的记忆文件**。这不是假想的坑，实测就有：
`workspace-qq/memory/self-unknowns.md` 有 14 条，但注入清单里没有它 ——
所以下一轮模型**根本读不到**。使用者会以为"它知道"，其实它不知道。
这类"写了却不生效"是最容易被忽略的一种失败，工具必须自己喊出来。

## 3. 校验②：模型会不会主动提议（只能实测）

这是**模型行为**，没有确定性测试能做。做法是把"它说记住了"换成**可核对的证据**：

### 做法 A：说一件明确值得长期记住的事，再看文件

```
你：记住我喝咖啡不加糖
它：（回一句自然的确认）
```

然后：

```bash
node src/index.mjs --memory
```

看 `memory/private-<你的QQ>.md` 里有没有多出一条。**没有就是没有** ——
它可能压根没提议，"好的记住了"只是句客套。

### 做法 B：看日志里那一行（最直接的证据）

`logs/bridge.log` 里每一次提议都会留一行，**无论接受还是拒绝**：

```
[memory] 记忆写入：接受 1 条、忽略 0 条
[memory] 记忆写入：接受 0 条、忽略 1 条（涉及身份或权限判断）
```

没有这一行 = **它这一轮根本没提议**。这比问它"你记住了吗"可靠得多。

### 做法 C：隔一轮再问它（验"用得上"，不是"存得下"）

```
它：记住了
（隔几条别的消息）
你：我刚跟你说过我喜欢怎么喝咖啡？
```

答对 = 落盘与注入都通；答不上来但文件里有 = **注入或上下文有问题**，
这时用体检工具的 §② 看那个会话下一轮到底注入了什么。

### 做法 D：重启机器人再问（验**跨重启**记忆）

内存镜像重启就清空，长期记忆在工作区文件里。重启后还能答上来，
才说明它靠的是**记忆**而不是当前会话的上下文。

> ⚠️ 已知的静默污染（实测，会影响判断）：
> `MEMORY.md` 里混进过"记忆指令本身的回显"（模型把提示词里那段
> `<<<MEMORY global 对所有聊天都成立的事>>>` 当内容记了下来）。
> 后果是**上下文被自己的说明污染**。体检工具的 §① 能看到这种条目 ——
> 认出来就删掉（在控制台「记忆」页签删，或删那一行）。
> **删完记得让它经桥接重写一遍快照**，否则下次读记忆会被回滚回来。

---

## 4. 一句话结论

* **"机制能不能记住"** → 跑 `verify-memory-roundtrip.mjs`。全绿 = 通。
* **"此刻记着什么、下一轮会不会用上"** → 跑 `node src/index.mjs --memory`。
* **"这个模型会不会主动记"** → 只能实测：看 `logs/bridge.log` 里有没有 `[memory] 记忆写入：`，
  以及记忆文件有没有真的长大。**测试永远答不了这一问，别把它当成答了。**
