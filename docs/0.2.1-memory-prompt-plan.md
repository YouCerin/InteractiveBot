**一句话（修订后）**：
把 QQagent 的**"按人档案 + 领域记忆 + 相关人过滤"**搬过来，

写入通道换成 **MCP 工具 + 桥接确定性触发**，
并新增一个**技能系统**把"加一个功能"从"改五处代码"变成"放一个目录 + 一个开关"。

### 1.3 QQagent 的实测结论（照抄进我们的设计前提）

1. **提示词路线太软**：`favor-judge.js:1-12` —— 包作者本机 **58 次真实运行里 `memory_impression` 零调用**，不报错、就是没想起来。判据在、工具在、提醒在，**但没有任何机制保证它一定落一条记录**。★ 我们已实测复现同一现象（见 `0.2.1-memory-diagnosis.md`），并据此改为桥接确定性触发。
2. **多段落位置决定成败**：判据写在系统提示里没用，必须把"动作清单"放到**用户消息变动段**（prompt.js:697-714）。但那个提醒**必须留在变动段**，否则每轮都在动它，会把【过去状态】几千 token 的前缀缓存全部打断。
3. **相关人过滤**：曾写死 `recent(12)`，与响应档位脱钩，出现了"记忆里混进模型根本看不到的人"（prompt.js:645-650）。
4. **整理的致命坑**：`replaceConsolidated`（memory.js:1172-1229）会删全部成员文件重建；不做"按 userId 先快照、重建后贴回"，**每次自动整理都会把所有人好感清零**（快照逻辑在 :1186-1194）。★ 我们**不引入好感度**，并且**从结构上避免**：成员档案里只有 `impressions`/`stats`/`domains`，整理只允许改 `impressions`。
5. **反幻觉断言**：整理后条数变多 = 疑似幻觉 → **整轮放弃保留原文**（orchestrator.js:1802）。
6. **分型判据**：模型想忽略也忽略不掉的走插件（确定性），模型自己判断的走 Skill。**不要把确定性动作放进需要模型自觉的路径**。

## 2. 目标架构

### 2.1 记忆分层（五层，各司其职）

```
┌─ L0 原始层  workspace-qq/logs/ + DSH session log（既有，不改）
│
├─ L-B 运行层  runtime/tasks/<会话>.json        任务台账（goal/steps/tried/blocked/主线）  ★ 新增
│             runtime/oplog/<会话>-<日>.jsonl   操作日志（turn/step 粒度，含参数与结果）  ★ 新增
│             runtime/archive/                 过期任务软删归档                          ★ 新增
│
├─ L1 全局层  MEMORY.md                     对所有会话生效（既有）
├─ L2 会话层  memory/group-<群号>.md        本群/本人的事（既有）
│            memory/private-<QQ>.md
├─ L3 成员层  memory/members/<会话>/<QQ>.json   按群友档案（印象 + 统计 + 领域 + 习惯） ★ 新增
├─ L3' 配方层 memory/recipes/<slug>.json    "怎么做"（trigger/steps/pitfalls/verify/置信度）★ 新增
├─ L4 归档层  memory/archive/<yyyy-mm>.md   软删归档（可追溯）                          ★ 新增
└─ L5 审计层  memory/audit.jsonl            所有记忆变更追加一行                          ★ 新增
```

> **L-B（运行层）与 L1~L5（长期层）的分工**：
> L-B 回答"**我正在干什么、干到哪了**"，生命周期是**任务级**（带 TTL）；
> L1~L5 回答"**我知道什么**"，生命周期是**永久**（带衰减）。
> 两者的注入位置不同：L-B 进 `volatileSuffix`（每轮都变），L1~L5 的稳定部分进 `stablePrefix`。
> 详见 `0.2.1-runtime-memory-design.md`。

**为什么成员层必须是 JSON 而不是 `.md`**：
`facts`/`global` 是**给模型读的自然语言条目**，改一个字都不能丢语义；
而成员档案要装 `impressions`/`stats`/`domains` 这类**结构化数据**（数组与对象），
用 markdown 存就得每次读回来做正则解析——那正是 QQagent 反复踩的"二次实现迟早分叉"。

### 2.2 写入通道：四条并存，职责不重叠

```
① 关键词确定性触发（桥接）  用户说"记住…" → 桥接必然抽取            ← ★★ 新增（D2b 第 1 层）
② 回合后自动抽取（桥接）    每 everyN=5 轮 一次小模型调用            ← ★★ 新增（D2b 第 2 层，默认开）
③ 模型调工具（结构化）      mcp: qq_memory_note / qq_memory_*       ← ★ 新增（D2b 第 3 层）
④ 模型提议（自然语言）      <<<MEMORY global|fact|slang|directive…>>> ← 保留，不动
```

**为什么 ①② 是核心增量**：`docs/0.2.1-memory-diagnosis.md` 证实，
在真实对话里模型**明确决定不记**（思考原文："不用提议记忆"），
11 个 turn 零写入。所以**写入必须由桥接自己发起**，不能指望模型。
① 是零成本的（纯本地字符串匹配），② 是可控成本的（每 5 轮一次）。

**为什么 ③④ 仍要保留**：`global`/`directive`/`slang` 是"用户说的事"，走自然语言更自然；
而模型偶尔确实会主动想记点什么（例如它发现了一条工作区约定），给它一条结构化通道比让它手写标记更可靠。
但**③④ 只作为补充，不再是唯一路径**。

**① 与 ② 共同覆盖的原料**：桥接在回合结束时有全部上下文——
`chatKey`、`peerId`、`senderId`、核实过的 `identity`（昵称/群名片/角色）、`tier`、消息原文、`tier`。
**注意**：`applyMemoryItems` 的 `senderId` 形参**已经传了但函数体内从未使用**
（`memory-store.mjs:303` vs `:309-368`）——桥接早就把解析身份所需的原料拿在手上了。


> ★ **没有 `favor` / `ledger` / `pending` / `cycles` / `cycleCount` / `lastVerdictAt`**（D3 已删除整套好感度）。
> `sentiment` 保留但**降级为纯标签**：它只出现在注入文本里（`· [好] …`），
> 没有任何代码会读它做判断。**零额外成本**（本来就在抽取调用里顺带产出）。

### 2.4 存储布局与隔离（按会话分开存放）

档案**按会话分开**，路径带上会话标识：

```
memory/members/<safeChatKey>/<QQ>.json     safeChatKey = <kind>_<peerId>，如 group_700000001
   例：memory/members/private_100000001/100000001.json
       memory/members/group_700000001/1234567.json
```

**为什么按会话隔离**：

1. 同一个人的信息在 A 群该不该让 B 群看到，取决于**内容本身**，不是身份——按会话存放让"哪来的"一目了然；
2. 跨群归并需要"跨群身份库"，我们没有，引入它等于造一个新子系统；
3. 隐私底线：把 A 群积累的内容带到 B 群，正是本项目一直在防的串场。

档案里**不含** `scopes` 字段（会话已由路径表达）。

### 2.5 ~~门槛结算~~ ⛔ 已删除（D3）

> 原设计照搬 QQagent 的"攒够 3 条判断 → 按净分 ±2/−3 结算好感"整套机制。
> **用户决策删除**：对一个**以功能性为主**的 AI，给群友打"好感分"没有意义——
> 它不改变回答的正确性，却带来一整套台账/门槛/冷静期/防刷分/审计/管理端后门。
>
> **删除清单**（详见 §3 M-1）：
> `favor` · `ledger` · `pending` · `cycles` · `cycleCount` · `lastVerdictAt` ·
> `lastFavorChangeAt` · `recordImpression` · `settleFavor` · `setPending` · `setFavor` ·
> `favorStates` · `favorMap` · `favorSnapshot` · `favorLedger` · `favorRules` ·
> `favorBand` · `sentimentScore` · `minPending` / `maxStep` / `minStep` / `cooldownMs` ·
> 兜底判定（`memory.judge`）· 管理端"结算好感/改台账/改分"按钮
>
> **保留**：`sentiment` 标签（降级为属性）、`normalizeSentiment` / `inferSentiment`（产出标签用）。
>
> **收益**：少约 600 行代码 + 一整套配置项 + 一组管理端交互 + 每 5 轮一次的额外 LLM 调用。

### 2.6 写入触发：三层并存（D2b，本次诊断后的核心修订）
> 背景：`docs/0.2.1-memory-diagnosis.md` 证实单靠"模型自愿提议"实测 **0 次写入**——
> 模型在思考里明确写下了"不用提议记忆"。所以写入**必须有桥接侧的确定性触发**。

```
① 关键词确定性触发       用户明确说"记住/记一下/别忘/记着" → 桥接必然抽取       零额外 token
② 回合后自动抽取         每 everyN=5 轮 一次小模型调用 → 抽取候选 + 领域归属     每轮均摊 ~60~160 token
③ 模型自愿提议           <<<MEMORY …>>>  + 新增 MCP 工具 qq_memory_*           补充通道
```

**① 关键词触发（零成本，治"我让它记它没记"）**

桥接在本轮消息上做本地字符串匹配。命中即**必然**：
1. 把该轮对话（含**紧邻上文**，因为"记住"常省略主语）交给抽取模型；
2. 抽取结果按 §2.8 的相关人 + 领域规则落盘；
3. **回执必写**，下一轮告诉模型"你答应用户记的，记成什么样了"。

触发词表（保守，宁少勿滥，避免每句闲聊都触发）：

```
记住 / 记一下 / 记着 / 记下 / 别忘 / 别忘了 / 帮我记 / 你要记得 /
以后都叫我… / 以后别… / 我的偏好是… / 我们约定…
```

⚠️ 命中判定**只有本地字符串**，不调 LLM；抽取才调。这样"用户没说"时成本严格为零。

**② 回合后自动抽取（默认开，N=5）**

仿 QQagent `favor-judge.js` 的**调用形状**（回合后一次极小调用 + 冷却 + 失败静默），
但产出的是记忆而非分数，且**一次调用同时产出三类结果**：

```
触发：chatKey 的回合计数 % 5 === 0 且本轮有实际内容
窗口：最近 24 条消息
输出：严格 JSON
  { "people": [ { "who": "无忘远霞", "note": "他说他家机器跑得动 1080p60",
                  "sentiment": "neutral" } ],
    "domain": { "name": "视频剪辑", "q": "FFmpeg 补帧用什么滤镜",
                "a": "minterpolate，他机器上 1080p60 跑得动" } | null,
    "facts":  [ "…" ] }
纪律：失败静默；每会话并发唯一；**不产出任何分数或判断记录**
```

| 约束 | 值 | 理由 |
|---|---|---|
| 默认开关 | **`true`** | ★ 用户决策：要"它真的会自己记" |
| 触发节奏 | **每 `everyN=5` 轮** | ★ 用户决策 |
| 冷却 | 同一人 3 分钟 | 省重复判定 |
| 最小条数 | 窗口 <4 条不问 | 没证据白花钱 |
| 每会话并发 | 只跑一个 | 避免同一批消息判两次 |
| 输出上限 | 2400 token | QQagent 实测 400/1200 会被思考吃光、JSON 截断 |
| 失败 | **静默** | 它是增强路径，绝不能影响聊天主流程 |
| 费用可见 | 控制台显示"每 5 轮一次额外调用" + 累计额外 token | 默认开就必须让人看得见 |

> QQagent 踩过的坑照抄：老 config 里落盘过 `maxTokens:400`，而 `deepMerge`
> **不覆盖已存在的键** → 改了默认值却不生效、整批判定全废。我们做自愈：读到历史坏值顶到当前默认。

### 2.7 领域记忆：对"同一人在同一领域"的问答记忆（D2c）

**要解决的问题**：同一个人反复问同一领域的事（例如"无忘远霞"反复问视频剪辑/FFmpeg），
机器人每次都从零回答，不记得**上次给过什么答案、他的环境是什么、哪条路走不通**。

**领域怎么定**：由 ② 的抽取调用**顺带产出领域名**（自由文本，≤12 字），桥接侧做归一：

1. 大小写/空白归一 + 同义词表（`ffmpeg`→`视频剪辑`、`剪辑`→`视频剪辑`…）；
2. 与已有领域名做相似度匹配（≥0.8 归并到已有领域，避免"视频剪辑/视频后期/剪辑"分裂成三个）；
3. 领域名上限 20 个/人；超了就合并最冷门的两个（**合并要留痕**，写审计）；
4. 领域归**信息**，不归行为——和 `fact`/`directive` 的分档是正交的（领域挂人，分档管可见性）。

**存什么**（每个人的每个领域一批要点，≤6 条）：

| 字段 | 含义 |
|---|---|
| `q` | 他问的问题（≤60 字） |
| `a` | 我们给过的**有效答案要点**（≤120 字）——只记要点，**不存原文** |
| `at` | 时间 |
| `source` | `keyword` \| `turn`（来自哪层触发） |
| `useful` | 是否被后续对话确认过（"谢谢/有用/搞定了"→ `true`；被纠正 → `false`） |

**注入时怎么用**（这是"针对某领域"的关键）：

```
【我记得的事 …】
〔成员档案｜相关人〕
  · 无忘远霞（QQ 100000001）：来过 412 次，最近 09-26
      · [好] 主动帮我解释了那句不是那个意思
      · 让建的堆放处：store/（data/ 放数据，apps/ 放工具）
      · 视频剪辑：问过 6 次 —— 最近：FFmpeg 补帧用什么滤镜（上次答：minterpolate，1080p60 跑得动）
```

**规则**：
1. **只展开当前对话领域**的 `notes`；其它领域**只给一行摘要**（"领域名：问过 N 次"），
   避免"问视频剪辑时把 QQ 机器人的 6 条笔记也塞进去"。
2. **领域命中怎么算**：本轮触发消息的关键词与领域名或该领域 `notes` 的 `q` 做 token 重合；
   命不中就只给摘要行。
3. **`useful=false` 的要点降权**（被纠正过的答案排在后面，或干脆不注入）。
4. **答案要点 ≠ 原文**：`a` 是我们**概括**的要点，不是聊天原文——
   与 `memory-store.mjs:575-579`"不要把记忆原文念出来"同一条纪律。
5. 注入这些内容时同样受 §2.8 的**字节预算**约束，领域笔记优先级**低于**印象条目。

**为什么不做向量检索仍能工作**：领域名本身就是一个**粗粒度聚类键**，
配合"只用当前领域展开"这一条，就已经把"同一人同一领域"的需求覆盖住了，
不需要 embedding（与设计文档 §0"纯摘要、无向量检索"一致）。

### 2.8 注入：相关人过滤 + 预算 + 可信度分区

```
【我记得的事（由系统提供，仅供参考）】
〔全局记忆｜高可信｜人人可见〕store/ 是工作区里的堆放点 …
〔管理员指令｜跨群生效〕遇到 X 就这样做 …
〔本会话记忆｜参考〕…
〔群内黑话｜仅本群〕滚木 = 什么都没有
〔成员档案｜相关人〕
  · 无忘远霞（QQ 100000001）：来过 412 次，最近 09-26
      · [好] 主动帮我解释了那句不是那个意思
      · 让建的堆放处：store/（data/ 放数据，apps/ 放工具）
（本会话还有 4 条记忆因预算未加载；要看某人的完整档案用 qq_memory_query）
```

**相关人怎么算**（这是 P4 的修法）：
只取"本轮真的会发给模型的消息里出现的发送者"，即
`triggerEntries[].senderId` ∪ 实际选中的历史消息 `senderId`。
⚠️ QQagent 的坑：曾写死 `recent(12)`，与响应档位脱钩 → **必须用实际注入的那批**，
不能用"最近 N 条"。

**预算**（P5 的修法）：
- 跨文件共享的**总字节预算**（建议默认 6000 字节，可配）
- 分配顺序按可信度：`directive` → `global` → 本会话 `fact` → 成员档案 → `slang`
- 每档内部按"最近性 × 命中次数"排序取头部
- 超限时**如实告知模型**"还有 N 条未加载"，并给出取用工具名（P2 的修法）

**可信度分区**（P6 的修法）：每档输出**结构化的档位标记**，并在指令段解释这些标记的含义——
把"可信度"从纯文字补救变成结构性区分。

### 2.9 巩固与遗忘

**规则版（0.2.1 必做，不调模型）**：

```
触发：定时（默认 6 小时）+ 手动 --memory --compact
规则：① 成员档案里 impressions 去重（归一化 + 相似度 ≥0.9 视为重复 → 更新而非追加）
      ② 超过 memory.impressionsPerMember（默认 8）时，按"最近命中时间"淘汰冷条目
         淘汰的去向是 **archive（软删）**，不是删除
      ③ stats.topics 只留命中 ≥2 的词，超 30 个按频次截断
      ④ 会话文件到 MAX_ENTRIES 时不再硬拒，改为"先淘汰最冷的一条再写"
```

**LLM 版（二期）**：合并同义印象、删过时印象。必须带两条护栏：
1. **反幻觉断言**：整理后条数变多 → 整轮放弃，保留原文（QQagent orchestrator.js:1802）
2. **整理前整目录快照**，可回滚

> 原第 3 条护栏（"重建成员对象时必须整份带过 favor/ledger/cycles"）**随好感度一起删除**——
> 那条坑的根源是"整理会重建成员对象"，而好感度把**状态**存在同一个对象里。
> 现在成员档案里只有 `impressions`/`stats`/`domains` 三类数据，
> 且 `stats`/`domains` 由桥接确定性维护，整理**只允许改 `impressions`**，从结构上避免这件事。

**衰减（D10）**：**不做**强度浮点衰减。理由：
浮点强度模型适合"话题记忆"，而群友档案是"关系记忆"——关系不该自己蒸发。
过时靠"淘汰到 archive"解决，靠人可查、可恢复。

### 2.10 提示词系统重构

**现状**：`#buildPrompt` 私有方法，14 段内联拼接，无 system 通道，无法 dump。

**目标**：

```
buildPromptSections({ kind, peerId, tier, identity, images, reason })
  → { stablePrefix, volatileSuffix, sections[] }
        │                    │
        │                    └─ 每轮都变的：相关成员档案、回执、来源标注、正文、图片说明
        └─ 只随 (kind, tier) 变的：平台规则、人设、权限段、记忆指令段、全局+指令记忆
```

**为什么这样切**：`stablePrefix` 的字节只随 `kind`/`tier` 变化 → 前缀缓存命中率不再是"巧合"。
QQagent prompt.js:605-612 就是按"变化频率"排序的，但他们没有断言；
我们加**测试断言**："同一 `(kind,tier)` 下 `stablePrefix` 的字节完全一致"。

**同时**：把拼装函数从私有方法**抽成可独立调用的纯函数**，新增只读命令：

```
node src/index.mjs --prompt --inject private:<QQ>          # dump 完整提示词
node src/index.mjs --prompt --inject group:<群号> --stats   # 附带每段字节数
```

这是**后续所有提示词优化的前提**（没有它，任何措辞改动都只能靠感觉）。

1. **会话归属**：MCP 服务器是**独立 stdio 子进程**，它只知道 OneBot 地址与 token，

   - 方案 A（推荐，成本低）：桥接在生成 `mcp-qq.config.json` 时**额外写入一个 scope token**

   - **决策前必须先验**：SDK profile 的 MCP 客户端是否每次运行重建（若是，方案 A 成本几乎为零）。

2. **system 通道**：`sdk-rpc.mjs:12-18` 记录了 SDK 只暴露 `initialize`/`session/prompt`/`shutdown`。

## 2b. 技能系统（D12-D14）

> 这是 `AGENT.md:162` / `PROJECT.json.roadmap` 里早就写下的 **P5**，本次正式纳入 0.2.1。

### 2b.1 现状：开关是"手写 if"，不是"系统"

桥接现在**已经有开关**，但它们是**散落的手写表达式**：

```js
// src/bridge.mjs
config.image?.enabled !== false          // :186, :1270
config.memory?.enabled !== false         // :1066, :1209
interim.enabled !== false                // :919
// src/humanize.mjs:76, src/speed.mjs:132,172
h.enabled === false
// src/index.mjs:379,384,494,625
config.usage.enabled / config.memory?.enabled / config.mcp?.enabled / config.ui.apiEnabled
```

| 问题 | 具体表现 |
|---|---|
| **加法成本高** | 加一个功能要改 **5 处**：`config.mjs` 默认值 → `config.mjs` 校验 → `PROJECT.json.keys` → `CONFIG-UI.md` → 至少一处 `if` 判断 |
| **没有统一元信息** | 界面靠 `PROJECT.json.config.keys` 平铺渲染，**不知道哪些键属于同一个功能**，也无法"整块开关" |
| **关闭语义不明确** | 关掉 `mcp.enabled` 只是不注册 MCP；关掉 `image.enabled` 是"一次网络请求都不发"；关掉 `memory.enabled` 是"只剥标记不落盘"。**每个功能各写各的，用户看不出区别** |
| **无法表达"为什么没生效"** | 只能看到"没反应"，看不到"未启用 / 依赖缺失 / 配置非法 / 运行期不可用" |
| **提示词段落没法跟着开关走** | 记忆指令段是内联在 `#buildPrompt` 里的（`bridge.mjs:1209-1218`），新功能想加一段提示词就得改核心 |

### 2b.2 技能是什么

**一个技能 = 一个可独立开关的功能单元**，自带四样东西：

```
skills/<id>/
  skill.json     清单：id / 名称 / 说明 / 默认开关 / 配置 schema / 依赖
  index.mjs      实现：导出下面这些可选的钩子
```

| 钩子 / 贡献 | 作用 | 关闭时 |
|---|---|---|
| `config` | 该技能自己的配置段（含默认值与校验） | 配置段仍在，但不生效 |
| `promptSections(ctx)` | 往提示词贡献段落（带 `priority`） | **整段消失** |
| `tools()` | 往 MCP 工具表贡献工具 | **工具消失** |
| `beforeRun(ctx)` / `afterRun(ctx)` | 回合前后钩子（例如表情包选图） | 不执行 |
| `onMessage(ctx)` | 消息进来时的旁路（例如表情包入库） | 不执行 |
| `status()` | 自报"为什么没生效" | — |

### 2b.3 开关语义（D13 / D14）

```jsonc
"skills": {
  "sticker":  { "enabled": true, "libraryDir": "workspace-qq/stickers", "maxPerTurn": 1 },
  "memory":   { "enabled": true, "...": "（记忆系统的配置移到这里）" },
  "humanize": { "enabled": true, "speed": "balanced" }
}
```

四条硬规矩：

1. **`config.skills.<id>.enabled` 是唯一开关来源**，不再有 `config.image.enabled` 这类影子开关。
2. **每轮重读，立即生效**——不重启桥接。这是桥接已有的性质（`config` 每轮被读），技能系统顺着它走。
3. **关掉 = 四样东西同时消失**（配置不生效、提示词段不拼、工具不注册、钩子不跑）。
   ★ 这条最要紧：本项目最该避免的失败模式是"界面关了但它还在偷偷工作"（`AGENT.md` 第 6 条约束）。
4. **关掉不该破坏任何机制**——照 `bridge.mjs:1200-1202` 对记忆的既有标准：
   "关掉它只是少一段指令与一段召回，不会破坏任何机制"。

### 2b.4 为什么不做"热加载插件目录"

QQagent 有 `plugins/` 热重载（放进去就生效，无需重启）。**我们不照搬**：

| 理由 | 说明 |
|---|---|
| 它是**任意 JS 落地即执行** | QQagent 自己的审计把这条列为风险（"等价于任意落地的 JS 会被执行"） |
| 我们的威胁模型更严 | 桥接跑在用户机器上、拿着 QQ 账号控制权，且**模型能写工作区文件**。若技能目录在可写路径内，等于把"模型写文件"升级成"模型注入代码" |
| 收益有限 | 我们目前只有**内部功能**要开关，没有第三方技能生态 |

**所以 0.2.1 的技能是"静态内置 + 动态开关"**：
技能目录在**包内**（`skills/`，不可被模型写入），启动时扫描一次并注册；
**开关**是运行时动态的。这样既拿到"随时开关"，又不引入代码注入面。
（第三方技能留到有真实需求时再单独评估，届时必须配 `AGENT.md` 第 5 条约束：
依赖必须能被 `src/vendor.mjs` 从 `vendor/` 找到。）

### 2b.5 目录与启动顺序

```
qq-bridge/
  skills/                      ★ 新增（包内，不可被模型写）
    index.mjs                  注册表：扫描 skills/*/skill.json，加载 index.mjs
    sticker/                   示例技能：表情包
    memory/                    把现有记忆系统改造成技能
    humanize/                  把现有拟人层改造成技能
  src/
    skills.mjs                 ★ 注册表 + 生命周期 + promptSections 合并
```

启动顺序（`src/index.mjs`）：

```
① 解析 config（含 config.skills 默认值合并）
② 扫描 skills/ → 得到技能清单（每个带元信息 + 默认开关）
③ 按 enabled 过滤出"生效技能"
④ 生效技能依次 setup(ctx)  → 收集它们的 tools / promptSections / hooks
⑤ 把 tools 汇进 MCP 服务器配置；把 promptSections 交给 #buildPrompt
```

**依赖处理**：`skill.json` 可声明 `requires: ['memory']`。**依赖缺失 = 该技能不生效**，
并在 `status()` 里如实说"依赖 memory 未启用"——不是笼统的"没反应"。

### 2b.8 表情包技能（用户点名的例子）

现状：**没有表情包库**。MCP 只有一个 `qq_send_sticker`，发的是 QQ 内置 `face`（id 1/4/13），
需要模型自己记 id——`persona.mjs:20` 还记着一条教训：源项目人设里引用了
`list_stickers` 等**并不存在的工具**，会诱发幻觉调用。

表情包技能要做的事：

| 组件 | 说明 |
|---|---|
| `libraryDir` | 表情库目录（工作区内），图片按**内容寻址**存（复用 `images.mjs:399` 已有的做法） |
| 入库 | `onMessage` 钩子里：消息含图片且被判定为表情包 → 存进库（纯本地，零 token） |
| **打标签** | 离线一次性：用小模型给每张图打 3~5 个场景标签（`开心/无语/赞同/敷衍/懵`），存 `library.json`。**打一次永久用**，运行时零 token |
| 选图 | `afterRun` 钩子：按本轮对话的**关键词与标签匹配** + 最近使用去重 + `maxPerTurn` 限制，本地打分选出 1 张 |
| 发送 | 走既有 `qq_send_sticker` 通道（新增按**文件路径**发送的能力，现在只支持 `face` id） |
| 提示词 | `promptSections` 贡献一段"你可以发表情，但别每轮都发"（关闭时整段消失） |

**为什么这样设计**：`persona.mjs:29-30` 的硬规矩是"人设里提到的每一个工具都必须真实存在"。
表情包技能让**发不发、发哪张**由桥接的确定性逻辑决定（标签匹配是本地计算），
模型只负责正常说话——**不依赖模型去调工具**，这与 §2.6 的教训一致。

### 5.3 模型行为层（只能实测，测试答不了）

★ **这一条必须写进文档，防止"测试全绿 = 它一定会记住"的错误结论**：

- 做法 A：说一件明确值得记的事 → 看档案文件有没有多出一条

## 7. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 成员档案是**第一次给每个群友建结构化档案** | 默认只在白名单会话里建；控制台可一键清空某会话全部档案；文档里写明数据位置 |
| MCP scope token 方案未取证 | M2 第一步就验；验不通就退化为"只允许当前 in-flight 会话"，并在文档写明并发限制 |
| ★ **回合后抽取默认开 = 额外费用** | ① 固化 `everyN=5`，不随聊天频率放大；② 控制台**显示累计额外 token**；③ 设**每日额外调用上限**，超了自动降级为只走关键词触发；④ 抽取模型可单独指定更便宜的模型 |
| 关键词触发误命中（闲聊里出现"记住"） | 词表保守；命中后抽取模型仍会判断"有没有值得记的"，误命中只是多一次小调用，不会写脏数据 |
| 领域名分裂（视频剪辑/剪辑/ffmpeg） | 同义表 + 相似度归并（≥0.8）+ 每人领域数上限 20；合并写审计可追溯 |
| 领域笔记被当成"我们核实过的事实" | 领域 `a` 是我们**概括的要点**，注入时与 `fact` 同样带"历史记录、仅供参考"降权 |
| 旧 `fact` 档数据迁移可能搬错 | **只提议、不自动写**：生成迁移候选清单，由人在控制台确认 |
| 提示词重构改动面大 | M4 独立成阶段，且 M1 已先建立"字节断言"作为回归网 |
| P15（写入链路从未验证）导致后续全部建立在沙地上 | **M0 必须先完成验证**；若发现链路断了，M1'-M4 暂停，先修链路 |
| ★ **技能开关迁移可能丢配置** | 迁移期**同时读新旧两套键**，旧键读到即写回新键并留提示；迁移有独立测试（S4）；`humanize.enabled` 这类账号存活相关项迁移时**强制保持默认 true**，不因迁移被意外关掉 |
| ★ **技能系统改动面大（碰 `bridge.mjs` 核心）** | 拆成 M5' 独立阶段；先做注册表与开关（S1~S3），**提示词段落注册放最后**；每步都有"关掉即消失"的断言盯着 |

## 8. 与 QQagent 的取舍对照表

| 机制 | QQagent 怎么做 | 我们怎么做 | 为什么不同 |
|---|---|---|---|
| 写入触发 | **纯模型自愿**（工具 + 判据 + 每轮提醒） | **三层：关键词 / 每5轮抽取 / 模型工具** | ★ 它靠自愿，自己实测 58 次零调用；我们加确定性层 |
| 写入通道 | 核心函数工具表（`tools.js`） | **MCP 工具** | 我们的模型在独立子进程里，工具只能经 MCP |
| 身份来源 | 工具参数里要求模型给 `userId` | **桥接解析，模型不必给** | 诊断 §2.4：群里模型拿不到 QQ 号 |
| 存储 | 每会话目录 + 每人 JSON | 每会话目录 + 每人 JSON | **一致**（这是它的设计优点） |
| **好感度** | **整套**（favor/ledger/pending/cycles/门槛/兜底判定） | ⛔ **整个删除**（D3） | ★ 用户决策：对**以功能性为主**的 AI 没有意义 |
| 情感标签 | 驱动分数 | **仅作属性标签**，不驱动任何行为（D4） | 标签有信息量，但不该有后果 |
| 兜底判定 | 默认开（为好感攒条目） | **改名为回合后抽取**，抽取记忆而非分数，默认开、每 5 轮 | 形状复用，目的换了 |
| 领域记忆 | 无 | **有**（按人+领域分组注入） | 用户新增需求 |
| 注入过滤 | 相关人（触发者 + 档位选中历史） | **照搬** | prompt.js:645-650 的实证 |
| 段落排序 | 按变化频率排 | **照搬 + 加字节断言** | 它没断言，我们补上 |
| 整理 | LLM 合并 + 反幻觉 + 快照 | 规则版先行，LLM 版二期；**只改 `impressions`** | 规则版零成本零风险 |
| 分层会话记忆插件 | 有（4 段注入 + 小时块检索） | **不搬** | 审计已标禁止；本仓缺消费方 |
| **技能/插件系统** | 有：`plugins/` 目录**热重载**（放进去就生效） | **有，但静态内置 + 动态开关**（§2b.4） | ★ 它的热重载＝任意 JS 落地即执行；我们的工作区**模型可写**，不能开这个口子 |
| 技能分型 | 插件（确定性）/ Skill（LLM 型） | **只有一种**：可开关的功能单元 | 我们还不存在"第三方技能生态"，先不做分型 |
| 衰减 | 无 | 无 | **一致**（都只做软删） |
| 可观测性 | 有审计 + 体检命令 | **审计 + 体检 + 零写入告警 + 技能状态** | ★ 它也没有"零写入告警"；本次问题正是缺这个 |
| 时间常识检索 | dayKey/hourKey/preferDay 加权 | 二期，数据模型先预留 | 收益高但成本高 |
