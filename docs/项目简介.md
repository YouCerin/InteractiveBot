# InteractBot 项目简介（0.2.2）

> **一句话**：让一个 QQ 号看起来像**一个真正会用工具的人**在用它 —— 消息交给一个**有完整工具链的
> agent**（DeepSeek Harness）去处理，而不是"套壳调一次大模型"。
>
> 本文回答三件事：**各模块是怎么实现的**（§2）、**它有什么不一样**（§3）、
> **agent 到底有多大权限**（§4）。字段级规格见 `CONFIG-UI.md`，扩展契约见 `docs/插件设计规范.md`，
> 验收口径与未验证边界见 `PROJECT.json` 的 `verificationStatus`。

---

## 1. 它是什么 / 数据流

```
QQ 用户
  │  一条消息（私聊 / 群里 @ 或命中关键词）
  ▼
SnowLuma（第三方 QQ 协议端，OneBot v11）          3000=HTTP 发消息 / 3001=WebSocket 收事件
  │
  ▼
qq-bridge（本项目，一个 Node 进程）
  │   ① 收：连 WS 收事件、下载图片、落语料库
  │   ② 判：该不该回（唤醒矩阵）、以什么权限回（三级名单）、回什么（维护每会话状态）
  │   ③ 转：拼系统提示词 → 经 stdio JSON-RPC 交给 DSH
  │   ④ 发：拿回回答 → 人味延迟/分条/去重 → 按会话发回 QQ
  ▼
dsh --profile sdk（DSH 官方 SDK 运行时，由桥接拉起为子进程）
  └─ agent 循环：**工具 / 沙箱 / 会话 / 压缩** 全归 DSH
       └─ 模型（本机默认 deepseek-official / deepseek-flash）
```

| 进程 | 谁的 | 职责 |
|---|---|---|
| SnowLuma | 第三方 | QQ 协议：收事件、发消息、拿群成员/好友名单 |
| qq-bridge | 本项目 | 上面那四件事 + 控制台 HTTP 接口 + 记忆/任务/配方的落盘与注入 |
| `dsh --profile sdk` | DSH 官方 | agent 循环、工具执行、工作区沙箱、会话与上下文压缩 |
| `mcp-qq-server` / `mcp-skills-server` | 本项目 | 两套 MCP 工具（QQ 动作 / 第三方技能），stdio，零依赖 |

**为什么这样切**：agent 循环、工具、沙箱、会话压缩这些都不自己实现（那是 DSH 的强项，重写只会做出一个更差的）；
桥接只补 DSH **够不到**的三处 —— QQ 通道、跨会话状态（谁在说、说到哪、答应过什么）、
以及"给 model 的提示词里到底该有什么"。这条取舍写在 `PROJECT.json` 的 `architecture.whyThisShape`。

## 2. 各模块的实现方式

### 2.1 桥接主干

| 模块 | 实现方式（一句话） |
|---|---|
| `src/index.mjs` | 装配与启动顺序：配置自检 → 建工作区 → 起 DSH → 连 QQ → 起控制台接口；全部只读 CLI（`--check/--doctor/--memory/--extensions/--personas/…`）也在这里 |
| `src/bridge.mjs` | 一条消息 → 一句回答：唤醒判定、准入、**串行锁**（同一会话不并发）、发送、记忆结算；提示词拼装已抽到 `channel-prompt.mjs` |
| `src/channel-prompt.mjs` | 提示词**装配**：来源标注 → 权限段 → 记忆段 → 任务段 → 配方段 → 会话状态段 → 技能片段。有**逐字基线快照**（4269 字），改装配顺序必须说明为什么 |
| `src/config.mjs` | `normalizeConfig`（默认值/类型/路径解析）+ `validateConfig`（fatal/warn 两级）；抽出来是为了**能测** —— 以前埋在启动流程里，只在启动时跑一次 |
| `src/api.mjs` | 控制台 HTTP 接口（只监听回环）：状态、配置读写、记忆文件、用量、扩展、人设库、昵称、SnowLuma、日志流 SSE。核心逻辑与 socket 分离，可单测 |
| `src/local.mjs` | **唯一的路径解析处**（全部从文件自身位置往上推，绝不用 `process.cwd()`）—— 整包可搬走靠它 |
| `src/plugins.mjs` | 内置插件登记表（8 条）：把散在各页签的开关集中出来，**逐个取证**标"即时生效 / 要重启"，`offEffect` 文案直接给界面 |

### 2.2 通道与进程

| 模块 | 实现方式 |
|---|---|
| `src/onebot.mjs` | OneBot v11 客户端（WS 收 / HTTP 发）+ 发送队列（节流、**按会话去重**、失败重试分类）；错误对象挂结构化 `transport` 描述符，人话提示逐字保留 |
| `src/sdk-rpc.mjs` | 与 `dsh` 子进程的 JSONL JSON-RPC 客户端（多会话路由） |
| `src/session-bridge.mjs` | 回合收集器（把散事件收拢成一轮：工具调用/结果、审批、思考）+ 会话路由器（丢弃未知 sessionId 的事件） |
| `src/session-id.mjs` | QQ 会话键 → DSH `sessionId`；顶部记着实测硬限制：**重启后不能复用 id**（所以默认每次启动换新） |
| `src/transport.mjs` | 传输契约：表驱动错误分类（`retryable` 是一等字段）、**带会话**的幂等键、断线缺口标注（"宁可标缺口，也不假装连续"） |
| `src/ports.mjs` | 端口占用探测（启动前置门控用）；记着一条 Windows 事实：**bind 成功 ≠ 端口空闲** |
| `src/process-guard.mjs` | 进程登记（`cache/processes.json`）：回答"现在有几个桥接在跑"；判"是不是原来那个进程"同时看 instanceId + 心跳，**宁可漏报不可误杀** |

### 2.3 记忆层（本项目最厚的一块）

核心取舍：**语义归模型、落盘权归桥接** —— 模型只能在回复里写标记**提议**，桥接校验后落盘并给回执。

| 模块 | 实现方式 |
|---|---|
| `src/memory-store.mjs` | 托管写入：解析 `<<<MEMORY fact\|slang\|directive 内容>>>` 四档作用域（global / 本会话 / 本群 / directive），按发起人身份与来源校验，写回执（下一轮告诉模型"到底记上没有"） |
| `src/memory-files.mjs` | 控制台唯一能改磁盘记忆的入口：只允许工作区内相对路径、只允许 `.md`、拒软链接、写带 sha256 冲突检测（409） |
| `src/memory.mjs` | 历史设计留档（"给 agent 一个记笔记的约定"）；**已不再进提示词**，保留给考古与旧断言 |
| `src/memory-inspect.mjs` | `--memory` 体检：只读摊开"它此刻记着什么、下一轮会注入什么"，并主动报**存在但不会被注入**的文件 |
| `src/memory-stats.mjs` | 写入计数 + **零写入告警**（跑满 10 轮却 0 落盘就报警）；只记数字不记内容 |
| `src/memory-consolidate.mjs` | 每小时**空闲时**跑一次的规则版整理（标点归一、摘转述前缀、相似合并），幂等且有断言；**不做语义改写** |
| `src/memory-supersede.mjs` | 更正用**标注**而非覆盖：旧条目不删、加 `〔已被更正〕`、停止注入、整理时原样保留 |
| `src/memory-keyword.mjs` | "记住 X" 这类**关键词直写**：零模型调用就落盘（模型"顺手记一笔"被实测证伪过） |
| `src/memory-usage.mjs` | 旁挂账本：回答"这条记忆多久没进过上下文"，**只排序提示、绝不自动降权/删除** |
| `src/memory-search.mjs` / `corpus.mjs` | 记忆检索 / 本地语料库（SQLite FTS5 + trigram，2 字以内自动回退 LIKE；七类隐私不落库；30 天 TTL） |

### 2.4 上下文与状态（DSH 够不到的那部分）

| 模块 | 实现方式 |
|---|---|
| `src/tasks.mjs` | 任务台账：把「当前任务」每轮注入当**锚**（DSH 的上下文压缩我们控制不了）。目标直接取**用户原话**、步骤从操作日志机械提炼 —— **零模型参与也完整**；含"回到第 N 步"（作废是**声明**不是清除） |
| `src/session-state.mjs` | 会话状态机：与任务台账**两条轴**（防复读 vs 防重复劳动），水位 + "话头恰好活一轮" |
| `src/recipes.mjs` | 配方库：从真实任务里自动沉淀"做法"（每 5 轮后台抽一次，失败只记一行但**必带原文片段**） |
| `src/oplog.mjs` | 操作日志：桥接自己记"干过什么"（不问模型）；只存索引 + 结果前 300 字，落盘前过隐私闸门 |
| `src/delivery-ledger.mjs` | 投递账本：**发送前落账**（真机上丢过一整条已生成的回复）；只报别人的 pending，**绝不自动重发** |
| `src/delivery-gate.mjs` | 投递前终检门：工具 JSON、注入标记、沙箱原始报错都到不了用户手里；正常中文一个字不动 |
| `src/markers.mjs` | 带内标记：`[reply:<id>]`（只认本会话近期真见过的 id）、`[sticker:名]`、`[img:…]` |
| `src/interim.mjs` | "先应一声"四类话术（thinking/searching/tooling/**blocked**）：带冷却的随机，绝不连续重复 |
| `src/humanize.mjs` / `speed.mjs` | 人味层：反应时间 + 按字数折算的打字时间 + 静默时段长延迟 + 分条；三档速度预设 |
| `src/text.mjs` | 消息段渲染、Markdown 降级、长文本分片 |

### 2.5 输入侧

| 模块 | 实现方式 |
|---|---|
| `src/images.mjs` | QQ 图片 → 工作区 `inbox/` → 模型（`on-demand` 默认只给路径；`auto` 直接塞图片块）。**本项目唯一一处外部输入能指挥进程发请求的地方**，所以 SSRF 防护是重点：协议白名单、**逐跳**校验重定向、域名先解析再校验、大小/超时/次数上限、按字节嗅探类型 |
| `src/trigger.mjs` | 唤醒判定矩阵（私聊 / @ / 关键词）+ 关键词体检（命中高频词会告警，因为"命中必然产生一次模型调用"） |
| `src/privacy.mjs` | 隐私硬闸（**双侧独立**：写入侧拒落盘 + 输出侧拒发送）；七类判据是**可核对的具体形状**（身份证校验位、Luhn、手机号、关键词+高熵…）；★ 刻意不做成配置开关 |

### 2.6 扩展层

| 模块 | 实现方式 |
|---|---|
| `src/extensions.mjs` | 技能内核：发现 `skills/<id>/skill.json`、两级校验（errors/warnings）、设置合并与脱敏、工具命名（**只有一处规则**）、提示词片段收集；★ 同 `id` 两个目录 → **两个都不装载**（fail-closed） |
| `src/extensions-service.mjs` | 开/关/改设置的动作层：**写盘 + 改活配置对象**两件事都做（这是全项目**唯一**"改配置且不要求重启"的通道） |
| `mcp/mcp-skills-server.mjs` | 技能工具的 MCP 服务器（stdio、零依赖）：工具表按**已安装**注册，每次调用**现读 config.json** ⇒ 开关真的即时；`session: required` 的技能由宿主把 `kind/peerId` 注入必填入参 |
| `mcp/mcp-qq-server.mjs` | QQ 工具的 MCP 服务器（14 个工具：戳一戳/表情/撤回/查成员/转发/发图/历史检索…），默认放行、黑名单拦"会伤害他人或账号"的动作 |
| `src/mcp-profile.mjs` | 把两个 MCP 服务器写进 sdk profile（运行时生成 patch + 配置）；没装技能时**整段不移写**（零成本） |

### 2.7 人设与称呼

| 模块 | 实现方式 |
|---|---|
| `src/persona.mjs` | 文本层：内置预设、名字块解析（正式名/别名/又称 → **别名就是唤醒词**）、反注入扫描（命中**整文件拒载**）、超长截断（保头尾） |
| `src/personas.mjs` | 人设库：`personas/<名字>.md` **一个文件一套人设**，文件名=人设名；`persona.active` 三态（文件 / `none` / 空=老路径）；改名与删除**牵着配置走**；读不到时**不静默退回内置** |
| `src/contacts.mjs` | 按人昵称：`memory/contacts.md` 一行一人，每轮只注入**当前说话人**那条、不打印号码；放在 `memory/` 下 ⇒ 自动被记忆篡改检测覆盖（模型偷改会被回滚） |

### 2.8 观测与自检

| 模块 | 实现方式 |
|---|---|
| `src/doctor.mjs` | 体检：包内依赖 / DSH / 配置自洽 / **真实**连接探测（不发消息、不调模型） |
| `src/ui-status.mjs` | 界面新鲜度：构建时写入源码哈希，运行时重算 —— 回答"我手上这份 dist 是不是当前源码构建的" |
| `src/log-tail.mjs` | 日志增量切片（游标语义写死在注释里：游标超出总行数要回到 0） |
| `src/usage.mjs` / `prices.mjs` | 用量记账（JSONL 追加 + 聚合）与成本估算（DSH 不提供人民币价格，所以价格表自己维护；口径写清"估算"） |
| `src/snowluma.mjs` / `snowluma-log.mjs` | 探测/拉起 SnowLuma、token 从**它自己的配置**读（避免两处漂移）；输出读**它的日志文件**而不是 stdout（stdout 是终端编码，中文会变乱码） |
| `mocks/*` | 39 套离线断言 + 探针（`probe-extensions` / `probe-ui-bundle` / `probe-ui-deadcode` / `session-grep`） |

### 2.9 安全与卫生

| 模块 | 实现方式 |
|---|---|
| `src/roster.mjs` | 权限三级 + **身份核实 ≠ 权限授予**（见 §4） |
| `src/credentials.mjs` | 从 `$DSH_HOME/.credentials.yaml` 读模型 key 注入子进程环境（只读那一个路径，密钥从不写日志/接口） |
| `src/token-discovery.mjs` | 保守读 SnowLuma token：**显式账号找不到就绝不复用别的账号的**、只采纳 enabled 且回环、拒符号链接/超大文件/控制字符；回退要说明原因 |
| `src/protected-files.mjs` | 受保护路径清单（可执行的数据）：使用者数据不许进包、大小写不许绕过、删除前要确认"这是我们自己的产物" |
| `src/vendor.mjs` | 依赖从包内 `vendor/node_modules` 加载（绕开 npm 与全局缓存），整个包可搬走 |

## 3. 特色（与"套壳调模型"的区别）

1. **它是"一个人"，不是"一个接口"** —— 人味层把延迟、打字时间、静默时段、分条都算出来；
   200 字回复实测总延迟约 11.3 秒，秒回是上一个 QQ 号被处置的最可能原因。
2. **记忆是"桥接托管 + 模型提议"** —— 模型只能提，桥接负责校验/落盘/回执/篡改回滚；
   "它说记住了"和"它真的记住了"被当成两件事分别验证。
3. **权限是代码判的，身份是协议端核实的** —— 群里的 owner/admin **不参与准入**；
   来源标注里明写"与权限无关"。这一条挡的是"自己建个群、给自己群管理就能拿到写权限"。
4. **只看不改的那半边也管住了** —— 只读用户不仅能查文件，也**不能**让机器人替他发消息/戳人/撤回
   （`qq_api` 这个万能口一起禁，否则前几条全白拦）。
5. **扩展是两型，且"随时开关"边界如实** —— 技能（第三方包，走第二个 MCP 服务器）与插件（自家能力块）；
   提示词下一轮生效、工具调用当场 fail-closed、装卸要重启 —— 三条都写在界面与规范里。
6. **人设是"一个文件一套"** —— 可新建/改名/切换/删除/恢复出厂两套；老配置行为一字不变；
   读不到时**大声报错**而不是静默退回内置。
7. **称呼分三层且不混** —— 用户怎么叫它（名字块=唤醒词）/ 它怎么称呼某个人（按人昵称）/
   说话人标注名（提示词里标"是谁在说话"）。
8. **对"静默失败"零容忍** —— 空 catch 被换成"同一段只喊一次"的告警；
   投递前终检门；记忆零写入告警；**测试自带负对照**（守卫要"验过牙"，不然"全绿"可能只是判据写错了）。
9. **上下文够得到的地方钉锚** —— DSH 的会话压缩我们控制不了，所以把任务/配方/会话状态**每轮注入**成锚。
10. **可搬迁** —— 所有路径从文件自身位置推；Node 与 `ws` 打包在 `vendor/`；`config.json` 不入库。
11. **可核对** —— 每个能力都有对应的只读 CLI 与探针（`--check --doctor --memory --extensions --personas --ui`），
    回答问题不靠猜。
12. **失败要让人知道** —— 所有"没做到"的路径都要求给模型/使用者一句可转述的话，而不是静默丢弃。

## 4. Agent 的权限（这一节是安全边界，改代码前必读）

### 4.1 谁能驱动它：三层名单（`src/roster.mjs`）

| 名单 | 作用 | 空的时候（**fail-closed**，刻意这么选） |
|---|---|---|
| `access.adminUsers` | 管理员：满权限 | **谁都不能用** |
| `access.dmAllowlist` | 私聊白名单（普通用户） | **只有管理员能私聊**（不退回"谁都能私聊"） |
| `access.groupAllowlist` | 群白名单（群里能不能用） | **所有群都不回** |

* **私聊**：`admin → 管理`；否则在白名单里 → 普通用户；否则不回。
* **群里**：先看**群**在不在白名单（不在就不回）；再看**发言人**：在 `adminUsers` 里就是管理员，
  **其余一律普通用户** —— 群主/群管理这个身份**不参与**准入判定。
* 身份核实走协议端（`get_group_member_info` / 好友列表），用于标注与审计；
  查身份**绝不抛异常、绝不长阻塞（2 秒超时）、查不到就 `verified:false` 且不编名字**。

### 4.2 agent 手上有什么

* **DSH 内置工具**：`read` / `glob` / `grep` / `write` / `edit` / `pwsh` / `todo_write` / `job_*` /
  `read_image` / `web_search` / `web_fetch` / `skill` / `present` …（随 DSH 版本，桥接不枚举、也不改）
* **`mcp__qq__*`（14 个）**：戳一戳、表情、撤回、查群成员、消息详情、群历史、合并转发、发图、
  `qq_search_history`（本地语料检索，**fail-closed**：必须显式给会话）、`qq_api`（万能口）
* **`mcp__skills__<id>__<tool>`**：已安装的第三方技能提供的工具
* **工作区沙箱**：`dsh.permissionMode` 默认 **`workspace-write`** —— agent 能在**工作区**（`workspace-qq/`）
  里自由读写与跑命令；**工作区之外被沙箱拒绝**（真机端到端实测：越界写文件被拒、并如实报告）。
  `danger-full-access` 会让 `--check` 打出醒目告警（"能读写整个磁盘且免审批"）。

### 4.3 硬墙 / 软墙（**别把提示词当沙箱**）

| 边界 | 实现方式 | 是硬墙吗 |
|---|---|---|
| 工作区之外的读写 | DSH 沙箱（`workspace-write`） | ✅ **硬墙**（DSH 侧强制） |
| 需要审批的动作 | DSH 的审批流；QQ 通道上**没有可交互的审批人** ⇒ 实际表现是"被挡住" | ✅ 硬（但代价是**做不到**，不是"能拒绝"） |
| 非管理员不得写文件/跑命令 | **提示词层**逐项列出被禁类别（`MODIFY_TOOLS`：write/edit/bash/pwsh/shell/run_code/todo_write/present） | ⚠️ **软墙**（拦得住"听话"，拦不住"越狱"） |
| 非管理员不得有社交后果的动作 | **提示词层**（`MODIFY_QQ_TOOLS`：戳一戳/表情/撤回/`qq_api`） | ⚠️ 软墙 |
| 隐私不许落盘 / 不许发出去 | 代码层双侧闸门（`src/privacy.mjs`） | ✅ 硬（且**刻意不做开关**） |
| 记忆不许记"谁是管理员/有什么权限" | 记忆侧硬拦 + 回执说明原因 | ✅ 硬 |
| 技能代码能做什么 | **没有沙箱**（跑在宿主进程里，进程内无法隔离） | ❌ 只能如实声明 + 界面提示 |
| 人设不许给模型下指令 | 反注入扫描 → **整文件拒载** | ✅ 硬（对"人设文件"这一输入面） |

> **一句话**：agent 的**实际**权限 = 沙箱允许的（工作区）+ 提示词允许的（权限段）。
> 前者是硬的，后者是**约定**。要硬拦非管理员，只能收回宿主工具（例如发图走 `qq_send_image`
> 而不是让技能自己调）或另起一个只读的 DSH 进程（代价已评估，未做）。

### 4.4 记忆的写入权

| 谁 / 什么 | 能写哪一层 |
|---|---|
| 用户说"记住 X"（关键词直写） | 全局 / 本会话 / 本群（按会话类型） |
| 模型提议（`<<<MEMORY …>>>` 标记） | 同上，但要过校验（身份、来源、内容级硬拦） |
| `directive` 档（跨群指令） | **只有管理员私聊**能写 |
| 控制台 | 直接改文件（带 sha256 冲突检测与快照刷新） |
| 绕过桥接偷改文件 | ❌ 下一轮被**篡改检测回滚**并留日志（含 `memory/contacts.md`） |

### 4.5 三条不能跨过的红线

1. **群内角色不是权限**（owner/admin/member 只用于标注）——跨过它 = 陌生人自建群即可拿到写权限。
2. **权限只能由代码判**（记忆里写"X 是管理员"被硬拦；提示词里的权限段是唯一判据）。
3. **隐私闸门不做成开关**（做成开关就等于给了一个静默关掉它的入口，而输出侧一旦漏了**撤不回**）。

## 5. 跑起来 / 核对它

```bash
cd packages/qq-bridge
node setup.mjs                     # ① 幂等：把 Node 运行时与 ws 依赖放进 vendor/
node src/index.mjs --check         # ② 配置自检（不连任何服务）
node src/index.mjs --doctor        # ③ 体检（真连一次协议端，不发消息、不调模型）
npm test                           # ④ 离线全套（2200+ 项断言；不花钱、不需要 QQ）
start.bat                          # ⑤ 启动（先起 SnowLuma，再起桥接；完成后自动开控制台）
```

只读巡检入口（排障时机器人可能没在跑，这些命令仍能回答）：`--memory`（记了什么/会不会注入）、
`--extensions`（技能与插件状态、工具全名、告警）、`--personas`（哪几套人设、在用哪一套）、
`--ui`（界面产物与源码是否同步）、`--processes`（现在有几个桥接在跑）。
