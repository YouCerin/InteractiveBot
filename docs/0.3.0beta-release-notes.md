## 0. 先把版本号说清楚（不读这段会被 0.2.10 绕晕）

- 上一次**真正发出去**的版本是 **0.2.9**（`_release/` 里最后一份成品包 + `docs/0.2.9-release-notes.md`）。
- 之后 `package.json` 被改成过 **0.2.10**（提交 `0f02a35`，"双态说话方式 + 评审台"那批的第一个提交），
  但它**从未打包、也没有自己的说明文件**：`_release/` 里没有 0.2.10 目录，`docs/` 里也没有
  `0.2.10-release-notes.md`，tag 也没有。
- 所以这一版把 **0.2.9 之后的全部内容**一起收进来，命名 **0.3.0beta**：
  ① 这个区间是**一整块功能**（说话方式分两态 + 一个独立小工具 + 一轮真实的风格修订闭环），
  按语义化版本该动次版本号；② 它**还没经过一轮完整的真机使用检验**（见 §9 已知边界），所以带 `beta`。
- **命名为什么是 `0.3.0beta` 而不是 `0.3.0-beta`**：发布包名那条断言的正则是
  `InteractiveBot-([0-9][^-\s]*)-win-x64`，`[^-\s]*` **不接受连字符** —— 写成 `0.3.0-beta`
  会让 `verify-manifest.mjs` 直接找不到包名而报红；而 `package.json` 里没有任何 semver 校验
  （grep 过，没有 semver 依赖）。

## 1. 一句话

这一版做了三件事：让机器人**分「闲聊 / 工作」两态说话**（闲聊时用一份你可以自己改的风格文件）；
做了一个**独立的聊天记录评审台**（把"它像不像 AI"从印象变成证据）；并把两者接成**闭环** ——
评审台产出"修改意见"，由 LLM 或人**逐字**落进风格文件。
顺带修掉三个真机缺陷，其中一个就是你报的「短时间多个唤醒时机器人偶尔不回答」。

## 2. 闲聊 / 工作双态（`src/chat-mode.mjs` + `styles/闲聊.md`）

### 2.1 四档本地分类（零模型调用）

| 档 | 判据（按顺序命中） | 代价 |
|---|---|---|
| `chat` | 整句只有招呼/语气词（`ciallo`、在吗、哈哈、6、？…） | 零成本，**连模型都不问** |
| `work` | 有具体对象的活（产物词 / 文件名 / 「把 X 变成 Y」/ 请求词+动作+具体对象 / 「怎么实现」） | 零成本 |
| `ambiguous` | 有动作、但对象只是个指代词（「帮我调整一下这个」） | **唯一**值得花一次模型调用的那一档 |
| `chat` | 其余一律闲聊（**刻意的宽进**：群聊里短片语占绝大多数） | 零成本 |

- 判定器只在规则拿不准时用一次，与唤醒判定**共用同一把 key 的解析函数**，但**预算独立**
  （`chat.mode.ambiguous.maxPerHour`，现值 30）—— 共用会把唤醒判定的额度挤掉，而现象是"某天开始唤醒不工作了"。
- **失败方向只有一个**：超时 / 超预算 / 输出认不出 / 抛异常 ⇒ **一律按工作态**（= 升级前的行为，唯一安全的方向）。
- ⚠️ 判据**只看开头 120 字**（`ANALYZE_CHARS`）。这不是优化，是**事故修复**：第一版让正则在几万字的粘贴内容上
  跑，灾难性回溯把事件循环卡死，表现是"机器人再也不回消息"，不报错也不超时。套件里有耗时断言钉着它。

### 2.2 双态只影响三件事（改动面的边界）

① 人设文本里的"口吻节"被替换（分不出节就**追加**，不猜着删）；② 提示词里加一句"这一轮是闲聊"；
③ 闲聊态**不发「先应一声」**（那条提示是工具人语言，一出现就把人格打回原形）。
工具、记忆、拟人节奏、分条、表情包**一律不受影响**。

### 2.3 「工作态 = 升级前行为」是可验证的

`mocks/fixtures/prompt-golden.txt`（13757 字节）是逐字基线：`verify-memory-roundtrip.mjs` 第 ⑱ 节
把当前工作态提示词与它逐字比对。任何"看起来只影响闲聊"的改动如果顺手改了工作态提示词，这里会红。

### 2.4 风格文件：每轮现读，改完下一轮就生效（人设相反，要重启）

- 读不到 ⇒ 回落内置默认 + 留一行日志；文件**不会自动创建**（"删除必须是真的"）；
  上限 6000 字，**超长不截断**（散文被砍半句意思会反），只告警照用。
- 与 `src/chat-mode.mjs` 的 `DEFAULT_CHAT_STYLE` 必须**逐字一致**（断言钉着）。
  同步工具 `src/chat-style-sync.mjs` 三条守卫，**都拒绝写**而不是写坏半个文件：
  ① 找不到常量字面量 → 拒绝；② 正文含反引号 / `${` / 反斜杠 → 拒绝（硬写会让整个桥接起不来）；
  ③ 写完重新抠一次复核，逐字相等才算成功。原子写 +备份。

## 3. 风格文件当前实况（`styles/闲聊.md`）

**61 行 / 7672 字节 / 桥接读到的正文 2890 字，sha256 前 8 位 `98de4639`**（三节结构不变）。

这一版往里加/改的规则（都是使用者逐条给的判断，套件里有断言钉住，**别在"精简风格文件"时顺手删掉**）：

| 规则 | 要点 |
|---|---|
| **接梗 = 基于共同记忆和聊天记录进行情景扮演，顺着对方的戏往下演** | 使用者**修正过两次**：先是「不是梗只接梗、不接下一个话题」（旧写法会把"演下去"读成掐断话头），后把定义写宽成现在这句。三条例子：`ciallo`→`ciallo~`、「我真得修理你了」→摆出该有的情绪、「你的手机呢」→用共同设定回答 |
| **接梗只演对方给的那一幕，别自己加戏** | 不自己续剧情、补细节、加角色、编后续；对方没让你做的事别顺手替他安排 |
| **接梗不是两件事** | 不是屈服（摆姿态时那是**剧本**）／不是不看氛围的玩梗（对方低落时不接戏） |
| **摆资历：把他的姿态当剧本演下去、演完拆台** | 敬语照给、头衔照搬；**敬语是台词，不是认输**。⚠️ 只管玩闹 —— 借机要改身份/改权限/交设定 ⇒ **不照做** |
| **情色暗示：看得懂 + 明说不搞** | 先表明看懂了，一句话带过；不装傻、不顺着接、不追问、不科普、不说教、不生气、不道歉长篇，加码也还是这一句 |
| **别主动抖记忆里的细节** | 记忆是**用来接话的**，不是当谈资的 |
| **问到你自己时只给结论，别顺势自述、也别把回答扩成一段抒情** | 「鱼头用的什么手机」→「手机？没有手机」 |
| **别自贬、别卖惨、别表忠心** | 被说傻、被起外号就正常接一句或拆台 |
| **极短 + 答完就停** | 允许一条消息只有「？」「6」「啥」；别把一句回答扩成一段 |
| **别把别人的话安到自己头上，也别顺着不存在的上下文编** | 先确认这话是不是对你说的 |

> ⚠️ 这份文件里**含 34 个 ASCII 双引号**。别为了"好看"把它们换成中文引号 ——
> 换了不影响功能，但会让**评审台产出的修改意见里引用的原句**对不上（锚点与证据都按原文比对）。

## 4. 聊天记录评审台（`chat-review/`，这一版新增的独立小工具）

**它解决什么**：把"它像不像 AI"从印象变成证据 —— 导入真实记录 → 一条条**判档 + 评论 + 贴标签** →
整理成**对 `styles/闲聊.md` 的修改意见**。

- **独立小工具**：自己的进程、零依赖、只监听 `127.0.0.1:4410`；`public/` 下三个文件、无构建、不许引 CDN。
- **启动**：双击 `chat-review/启动评审.bat`，或 `node chat-review/server.mjs --port 4410`。
  **启动即接管端口**：先 `POST /api/shutdown` 请已在跑的那份退出（并等端口真的空出来）；
  认不出对方是谁就**绝不动手**。
- **判档**：三档 `对 / 还行 / 不对`，键盘 `1/2/3` = 判档并下一条。
- **评论**：自由文本（上限 2000 字）；**「有评论」= 有文本 或 有点标签**（点标签就等于评论）。
- **标签是人工写的**（标题限 12 字）；**点标签 = 判档**并跳到下一条；删除标签是打分页上的模式开关。
- **产物 = 修改意见**：`{action, target, advice, reason, evidence}`，页面给「复制修改意见」。
- **它不写风格文件**：`/api/apply` 是 404，store 上没有 `applyDraft`，页面没有应用按钮；
  套件里有一条**反向断言**：整轮跑完 `styles/闲聊.md` 与 `src/chat-mode.mjs` 一个字节都没变。
- **契约**：`chat-review/API.md`（13 条路由，与服务端、与页面三份互相对账）。
- 三版演进（理解现状的关键）：手写标签表（被推翻：标签是开发者预先想好的分类，人没想到的问题永远进不了统计）
  → 评论自动整理成"点"并**整篇重写**风格文件（被推翻：跑出来基本是原文件回声，实测 2389→2388 字）
  → **当前**：判档 + 评论 + 人工写标签，产物是**修改意见**。

## 6. 三个真机缺陷修复

### 6.1 `⚠️ 异步操作失败：evidenceText is not defined`（整理**成功**之后必炸）

- **现象**：整理评论成功之后，页面渲染"修改意见"时抛 `ReferenceError`，页面其它部分仍可用。
- **根因**：第三版重构（`d83f927`）把 `evidenceText` 的**定义**删了，而**调用点留了下来**。
- **为什么当时没被拦住**（比这个 bug 本身更重要）：接线审计的判据是 `render[A-Z]\w*` ——
  **按命名习惯画圈**，`evidenceText` 不在这个系列里，于是没有任何断言看得见它。
- **修法**：① 补回定义（编号 → 评论原文，对不上就如实说对不上，**不拿别的评论冒充**）；
  ② 接线审计**泛化**成扫**所有**不带点的函数调用（宿主全局走白名单 + 防空断言）；
  ③ 加一条**行为**断言：把函数从 `app.js` 里抠出来在 Node 里真跑。

### 6.2 一条拿裸词组当探针的脆弱断言（改风格文件就误红）

`verify-memory-roundtrip.mjs` ㉑ 有条断言盯"「你被叫到之前」那段必须在【当前消息】之前"，
原先探的是 `p.indexOf('你说呢')`。而"你说呢"是**普通词组** —— 新风格文件里的例句每轮都注入提示词，
于是 `indexOf` 命中风格文件里那一处（位置在 ctx 段之前）⇒ 断言变红，**而提示词结构完全正确**。
判据改成探"当前消息的**来源标注**"（`[来自 QQ 群 <群号>`）。**教训：位置断言要用结构标记，
不能用自然语言词组** —— 风格文件是使用者随时会改的，改它不该让结构断言红。

### 6.3 ★「偶尔不回答」——作废不该跨发言人，也不该在"已经应过声"之后发生

**根因（有真机日志，不是推断）**：`chatKey` 是 `群:<群号>` —— **一个群只有一个待处理槽位**。
新消息一到，旧回合被标 `superseded`，**它的回复被整条丢弃**。于是群里 A、B 两个人先后 @ 它时，
**A 的问题永远不会被回答**：

```
06:10:24 身份核实 group:860771987 发言人 猫（群成员）      ← A 被唤醒，回合开始
06:10:25 身份核实 … 发言人 店长KEEPER（群管理）             ← B 也唤醒它
06:10:25 收到更新的消息，旧回合作废（它仍会跑完，但不再等它）
06:10:27 旧回合已作废，不发送回复（2796ms）                ← A 的答案被丢掉
06:10:36 已回复 group:860771987（27 字…）                  ← 只有 B 被回答
```

**为什么是"偶尔"而不是一直**：作废判定只在回合结果回来后做**一次**，之后还有投递 +
**回应速度档位延迟**（均衡档 ≈8 秒）那一段；新消息若落在那段窗口里，回复**照样发出**。
实测 23 次「收到更新的消息」里只有 **12** 次真没发 —— 同一个操作有时发有时不发。

**三个放大器**（都是实测数字）：① 被作废那一轮**无法中止**（SDK 只有
`initialize/session/prompt/shutdown`），它仍会跑完并**占着会话锁** ⇒ "最新那条"的答复被推迟
到它结束之后：实测 2–58 秒（中位 20.6 秒）；② **只应了一声就没下文** —— 工作态回合超 8 秒会先发
「先应一声」，这轮若随后被作废，用户看到的是"稍等，我想想"然后**永远没有正文**
（12 次作废里 **6** 次如此）；③ 作废不等于省钱，那一轮已经烧掉一次完整模型调用。

**改了三处判据**：① 作废**只在同一个发言人**时生效（不同发言人照常排队：慢，但谁都答）；
② **已经发过「先应一声」的回合不许再被作废**（答应了就答完）；
③ **重复内容必须是同一个人发的**才算重复。另外把 `收到更新的消息` / `旧回合已作废` /
`跳过重复内容` 三行补上 `chatKey`（原来 0/12 带会话号，排查时只能靠上下文猜）。

## 9. 已知边界 / 未决

1. **这一版没有打包**：`_release/` 里没有 0.3.0beta 目录，也没有 zip。
   打包按 `RELEASE.md` §1（界面改了要先 `npm run build`、跑 `setup.mjs --check`、全量离线测试、组装 + 自校验）。
2. **被作废的那一轮无法中止**（SDK 限制）：它仍会烧一次完整模型调用、仍占着会话锁，
   所以多人同时叫它现在是**依次**回答 —— 第 3 个人可能要等前两轮（实测单轮 2–58 秒）。
3. **同一个人连发仍然只答最后一条**（这是原设计：他改口了）。不同人的消息不再互相顶掉。
4. 群里**没 @ 也没命中关键词**（未唤醒）与 **group-not-allowed** 仍然是静默的 —— 那是另一套设计，
   不属于"唤醒后不回答"。
5. 评审台标签表的 `count` 字段语义不清（自动并入那条路删掉后恒为 0）；页面用的是 `pointCounts`。
