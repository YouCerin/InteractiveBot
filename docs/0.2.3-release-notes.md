## 1. 这一版解决的六类问题

| # | 以前的样子 | 现在 |
|---|---|---|
| **能力块没有开关** | 记忆 / 投递账本 / 本地语料库这些能力**早就是模块**，但配置里一个键都没有 —— 既看不见，也关不掉 | 逐个补上真配置键并登记成**插件卡**：是什么 / 关掉会怎样 / **即时生效还是要重启**（附取证位置） |
| **两个功能抢同一个问题** | 比如"这条消息要不要回"—— 判据与总开关分散在不同页签，各说一半 | 新机制「**二选一**」（`switchKind: 'choice'`）：**一个键两个取值**，界面上是一排按钮。选了 B 就**天然**没有 A，后端**没有任何互斥检查**（也不需要） |
| **QQ 工具的安全边界是黑名单** | `qq_api` 的动作由模型自选，而黑名单只能拦"想得到的" —— **实测漏过读凭据（`get_cookies`）与把本机文件外发（`upload_group_file`）** | `qq_api` 改成**只读白名单**（fail-closed），并新增**档位** `mcp.profile`（`full` 默认 / `readonly`）与 `mcp.genericApi` |
| **机器人不会沉默** | 群聊里命中关键词**必答**，哪怕那句话其实是说给别人听的 | 新增 `wake.policy = semantic`（**实验性**）：规则先唤醒，再由**判定器**否决 → **可沉默**。默认仍是 `rule`（= 升级前的行为，一次额外调用都不产生） |
| **改完要重启才有窗口** | `start.bat` 前台跑，**关掉那个终端窗口机器人就下线** | `start.bat` 默认**后台启动**（不留窗口、关窗口不掉线）；`--foreground` 是逃生舱 |
| **额外一次模型调用只能起进程** | 唯一的通路是起一个一次性 DSH 进程（2.8~4.4 秒 + 整套系统提示词） | 新增 `src/model-direct.mjs`：一次 `/chat/completions`（**实测 1092ms**），判定与被卡住的回合后抽取（R4b）共用 |

## 2. 插件从 8 张变成 10 张

`src/plugins.mjs` 现在登记 **10 张卡**：

```
🧠 跨重启记忆   🖼️ 看图   🔧 QQ 原生功能（MCP）   ⏱️ 人味层   📊 用量记账
📣 唤醒策略（二选一）   📮 投递可靠性   🗂️ 本地语料检索   🎭 人设   🔐 名单与权限
```

* **新增 3 张**：`wake-policy`（二选一）、`delivery`（投递账本）、`corpus`（本地语料检索）；
* **删掉 1 张**：`trigger`（原「唤醒规则」）—— 用户指出"功能太过简单且与唤醒策略冲突"，
  而实际更糟：它和 `wake-policy` **回答的是同一个问题**，一张只显示判据里的一个开关、
  另一张显示"用哪套判据"，**两处各说一半**。判据本身现在归到「唤醒策略」卡里的一节（见 §4）。
* ★ **三个新键的默认值都等于升级前的行为**（`delivery.ledger` 开、`corpus.enabled` 开、
  `mcp.profile = full`）—— 加开关的目的是"能看见、能关"，**不是顺手收紧默认值**。

## 3. 唤醒策略（这一版最大的一件）

### 3.1 它是什么

`wake.policy` **一个键两个取值**：

| 取值 | 含义 |
|---|---|
| `rule`（默认） | 规则唤醒 = **升级前的行为**：私聊 / 被 @ / 命中关键词 → 必答。**一次额外调用都不产生** |
| `semantic`（标「实验性」） | 规则先唤醒，再由**判定器**否决 → **可以沉默** |

**为什么是一个键而不是两个开关**：两者回答的是**同一个问题**。两个独立开关会出现两种
无意义状态 —— 两个都开（两套判据打架）与两个都关（机器人不知道该不该回）。

### 3.2 判定器看不到什么、能看到什么（**这条最要紧**）

| 给它 | 不给它 |
|---|---|
| **本会话**最近 12 条 `user` / `bot` 消息（每条截断 200 字） | ❌ **模型的内部推理**（`role:'thinking'`） |
| 当前这条消息（截断 200 字） | ❌ 系统提示（`role:'notice'`） |
| 机器人自己的 QQ 号、本次 **@ 的是谁**、发言人、是否 @ 了它 | ❌ 记忆文件 / 任务台账 / 配方库 / 人设正文 / 工具结果 / 技能提示词段 |

★ **范围只限这一个会话**（按 `chatKey`）—— 拿不到"这个人在别的群说过什么"。
★ ⚠️ 判定提示词**不过 `privacy.mjs`**（那道闸门管的是记忆落盘与发给 QQ 的正文）。
所以相对"什么都不做"，多出来的是：**① 一条最终被判为沉默的消息，它的正文也已经被发出去过；
② 机器人自己说过的话会被重发一次。** 两者都受 `wake.judge.maxPerHour`（默认 60/小时）约束，
而 `wake.policy = rule` 或 `wake.judge.shadow = true` 可以把它整个关掉。
★ 本地那条记录（oplog 的 `type:'wake'` 行）**是过隐私筛的**。

### 3.3 判据是「收件人维度」，不是「话题相关性」

> **唯一要回答的问题：这句话是说给谁听的？**
> 说给机器人 → 回答；说给别人 / 说给整个群 → 沉默。

这条是**改出来的**（见 §6）：第一版把"该沉默"写成「群友之间在互相对话，**与机器人无关**」，
于是"提到它的名字"＝"与它有关"＝不该沉默 ⇒ **它必然永远回答 answer**，
语义唤醒退化成规则唤醒、只多花了一次调用的钱。
现在判据里显式写着：**"提到它的名字"本身不构成回答理由**、**"话题与它有关"也不构成回答理由**。

### 3.4 判定走哪条路：**由"有没有专用 key"决定，界面上没有按钮**

| `wake.judge.apiKey` | 实际走哪条 | 时间 |
|---|---|---|
| **留空（默认）** | **一次性 DSH 进程**（用主对话那套凭据，不需要额外配任何东西） | 约 3~5 秒 |
| **填了** | **直连**一次 `/chat/completions`，**只用这把 key** | 约 1 秒（实测 1092ms） |

★ 为什么不做成两个按钮让使用者选：两条路在唤醒流程里做的是**同一件事**（让一个模型判断
"这句话是不是说给我听的"），让人选一个自己无法判断好坏的东西没有意义；
而"要不要单独配一把 key"本身就是那个选择的**可观察依据** —— 它带来独立计费/限流与
"不动主 key"这两个真实差别。
★ 直连那条**只认**这把专用 key：**不会**拿 `dsh.apiKey` / 环境变量 / DSH 凭据文件去发请求。
★ `wake.judge.apiKey` 是**密文字段**（界面只回"配没配"、值不回显；清除 = 退回 DSH）。
★ ⚠️ **需要走代理才能访问模型端点的网络**：直连那条**没有做代理发现**
（Node 的 fetch 默认不认 `HTTP_PROXY`）—— 那就**不要**填这把 key，留着走 DSH 那条。

### 3.5 三条安全线（都是取证出来的）

| # | 边界 | 为什么 |
|---|---|---|
| ① | 判定器**只做减法**：规则说"不回"的消息走不到它面前 | 它**没有任何办法让机器人多说一句话**。这正是不需要 hermes 那套状态机（对话态窗口 / epoch / 退出闸门 / episode）的原因 —— 那套机器存在的唯一理由是"判定器能主动发起回复" |
| ② | 闸门在**准入之后、跑回合之前** | DSH 的 SDK **没有 cancel/abort/steer** ⇒ 进了回合的那一轮**注定烧完**。只有在这里否决，"沉默"才真的省钱 |
| ③ | 私聊与被 @ **不进判定器** | 那是"必答"。让判定器审它既浪费额度，又会让 @ 的响应平白多等几秒 |

### 3.6 失败一律放过（fail-open）

**超时 / 报错 / 输出认不出 / 超预算 / 被取消 —— 全部放过**，退回规则行为。
唯一的坏结果是"多回一句"，不会出现"判定器一坏机器人就变哑巴"。
另有 `wake.judge.maxPerHour`（默认 60/小时）兜住最坏情况。

### 3.7 影子模式（`wake.judge.shadow`，默认**关**）

* **关（默认）** = 判定**真的生效**：被判"沉默"的消息不会得到回复，**且没有任何提示**；
* **开** = 判定照跑、结论只写进 `runtime/oplog/`，**行为一个字都没变** —— 用来先观察它想拦什么。

★ **这一项即时生效**（每轮现读）；`apiKey` / `model` / `baseUrl` / `timeoutMs` / `maxPerHour`
要重启才生效。

## 4. 界面：这一版真正做了什么

### 4.1 「二选一」按钮（第一次用上这套机制）

唤醒策略那张卡**不渲染开关**，渲染**两个并列按钮**（当前值高亮）；标「实验性」的那一侧
必须显示「实验性」徽标；**不显示"关掉会怎样"**（二选一没有"关"），改成每个按钮各自一句
"选它会怎样"。

### 4.2 「唤醒方式」搬到「唤醒策略」下面（原「人设」页的「什么时候回我」）

用户要求。搬的理由：`wake.policy = rule` 时，**这一节就是那条策略的全部内容**；
`semantic` 也只是在它之上加一层否决 —— 放在人设页会让"它用什么判据决定回不回"被劈成两处。

★ 搬家时**原样保留**三样（都是踩出来的）：群聊总开关的**风控文案 + 二次确认**、
关掉总开关时另外三个开关**一起变灰**、关键词的**高频词告警与成本提示**。
★ 它**不藏在「详细设置」里** —— 那是每天要看的东西。

### 4.3 桥接日志卡（后台启动之后它是唯一能看到启动期信息的地方）

* 游标回绕（文件被轮转/重建）时**清屏重建**，否则新旧日志拼在一起像时间倒流；
* 手动往上滚时自动关掉跟随；新增「清屏」按钮（只清界面，**不删日志文件**）；
* 启动期的告警（`earlyLogLines`）现在**真的会进 `logs/bridge.log`** ——
  以前 logFile 赋值晚于 MCP/技能装配，那几行只出现在窗口里，窗口一关就没了。

### 4.4 「未保存改动」的小圆点映射跟着搬家一起改了

`Home.tsx` 的 `pathToTab()` 原本把 `trigger.*` 映射到**人设页** —— §4.2 一搬，
那个小圆点就会**亮在错的页签上**。已改成 `extensions`。
★ 这条是**控制台会话**在搬完之后补上的（我改结构时漏了它）；它同时重建了 `dist`。

## 7. 这一版**刻意不做**的事（都有理由）

| 不做 | 为什么 |
|---|---|
| **记忆模块 / 提示词模块的任何改动**（`memory.*` 拆键、`memory.scope` 二选一、人设段落化、身份装载、反注入段） | 用户明确要求这两块不动。设计里分析过但**一行代码没碰** |
| **`continuation`（对话态自动接续）** | 它是这五项里**唯一会新增消息量**的一项，与"群聊涉及账号风控、不主动插嘴"的既有立场冲突；而且需要 hermes 整套状态机（移植成本从约 200 行抬到 1000+ 行）。改"什么算触发"是**产品决策**，不该由一次插件化顺手带进来 |
| **给"边界项"做开关**（投递前终检门 / 出站幂等键 / 隐私双侧闸门 / 篡改回滚 / 凭据发现规则） | 它们是**边界不是功能**。关掉终检门会把工具 JSON 与内部占位符直接发到 QQ；关掉幂等键会退回"裸文本当键"、误丢不同会话里的同一句话 —— 那是**已修的缺陷**。做成开关等于让"关掉功能"这个动作制造出新缺陷 |
| **`mcp.adminTools`（允许踢人/禁言）** | 那等于加一个"允许踢人"的开关。改为**删掉工具结果里那句假承诺**（"请让使用者在配置里放开" —— 从来没有这个配置项） |
| **`corpus` 算记忆模块？** | 用户拍板**不算**：记忆是 `memory/*.md`、**模型可提议写** + 篡改回滚；corpus 是 append-only 的 SQLite、**模型只能读**。数据面、读写权、失败后果都不同 |
| **改 `config-ui/src/**`（在 S0~S5 阶段）** | 用户当时要求"只修改指导文件"。所以那时界面要求全部写进 `CONFIG-UI.md`；界面由**另一个会话**按那份规格实现，落地后我这边只做了三处纠偏（见 §6 与提交记录） |
| **组装发布包** | 延续 0.2.1/0.2.2 的做法，本轮也没组（`_release/` 下最新的仍是 0.2.0） |

## 8. 已知边界与待办（如实列出）

1. ★★ **`[reply:…]` 引用回复永远失效**（§6 第 8 条）：注入显示带 `#`、解析只认裸数字。
   修法很小（接受可选的前导 `#`）但**本轮没做** —— 它属 H6 那条线，与唤醒无关，
   而且改它要有对应的标记测试。
