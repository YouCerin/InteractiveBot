## 0. 前置结论：这七个包是什么

**它们全部是同一套宿主生态的产物，宿主是「QQ Agent」——一个 Electron 桌面应用 + OneBot v11（SnowLuma）协议端的 QQ 机器人，不是 DeepSeek Harness（DSH）插件。**

## 1. AI状态查询（ai-status v1.5.5）

### 1.1 定位
查询机器人当前状态并**直接发一张深色状态面板图**到当前会话；渲染失败自动回退为文字卡。它同时是整套生态的「**状态枢纽**」：其它插件只要上报一个能力，就会自动出现在它的面板里。

### 1.2 面板字段（逐项）
| 分区 | 内容 |
|---|---|
| 模型与渠道 | 当前模型、渠道域名；内置中文品牌映射（如 `deepseek-v4-pro` → 深度思索 v4-pro、`token.sensenova.cn` → 商汤），映射表可随时补充 |
| 用量 | 今日 token 用量、缓存命中率 |
| 花费 | 今日花费；DeepSeek 峰谷时段、两档单价、当前处于高峰/闲时、转档倒计时、一口价模型标注「不分峰谷」 |
| 会话 / 运行 | 今日会话数、进程运行时长 |
| 系统资源 | 进程内存与堆、系统内存余量、CPU 占用；超阈值给「重启建议」 |
| 告警 | 日志告警条数与摘要 |
| 节日 | 最近节日倒计时（内置节日表，`upcomingHoliday()`，不联网） |
| 插件状态 | 其它插件上报的运行状态，自动聚合成分区 |
| 健康提示 | 内存/CPU 告警 + 各插件 `tips` 合并成的顶部徽章 |
| 配色 | `theme` 设置项：dark（默认）/ light |

### 1.3 指令与触发
- 指令**必须带反斜杠**：`\状态`、`\AI状态`、`\用量`、`\花费`、`\模型`、`\峰谷`、`\运行时长`、`\内存`、`\CPU`、`\节日`。
- **不带反斜杠不响应**；以 `/` 开头的斜杠指令（`/状态`、`/status`）被明确判定为"其它机器人的命令"，也不响应。
- v1.5.4 起增加 `commandRoute` 直达：`AI状态/状态/用量/花费/成本/模型/峰谷/运行时长/内存/CPU/节日` 由系统直接执行工具，**不经过模型判断**（省 token、更快）。`日志`、`告警` 未进直达表，因为与另一个插件的词撞车。
- 工具 `get_ai_status`，参数 `format`：`image`（默认）或 `text`（6 行文字卡）。图片由工具自己发出，提示词明令禁止模型转发或复述面板细节。

### 1.4 对外能力（状态枢纽协议）
- 任何插件/技能导出 `providers`，键名为 `status.<插件目录名>`，面板即自动扫描显示，**无需修改 ai-status 代码**。
- 上报对象字段：`icon`（emoji）、`title`（必填）、`lines`（`[标签, 值]` 数组，最多 4 条）、`tips`（字符串数组，并入顶部健康徽章）、`priority`（默认 50，越小越靠前）、`adminOnly`（v1.4.5+，只给管理员看）。
- 三条硬约定：**必须同步返回**（禁止 IO/await）、返回 `null/undefined` 表示本次不上报、抛异常会被调用方吞掉（一个插件状态坏了拖不垮整张卡）。
- 另对外开放 `cost.display-override` 能力：别的插件可以只改「今日花费」的**显示文案**，真实计费与预算统计不受影响。
- 软依赖外部能力：`llm.rate-stats`、`cost.display-override`、`message.owner-check`——有提供方就用，没装自动跳过，插件其余功能照常。

### 1.5 权限门禁
- `sensitiveAdminOnly`（总开关）：开 = 下方清单生效；关 = 所有状态对所有人公开。
- `adminOnly`：逗号分隔的键名清单，支持中文。可选键：`model` / `vendor` / `system` / `plugins` / `tips` / `pid` / `cost` / `usage` / `peak` / `rate` / `logs` / `budget` / `holiday` / `runtime`，也可点名单个插件 `plugins.插件id`。默认 `system,plugins,tips,pid`。
- 普通用户会收到精简面板；提示词明确要求模型**不要**以权限不足为由拒绝调用。

### 1.6 数据与依赖
- 配置：`config.example.json` 只是样例；实际配置在 `data/config.json` → `skills["ai-status"].settings`，**必须走控制台表单或 `POST http://127.0.0.1:3210/api/config`** 修改（内存有缓存，手改不生效且会被覆盖）。
- 依赖宿主核心模块（`src/config.js`、`src/holidays.js` 等），**不能脱离 QQ Agent 独立运行**。
- 自带测试：`test/ai-status-test.mjs`（10 项断言，覆盖档位判定/周末闲时/一口价/无价目/门禁一致性）。

### 1.7 值得注意
- v1.5.5 修了一个会误导人的 bug：**一口价模型（无高峰档）在高峰时段被错贴「高峰档」**，让人以为渠道在翻倍计费。现在改为「没有 `peak` 字段就不显示档位」，并明示「（不分峰谷）」。
- 档位标签同时出现在 4 处（文本卡花费行、面板徽章、渠道行、面板 chip），统一由 `tierLabel`/`tierNote` 一处决定，避免各自漂移。

## 2. 每日打卡（check-in v1.0.0）

### 2.1 定位
一个**技能**（`skill.json` + `index.js`），不是插件。让机器人在群里主持一个可自定义的每日打卡活动：记住谁今天打了、谁没打，并能催促未打卡的人。

### 2.2 三个工具（全部由模型判断何时调用）
| 工具 id | 名称 | 行为 |
|---|---|---|
| `check_in` | 打卡 | 记录某人今天完成打卡，**每人每天只能打一次**；重复打卡会告知"已打过"并报出当前人数 |
| `check_in_status` | 查询打卡情况 | 列出今天已打卡 / 未打卡名单；传 `name` 可只查某人 |
| `remind_check_in` | 催促打卡 | **直接把催促消息发到群里**（确定性最强）；传 `name` 只提醒一个人 |

### 2.3 机制
- **按自然日重置**：只取"今天"的条目，没有即视为无人打卡；每人每天一次。
- **数据结构**：`{ [chatKey]: { [YYYY-MM-DD]: { [memberKey]: { name, at } } } }`。
- **成员唯一键**：优先 QQ 号；只有昵称时加 `~` 前缀，避免与 QQ 号撞 key（同名昵称会互相覆盖，所以模型能拿到 QQ 号时优先传 `userId`）。
- **未打卡名单**：依赖宿主 `store.activeMembers(chatKey)` 拉活跃成员；拿不到就只报已打卡的人，不报错。
- **持久化**：`<DATA_DIR>/skills/check-in/checkins.json`，**原子写**（先写 `.tmp` 再 rename），文件损坏时从空开始（打卡记录坏了不该让技能挂掉）。
- **自动清理**：按 `retentionDays`（默认 30 天）清理过期记录，防止数据无限膨胀。
- **动态提示词**：`promptSections()` 把自定义的打卡名称注入系统提示词，每次对话都带上；`skill.json` 里也有一份静态规则段（priority 45）。

### 2.4 配置项
| 键 | 默认 | 含义 |
|---|---|---|
| `checkinName` | 今日打卡 | 打卡活动名（如「早起打卡」「学习打卡」） |
| `checkinText` | 空 | 群友打卡时机器人附带的固定话术；留空让模型自由发挥 |
| `remindText` | 空 | 催促文案；留空用默认催促语 |
| `retentionDays` | 30 | 打卡记录保留天数 |

### 2.5 依赖
`import { DATA_DIR } from '../../src/config.js'`——复用核心导出，多实例下与正在运行的进程一致（避免"实例 #2 的打卡写进了 #1 的目录"）。**不能脱离宿主运行**。

## 3. 情绪插件（心情与生活系统 v4.0.0）

### 3.1 定位
给"人设"用的**数值引擎**：模拟她的情绪、疲劳、生理节律与"现在在干什么"。核心设计原则是**数值全部本地判定，零 token**，只在提示词里注入「你现在是什么状态、该怎么说话」。

### 3.2 情绪五维（0~100 连续值 → 5 个语义档）
档位表 `MOOD_BANDS`：1-9 一点 / 10-29 有点 / 30-59 中度 / 60-84 强烈 / 85-100 极度。

| 维度 | 衰减周期 | 触发来源 |
|---|---|---|
| happy 开心 | 45 分钟/档 | 被夸、被哄、玩得开心 |
| excited 兴奋 | 15 分钟/档（来得猛去得快） | 新鲜事、被撩、期待 |
| angry 生气 | 40 分钟/档 | 挨骂、被凶、被冒犯 |
| jealous 吃醋 | 90 分钟/档（**最持久**） | 主人对别人热情 |
| sad 难过/抑郁 | 60 分钟/档 | 被冷落、被拒绝、搞砸事 |

每一维的第 N 档都配了一句**演出指引**（"数据 → 怎么演"），例如"生气到顶格：几乎不想说话，或一句狠话甩过去然后冷场；气头过了就收，别记仇到第二天"。这层指引就是注入提示词的内容。

### 3.3 愤怒三通道
`rageDeltaFromEntries()`：挨骂 / 被甩脸 / 护亲（有人欺负她主人）三条独立通道累加，75 以上是顶格档；配套 `rageApplyCap()`（上限）、`rageBlock()`（注入块）。

### 3.4 吃醋、抑郁、满足
- 吃醋：`jealousyDeltaFromEntries()`（主人对别人热情时上涨）、`jealousyReleaseCheck()`（40 = 触发占有欲释放）、`jealousyTierBlock()`（75 = 醋爆档）。
- 抑郁 `depress`：连续搞砸、被忽视时累积（搞砸事 +10）；60 以上进入抑郁态（演出上限被压）、85 以上是「灰」；`depressMods()` 给出对其它维度的修正。
- 满足 `satisfaction`：被好好对待后留下的余韵（40 以上算有满足感、75 以上"整个人是满的"）。
- 吵架速度 `spunk`：30 以上开始抢话还嘴、70 以上"气头上"（`spunkFightHit` / `stepSpunk` / `spunkFactor`）。

### 3.5 疲劳五段
`stepFatigue()` + `fatigueFactor()` + `fatigueBlock()`：说话越多越累，睡着才恢复；50 以上"挺累的"、75 以上"困得不行"。疲劳还会反过来触发**恢复池**。

### 3.6 被冷落检测
`detectNeglect()` → `applyNeglect()`：她发言后 X 分钟没人接 → sad 上升（可封顶），并有低概率"哼一声"。

### 3.7 全局自身状态机（self-state）
三态：`awake` 醒着 / `busy` 在忙 / `sleeping` 睡了。跨会话、跨群、全局唯一。
- **谁写**：观察她自己的发言——说了睡觉的话就标 `sleeping`（`stateFromSelfText()`），说了"在干某事"就标 `busy`。
- **自然衰减**：`sleeping` 最多持续 8 小时、`busy` 最多 2 小时，之后视为醒着（防止一次误判把她永久锁死）。
- **睡眠闸（省 token 的关键）**：`sleepGate()` + `blockWhileSleeping` 开启时，她"睡着"时**普通消息直接不响应**（不调模型）；只有被 @、被引用、被戳 + 喊醒词（醒/起来/别睡/叫醒…）才放行，并带上"被喊醒"标记，让她用睡迷糊的口吻回复。
- **提示词注入**：awake 但 40 分钟内说过睡觉 → 提醒"你刚说过要睡，别再兴奋聊太久"；busy → 告知"你正在干某事，回话要贴合"；刚被喊醒 → "你刚被叫醒，迷迷糊糊"。
- **洗澡账本**：`readBathState()` / `settleBath()` / `bathStartFromSelfText()` 等；`BATH_EFFECTS` 定义洗澡的状态收益。

### 3.8 恢复池与作息表（"她现在在干什么"）
- **恢复池**（疲劳驱动）：疲劳 ≥ 阈值（默认 50）且她闲着 → 每 10 分钟判定一次，30% 概率选一件恢复行为进入 `busy`；冷却 90 分钟。行为与权重：看风景 1.0、撸猫 0.8、玩游戏 0.8、洗澡 0.9、吃好吃的 1.0、和哥哥贴贴 1.2、逛街 0.5。每件行为有数值结算（如洗澡：疲劳 −25、开心 +2）。
- **作息表**（时段驱动，参考而非硬规则）：按 `[from, to)` 小时给候选事项 + 权重（如 7-9 点"刚起来吃早餐"），选中概率 18%/次、冷却 50 分钟；已有事项时 12% 概率"玩腻了换一件事"；**下午档必含「洗澡」候选**，一天只洗一次（洗过权重清零）。
- `scheduleBlock()` / `selfStateBlock()` 负责把当前事项写进提示词，让她记得自己在干什么。

### 3.9 插件化实现方式（技术要点）
上游（C2 的「心情系统插件树 v4.0」）把数值核心放在宿主 `src/` 里，需要改 5 处核心代码。本移植版用 v0.4 的 hooks **完全等价替换，没有改一行核心代码**：

| 上游接线 | 本插件 |
|---|---|
| `orchestrator.observeTrigger()` | `hooks['before-context']` |
| `prompt.js` 里 13 个注入块 | `hooks['before-llm-messages']` |
| `sender.js` 出口观察她自己的话 | `hooks['after-tool']` |
| `orchestrator.wake` 的 sleepGate | `hooks['before-context']` 记录 + `hooks['before-tool']` 拦截 |
| 后台衰减钟 / 作息表推进 | `activate()` 里的定时器（默认 60 秒心跳） |
| `panel.html` 15 格面板 | `configSchema` 的 `type:'live'` 只读字段 + 3 个工具 |
| `src/config.js` 的 DATA_DIR | `lib/config.js` 转发核心导出 |

- 对外提供 **只读能力 `mood.snapshot`**：核心按名字来问、谁提供谁答，以后换引擎只要仍提供这个名字，面板与核心都不用改。
- 注册 3 个工具：`mood_status`（读心情与状态）、`mood_adjust`（手动把某项设为 0-100，不可撤销但会被自然衰减拉回）、`mood_reset`（清零并回到 awake）。
- 设计红线：**永远不做硬拦截**（睡眠闸是唯一既定例外）；状态文件坏了/缺了就全当平静，绝不锁死；所有失败静默吞掉，不影响正常回复。

### 3.10 配置项
插件级：`enabled`（总开关）、`inject`（是否注入演出指引，关掉只算不用）、`tickSeconds`（心跳间隔，默认 60，范围 15-600）、`blockWhileSleeping`（睡眠时禁止发言）、`selfState`（全局自身状态机）、`ownerQq`（主人 QQ；留空自动从 `owner-identity` 能力取，用于"护亲"判定）。
引擎级默认值在 `lib/*.js` 的 `*_DEFAULTS` 里（几百项，插件不重复声明，避免上游改默认值时失同步）。

### 3.11 已按需求移除的模块（重要）
`REMOVED_MODULES = ['love','lust','arousal','want','sister','solo','soloVoice','ownerHealth']`——情爱 / 性欲 / 色色兴奋 / 想要 / 姊妹亲密，以及依赖它们供数的贤者时间、自慰心声、哥哥健康。
移除方式：**不改引擎代码**，全部走引擎自己的开关（`enabled:false`），关掉即"不注入、不推进、不结算"，随时可以一行改回来；同时补齐了原先漏掉守卫的几个写盘函数。

## 5. 音乐卡片（qq-agent-music）

### 5.1 定位
从 QQ Agent 本体（`src/`）抽出的**完整音乐能力栈**，自包含、**零第三方依赖**（仅 Node 18+ 全局 `fetch`）。两个用途：维护本体音乐功能时先读它的架构；或把 `scripts/` 移植进任何 Node 项目获得搜歌/歌词/归档能力。

### 5.2 能力清单
| 能力 | 入口 | 说明 |
|---|---|---|
| 统一搜歌 | `searchMusic(keyword, {platform, limit})` | 网易云优先，无结果/版权怀疑自动换 QQ 音乐；结果按查询词重排防翻唱 |
| 歌词获取 | `getLyrics({name, singer, jumpUrl})` | 链接解析 id → 按名搜网易云 → 按名搜 QQ 音乐，逐级兜底 |
| 链接归档 | `MusicStore` 类 | 每条一个 JSON 文件（`data/Music/`），滚动保留最近 1000 条 |
| 卡片发送 | `sendMusicCard(chatKey, song)`（本体内） | OneBot 原生音乐段优先，协议端不支持退自定义卡片 |
| 卡片解析 | `extractMusicFromSegments(segments)`（本体内） | 群友分享的音乐 JSON 卡片 → 结构化信息 → 入站归档 |

**版权红线：只取元数据（id/歌名/歌手/链接），绝不下载音频**；音乐以"分享卡片"形式发出，群友点开跳官方 App 播放。

### 5.3 三个模型工具
| 工具 | 参数 | 关键约束 |
|---|---|---|
| `send_music` | `keyword`（必填，可含歌手）、`platform`（auto/netease/qq） | 先歌后话：收到点歌立即发卡片再回应；keyword 必须来自**本次消息**（禁止拿记忆里"之前发过的歌"顶替）；失败如实说"没找到"，重试最多 1 次，不许编造；不被要求不主动发歌，一次最多一首 |
| `get_music_links` | `query`、`limit`（默认 5，最大 20） | 先查本会话，本会话没有且带 query 时跨会话找；没归档过就如实说，**不编造链接** |
| `get_lyrics` | `name`、`singer` | 不传 name 取本会话最近一条；歌词超 4000 字截断；引用一两句即可，拿不到（纯音乐/版权）如实说，**绝不编造歌词** |

### 5.4 搜索后端与关键设计
- 网易云：`music.163.com/api/search/get/web`，需带 `referer: https://music.163.com`（不带会 403）。
- QQ 音乐：`c.y.qq.com/soso/fcgi-bin/client_search_cp`，需带 `referer: https://y.qq.com`。
- **防翻唱重排 `rankByQuery`**：平台接口常把翻唱/remix 排在原唱前（搜"晴天 周杰伦"第一是深情版）。按查询分词命中率打分（歌名与第一个分词全等再 +0.5），同分保持原顺序；多取几条（≤10）重排后再截断。
- **版权怀疑链**（auto 模式）：查询带歌手（≥2 分词）而网易云前三名歌手一个词都不沾 → 疑似该歌手曲库不在网易云（典型：周杰伦仅在 QQ 音乐）→ 去 QQ 验证，那边歌手沾词就整体换平台。
- **歌词逐级兜底**：归档链接解析平台 id（网易云 `?id=` / QQ `songmid` 或 `/songDetail/<mid>`）→ 按名搜网易云 → 按名搜 QQ；QQ 歌词是 **base64 LRC，需解码**；`stripLrc` 去时间轴与重复行。
- **失败要如实**：搜索无结果/接口报错时原样告知（含聚合错误信息），模型不得编造歌曲或歌词。

### 5.5 归档存储（MusicStore）
- 每条一个 JSON，文件名 `<ts36>-<seq4>-<rand4>.json`：`ts36` 毫秒时间戳 36 进制（字典序 = 时间序）、`seq4` 进程内单调序号（**同毫秒连发两首歌时纯时间戳排序会随机颠倒**，序号保证字典序 = 写入顺序）、`rand4` 防碰撞。
- 滚动保留最近 `MAX_FILES = 1000` 条，超出删最旧；`recent({chatKey, query, limit})` 按文件名倒序扫、逐条 parse，坏档跳过不阻塞。
- 归档失败只 `console.warn`，**不影响发送/聊天主流程**。
- 记录样例：`{ chatKey, mid, name, singer, platform, jumpUrl, audioUrl, ts }`（`mid` 是消息 id，机器人自己发的为 null）。
- 本体目录 = `DATA_DIR/Music`；可移植副本改为构造参数 `new MusicStore({ dir })`，默认 `./data/Music`。

### 5.6 OneBot 卡片收发与装配
- **出站**：走 per-chat 发送队列（串行化 + 排队），发前限频并 `sleep(600-1500ms)` 模拟真人停顿；两级卡片——① OneBot 原生音乐段 `{type:'music', data:{type:'qq'|'163', id}}`（体验最好）② 失败退自定义卡片（`url`/`audio`/`title`/`content`）。原生段异常一律被吞掉、不向上抛。
- **入站**：音乐卡片在 OneBot 里是 json 段。`musicCardInfo()` 判定（`app` 匹配 qqmusic/netease/kugou/kuwo…，或 `meta.music` 存在，或 tag 含"音乐"），提取歌名/歌手/平台/链接；`extractMusicFromSegments()` 遍历所有 json 段收录；`renderJsonCard()` 把卡片转成模型可读文本（`[音乐分享：《晴天》 歌手：周杰伦 · 来自QQ音乐]`，识别不出歌名则 `[音乐卡片：未能识别]`）。
- **装配点**（改功能时动哪里）：`app.js` ~302 建 store、~313 注入 orchestrator、~480 入站归档钩子；`orchestrator.js` ~443 注入 `ctx.musicStore`；`tools.js` ~618-754 工具定义；`sender.js` ~175-212 发送；`onebot.js` ~277-343 卡片识别。

### 5.7 同步提醒
`scripts/music-search.js` 与本体 `src/music-search.js` 是**同一份代码的副本**；`scripts/music-store.js` 仅差在目录注入。**改本体音乐代码时必须同步更新本技能，反之亦然**。跑通验证：`node scripts/test-music.mjs "晴天 周杰伦"`。

## 6. 跑团插件 3.0（dice 2.0.0 + kp 2.2.0）

一个压缩包里装了两个互相独立、可分别开关的插件，加一份宿主插件机制说明。

### 6.1 dice：TRPG 掷骰（Dice! 风格）

**定位**：群内掷骰与 COC 7th 检定，加角色卡、先攻、骰池、牌堆、旁观、对局日志；同时向 KP 插件暴露掷骰能力。**零第三方依赖**，纯 Node 内置模块。指令语义按 Dice!（Dice v2）公开文档独立实现（Dice! 本体是 C++ QQ 机器人，无法在 Node 里跑）。

#### 前缀与表达式
- 前缀可用 `.`、`。`、`!`、`！` 任一；无空格写法也认（`.rd100`、`.r3d6k2`、`.rh1d100`）。
- 表达式语法：`([次数]#)[个数]d[面数](b[奖励骰])(p[惩罚骰])(k[取最大个数])`；运算符 `+ - * /` 与括号，`X`/`x`/`×` 视为乘。
- 上限：个数 1~100、面数 1~1000、次数 1~10、奖惩骰 ≤9；超出夹到上限不报错。
- 奖惩骰由 `rollPercentile` 实现（个位骰共享、多十位骰取优/取劣）；`maxOfExpression` 求理智大失败满值。
- **坏表达式明确报错**（`.r 1d`、`.r 1d100@`、`.r ()`），不会静默退回默认骰给一个假结果。
- ⚠️ **表达式里不要加空格**：`.r 1d100 + 1d4` 会被切成两个参数，只掷其中一项。

#### COC 7th 判定（`coc.js`）
- 成功等级 `SUCCESS` 0~5：大失败 / 失败 / 常规成功 / 困难成功 / 极难成功 / 大成功。
- `difficultyTarget`：困难 = 半值、极难 = 五分之一值；`classifyRoll` + `HOUSE_RULES` 支持房规 0~6（`.setcoc`）。
- `cocCheck` 支持奖励骰/惩罚骰互相抵消、`autoSuccess`（自动成功）、属性运算修饰（`.rc 体质*5`、`-10`、`+5`、`/2`）。
- `sanCheck`：输出临时性疯狂（损失 >5）、不定期疯狂（≥SAN/5）、永久疯狂（SAN ≤0）。
- `growthCheck`：`roll > skill || roll ≥ 96 → +1D10`。

#### 角色卡（`sheet.js`）
- `CORE_ATTRS` 区分 `attrs`（主属性）与 `skills`（技能），另有 `exprs`（自定义掷骰表达式）。
- `KEY_ALIAS` 名字归一化：`str`→力量、`灵感`→智力、`电脑`/`计算机`→计算机使用、`侦察`→侦查、`hp`→生命、`san`→理智…（**`母语` 不并入教育**，它是独立技能）。因此 `.rc 力量` 和 `.rc str` 查的是同一个数。
- 上限 20 张卡/人、200 项/卡。
- `clearCard`（`.st clr`：清空当前卡数值，卡还在）与 `clearCards`（`.pc clr`：删掉全部卡）语义不同，别用错。
- `importCards` 是**合并**而非覆盖。

#### 指令总表（按类）
- **掷骰**：`.r`、`.r 3d6`、`.r 2d6+2 猎枪伤害`（原因与表达式顺序可互换）、`.r 3#1d6`、`.r 1d100b2`、`.rb2`、`.rp2`、`.r3#p 手枪连射`、`.rh`（暗骰，结果私聊）、`.r 沙漠之鹰`（调用卡上表达式）。
- **检定**：`.rc 侦查 50`、`.rc 侦查`（省略成功率 → 本地直读角色卡）、`.rc 困难侦查`、`.rc 极难侦查`、`.rc 自动成功爆破 50`、`.rc 体质*5`、`.rc3#p 手枪 50`、`.ra`（与 `.rc` 完全同义）。
- **理智 / 成长**：`.sc 1/1D6`、`.sc 1D10/1D100 60 直视外神`（省略 san 取卡、结果写回卡）、`.en 教育`（结果写回卡）。
- **默认骰 / 房规**：`.set`、`.set 20`、`.setcoc`、`.setcoc 3`、`.setcoc show`、`.setcoc clr`。
- **角色卡**：`.pc new [卡名]`、`.pc build`（随机生成 COC 7th 属性卡并存档）、`.pc show`、`.pc list`、`.pc tag`、`.pc nn`、`.pc del`、`.pc clr`。
- **属性**：`.st 力量:60 体质:55`（全角冒号也行）、`.st 力量60str60敏捷75dex75`（**连写**，专为从 Excel 抄一长串准备，一次可录上百项）、`.st 力量=60`、`.st hp-1`、`.st san+1D6`、`.st show`、`.st del`、`.st clr`、`.st &沙漠之鹰=1D10+1D6+3`。
- **生成 / 先攻 / 骰池 / 牌堆**：`.coc`、`.coc7 [组数]`（3D6×5 等规则，含 HP/MP/伤害加值）、`.dnd`（4D6 去最小）、`.ri [加值/表达式] [名字]`、`.init`、`.init clr`、`.w 5a10`、`.ww 敏捷+剑`、`.deck new 名=卡1|卡2|::3::卡3`、`.deck show/clr`、`.draw 名 [数量]`、`.drawh 名`（暗抽）。
- **其它**：`.jrrp`（今日人品）、`.ob join/exit/list/on/off/clr`（旁观暗骰）、`.me 笑出了声`（第三人称）、`.name [cn|jp|en] [数量]`、`.nn`、`.log new/on/off/end`（对局日志，`.log end` 导出到 `data/dice/logs/*.txt`）、`.bot on/off`、`.dismiss`（撤回自己 2 分钟内的掷骰结果）、`.help [词条]`。
- **不会误触发**：无前缀（`r 1d100`）、非注册指令（`.roll`、`.scatter`、`.english`、`.setting`）以及拼错的指令都不拦截，照常走正常聊天 / KP 流程。

#### 存储与存档保护
- `data/dice/group_<群号>.json`，含 `sheets`、`recentChecks`（`MAX_CHECKS=200`）、`initiative`、`decks`、`jrrp`、`logs`、`observers`、`nicks`、`muted`、`lastOutput`。
- **三层保护**：① `.bak` 每次成功保存后刷新，永远是"最近一份有内容"的存档；② 读出损坏时留 `.bad-json-<时间>` 现场；③ **写前拦截**——要写的若是空白状态而磁盘上那份明显有内容，先整份留档再写并打日志。
- 以前这里是 `catch { return fallback }`，文件被占用/半截写入/JSON 损坏时会静默返回空白，紧接着保存就把空白盖上去，**玩家辛苦录的角色卡一次性没了且无法追溯**。

#### 设置与实现
- 设置项：`houseRule`、`defaultFaces`、`allowPrivate`、`onlyBoundGroups`（默认 `enabled:false`）。
- dice **没有 `tools()`**，纯靠 `onIncoming` 钩子拦截指令；`rng.js` 随机源可注入固定序列，便于确定性自检（`selftest.mjs`，文档写 177 项断言）。
- 处理完掷骰指令后会调用 KP 的 `appendTranscript` 把玩家原话补进对局记录，保证导出的团本记录不缺玩家掷骰。

### 6.2 kp：TRPG 守秘人（KP）

**定位**：让机器人担任跑团主持人——读取本地团本文件夹、按群主持游戏，支持群内指令（开始/中止/结束）、读取掷骰结果推进剧情、完整存档与战报导出。

#### 它是怎么"主持"的（重要技术事实）
**kp 不直接调用 LLM**：它用 `api.orchestrator.scheduleWake(chatKey, 0, {forced:true})` 唤醒宿主，靠 `systemPrompt` / `userPrompt` / `outputExpectation` 三个钩子注入主持提示词。所以"KP 主持"本质是**改提示词 + 定时唤醒**，不是独立 agent。

#### 7 个模型工具
| 工具 | 作用 |
|---|---|
| `kp_files(action=list/read, file=…)` | 列出/读取团本文件夹里的文本文件（只能读本群绑定的文件夹，越界拒绝） |
| `kp_rules(query)` | 检索内置的 COC 7th 守秘人规则书原文（技能难度、战斗、理智、追逐、魔法等） |
| `kp_roll(action=roll/check/san, …)` | **替 KP 掷骰**：掷表达式 / 做检定 / 做理智检定（需掷骰插件已启用） |
| `kp_checks(limit?, sinceMinutes?)` | 读最近的掷骰/检定结果（由 dice 判定并记录） |
| `kp_card(action=list/get/set, …)` | 列全群角色卡 / 看某人数值 / 登记"谁扮演谁"（只建卡，不填数值） |
| `kp_state` | 读取本群当前进度（状态/场景/角色表/笔记/最近进展/当前遭遇） |
| `kp_update(scene?/notes?/event?/playerQq?/playerName?/encounter?/round?/order?/gameDay?/gameHour?/restHours?/introDone?)` | 写回进度；`encounter`（combat/chase/none）+ `round` + `order` 记录**当前遭遇与出手顺序**——每轮唤醒都是新会话，不写下来 KP 就不知道"现在第几轮、该谁动" |

#### 规则检索的实现（必须知道）
`searchRules()` 是**关键词分段计分**（命中词数 → 长词加权 → 整串命中提权），**不是向量 RAG、没有 embedding**。所以**措辞不合就查不到**。
- `rules/coc7-rules.md` 直接注入系统提示词。
- `rules/COC7th守密人核心规则书.txt`（1 MB 全文）供检索，是**第三方翻译，公开分发前建议删除**；删掉后主持/掷骰/存档/战报都照常，只有 `kp_rules` 会提示找不到（想查细节可把自己的规则书 PDF 放进团本文件夹用 `kp_files` 读）。

#### 主持流程
- **指令**：`matchCommand` 模糊匹配「游戏开始/继续/开团」「游戏中止/暂停」「游戏结束」——**意思差不多即可触发**，疑问句（"游戏开始了吗"）和普通行动描述不会误触发；系统直接处理、不经过 AI。
- **开局**：`cmdStart` 按「剧本 > 角色 > 其它」优先级通读团本（`SCENARIO_TEXT_MAX=60000`、单文件 `MAX_READ_CHARS=120000`、最多 500 文件）→ `scanMembers` 扫描群成员昵称 → `ensurePlayerCards` 建同名空卡 → **导入信息合成一条消息一次性发出**（不分段、不截断）。
- **只读剧情，不抄数值**：团本里的角色卡文件（Excel 等）只当剧情设定；**数值一律由玩家自己用 `.st` 录入**——各家表格格式不同，自动解析容易把「已用点数」当成技能，错数值比没数值更糟。
- **30 秒发言聚合**：游戏中 `return 'defer'` + `scheduleDefer`（`DEFER_MS=30000`），等"30 秒内不再有人发言"后对这段时间的发言总结、裁决并回复，不逐条秒回。
- **场外内容物理剥离**：玩家用 `（…）` 写超游内容，`stripOoc` + `store.updateByMid` **原地改写已入库的消息**；整条都是场外则不唤醒。不是靠提示词叮嘱。
- **游戏内时间**：按调查员活动推进（第几天/几点），进入新阶段（清晨/上午/中午/下午/傍晚/晚上/深夜）时提醒玩家；一晚需至少 6 小时睡眠，不足会扣体质、给惩罚骰。
- **掷骰分工**：玩家主动尝试 → KP 点名让玩家发 `.rc`；NPC/怪物 → KP 自己用 `kp_roll`；暗骰/伤害 → `kp_roll(action=roll)`。NPC 技能值有统一"尺子"（路人 30~45、专业人士 50~65、精英 70~85、怪物按剧本或 50~60）。**伤害必须连过程一起说**（`1D6+1D4=4+3=7，HP 12→5`），只描写不报数或只丢数字都算不合格。
- **`outputExpectation` 接管**：KP 主持人时整段取代宿主的【输出期望】，防止"定时提醒 → 只回 1~2 句"把 KP 压成一句闲聊。
- **流程隔离**：一文件夹 = 一群；每群进度单独存档，换群、重启都不串台。

#### 存储、导出与恢复
- 存档 `data/kp/group_<群号>.json`（同样有防静默清零的三层保护）。
- 战报 `data/kp/exports/group_<群号>_战报_<时间>.md`（`renderReport`）。
- `recover.mjs <群号>` 可从 `data/messages/` 聊天记录**重建**战报与存档（输出 `.md` 可读战报 + `.json` fullLog 可人工回填）。
- 路由 `GET /api/kp/bindings`；设置项 `groups`（records：`groupId` / `scenarioDir`（`type:dir`）/ `scenarioName`）。

### 6.3 两个插件如何协作
**数据单向归属，谁也不存第二份**：

| 数据 | 唯一数据源 | 谁读 | 谁写 |
|---|---|---|---|
| 角色卡（属性/技能/表达式） | dice `data/dice/group_<群号>.json` 的 `sheets` | dice 本地直读；kp 经 `api.plugins.dice` 读 | dice（玩家 `.st` 手录，或 `.pc build`/`.coc` 生成） |
| 检定流水 | dice 同文件 `recentChecks` | **kp 读**（裁决与推进剧情） | dice |
| 掷骰运行时状态（先攻/牌堆/旁观/称呼/静音/今日人品/日志） | dice | dice | dice |
| 剧情（进度/场景/笔记/玩家↔角色表/完整发言记录） | kp `data/kp/group_<群号>.json` | kp | kp |
| 检定房规 / 默认骰面数 / 是否只响应绑定群 | 宿主 `config.json` 的 `plugins.dice` | 双方 | dice |

- kp 经 `api.plugins.dice` 调 `getValue/getSheet/getRecentChecks/importCards/getInitiative`；`kp_roll` 用的是 dice 引擎。
- dice 拦下指令后调 `kp.appendTranscript` 补记；kp 遇到 `. 。 ! ！` 前缀主动放行，**加载顺序无关**。
- **可分别开关**：停 dice 后 kp 仍能主持（`kp_roll` 提示「掷骰插件未启用」）；不装 kp 也能纯掷骰（`.pc`/`.st`/`.rc`/`.sc` 全在 dice）。完整跑团建议一起装。
- **两者默认 `enabled:false`**，装好要到「设置 → 插件」勾选启用，并按表单绑定 群号 ↔ 团本文件夹。

### 6.4 热插拔与热重载（宿主机制）
- 启用/停用即时生效；装载新插件/改代码点「重新扫描插件」即可，不用重启。
- 热重载按**插件目录整体**算一个 generation（扫该目录下所有 `.js/.mjs/.cjs/.json` 的 `路径:mtime:大小` 签名），签名一变整张模块图重新实例化——解决"只改子模块时上游 URL 没变、新代码永远加载不到"的经典坑。
- 改 `plugin-loader-hooks.mjs` 或 `plugin-loader.js` 本身需要重启一次。

### 6.5 亮点与坑
亮点：① 数据唯一归属，杜绝两份数值打架；② 存档三层保护；③ 场外内容物理剥离而非提示词叮嘱；④ `outputExpectation` 整段接管，防定时提醒把 KP 压成闲聊；⑤ 热重载按目录整体算 generation；⑥ dice 零依赖、随机源可注入做确定性自检。

坑：① 表达式不能带空格；② 团本 Excel/PDF 角色卡不解析数值，必须手录；③ `kp_rules` 关键词检索、措辞不合查不到；④ 内置完整规则书是第三方翻译，公开分发前建议删；⑤ 自检项数文档不一致（顶层 README 写 184 项、`dice/README.md` 写 177 项）；⑥ 团本文件夹「浏览…」仅 Electron 桌面版可用，浏览器版需手贴绝对路径。

## 7. 主动找聊（proactive-chat v1.0.0）

### 7.1 定位
给机器人一份"该找谁聊"的名单：到点自己找上门，**开口前先看档案**（对方怎么说话、喜欢什么、最近在干嘛），于是主动开口时自然顺着对方的风格来。**说什么由机器人自己决定**，插件只负责"什么时候、找谁、带着什么背景"。

### 7.2 三层结构（都不重复造轮子）
| 层 | 做什么 | 复用谁 |
|---|---|---|
| **调度** | 每人一份节奏：间隔区间 / 每日上限 / 免打扰时段 / 可选"对方刚说过话就先不打扰" | 开口走宿主自带的「主动机会」路径 `orchestrator.wake(chatKey, {proactive:true})`——无触发批、不打断，模型自己决定抛什么话题，也可以判断此刻不该说话 |
| **档案** | 本地统计说话风格：口癖（n-gram）/ 平均句长 / 颜文字率 / 表情率 / 提问率 / 活跃时段 | 纯本地计算，**不花 token** |
| **探测** | 资料卡 + QQ 空间近况 | 走协议端接口，候选 action 逐个试（SnowLuma 那套是 `get_qzone_feeds` / `get_qzone_msg_list`），拿不到就只用风格层 |

档案摘要会**写进宿主记忆**（`memory.append(chatKey, 'memberImpression', …)`），所以下一次主动开口时模型的【记忆】里就带着"他说短句、爱用颜文字、喜欢猫"，自然顺着来（摘要 ≤240 字）。

### 7.3 调度细节
- 心跳 `setInterval`，`checkIntervalMs` 默认 60000 ms，下限 15 秒。
- 挑选目标走纯函数 `pickDue`，依次判：是否启用 → `inQuietHours`（支持跨零点，起止相同 = 关闭免打扰）→ 今日次数是否达 `dailyMax` → 是否已过 `nextAt` → 可选 `respectRecentReply`（默认 false）。
- 间隔随机：`gapMin = max(minGapFloorMin, minGapMin + rand×(max−min))`；**间隔下限兜底 15 分钟**（把目标的间隔下限设成 0 也不会每分钟开口，想更密改 `minGapFloorMin`）。
- 默认"**自由找我**"（`respectRecentReply=false`）：对方刚说完话也照常主动开口；想安静就设 true，回到"对方 30 分钟内说过话就先不打扰"。

### 7.4 记忆 / 档案的写入节奏（与"是否聊天"解耦）
写记忆**不再需要等对方说完话**，也不再由"聊了一次"顺带触发——它有自己的钟：
- `consolidateOnSchedule=true`：心跳到点就写。
- `consolidateEveryHours=12`：每 12 小时给每个开启的目标写一次（刷新资料/空间 → 提炼印象 → 追加进档案与宿主记忆）。
- `autoConsolidate=true`：总闸，关掉则上面两个都不生效（省 token）。
- `profileRefreshHours=12`：资料卡/空间的重拉间隔。
- 判定是纯函数 `dueForConsolidate(...)`，所以**重启不会漏写**，超过 12 小时立刻补一次。手动补写：面板每行「写记忆」按钮，或 `POST /api/plugin/proactive-chat/action {op:'consolidate'|'consolidateAll'}`。

### 7.5 群内指令（只有主人能用）
非主人发这些词会被**静默吞掉**（不回复，也不让机器人陪他聊这个话题）。

| 发什么 | 效果 |
|---|---|
| `找聊` | 列出所有目标：开关 / 间隔 / 今日次数 / 上次 / 下次 / 档案时间 |
| `找聊 加 <QQ> [备注]` | 加一个目标（默认开启，间隔 90~240 分、每日 3 次、23~8 点免打扰），并立刻建档案 |
| `找聊 删 <QQ>` / `找聊 开|关 <QQ>` | 删除 / 单独启用停用 |
| `找聊 间隔 <QQ> 30 60` | 间隔区间（分钟，随机取） |
| `找聊 上限 <QQ> 5` | 每日最多主动聊几次 |
| `找聊 免打扰 <QQ> 1 7` | 免打扰时段（小时，可跨零点） |
| `找聊 话题 <QQ> 喜欢猫，别聊工作` | 记一句"顺着聊"的偏好（会写进记忆） |
| `找聊 现在 <QQ>` / `找聊 现在` | 立刻聊一次（不受间隔限制，仍受开关约束）/ 对所有开启目标各一次 |
| `找聊 档案 <QQ>` | 看学到的风格 / 资料卡 / 空间近况 / 写进记忆的那句话 |
| `找聊 更新 <QQ>` | 重拉资料+空间+风格，刷新档案与记忆 |

### 7.6 Web 面板
`GET http://127.0.0.1:<server.port，默认 3210>/api/plugin/proactive-chat/panel`
功能：加目标 + 备注、表内直接改间隔/上限/免打扰（失焦即存）、每行「现在聊 / 写记忆 / 停用 / 更新档案 / 删除 / 展开档案」、顶部「自由找我」开关 + 「记忆间隔（小时）」+ 保存设置、全部现在聊一次、全部写一次记忆。

### 7.7 配置项（`data/config.json` → `plugins.proactiveChat`）

### 7.8 安装 / 卸载（逐行核过）
**`install.ps1` 做的事**：① 定位 QQ Agent（常见安装位置 → 必要时扫盘 Depth 3，只读）；② 备份到 `<app>\_backup-before-proactive-<时间戳>\`（含插件目录、`policy.js`、自检脚本、`config.json`）；③ 拷 `payload`（覆盖 `plugins\proactive-chat` 有前置备份）；`_shared\policy.js` 若已存在且含 `export function isOwner/readPolicy` 则**保留原件**，否则先 `.bak-<时间戳>` 再替换；④ 用临时 mjs 写 `plugins.perms.owners=[你的QQ]` 与 proactiveChat 默认项（**owners 已有值时 KEEP 不动**）；⑤ `node --check` 四个文件 + 跑 82 项自检；⑥ 打印面板地址。
**`uninstall.ps1`**：插件目录**改名**为 `plugins\_removed-proactive-chat-<时间戳>`（不直接删，随时能翻回来）；`config.json` 先备份 `.bak-<时间戳>` 再删 `plugins.proactiveChat`；`_shared\policy.js` 保留（别的插件可能也在用）；`-PurgeData` 才连档案一起删。**可逆性良好**（但备份目录不会自动回收）。

**风险核验结论**：
- **无**联网下载、**无**注册表操作、**无**计划任务、**无**防火墙改动、**无**提权命令（grep 全目录仅 6 处，全是 `Copy-Item`/`Remove-Item` 临时文件与 PurgeData）。
- 唯一的"广域"操作是找不到 app 时的全盘扫盘（只读）。
- 隐私面：会读 `data/messages/private_*.json` 等聊天存档，并拉资料卡与 QQ 空间；摘要会随提示词发给模型（第三方内容外发 + 耗 token）。
- 面板与 `/action` 接口**无鉴权**（仅 localhost 可达，POST JSON 有 CORS 保护），本机其它程序可调用它触发"现在聊"——不要把这个端口暴露到公网。
- 会改/新增共享模块 `plugins/_shared/policy.js`。

### 7.9 自检脚本 `verify-proactive-chat.mjs`
实际路径在 `payload\scripts\`（不是根 `scripts\`），共 **82 项**：探测命中/换 action/全不支持、`flattenTexts`、风格分析、`memoryNote` 长度、命令解析 12 种 + 普通聊天不吞、免打扰跨零点、`pickDue` 六类跳过、`dueForConsolidate` 四种、`minGapFloorMin=15` 兜底，以及**真实 PluginHost 分发链**（加目标 → 建档案 → 写记忆 → `wake(proactive:true)` → 非主人被吞 → 四个 HTTP op → 面板控件）。跑它需要 node 与真实 app 源码（`src/config.js`、`runtime.js`）。

### 7.10 使用步骤
0) 托盘退出 QQ Agent（避免它退出时把配置写回覆盖）；1) 双击 `install.cmd`（双击没反应就右键以管理员运行；找不到 app 就把「含 QQ Agent.exe 的文件夹」拖到 `install.cmd` 上），输入自己的 QQ 号；2) 重启 QQ Agent（插件只在启动时加载）；3) 浏览器打开面板加目标。日常改节奏走面板，或 QQ 里发 `找聊 …` 系列指令。

## 9. 如果要用起来：注意事项汇总

1. **装插件基本都要重启**（ai-status 明确说明：提示词、工具、能力都是加载期注册的，热重载管不到；跑团/dice 支持「重新扫描插件」热插拔）。
2. **配置不要手改 `data/config.json`**（ai-status 明说：内存有缓存，手改不生效还会被控制台覆盖回去），走控制台表单或 `/api/config`。
3. **权限**：ai-status 有逐项门禁；proactive 只有主人能用（`plugins.perms.owners`）；健康系统的 `/健康` 无权限限制。
4. **token 成本**：情绪插件与健康系统是"零 token 判定"（划算）；proactive 每次主动开口 = 一次模型调用，每 12 小时的写记忆也要调一次模型，嫌费就调大 `consolidateEveryHours` 或关 `autoConsolidate`。
5. **隐私**：proactive 会读私聊存档并拉资料卡/空间，摘要进提示词；健康系统会把身体状态注入 system 消息。用于他人群聊前请确认边界。
6. **本机接口无鉴权**：ai-status 的 `127.0.0.1:3210/api/config`、proactive 的面板与 `/action`、kp 的 `/api/kp/bindings` 都只靠 localhost 兜底，别做端口转发到公网。
7. **版权**：音乐包只取元数据不下载音频（合规）；跑团内置的完整规则书是第三方翻译，公开分发前建议删除。
8. **改动前先跑自检**：`test/ai-status-test.mjs`、`dice/selftest.mjs`、`kp/selftest.mjs`、`payload/scripts/verify-proactive-chat.mjs`。注意自检需要宿主源码在场，单独拷插件目录跑不了。
