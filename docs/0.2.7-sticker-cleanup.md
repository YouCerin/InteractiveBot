# 表情包相关的五处小毛病 —— 修正记录（0.2.7）

> 这份文档记的是"**改了哪几处、为什么**"，体例同 `0.2.2-pixiv-skill-migration.md`。
> 起因是接手时对着 `--extensions` 与源码逐处核对，发现**表情包这一条链路上有五处
> "看起来在工作、其实不成立"的地方**（死代码、假告警、过期文档、措辞不一致）。
> 它们都不会报错，只会让人（或下一个接手的人）对系统做出错误判断 —— 正是本项目
> 最忌讳的那一类缺陷。

---

## 0. 先讲清一条背景（否则每处修改看起来都像吹毛求疵）

0.2.4 把「自主发表情」做成技能时，定了一个正确的边界：**功能是技能，判定必须在宿主**
（`docs/插件设计规范.md` §7）。但在落地时，把一句**本该属于宿主的活**写进了技能：

> "告诉模型可以写 `[sticker:标签]`" —— 这一句需要**按当前库里哪些标签真有货**现算。

技能侧读不到库，`promptSections()` 按契约又必须是**纯函数**（无 IO、每轮都调）。
于是当时写成"宿主会把现算好的行通过 `context.stickerLines` 传进来"。
**而宿主从来没有传过这个字段** —— 详见 §1。下面五处，四处是这一句话的连带后果。

---

## 1. 技能层 `promptSections()` 是死代码（最实质的一处）

**改法**：删除 `skills/sticker/index.js` 的 `promptSections()`，`skill.json` 里写明
`"prompt": { "source": "none" }`。

**为什么**：宿主调它时**不传 ctx**：

```js
// src/bridge.mjs:2451（原样）
const { lines } = collectSkillPromptSections({ skills: this.skills, config: this.config, log: ... })
```

而收集器只给技能两样东西（`src/extensions.mjs:801`）：

```js
const r = skill.module.promptSections({ ...ctx, config })   // ctx 默认 {}
```

⇒ 技能永远只收到 `{ config }`，`context.stickerLines` 恒为 `undefined`
⇒ `promptSections()` **恒返回 `[]`**（`extensions.mjs:814` 还会把空内容丢掉）。

**真正进提示词的是宿主自己算的那份**：
`bridge.mjs` 的 `#stickerPromptBits()`（`readStickerLibrary` + `labelCoverage`）
→ `buildChannelPrompt({ stickerLines })` → `channel-prompt.mjs`
→ `renderMarkerInstructions()`，并进**同一个标记段**。

**附带的连带修正**：

| 位置 | 原来写的 | 现在 |
|---|---|---|
| `src/channel-prompt.mjs:110` | `/** 表情包技能贡献的…那几行 */` | 由宿主现算，不是技能贡献 |
| `src/channel-prompt.mjs:291` | `★ 0.2.4：stickerLines 是表情包技能贡献的那几行` | 同上（并注明技能侧那个函数已删） |
| `src/markers.mjs:146` | `★ 0.2.4：stickerLines 让**表情包技能**把自己那几行并进同一个段` | 同上 |
| `src/markers.mjs:168` | `// 表情包技能贡献的写法（…由它按"库里真有货"现算）` | 同上 |
| `src/bridge.mjs:2475` | `两段都由同一个 stickerPromptFacts 喂，口径不会漂` | 真正算它们的是 `#stickerPromptBits()`；`stickerPromptFacts` 全仓库**零调用方** |

**还有一个连带发现**：`src/sticker-library.mjs` 里的 `stickerPromptFacts()` 是
**零调用方的导出函数**（全仓库 grep 只有定义处 + 上面那句错注释）。
它和 `#stickerPromptBits()` 里的两行等价，所以直接删掉 —— 留着只会让下一个人
以为"这就是提示词那条路"（它确实就是这么骗过我们一次的）。

**断言（防止它被加回来）**：`mocks/verify-sticker-skill.mjs` 第 ② 节新增两条 ——
入口不许再导出 `promptSections()`、不许再出现 `stickerLines`；
并新增一条"清单必须声明 `prompt.source = none`"，与实现互相印证。

## 2. `session: "required"` 是一句永远无法生效的承诺

**改法**：`skills/sticker/skill.json` 的 `"session"` 从 `"required"` 改成 `"none"`。

**为什么**：`session: required` 在宿主里**只有两处效果**：

1. 往**工具入参** schema 里注入并必填 `kind`/`peerId`（`mcp/mcp-skills-server.mjs:119-131`）；
2. 提示词片段非空时，追加一句"kind/peerId 就是当前会话"（`src/channel-prompt.mjs:198`）。

本技能**既没有工具**（`setup()` 空实现），**也不贡献提示词片段**（§1 之后为 `none`）——
两处都不成立。原来那条断言的理由是"它要知道当前会话才能发对图"，而真相是：
群聊/私聊的判定确实存在，但它在**宿主**侧发生（`bridge.mjs` 的 `#decideSticker`
手上就有 `kind`），不靠技能清单声明。

**断言**：`verify-sticker-skill.mjs` 第 ② 节的 `session === 'required'` 改成 `=== 'none'`，
并把"为什么"留在注释里 —— 防止有人凭"required 看起来更安全"改回去。

## 3. 控制台给「刻意不要工具」的技能打假告警

**改法**：`config-ui/src/sections/ExtensionsTab.tsx` 的状态徽标判据从
`s.tools.length === 0` 改成 `s.tools.length === 0 && (s.declaredToolCount ?? 0) !== 0`；
`config-ui/src/lib/api.ts` 的 `SkillInfo` 补上 `declaredToolCount` 字段。

**为什么**：后端早就算好了 `declaredToolCount`，注释也写明了判据（`extensions.mjs:889-894`）：

> 像「表情包」这种**刻意不要工具**的技能……调用方不能拿"工具数 0"当成"忘了接线"——
> 否则每次巡检都会打一条假告警，假告警用久了就没人看了。

CLI 已经按这个判据修过（`src/index.mjs:190-194`，0.2.4 修）；
**只有界面这一处漏改** —— 所以一旦打开表情包技能，技能卡就显示
「开着，但没给模型任何工具」这条**假告警**。三处口径不一致比三处都错更难查：
使用者会以为是新装的技能坏了，而实际上它工作得好好的。

**⚠️ 改完必须重建界面**（仓库规矩：`config-ui/` 改了 src 就要 `npm run build`）：

```bash
cd packages/qq-bridge/config-ui && npm run build
```

本次已重建（`dist/assets/index-BKpnjRUL.js`，`dist/ui-build.json` 的 `sourceHash` 已更新）。

## 4. `docs/插件设计规范.md` 的插件表过期

**改法**：把 §7 末尾那张表从 9 行改成 **11 行**，并修三处错：

| 错 | 实际 |
|---|---|
| 写「现存 **9** 个插件」 | **11** 个（漏了 `delivery` 投递可靠性、`corpus` 本地语料检索） |
| 仍列着 `trigger`（📣 唤醒规则，`trigger.groupEnabled`） | 0.2.3 就删掉了 —— 判据并入 `wake-policy`（`src/plugins.mjs:135-145` 有整段说明，`mocks/verify-extensions.mjs` 还有一条"不许再有 trigger"的断言） |
| `sticker` 行写"详细设置：扩展页（同卡片）" | `plugins.mjs:115-120` 明确设成 `uiTab: null`：那张插件卡**没有**展开区，设置表单属于**技能卡**（由 `skill.json` 的 `configSchema` 渲染）。写成有，界面会多出一个点了没反应的「详细设置」 |

顺手把"形状"那段也写全：`persona` 与 `wake-policy` 都是**枚举/二选一**（不是布尔），
`access` 是**名单**（没有"关"这个动作）。

## 5. 措辞与过期注释（两处小不一致）

| 位置 | 原来 | 现在 | 为什么 |
|---|---|---|---|
| `src/onebot.mjs:373` | `同时给了**贴纸图**与内置表情 id` | `同时给了**表情包图**与内置表情 id` | 全项目只有这一处把它叫"贴纸图"；同一个东西两种叫法，排障时搜日志搜不全 |
| `mocks/verify-extensions.mjs:473-478` | "现在还没有真插件用上 `choice`（`wake.policy` 要等语义唤醒落地）" | 已过期：`wake-policy` 就是真的 `choice` 插件 | 该断言本身用**合成 spec**，所以注释过期不会让它失败 —— 但会误导下一个人以为 `choice` 还没人用 |
