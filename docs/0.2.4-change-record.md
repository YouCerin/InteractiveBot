## 2. 为什么界面源码**一行都不用改**（这一条是设计，不是省事）

窗口加载的是 `lib.consoleUrl(port)` = `http://127.0.0.1:<端口>/`，也就是
**桥接自己伺服的那份 `config-ui/dist`**。于是：

```
config-ui/src ──(npm run build)──> config-ui/dist ──(桥接伺服)──> 窗口
                                                  └──────────────> 浏览器（老路径）
```

只有**一条**链路、**一份**产物。如果改成 `loadFile('dist/index.html')`，就变成两条：

| 后果 | 为什么严重 |
|---|---|
| "窗口用的 UI"与"桥接伺服的 UI"可以是**不同的两份** | 用户报"我看到的界面上没有这个按钮"，而排查的人在看另一份 dist |
| 构建溯源（`ui-build.json` + `--ui`）**答不了**窗口那份是哪来的 | 这套机制存在的唯一理由就是回答"你看到的 UI 与源码是不是同一份"，而它**真的脱钩过一次**（包里旧 5 小时、1100 项测试全绿） |
| `/api/*` 变成**跨源**请求 | 窗口是 `file://`，接口在 `http://127.0.0.1:3410` ⇒ 要给桥接加 CORS —— 等于为了"少一次 HTTP 伺服"去放宽一个本地接口的边界 |

★ 所以这一版对界面**零侵入**：不加接口、不加字段、不加 `isDesktop` 分支。
唯一受影响的界面体验是两处**文案级**的事（关窗口不再等于退出、外链走系统浏览器），
已写进 `CONFIG-UI.md` §2.5 给界面生成者。

## 3. ★★ 三条沙箱限制（这一轮真正的难点，全都实测过）

先说结论：**这台机器的 DSH 沙箱禁止三件事，而 Electron 的打包链三件全撞上了。**

诊断脚本留在 `cache/spawn-probe*.mjs`（它们是"结论是怎么得出的"的证据，不是产品代码）。

### 3.1 任何 `stdio: 'pipe'` 的 `spawn` 都被拒

实测矩阵（`cache/spawn-probe2.mjs` / `spawn-probe3.mjs`）：

| 调用 | 结果 |
|---|---|
| `spawn(node, [...], {stdio:'inherit'})` | ✅ |
| `spawn(node, [...], {stdio:'ignore'})` | ✅ |
| `spawn(node, [...], {stdio:['ignore', fd, 'ignore']})`（stdout 直写文件） | ✅ |
| `spawn(node, [...], {stdio:['ignore', fd, 'pipe']})` | ⛔ **EPERM** |
| `spawn(node, [...], {stdio:['ignore','pipe','ignore']})` | ⛔ EPERM |
| `spawn(node, [...])`（默认 = 三路都是 pipe） | ⛔ EPERM |

**判据是 `pipe` 本身**，不是"哪一路"：只要有**任何**一路是 `pipe`，整个 `spawn` 就被拒。
（第一版补丁只把 stdout 改成文件、stderr 留 `pipe` —— **仍然 EPERM**。那份诊断脚本就是
为了分清这两者才写的。）

**它挡住了什么**：electron-builder 收集运行期依赖时，固定会
`powershell.exe -EncodedCommand → npm list`，并把子进程 stdout **用管道**读到临时文件
（`app-builder-lib/out/node-module-collector/nodeModulesCollector.js` 的
`streamCollectorCommandToFile`）。于是 `⛔ spawn EPERM`、`failedTask=build`、打包失败。

**怎么绕（两层，缺一不可）**：

1. `scripts/patch-electron-builder.mjs` —— 给那一处打 **4 个 hunk** 的补丁：
   把"父进程用管道读、再转写进文件"改成"子进程**直接把 stdout/stderr 写那两个文件**"。
   * 补丁是**逐段精确命中**的：命中数不是 1 就**非零退出**（宁可构建停下，
     也不要一个"看起来成功"的包）。
   * 打完还有**形态自检**：无 `pipe`、有 `streamFinished = true;`。
     ⚠️ 漏了后者会让 Promise **永不 settle** ⇒ 构建**卡死而不报错**（比失败更难查）。
   * 4 个 hunk 分别是：stdout→fd + stderr→fd、把 `pipe`/`stderr.on` 换成"已写完"标记、
     去掉 `outStream.destroy()`、去掉 `outStream` 的两个监听。
2. `scripts/build-tools/npm-stub.mjs` + `npm.cmd` —— 补丁后收集器能跑完，
   于是它真的会去调 `npm list`；而桌面壳的运行期依赖是 **0**，所以给它一个**确定性的答复**
   （空依赖树）。收集器拿到空树后回落到它的**纯文件遍历**通路（`PM.TRAVERSAL`），
   遍历结果同样是"没有 node_modules 要收"。
   * 替身**认不出参数就非零退出**（97）：那说明 electron-builder 的收集方式变了，
     构建该停下来让人看一眼 —— 安静地给一个假结果可能打出缺东西的包。
   * `npm.cmd` 必须**纯 ASCII**：cmd 按系统代码页解析 `.cmd`，中文注释会**吞掉换行**
     ⇒ 每一行中文都变成一条"不是内部或外部命令"。**写完第一版当场就踩了**。

## 5. 桌面壳的三条边界（改之前先读）

| # | 边界 | 为什么 |
|---|---|---|
| 1 | 窗口加载**桥接伺服的地址**，不 load 本地 dist | §2 |
| 2 | 起桥接一律 `node src/index.mjs --background`，壳**不自己拼 spawn 参数** | 那句"已经有一个桥接在运行"的判据（process-guard 的登记）只在 `src/index.mjs` 里有一份。两份必然分叉，而分叉的表现是"同一句话被回两次"（两个桥接抢同一个 OneBot 事件流） |
| 3 | 端口只读 `config.json` 的 `ui.apiPort`，**不 import 桥接的 `config.mjs`** | 那会把整套默认值合并与校验卷进一个"只想知道端口"的进程。四种情形（没写 / 读不到 / 坏 JSON / 越界）各自有话说，**绝不静默取默认值** —— "改过端口但界面连不上"正是这条会掩盖的事故 |

### 5.1 顺带处理掉的两个竞态

| 竞态 | 处理 |
|---|---|
| 双击 exe 时**上一个桥接正在启动**（还没绑定端口）⇒ 探测失败 ⇒ 又 spawn 一个 ⇒ 撞上 `--background` 的"已经有一个在运行"（exit 1）⇒ 窗口**永远等不到**它以为起了的那个进程 | 起之前先给 **5 秒确认窗口**（每 700ms 探一次），确认真的没人应答再 spawn |
| 桥接是**别人起的**（比如用户先跑了 `start.bat`），后来被别的东西停掉 ⇒ 桌面壳每 4 秒去把它**再拉起来** | 只自动重连 `state.startedBy === 'launcher'` 的那一个。"谁在管这个进程"必须说得清 |

### 6.1 ★★★ 那一句中文注释（这一轮最该记下来的事故）

**症状**：`启动机器人.bat --check`（以及子目录里的两个诊断 bat）跑起来只打十几行

```
'em' is not recognized as an internal or external command
'his' is not recognized as an internal or external command
'stalled' is not recognized as an internal or external command
...
```

**看起来像**：批处理文件本身写坏了 / cmd 版本不对 / 路径里有中文。
**实际是**：`start.bat` 第 93 行有一句中文注释

```bat
rem longer the console. (「启动机器人.bat」 routes double-click to the app;
```

cmd 用**系统代码页（GBK）**解析 `.bat`，而文件是 UTF-8 ⇒ 那几个中文字符的字节
被当 GBK 读时**吞掉了行尾** ⇒ cmd 把**下一行**当成这一行的一部分 ⇒ `if /i not "%~1"=="--no-browser" (`
这个块从中间断开 ⇒ 里面每一条 `echo` / `start` 都变成"不是内部或外部命令"。
`chcp 65001` 在文件里也救不了它 —— 代码页影响的是**输出**，不是 cmd 解析文件的编码。

**为什么最该记下来**：这条规则**早就写在 `AGENT.md` 第 11 条里**，而且同一天我：
① 写 `scripts/build-tools/npm.cmd` 时踩过一次（当场发现）；
② 改 `start.bat` 时又踩了一次，**而且没发现** —— 因为 `npm test` 的 **51 套全绿**。
没有任何一套在检查"`.bat` 是不是纯 ASCII"：**规则只写在文档里，就等于没有**。

**根因里还有一层**：那句中文是**我为了让注释更清楚**而写进去的（想点明"双击走的是
哪个入口"），也就是"为了让文档更好而破坏代码"。同一个文件里其它地方都用英文指代
（`the Chinese-named launcher .bat`），只有这一处偷懒写了中文名。

**修法（三件事，缺一不可）**：
1. 把那句改成英文指代（`The Chinese-named launcher .bat routes a plain double-click to the app`），
   并在那里**留下一段警告**（告诉下一个人为什么这个文件里不能出现中文）；
2. ★ **补上机器判据**：`mocks/verify-text-encoding.mjs` 新增
   "所有 `.bat` / `.cmd` 都是纯 ASCII" —— 报出**第一处所在的行**（不是只报字节数，
   否则拿到"有 21 个非 ASCII 字节"还是不知道在哪）；判据是"**任何**非 ASCII 字节"
   （不做"只查中文"的聪明事：批处理文件纯 ASCII 本来没有代价）；
3. ★ **负对照验牙**：`cache/bat-ascii-negative-control.mjs` 造一个 good.bat 与一个
   带中文注释的 bad.bat，断言判据**命中 bad、不误报 good**（实测：`bad.bat(21 个字节)`）。

**顺带更正一处文档不实**：`AGENT.md` 第 11 条原先举例里写过
"`scripts/verify-text-encoding.mjs` 会盯着这条" —— **当时它并不盯**（路径也写错了，
实际在 `mocks/` 下）。那句话现在才是真的。

### 6.2 挪进子目录之后，`%~dp0` 变了

两个诊断 bat 原来是包根的单文件，内容里有：

```bat
cd /d "%~dp0"
call "%~dp0start.bat" --check
```

挪进 `backup-commands/` 之后，`%~dp0` 指的是**子目录** ⇒
它会去找 `backup-commands\start.bat`，那个文件不存在。
**这类断掉最难发现**：它只在"有人真的需要这个工具"（界面已经打不开）时才报错。

现在两处都用 `call "%~dp0..\start.bat"`，并且**实跑过一次**确认能走到 `--check`
（输出里有"配置文件：… / 管理员：…"那一段才算真的走到了）。
★ 这一步之所以要写下来：我第一版写的是 `cd /d "%~dp0"` —— 那是**原样抄过来的**，
抄的时候没有问"这个变量现在指哪"。

### 6.3 ★★ 中文目录名会让**组装进程直接崩掉**（Node/Windows 的坑）

**症状**：`assemble-release.mjs` 走到新加的那个目录时**静默半途而废** ——

```
   📁 vendor\node_modules\ws
（日志到此为止，进程退出码 -1073740791 = STATUS_STACK_BUFFER_OVERRUN）
```

没有异常、没有堆栈、没有"哪一项失败了"，**目录只拷了一半**。

**定位过程**（每一步都用独立子进程试，因为崩溃会带走整个进程）：

| 试法 | 结果 |
|---|---|
| `cpSync('backup-commands', dst, {recursive:true})` | ✅ 成功 |
| `cpSync('备用命令', dst, {recursive:true})` | 💥 **崩溃 -1073740791** |
| `cpSync('备用命令', dst)` （不带 recursive） | ⚠️ 正常抛错（`ERR_FS_EISDIR`） |
| `cpSync('…\备用命令\a.txt', dst)` （单个中文名**文件**） | ✅ 成功 |

**结论**：崩的是**"非 ASCII（中文）目录名" + `cpSync` 递归**这一组合。
中文**文件名**没事（一直这么用），中文目录名 + 非递归也"只是抛错"。
第一版目录名叫「备用命令（界面起不来时用）」，**正好踩中**。

★ 这是本仓库**第 8 条不变量的兄弟**：`AGENT.md` 第 8 条早就记着
"`rmSync` 删中文名**文件**会把进程崩掉（-1073740791）"。同一个族、同一个退出码 ——
**当初只记了"文件 + rmSync"，没有意识到"目录 + cpSync"也一样**。
∴ 修法是三层，缺一不可：
1. 目录改名 `backup-commands`（纯 ASCII）—— 与"`.bat` 一律纯 ASCII"是同一个立场的延伸；
2. 在 `assemble-release.mjs` 的清单那里把这个坑**写清楚**（含那份实测矩阵），
   因为"为什么这个目录不能叫中文名"从代码上是看不出来的；
3. ★ 在 `mocks/verify-release-hygiene.mjs` 加一条**回归断言**：
   拷贝清单里的目录名必须是纯 ASCII 且**必须存在** —— 把"重命名回中文名"这件事挡住，
   而不是指望下一个人记得读过这段注释。

> ★ 顺带一个观察：这类崩溃**都没有可捕获的异常**，所以"让失败说话"这条项目纪律
> 在这里救不了你 —— 只能靠**子进程退出码**与**产物体积**（这次是"目录数少了一个"）。
> 这也是为什么 `assemble-release.mjs` 结尾那段"文件数 / 合计 MB"的打印是有用的：
> 它是**唯一**能看出"这次组装少了一半"的地方。

## 7. 这一版**刻意不做**的事

| 不做 | 为什么 |
|---|---|
| **改 `config-ui/src/**`** | §2：不需要改。而且用户从 0.2.2 起就要求 UI 改动只改指导文件 |
| **去掉 `vendor/node`**（能省 85.6 MB） | 桥接现在跑在**已经在真机上跑通**的那份 Node 上。改用 Electron 自带的 Node 等于把 `node:sqlite` 押在一个没验过的组合上 |
| **代码签名** | 需要证书（要买）。未签名的 exe 显示"未知发布者"、首次运行可能被 SmartScreen 拦一下 —— **预期内**，不是打包出错 |
| **单文件自解压 / NSIS 安装程序** | 单文件每次启动要解 ~200 MB 到临时目录（首次启动明显更慢，用户以为卡住）；安装程序与"整目录拷走就能用"的既有发布形态冲突 |
| **Electron 自动更新** | 与"整目录拷走就能用"冲突，而且更新器要联网 + 签名 |
| **把 SnowLuma 登录界面嵌进窗口** | SnowLuma 是自己的程序、自己的控制台（`127.0.0.1:5099`）。托盘的「打开 SnowLuma 控制台」已经够，嵌进来只会多一个会过期的集成面 |
| **`ui.apiPort` 热重载** | 端口是**启动时**读一次的。做热重载会带来"窗口连旧端口、桥接在新端口"的中间态，而那个状态**没有可用的错误提示**（两边各自都觉得自己是对的）。现在写明"改了端口要重开窗口" |
| **托盘菜单可配置** | 现有 9 项每一条都对应一个明确的失败场景。配置化会带来"改坏了没有菜单可点"的死锁 |
