# QQ 视频入站接线（方案 A）—— 改动记录 0.2.7

> 这份文档记的是**核心侧**的改动，与技能侧那份分开：
> · 技能侧（上游 video-frames 1.0.0 → InteractBot 技能）：`docs/0.2.7-video-frames-migration.md`
> · 核心侧（把 QQ 视频的直链接进提示词）：**本文**
>
> 起因是一个真实提问：「群里发的视频为什么解析不了？」——查下来**数据一直都在**，
> 是桥接在渲染那一步把它丢掉了。

---

## 1. 问题：地址在渲染那一步就没了

改之前，视频段只渲染成三个字：

```js
// src/text.mjs（改前）
case 'video':
  parts.push('[视频]')
  break
```

对比紧挨着的图片段（它**刻意**把可下载线索单独带出来）：

```js
case 'image':
  images += 1
  imageRefs.push({ url, file, fileId, summary })   // ← 视频没有对应物
  parts.push('[图片]')
```

后果是一条**完全断掉**的链路：

| 环节 | 改前 |
|---|---|
| 消息渲染 | 只留 `[视频]`，`data.url` 原地丢弃 |
| 落盘 | 没有任何地方下载视频（收集器只吃 `imageRefs`） |
| 提示词 | `channel-prompt.mjs` 只有图片那一段，没有视频分支 |
| 工具面 | QQ 工具里有 `get_image`/`get_record`/`get_file`，**没有** `get_video` |

于是：「视频识别」技能装好了、ffmpeg 配好了，**模型手里却既没有路径也没有链接**，
它唯一能做的就是告诉对方"我看不了视频"。

而**上游其实给了地址**：SnowLuma 的视频段是 `{ type:'video', data:{ file, url } }`
（`snowluma/index.mjs` 的 `video.toSegment`，url 是带 rkey 的直链）。
所以缺的从来不是数据，是这一步没人接 —— 与当初图片的情况一模一样
（`src/images.mjs` 顶部那段取证写的就是这个）。

---

## 2. 为什么选"方案 A"：只递链接，不在核心下载

两个方案摆在一起时，取舍是这样的：

| | 方案 A（**已采用**） | 方案 B |
|---|---|---|
| 做法 | 核心只把**直链**交给模型；模型调 `video-frames(source=直链)`，**技能自己下载** | 核心收到消息就下载进工作区，交给模型**路径**（与图片同构） |
| 核心改动 | `text.mjs` + `channel-prompt.mjs` + `bridge.mjs` 三处 | 还要新增：视频下载器、大小/超时配置键、保留与清理政策、对应测试 |
| 下载器 | **复用技能里那一个**：已有 SSRF 守卫、大小上限、超时、临时文件即删、"这不是视频"拒收，且已被 123 项断言覆盖 | 核心要**再实现一份**同样的守卫体系 |
| 代价 | 直链会进提示词/会话历史；rkey 有时效 | 多一套要长期维护的下载政策 |

结论：**会取视频的那一方已经写好并且测过了，核心没必要再写第二份。**
（这也是本项目一贯的分工：能力在技能，事实与门控在宿主。）

## 3. 改动清单（逐处）

### 3.1 `src/text.mjs`：把直链带出来

* `case 'video'` 新增 `videoRefs.push({ url, file, fileId })`（与 `imageRefs` 同一条理由）；
* `renderSegments()` 的返回值新增 `videoRefs`（**空数组**，不是 `undefined`）；
* **正文渲染一个字都没改**（仍然是 `[视频]`）—— 老断言与提示词基线因此不受影响。

### 3.2 `src/channel-prompt.mjs`：措辞与位置在这边

新增两个入参：`videos`（原始 refs）与 `videoTool`（**门控事实**：`{usable, name, why}`），
在图片段之后追加「视频」段：

* `usable === true`：给出**真工具名** + 直链，并说清
  "视频本身喂不进模型 / 抽帧后要用 `read_image` 读 / 抽出来是**静止截图**、听不到声音 / 直链有时效"；
* `usable === false`：**不出现任何工具名**，如实说"含 N 个视频，但当前看不到画面（原因）"，
  并明确"**不要凭'有视频'去猜内容**"；
* 没有视频段时**一行都不出现**（逐字基线不受影响，有断言钉着）。

> 为什么措辞放在 channel-prompt 而不是桥接：该文件自己的原则是
> "**拼装顺序与措辞在那一边**，桥接只做状态装配"（`bridge.mjs:2468`）。

### 3.3 `src/bridge.mjs`：门控（这一格只有桥接知道）

* 新增 `#videoToolFacts()`，逐个确认：
  ① 技能装了没有 —— `# ② `isSkillEnabled`（唯一开关口径）
  ② **QQ 工具总开关**（`mcp.enabled`）关着没有 —— 关着时技能工具**根本没挂给模型**
     （与 `collectSkillPromptSections` 里那条总闸同一个判据，两处必须一致）
  ③ 技能自检过了没有 —— 缺 ffmpeg 就是在这一步被挡下
  三条都过，才用 `skillToolFullName()` 拼出**真工具名**（绝不写死）；
* 自检**现调**而不是读装载时的快照：自检现在是同步扫 PATH（不 spawn），
  所以"装好 ffmpeg / 改好路径"之后**提示词下一轮就跟着变**，不必等重启；
  调用失败一律当不可用（fail-closed：宁可少教一个工具，不可教一个调不通的）；
* `#buildPrompt()` 传入 `videos` 与 `videoTool`。

### 3.4 `skills/video-frames/index.js`：技能侧也要门控（★ 端到端测试抓出来的）

**这是本轮最有价值的一处发现。** 端到端套件跑出来时红了一条：

```
❌ ★★ 不出现工具名
```

原因不是宿主那段写错了，而是**技能自己的 `promptSections()` 还在教模型调工具** ——
`collectSkillPromptSections` 只看"开关开没开"，**不看自检过没过**。
于是提示词里同时出现：

* 技能段："要看视频就用 `mcp__skills__video-frames__frames` 抽帧"
* 宿主段："含 1 个视频，但当前看不到画面"

**自相矛盾**，而且模型会照着前者去调一个必然被拒绝的工具。
修法：`promptSections()` 里先问一次自检，`ok === false` 就返回 `[]`。
理由是本项目最硬的那条规矩 —— **提示词里凡是写了的能力都必须是真的**
（`markers.mjs`、`persona.mjs` 都写着）。

⚠️ 门控**只在能拿到工具名时生效**（即本宿主）：上游宿主里这一段是它**唯一**的视频指引
（那边没有工具，画面由宿主自己拼进消息），不可用时它会自己退回"只读元信息"，
所以**那一段必须留着** —— 否则同一份代码在上游宿主里会静默失效。

### 3.5 **刻意没做**的

| 东西 | 为什么 |
|---|---|
| 视频**缩略图/封面**（有些协议端会带 cover） | 只做方案 A 的最小闭环；封面不能替代"看懂视频" |
| `#recordCorpus` 的 `mediaCount` 计入视频 | 那是统计口径的小事，改了要连带看报表；与"能不能看懂"无关 |
| 在核心下载视频（方案 B） | 见 §2 |
| 把 `[引用]` 的被引用消息也带上 | 那是另一个缺口（模型看到 `[引用]` 但看不到原文），要单独定做法 |

|---|---|

## 6. 第一次真机尝试（2026-09-29 23:05，群 700000001）—— 如实记录

**结论：入站接线通了；抽帧没跑成，原因与本次改动无关（缺 ffmpeg 路径），但暴露出一处误导性文案。**

时间线（证据：`logs/bridge.log` + `workspace-qq/runtime/oplog/group_700000001-2026-09-29.jsonl` + `runtime/delivery-ledger.json`）：

| 时刻 | 发生了什么 | 说明什么 |
|---|---|---|
| 23:03:56 | 桥接重启 | 新代码已生效 |
| 23:05:04 | `[wake] 判定=answer（消息点名呼唤机器人（小鱼）并让它看视频…）` | **入站信息到了**：判断层知道这条消息在让它看视频 |
| 23:05:12 | `tools/call qq_group_history {groupId:700000001,count:10}` | 模型自己去翻历史 |
| 23:05:15 | `tools/call qq_message_detail {messageId:1001587961}` | 翻出那条视频消息 |
| 23:05:18 | `tools/call video-frames__frames {"source":"https://multimedia.nt.qq.com.cn/download?…rkey=…","count":6}` | ★ **直链完整到达了模型**（`rkey` 参数都在），模型也**真的发起了抽帧** |
| 23:05:18 | `tool/result ok:false`：`未找到 ffmpeg，抽帧用不了…` | 工具**在执行前就被拒绝**（fail-closed） |
| 23:05:21 | `tools/call pwsh`：`Get-Command ffmpeg` → `not in PATH` | 模型自己去找 ffmpeg（多花了一跳） |
| 23:05:35 | 回给群里 147 字：「…视频抽帧要用 ffmpeg，**这台机器上没装**…」 | ★ **把错误文案转述成了假事实** |

**根因**：`config.json` 里 `skills['video-frames'].ffmpegPath` 是**空字符串**，而 ffmpeg 也不在系统
PATH 里（使用者把它解压在 `D:\#DownLoad\…-full_build\bin\`）。技能只查两个地方 —— **设置里的路径**与
**系统 PATH**，都查不到 ⇒ 自检不过 ⇒ 工具拒绝。

**这次暴露的真问题（已修）**：文案把"**没配路径 / 没在 PATH 里找到**"说成了「**未找到 ffmpeg**」，
读起来像"机器上没有 ffmpeg"；模型逐字转述，于是在群里说了「**这台机器上没装**」——
**一句彻头彻尾的假话**，而错因是它其实只是"没被告诉路径"。

修法（4 处）：

1. `available()` 的文案改成说清"**我查了什么**"：
   「抽帧用不了：设置里**没填 ffmpeg 路径**，系统 PATH 里也没有 ffmpeg。
   ⚠️ 这**不代表机器上没装** —— 装好了的话，把 ffmpeg.exe 的完整路径填进
   「控制台 → 扩展 → 视频识别 → 设置 → ffmpeg 路径」就行（即刻生效，不用改 PATH、也不用重新下载）。」
2. 路径填错那条：措辞收敛成"设置里的 ffmpeg 路径**不存在**：<你填的那个>"（不再含糊）。
3. 工具描述里补一句：**别自己去 find/搜文件、也别反复重试**，把这句话转告管理员即可
   （这次模型真的花了一次 `pwsh` 去磁盘上找 ffmpeg，这句能省掉那一跳）。
4. 断言（回归测试）：`verify-video-frames.mjs` 新增
   **"不许把'没配路径'说成'机器上没装'"** —— 要求文案同时含"没填"与"不代表"。

**这次**证明了**（之前只有离线断言，现在有真机证据）：

* 视频段 → 直链 → 提示词这一步是通的；
* 模型能拿到带 `rkey` 的完整直链，并会真的调抽帧工具；
* 失败被**如实**返回（不是静默失败），模型没有编造视频内容（它说"看不了"）。

**这次仍然没验到**（因为 ffmpeg 先挡住了，`sources.js` 的下载+抽帧从没在真直链上跑过）：

* rkey 直链能不能直接 `GET`（腾讯 CDN 要不要 Referer）；
* 抽出来的帧能不能被 `read_image` 读到。
  填好 ffmpeg 路径、**重新发一次视频**（旧 rkey 会过期）之后，这两格才会被真正验证。

## 7. 同一次真机反馈带出的界面修正（见技能侧那份 §3.7）

控制台截图暴露了两处**界面**问题，改动落在技能与扩展内核两侧，记在
`docs/0.2.7-video-frames-migration.md` §3.7，这里只列结论：

1. **卡片显示的是装载时的自检快照** —— 技能是"启动之后才打开"的，卡片却一直写
   「开关没打开」+「暂时用不了」，再也不会变。⇒ 改成**现调**（`callSkillAvailable()`），
   `describeSkill` / `skillStatus` / 桥接的门控三处共用同一个函数；
2. **同一句警告显示两遍** ⇒ 删掉界面里重复的那一块（`config-ui` 已重建）；
3. **显示名「视频抽帧」→「视频识别」**（id / 目录名 / 工具全名**不动**，既有配置照旧生效）。

⚠️ 这三处都需要**重启一次机器人**才生效（技能清单、扩展内核、桥接都是启动时加载的），
外加**刷新控制台页面**（拿新的 `dist`）。
