## 3. git 管不到、必须手工清的产物

**为什么单列一节**（0.2.4 的教训）：`git checkout` / `read-tree` 只还原**被跟踪的文件**。0.2.5 留下的
Electron 工具链、构建产物与发布包**从来没进 git**（都已 gitignore），所以回退之后**它们仍在磁盘上** ——
其中最要命的一条是：

```
_release/InteractBot-0.2.5-win-x64/app/InteractBot.exe   ← 双击它跑的是 0.2.5
```

也就是"代码回退了、你双击的那个 exe 没回退"。

| 路径 | 约 | 说明 |
|---|---|---|
| `packages/qq-bridge/.build-desktop/` | 324 MB | exe 构建产物 |
| `packages/qq-bridge/desktop/` | ~400 MB | 源码已随回退删除，这里只剩未跟踪的 `node_modules` + `.npm-cache` |
| `packages/qq-bridge/cache/desktop-stage/` | 小 | 打包用的 stage 目录（**只删这一个子目录**：`cache/` 里还有 MCP 的 token 缓存，不能整个删） |
| `_release/InteractBot-0.2.5-win-x64/` | 413 MB | 0.2.5 发布包（含 200 MB 的 `app/InteractBot.exe`） |
| `_release/InteractBot-0.2.5-*.zip` | — | 若组过 zip 的话 |
| `_release/InteractBot-0.2.4-win-x64.zip` | 163 MB | 上一次回退**漏掉**的那个 zip（`rollback-0.2.4-clean.mjs` 的清单只列目录、不含 `.zip`） |

清理工具：`node docs/rollback-0.2.5-clean.mjs`（只报告）/ `--apply`（真删）。
两条纪律照旧：**先报告后动手**、**删目录前先改名确认删得掉**（"删到一半"比"没删"更坏）；
**老版本（0.1.0 / 0.2.0）一律不动**。

> 仓库之外还有一处（手工看一眼即可）：`%APPDATA%\InteractBot` 是桌面壳跑出来的 Electron profile（很小），
> 不影响任何东西；想清就 `Remove-Item "$env:APPDATA\InteractBot" -Recurse -Force`。

## 4. 这次回退**顺手丢掉**的一条真缺陷修复（与独立 UI 无关，随时可以补回来）

做桌面壳时挖出并修掉过一个**发布包级**缺陷：

> `src/ui-status.mjs` 在**运行期** require `scripts/ui-build-stamp.cjs`，而发布包的拷贝清单从来只拷 `src/`、
> 不拷 `scripts/` ⇒ **包里的桥接一启动就死**（`MODULE_NOT_FOUND`）；又因为 `respawnBridge` 用的是
> `stdio:'ignore'`，连 `logs/bridge.log` 都不会生成 ⇒ 桌面壳只能干等 90 秒超时。

实测：`_release/InteractBot-0.2.0` 起**每一份包**都有这个缺陷 —— 也就是说 **0.2.3 本身也有**。
它一直没被发现，是因为从来没人从包里跑过桥接（开发机一直跑仓库里那份）。

修法三处（都在封存分支里，逐字可查）：

1. `scripts/assemble-release.mjs` 的 `COPY_FILES` 加上 `'scripts/ui-build-stamp.cjs'`（它是**运行期依赖**，不是可选构建脚本）；
2. `scripts/check-release-package.mjs` 的 `MUST_EXIST` 加上它（并加一条"扫 `join(PKG_ROOT, …)` 指到的文件是否在包里"的兜底判据）；
3. `src/ui-status.mjs` 改成**缺助手时降级不崩**（如实报 `uncheckable` 并指名缺哪个文件）。

★ 想补回来：从 `backup/0.2.5` 取这三处改动即可 —— **它与桌面壳没有依赖关系**（不需要 Electron、不需要壳）。
本次按"回退至 0.2.3"的口径**没有**保留它，如实记在这里。

## 5. 为什么不把这条线留在主干

按用户给的判据：**独立 UI 需要把很多既有内容重置，对以 QQ 桥接为主线的开发环境是负收益。**
当时的实测代价：

- **工具链**：Electron 38.8.6 + electron-builder（构建期约 72 MB；运行时约 200 MB/份，还要走镜像下 136 MB）；
- **发布形态**：包从 **88.6 MB** 涨到 **413 MB**，exe 未签名、只在 Windows x64 上打过；
- **环境纠缠**：本机 DSH 的 node 垫片会设 `ELECTRON_RUN_AS_NODE`（源码侧启动必须自己摘掉它才拿到 `app`），
  受限环境里 Chromium 的单实例锁与 mojo 通道又建不起来 —— 开发与验证都被拖进 Electron 的坑里；
- **交付面**：多出"壳"这一条线要各自构建、各自验收（UI 要 `npm run build`，壳要 `npm run desktop:pack`，
  还要防两边脱钩），而它换来的收益只是"不用浏览器"。
