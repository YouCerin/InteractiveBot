# InteractBot 插件设计规范（0.2.2）

> **这份文档是什么**：本项目**扩展体系**的契约与纪律。写给三类人 ——
> 想给机器人写能力包的人（技能作者）、要改桥接的人、以及要审这套设计的人。
>
> **按需要跳（0.2.2 补齐了"安装/开发"这两件最日常的事）**：
> · 想**装/卸/升级**一个技能 → **§11** · 想**写**一个技能 → **§12**（含最小可跑模板）
> · 字段快查（必需性 + 错了会怎样） → **§13** · 出问题了 → **§14** · 交付前自检 → **§15**
>
> **配套文档**：
> · 界面规格见 `CONFIG-UI.md` §2.10（「扩展」页签）
> · pixiv 查图插件的**真实适配过程与逐处改动**见 `docs/0.2.2-pixiv-skill-migration.md`
> · 后端实现见 `src/extensions.mjs`（内核）、`src/extensions-service.mjs`（开关/设置）、
>   `src/plugins.mjs`（内置插件表）、`mcp/mcp-skills-server.mjs`（工具进程）

## 0. 先纠正一个容易串味的名词

| 名字 | 在本项目里指什么 | 不是什么 |
|---|---|---|
| **技能（skill）** | **外部能力包**：`skills/<id>/skill.json` + 一个 ESM 入口。第三方写的、可以整目录拷走的东西（例：pixiv 查图插件） | 不是 DSH 的插件，也不是"提示词模板" |
| **插件（plugin）** | **桥接自带的能力块**：记忆 / 看图 / QQ 工具 / 人味层 / 唤醒 / 用量 / 人设 / 名单。它们是桥接**自己的代码**，只是被登记成"看得见、可开关" | 不是第三方可以往 `plugins/` 里丢的东西 |
| **配方（recipe）** | 从真实任务里提炼出来的**做法**（属于记忆层，`memory/recipes/*.json`） | 不是扩展：它不注册工具、不改提示词装配 |
| **DSH 插件** | 给 DeepSeek Harness 本体写的 cordis 插件（见 `.dsh/skills/dsh-plugin-development`） | 与本项目这套**完全无关**（桥接是外部进程 + SDK RPC，不是 DSH 插件） |

**为什么分两型而不是统一成一套**：技能是第三方代码 —— 必须隔离、可装可卸、契约稳定、
失败要 fail-closed；插件是自家代码 —— 只需要"看得见 + 能开关"。
为了"统一"去把记忆重写成一个技能包，只会把安全边界弄丢。

## 1. 技能包的结构

```
skills/<目录名>/                  ← 目录名建议 == 清单里的 id（不强制，但排障时省事）
├── skill.json                    ← 清单（**唯一**的元数据来源）
├── index.js                      ← 入口（ESM，默认名；可在清单里改）
├── （可选）其他 .js / 资源        ← 同目录相对 import 是允许的
└── （可选）test/、README.md       ← 自测与文档（宿主不读，但强烈建议带）
```

`skills/.开头` 的目录**不是技能**（留给上游原件的留档，例如 `.upstream-original/`）。
没有 `skill.json` 的目录也不是技能。坏清单的技能**会被发现但标为"装不上"**，
并把原因显示出来 —— 绝不静默消失。

## 2. `skill.json` 清单字段

### 2.1 必填

| 字段 | 类型 | 说明 / 错了会怎样 |
|---|---|---|
| `id` | string | 小写字母/数字/短横线，2–40 字。**工具全名与配置键都用它**，改了等于换了个技能 |
| `name` | string | 界面上显示的名字（中文可） |
| `version` | string | 技能自己的版本；排障时第一问 |
| `apiVersion` | number | 本规范当前是 **1**。不匹配 → **拒绝装载**（"按别的宿主契约写的"） |
| `entry` | string | 技能目录内的相对路径，`.js`/`.mjs`。绝对路径或含 `..` → 拒绝 |

### 2.2 强建议

| 字段 | 类型 | 说明 |
|---|---|---|
| `description` | string | 一句话说清它给机器人加什么能力（界面上直接显示） |
| `author` | string | 出问题时知道找谁 |
| `category` | string | `media` / `search` / `tool` / `other`…（仅用于分组显示） |
| `icon` | string | 一个 emoji（界面上的图标） |
| `enabledByDefault` | boolean | **默认 `false`**：装上去先不要联网、不要给模型加工具 |
| `permissions` | object | `{ "net": ["www.example.com"], "listen": ["127.0.0.1"] }` —— **声明性**的，宿主会显示在界面上（见 §5.3） |
| `session` | `"required"` \| `"hint"` \| `"none"` | 是否要"当前会话"。默认 `hint`；要判群聊/私聊的**必须**用 `required`（§4.4） |

### 2.3 设置与界面（`settings` + `configSchema`）

```json
"settings": { "enabled": false, "maxResults": 10, "cookie": "" },
"configSchema": {
  "enabled":    { "type": "boolean", "label": "启用" },
  "maxResults": { "type": "number", "label": "条数上限", "min": 1, "max": 50, "step": 1,
                  "description": "模型请求的条数会被夹到这个范围内" },
  "cookie":     { "type": "string", "label": "Cookie", "secret": true,
                  "placeholder": "PHPSESSID=…" }
}
```

* `type`：`boolean` / `string` / `number` / `integer` / `enum`（`enum` 必须带 `values`）。
* `secret: true`：**密文字段**。界面上是密码框、不下发原值、留空即不修改（§5.2）。
* `label` / `description` / `placeholder` / `min` / `max` / `step`：界面直接用，**不要指望界面替你补默认值**。

> ⚠️ **两条会静默失效的错法**（校验器会告警，别等用户发现）：
> ① `settings` 里有键、`configSchema` 里没有 → 这一项**在界面上根本不会出现**，用户永远改不了；
> ② `configSchema` 里有键、`settings` 里没有默认值 → 界面显示为空，而运行时拿到 `undefined`。

### 2.4 工具声明（`tools`）

```json
"tools": [
  { "id": "search", "name": "Pixiv 搜图", "description": "…",
    "permission": "read", "parameters": { "type": "object", "properties": {}, "required": [] } }
]
```

* `tools[]` 是**说明性元数据**（供宿主核对与界面展示）；真正的注册在 `setup()` 里 `api.registerTool`。
* `permission`：**`read`（默认）或 `write`**。`write` 会被宿主在工具描述里追加
  「这是写入类动作，只有管理员可以让我做」——⚠️ 这是**提示词层**的约束，不是硬闸门（§5.4）。
* 清单里声明了、`setup` 里没注册（或反过来）→ 宿主在 `--extensions` 与界面上告警。

### 2.5 提示词片段（`prompt`）

* `prompt.source: "runtime"`（**推荐**）：片段以入口模块导出的 `promptSections()` 为唯一来源。
* `prompt.source: "manifest"`：用清单里的 `prompt.sections[]` 静态文案。
* **不要两处都写**：上游宿主两份都读时会出现同一段话两种措辞（校验器会告警）。

## 3. 入口模块契约

```js
// skills/<id>/index.js —— 只用 Node 内置模块；不要 import 宿主的 src/
export function setup(api) {}                    // 必须导出；注册工具
export function available(context) { return { ok: true } }   // 可选；**必须同步**
export function promptSections(context) { return [] }        // 可选；**纯函数**
export function dispose() {}                     // 可选；宿主停用时回收
export function diagnose(context) { return {} }  // 可选；界面上的「自检」
```

### 3.1 谁在什么时候调用（**两个进程**，这条最容易踩）

| 导出 | 调用进程 | 时机 | 要求 |
|---|---|---|---|
| `setup(api)` | **MCP 工具子进程**（注册真工具）+ **桥接主进程**（只要提示词片段，工具回调是空实现） | 启动时各一次 | **必须无进程级副作用**；要联网/开端口请在 `execute()` 里懒加载 |
| `available(context)` | 工具子进程 | 装载时一次 + **每次工具调用前** | **同步**返回；只判"开关/依赖在不在"，**不要判网络通不通** |
| `promptSections(context)` | 桥接主进程 | **每一轮**拼提示词时 | **纯函数**：无 IO、无副作用、同步返回 |
| `execute(ctx, args)` | 工具子进程 | 每次工具调用 | 可以异步、可以联网；返回 `{content}` 或 `{content, isError:true}` |
| `dispose()` | 工具子进程 | 宿主停用/退出时 | 关掉自己开的端口、清缓存 |
| `diagnose(context)` | 桥接主进程（控制台点「自检」） | 按需 | ⚠️ **不许回显密钥原文**，只说"有没有、长度多少" |

> ⚠️ `setup()` 会被调用**两次**（两个进程各一次）。这就是"不要写进程级全局状态"的由来 ——
> 一个典型的翻车写法是 `undici.setGlobalDispatcher(...)` 或 `process.env.HTTPS_PROXY = ...`：
> 那是**进程级**的，会波及宿主自己的所有出网请求（pixiv 插件为此专门写了回归测试）。

### 3.2 `api` 对象（宿主提供的全部能力）

| 方法 | 说明 |
|---|---|
| `api.registerTool(tool)` | 注册工具；`tool = { id, name, description, category, icon, permission, parameters, execute }` |
| `api.config()` | 本技能的**有效设置**（清单默认值 ← 用户配置，已按 `configSchema` 收敛类型）。**每次调用现读**，所以改设置立即生效 |
| `api.toolName(toolId)` | 返回**模型实际看到的工具全名**（`mcp__skills__<id>__<toolId>`）。★ **提示词里必须用它**，不要写死字面量 || `api.hostTool(name)` | 宿主自己的工具名映射（目前有 `send_image` → `mcp__qq__qq_send_image`）。技能要"把结果交给宿主某个能力"时用它 |
| `api.skill` | `{ id, dir, version }` |
| `api.log/warn/error` | 写宿主日志（**不要**往 stdout 写东西 —— 那是 MCP 协议通道） |

### 3.3 工具命名（**只有一处规则**）

```
模型看到的全名 = mcp__<MCP服务器名>__<技能id>__<工具id>
                 ↑ DSH 的 MCP 客户端加        ↑ 本宿主自报的裸名
```

* 宿主实现：`skillToolFullName()` / `skillToolLocalName()`（`src/extensions.mjs`）。
* ⚠️ 上游 QQ Agent 的命名是 `pixiv-lookup__search`（没有 `mcp__…` 前缀）。
  技能若在提示词/描述里**写死**那个名字，模型会去调一个**不存在**的工具，
  而且失败得很安静（它只会说"查不到"）。所以规则是：**用 `api.toolName(id)`，不要写死**。

### 3.4 会话上下文（`ctx`）

| `session` 声明 | 宿主行为 | 什么时候用 |
|---|---|---|
| `required` | 宿主自动把 `kind` / `peerId` 加进**每个工具的入参 schema**（必填），并在提示词里补一句说明 | 要判"群里能不能用"、要往"当前会话"发东西 —— 默认选它 |
| `hint` | 宿主尽力给（可能不准） | "猜错也无所谓"的只读查询 |
| `none` | 不给 | 与会话无关的工具 |

`ctx = { kind: 'private'|'group'|'unknown', chatId, peerKey, config, settings, toolName(id) }`

* `ctx.kind` / `ctx.chatId` / `ctx.peerKey`：由宿主从**模型填的** `kind`/`peerId` 得来（见上表），
  这两个参数**不会**进业务参数（宿主会剥掉，技能只拿到自己声明的那些）。
* `ctx.config` / `ctx.settings`：**每次调用现读**的活配置 / 收敛后的有效设置（改设置下一次调用就变）。
* `ctx.toolName(id)`：与 `setup(api)` 里的 `api.toolName(id)` **同一个口径**
  （`mcp__skills__<id>__<tool>`）—— 技能在 `execute()` 里要写"让模型去调哪个工具"时用它。
  ⚠️ 这条是 0.2.2 修的缺陷：第一版给的是 MCP 服务器**内部的注册键**（`<服务器名>::<裸名>`），
  那个名字**模型根本调不到** —— 技能照着写给模型 ⇒ 模型去调一个不存在的工具，且失败得很安静。

> ⚠️ **为什么默认推荐 `required`**：MCP 的 `tools/call` 上**没有会话标识**，
> 而同一个 MCP 进程会**并发服务多个会话**（桥接的锁是按会话分的）。
> 靠"最近一次会话"去猜，会把 A 群的动作做到 B 群里 —— 所以宁可让模型多填两个参数
> （号码就在它这轮的来源标注里，它本来就看得到）。

## 4. 生命周期与"随时开关"

### 4.1 状态机

```
  发现（扫 skills/）→ 清单校验 ──失败──→ 标红显示原因（不装载，不影响别的技能）
                        │通过
                        ▼
              装载（MCP 子进程注册工具；桥接主进程取提示词片段）
                        │
      ┌─────────────────┴──────────────────┐
      ▼                                    ▼
  启用 config.skills[id].enabled=true   停用 enabled=false
      │                                    │
      └────────── 随时切换（无需重启）───────┘
                        │
                   卸载（删目录）→ **需要重启**（工具表与 profile 是启动时定的）
```

### 4.2 开关：`config.skills.<id>.enabled`

* **唯一开关**就是它（没有第二处）。
* 没写过这个键时取 `enabledByDefault`，**默认 false**（装上去不自动联网、不自动加工具）。
* 切换走 `POST /api/extensions/toggle`，**即时生效**。

### 4.3 "即时"到什么程度（如实划界，**这是本规范最重要的一张表**）

| 什么 | 何时生效 | 靠什么 |
|---|---|---|
| 提示词片段 | **下一轮对话** | 桥接每轮现调 `promptSections()`，关掉的技能**一个字都不出现** |
| 工具调用 | **当场**（fail-closed） | 工具子进程**每次调用现读** `config.json`；关掉就返回一句可转述的中文说明 |
| 设置（Cookie/上限/代理…） | **下一次调用** | 同上，`api.config()` 现读 |
| 工具**表**（模型看到的工具清单） | **要重启桥接** | 工具表是 DSH 启动时加载的；本宿主按"已安装"注册，所以开关不需要重启，但**装/卸**需要 |
| profile 里的 MCP 段 | 启动时写；没技能时**整段移除** | `src/mcp-profile.mjs` |
| ★ **全部技能工具与指引** | 由 **`mcp.enabled`（QQ 工具总开关）** 一并决定 | 两个 MCP 服务器（QQ 工具 / 技能工具）由同一个开关管：`mcp.enabled=false` ⇒ 模型只能用文字回复，**技能工具不会挂上去，提示词片段也一条都不注入**（否则提示词会教模型调不存在的工具）。判据在 `collectSkillPromptSections()`，界面/自检同一个口径 |

> **为什么不把工具也做成动态增删**：MCP 的 `tools/list` 是 DSH 启动时读一次的快照
> （我们的客户端不支持 `tools/list_changed` 的推送路径）。所以选择是"**工具表按已安装注册，
> 开关靠 fail-closed + 提示词撤回**" —— 好处是开关真的即时，代价是关掉的技能在工具表里
> 还留着一个名字。这条**必须**写在界面上（`CONFIG-UI.md` §2.10 的三种开关语义）。

### 4.4 并发提醒

* 多会话并发时，`session: hint` 的 `ctx.kind` 可能指向**最近的那个会话**；
* 需要严格判定的技能（群聊白名单、往当前会话发东西）用 `session: "required"`；
* 技能自己的模块级状态（如断路器）是**进程级**的，跨会话共享 —— 这符合"上游挂了是所有群一起挂"的真实故障形状，但要**写进注释**。

## 5. 安全边界（逐条，都是硬要求）

### 5.1 代码在哪跑

* 技能代码**跑在宿主进程里**（桥接主进程做 `setup`/`promptSections`，MCP 子进程做 `execute`）。
  **没有沙箱** —— 一个技能可以做它想做的任何事。所以：
  * 只有你信任的技能才装；
  * `permissions` 必须如实声明，界面上要显示；
  * 宿主**不做**代码级拦截（写清楚，别让人以为有）。

### 5.2 密钥

* 只放在 `configSchema.secret: true` 的字段里；
* **清单里不许带非空默认值**（校验器告警）；日志/报错/`diagnose()` **不许回显原文**，只说"有没有、长度"；
* 界面：密码框 + `secretSet` 布尔 + 「留空即不修改」+ 清除需二次确认（`null` 才清除）；
* 存储：明文放在 `config.json`（与桥接其它密钥同一份文件、同一套权限），**不要**另建一份。

### 5.3 网络与本机端口

* `permissions.net`：会主动请求的域名清单；
* `permissions.listen`：会在本机开的端口 —— 界面必须**醒目提示**（这是最容易被忽视的一类副作用：pixiv 插件的本地图片桥就是）；
* 代理：**只作用于技能自己的请求**，绝不许设 `process.env.*_PROXY` 或改全局 dispatcher（会波及宿主调模型 API）；
* 出网失败必须翻译成人话并给出下一步，而不是把 `ECONNREFUSED` 抛给用户。

### 5.4 工具权限（`read` / `write`）

* `read`（默认）：只读动作，普通用户可用；
* `write`：会在描述里追加"只有管理员可以做"。
* ⚠️ **这是提示词层的约束，不是硬闸门**：MCP 调用里没有调用者身份，
  所以真正拦得住的是"模型愿不愿意照做"。要硬拦就得把动作收回宿主工具（例如发图走 `qq_send_image`）。

### 5.5 发图（内网地址）—— 一条真实需要的例外

技能常在本机开个小端口中转图片（pixiv 的直链是 `http://127.0.0.1:<port>/i/xxx`），
而宿主的图片守卫**默认拒绝回环/私网地址**（防 SSRF）。所以：

* 新增开关 `security.allowPrivateImageHosts`（**默认 false**）；
* 打开后**只**放开"内网/回环"这一条判定：协议仍只许 http/https、逐跳重定向仍校验、
  类型仍按内容嗅探、大小与超时上限照旧；
* 发图链路**由宿主自己下载**（`qq_send_image`），**不把 URL 交给协议端**去取 ——
  理由：SSRF 面不转移、能带 Referer（pximg 防盗链）、失败原因能回到模型；
* 打开它时 `--check` 会给一条明确告警（"模型给出的内网地址也会被真的取回来发出去"）。

## 6. 界面契约（要求界面做到什么）

完整规格在 `CONFIG-UI.md` §2.10，这里只列**不可让步的几条**：

1. 每张技能卡必须显示：名称/版本/作者、开关、状态、**权限声明**、**工具全名**、
   提示词片段预览、设置表单、自检入口、**清单告警**；
2. 三种开关语义**不许含糊**：即时生效 / 需要重启（附原因）/ 不适用（名单类，不渲染 Switch）；
3. `plugins[].offEffect`（"关掉会怎样"）**原文显示**，界面不要自己改写；
4. 密文字段：密码框 + 不回显 + 留空即不修改 + 清除二次确认；
5. `warnings` / `errors` / `available.reason` **必须能看到**（它们正是"静默失效"的告警）；
6. 空状态要给出**可执行的下一步**（拷目录到 `skills/<id>/` → 重启）；
7. 保存技能设置后的提示是「**已保存，立即生效（不需要重启）**」—— 与普通配置页的"需要重启"相反，别抄错。

接口（都已实现，见 `CONFIG-UI.md` §5）：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/extensions` | 列表（技能 + 插件 + 状态 + 脱敏设置） |
| POST | `/api/extensions/toggle` | 开关（即时生效；cold 项如实回 `restartRequired`） |
| POST | `/api/extensions/settings` | 技能设置（密文语义与 `/api/config` 一致） |
| GET | `/api/extensions/diagnose?id=` | 技能自检 |

## 7. 插件（内置能力块）契约

登记表在 `src/plugins.mjs`，每条就是一份**声明**：

| 字段 | 要求 |
|---|---|
| `id` / `name` / `icon` | 稳定标识与显示名 |
| `enabledPath` | **既有配置键**（`memory.enabled`…）。★ 不许为新插件另造一套开关 |
| `hot` | 改完是否即时生效。★ **必须取证**：判据是"那段代码是不是每轮重读配置"，并在 `why` 里写 file:line |
| `what` / `offEffect` | 是什么 / **关掉会发生什么**（界面直接显示） |
| `uiTab` | 详细设置在哪一页（插件卡只做开关，不复制字段） |

三条纪律：

1. **不改行为**：本表是纯数据 + 读取。开关仍然由各处既有代码读它们自己的 `config.*` 决定 ——
   否则会出现"两处开关"，而且它们迟早不一致。
2. **`hot` 不许猜**：把 `cold` 写成 `hot` 是一种恶意（用户以为关掉了，其实还在跑）。
3. **开关的形状要如实**：枚举（`persona.preset`，关=取 `none`）、列表（名单类，**没有"关"这个动作**）
   都要如实表达 —— 硬做成布尔开关会出现一个"点了没反应"的控件，那是最伤信任的一种。

新增一个插件的步骤：① 确认它已有一个 `*.enabled`（或等价的）配置键；
② 在 `BUILTIN_PLUGINS` 里加一条（含 `hot` 的取证与 `offEffect` 文案）；
③ 在 `mocks/verify-extensions.mjs` 第⑧节补一条断言；④ 在 `CONFIG-UI.md` §2.10 的插件表里对齐文案。

### ★★ 一个必须写清的边界：**功能是技能，判定必须在宿主**（0.2.4 立的规矩）

0.2.4 加了内置技能「表情包」（`skills/sticker`），它给后来者立了一条容易搞错的边界：

| 什么 | 放哪 | 为什么 |
|---|---|---|
| 清单、设置、标签词表、**离线**导入/打标签脚本 | `skills/<id>/`（可整目录拷走） | 它们不碰宿主状态机，任何人拿来就能用 |
| "这一轮发不发、发哪张"的**判定** | **宿主** `src/sticker-decision.mjs` 等 | 见下 |

**判定为什么不能放技能里**（三条，任何一条都足够）：

1. 它要碰**宿主的状态机**：配额台账、隐私闸门与投递闸门的**顺序**、拟人延迟、
   发送失败冷却 —— 而技能契约要求"不 import 宿主内部模块、能整目录搬走"
   （§12.3 第 2 条）。让技能碰这些，等于把宿主的内部顺序搬到外部代码里。
2. 它必须是**可离线单测的纯函数**（`sticker-decision.mjs` 有 83 项断言）。
   塞进技能目录 = 让"发错图"这条最贵的失败路径离开宿主的测试覆盖面。
3. **技能没有"自主插入"的钩子**。本规范的入口契约只有
   `setup / available / promptSections / dispose / diagnose` —— **没有**
   `onMessage` / `afterRun`。所以"桥接在投递前自主补一张"这件事，
   技能**做不到**，只能由宿主在投递管线里做。

∴ 现在**刻意不给技能加决策钩子**：加了也没有调用方（宿主的判定是内置引擎），
那只会变成一段"看着像接线、其实没接"的死代码。真要给第三方开这个口子，
得先想清楚"多个技能同时想发一条消息"的仲裁规则 —— 那是一次契约升级（升 `apiVersion`），
不是顺手加个字段。

**★ 顺带一个反直觉的结论**：内置技能「表情包」的开关（`skills.sticker.enabled`）
**不受 `mcp.enabled` 约束**。§4.3 那条"关掉 QQ 工具总开关 ⇒ 技能工具与提示词片段
一起失效"的理由是"否则提示词会教模型调不存在的工具"；
而自主发表情**不经过 MCP**（它在桥接的投递管线里），也没有工具可调，
所以关掉 MCP 时它**照常工作**。两件事的判据不同，不要套用。

**现存 9 个插件**（0.2.4 加了「表情包」；`node src/index.mjs --extensions` 会打出同一份表和它的真实状态）：
| id | 名字 | `enabledPath`（既有配置键） | 即时生效？ | 详细设置在哪 |
|---|---|---|---|---|
| `memory` | 🧠 跨重启记忆 | `memory.enabled` | ✅ 即时 | 记忆页 |
| `sticker` | 🧩 表情包 | `skills.sticker.enabled` | ✅ 即时 | 扩展页（同卡片） |
| `image` | 🖼️ 看图 | `image.enabled` | ✅ 即时 | 高级页 |
| `qq-tools` | 🔧 QQ 原生功能（MCP） | `mcp.enabled` | ★ 需重启 | 扩展页（同卡片） |
| `humanize` | ⏱️ 人味层 | `humanize.enabled` | ✅ 即时 | 节奏与成本页 |
| `trigger` | 📣 唤醒规则 | `trigger.groupEnabled` | ✅ 即时 | 人设页 |
| `usage` | 📊 用量记账 | `usage.enabled` | ★ 需重启 | 概览页 |
| `persona` | 🎭 人设 | `persona.preset`（枚举：关 = 取 `none`） | ★ 需重启 | 人设页 |
| `access` | 🔐 名单与权限 | `access.adminUsers` | —— | 协议端页 |

★ 两个**形状**上的例子（别硬套布尔开关）：`persona` 是**枚举**（"关" = 选 `none`）；
`access` 是**名单**（没有"关"这个动作，硬做成 Switch 就会出现一个点了没反应的控件 → 界面不渲染它）。

## 8. 验收口径（怎么证明它是对的）

### 8.1 离线（不需要 QQ、不花钱）

```bash
cd packages/qq-bridge
npm test                          # 含 verify-extensions.mjs（清单/设置/命名/片段/开关/发图守卫）

node mocks/probe-extensions.mjs --enable <技能id>   # 看"提示词里到底会多出什么字"
```

### 8.2 真机（装一个新技能时的最小清单）

1. 把技能目录拷到 `skills/<id>/`（里面要有 `skill.json`）→ **重启桥接**；
2. `node src/index.mjs --extensions` 应看到技能与它的工具全名；有告警要先解决；
3. 启动后看日志：`技能工具已挂到 sdk profile：N 个技能`；
4. 在「扩展」页打开开关（无需重启）→ 随手问一句触发技能的话；
5. 看模型是否调用了**正确的工具全名**（日志里能搜到 `mcp__skills__<id>__<tool>`）；
6. 关掉开关 → 再问一次：**提示词里不该再提它**，且万一被调用会得到"已关闭"的中文说明；
7. 需要发图的技能：确认 `security.allowPrivateImageHosts` 与图片守卫的行为符合预期。

## 9. 已知边界（如实列出，不要当成 bug）

1. **装卸技能要重启**（工具表与 profile 是启动时定的）；开关不需要。
2. **工具前缀不可改**（`mcp__skills__` 由 DSH 的 MCP 客户端加），技能必须用 `api.toolName()` 取真名。
3. **技能没有沙箱**：进程内可做任何事；`permissions` 只是声明 + 界面提示。
4. **并发会话下 `ctx`**：`hint` 模式可能不准；要严格就用 `required`。
5. **`qq_send_image` 用 base64 图片段**：SnowLuma 的文档确认支持 `base64://`
   （其包内注释列了 `file:// / http(s):// / base64://`），但**本机没有做过真机发图验证**（需要真 QQ 环境）。
6. **可选依赖**：技能要用的 npm 包由宿主从 `vendor/node_modules` 软链到 `skills/node_modules`
   （白名单目前只有 `undici`，pixiv 的代理支持需要它）。包里没有该依赖时，技能会**自己报「代理不可用」**。
7. **技能不会自动更新**：换版本 = 换目录 + 重启。
8. **配方的自动抽取不注册工具**（那是记忆层的事，见 §0）。

## 10. 版本与兼容

* `apiVersion` 是**硬闸**：不匹配直接拒绝装载（宁可装不上，也不要"装着但运行期出错"）。
* 新增字段的规则：**只加可选字段**（旧技能不写也能跑）；改语义必须升 `apiVersion`。
* 宿主新增 `api.*` 方法：技能用 `typeof api.x === 'function'` 探测后再用（见 pixiv 的 `hostName`/`hostTool`），
  这样同一份技能包在"上游 QQ Agent"与"InteractBot"两个宿主里都能跑。
* 本规范随宿主版本走；破坏性变更必须同时改：本文件、`CONFIG-UI.md` §2.10、
  `src/extensions.mjs` 的校验器、`mocks/verify-extensions.mjs`。

## 11. 安装 / 卸载 / 升级 / 回滚（照着做就行）

### 11.1 技能

| 动作 | 怎么做 | 什么时候生效 | 检查点 |
|---|---|---|---|
| **装** | 把**整个目录**拷到 `packages/qq-bridge/skills/<目录名>/`（里面必须有 `skill.json`） | ★ **要重启桥接** | `node src/index.mjs --extensions` 应列出它；有 `errors` 先修（`warnings` 也要看） |
| **启用** | 控制台「扩展」页的开关 —— 也就是 `config.skills.<id>.enabled` | ✅ **即时**（提示词下一轮、工具当场） | 卡片上应显示可用/不可用**原因** |
| **改设置** | 同一张卡的设置表单（密文**留空 = 不改**） | ✅ 下一次调用 | 保存提示应是「已保存，立即生效（不需要重启）」 |
| **停用** | 关掉那个开关 | ✅ 即时 | 提示词里不该再出现它；万一被调用会得到"已被管理员关闭"的中文说明 |
| **卸载** | **先停用**，再删目录 | ★ **要重启** | 重启后 `--extensions` 不再列出它。⚠️ `config.skills.<id>` 会**残留**（宿主不会自动清）—— 无害，但建议手删；同名重装会复用它 |
| **升级** | 换掉目录内容（**保持同一个 `id`**） | ★ **要重启** | 对比卡片上的 `version`；设置项若有增删，旧值残留在配置里（无害，界面上不再显示） |
| **回滚** | 拷回旧版本目录——**必须保证同时只有一个同 `id` 的目录** | ★ **要重启** | 见下面第 1 条警告 |

> ⚠️ **三条最容易踩的**：
> 1. **备份目录必须改 id，或者放到 `skills/` 外面。** 以点开头（`skills/.bak-pixiv/`）是**推荐**做法 ——
>    扫描会跳过一切 `.` 开头的目录。**同 id 两份 = 两个都不装载**（0.2.2 起 fail-closed，见 §13 第 10 条）：
>    以前会"先到先得"，而 readdir 的顺序取决于文件系统，可能出现"静默跑的是备份那份"。
> 2. **目录名建议 == `id`**，但不强制；排障时目录名对得上更省事（报错里给的是目录名）。
> 3. **装/卸/升级都要重启** —— "随时开关"只覆盖**开关与设置**，不覆盖这两件事（§4.3 那张表）。

### 11.2 插件（内置能力块）

插件**没有安装动作**：它是桥接自己的代码 + `src/plugins.mjs` 里的一条登记。
要新增一个插件的步骤见 §7 末尾；开关就是那条 `enabledPath` 指向的**既有配置键**。
★ 想给机器人加"新的能力"时先问一句：**它是第三方代码吗？** 是 → 写技能；
不是（要改桥接内部逻辑）→ 那不是插件，插件只是"把既有开关登记出来"。

### 11.3 技能要用的 npm 包（依赖）

* 宿主**不跑 `npm install`**：把包放进 `packages/qq-bridge/vendor/node_modules/`，
  宿主启动时把**白名单里**的包软链到 `skills/node_modules/`（`SKILL_NODE_MODULES`，目前只有 `undici`）。
  实现：`ensureSkillNodeModules({ skillsDir, vendorNodeModules })`。
* 包里没有该依赖时，技能应当**自己报"XX 不可用"**（人话 + 下一步），
  而不是抛一个没人看得懂的 `ERR_MODULE_NOT_FOUND`。
* 为什么要白名单：软链等于把宿主的依赖面借给第三方代码 —— 白名单是**唯一**的收敛点。

## 12. 开发一个技能（从零到能跑）

### 12.1 最小可跑模板（拷过去改就能用）

`skills/hello/skill.json`：

```json
{
  "id": "hello",
  "name": "打招呼",
  "version": "1.0.0",
  "apiVersion": 1,
  "description": "演示用：把一句话回给宿主",
  "author": "你",
  "icon": "👋",
  "entry": "index.js",
  "enabledByDefault": false,
  "session": "required",
  "settings": { "enabled": false, "prefix": "收到：" },
  "configSchema": {
    "enabled": { "type": "boolean", "label": "启用" },
    "prefix": { "type": "string", "label": "前缀", "description": "回话前加的那几个字" }
  },
  "tools": [
    {
      "id": "echo",
      "name": "回一句",
      "description": "把 text 原样回给模型（演示）",
      "permission": "read",
      "parameters": { "type": "object", "properties": { "text": { "type": "string" } }, "required": ["text"] }
    }
  ],
  "prompt": { "source": "runtime" }
}
```

`skills/hello/index.js`：

```js
// ⚠️ 只用 Node 内置模块；不要 import 宿主的 src/（技能要能整目录搬走）
export function setup(api) {
  const cfg = api.config() // 每次调用现读 —— 改设置立即生效
  api.registerTool({
    id: 'echo',
    name: '回一句',
    description: `把一句话回给宿主（前缀：${cfg.prefix}）`,
    parameters: { type: 'object', properties: { text: { type: 'string' } }, required: ['text'] },
    async execute(ctx, args) {
      // ctx: { kind, chatId, peerKey, config, settings, toolName(id) }
      // 失败要**翻译成人话**并给下一步，别把异常原文抛给模型
      if (!args?.text) return { content: '需要 text 参数（我这边没收到）', isError: true }
      return { content: `${ctx.settings.prefix}${args.text}` }
    },
  })
}

// 可选：能力自检（**必须同步**、只判"开关/依赖在不在"，不要判网络通不通）
export function available(context) {
  return { ok: true }
}

// 可选：提示词片段（**纯函数**，每轮都会调；用 api.toolName 取真实工具名，别写死）
export function promptSections(context) {
  const t = context?.toolName ? context.toolName('echo') : 'echo'
  return [{ id: 'hello', title: '打招呼', priority: 50, content: `需要回一句时用 ${t}。` }]
}
```

> 注意 `promptSections` 的 `context` 里**也有** `toolName(id)`（与 `setup` 的 `api.toolName` 同口径）。
> 提示词片段是**每轮**拼的，所以它会被高频调用 —— 里面不要做 IO。

### 12.2 本地开发循环（改完怎么快速验）

```bash
cd packages/qq-bridge
node src/index.mjs --extensions                 # ① 清单/告警/工具全名 —— 每次改完先跑它
node mocks/probe-extensions.mjs --enable hello  # ② 看"提示词里到底多出什么字"（最有用的一步）
node src/index.mjs --check                      # ③ 配置自检（技能问题也会在这里报）
npm test                                        # ④ 全套离线断言（含扩展内核与会话/开关语义）
```

装上真机（**需要重启桥接**）：

1. 拷目录 → 重启 → `--extensions` 里能看到它、且没有 `errors`；
2. 启动日志里应出现 `技能工具已挂到 sdk profile：N 个技能`；
3. 控制台「扩展」页打开开关（**不用重启**）→ 跟机器人说一句会触发它的话；
4. 在日志里搜 `mcp__skills__<id>__<tool>`：**模型真的调到了那个全名**才算通；
5. 关掉开关再问一次：提示词里不该再提它。

### 12.3 八条纪律（踩过的都在这儿）

1. **不许往 stdout 写东西** —— 那是 MCP 协议通道，写一个字符就把协议弄坏（用 `api.log/warn/error`）。
2. **`setup()` 会被调用两次**（桥接主进程一次、工具子进程一次），**不要有进程级副作用**：
   典型翻车是 `process.env.HTTPS_PROXY = …` / `undici.setGlobalDispatcher(…)` —— 那会波及宿主调模型 API。
   要联网/开端口请在 `execute()` 里懒加载。
3. **工具名一律用 `api.toolName(id)`**（或 `ctx.toolName(id)`），**绝不写死**（§3.3）。
4. **要判群聊/私聊就必须 `session: "required"`** —— MCP 的 `tools/call` 上没有会话标识，
   `hint` 只能猜，猜错会把 A 群的动作做到 B 群（§3.4）。
5. **失败要翻译成人话 + 给下一步**（"代理不可用，去设置里填代理"），不要抛原始异常。
6. **`permissions` 如实声明**：`net` 写域名、`listen` 写端口 —— 界面会显示，
   尤其是 `listen`（会在用户机器上开端口）必须让人一眼看到。
7. **密钥只放 `configSchema.secret: true` 的字段**，清单里不给非空默认值，
   `diagnose()`/日志里不回显原文（只说"有没有、长度"）。
8. **写测试**：至少覆盖"关掉时会拒绝"与"工具名/参数形状"；
   上游项目若已有测试，保留它们（pixiv 插件就带了 `verify-*.mjs`）。

### 12.4 交付前逐步清单

- [ ] 目录：`skills/<id>/`，含 `skill.json` + 入口 + （建议）`README.md` / `test/`
- [ ] `apiVersion: 1`、`id` 合法（小写/数字/短横线，2–40）、`entry` 存在且在目录内
- [ ] `settings` 与 `configSchema` **键集一致**（少了哪边都会静默失效：§2.3）

## 13. 速查：文件与字段（错了会怎样）

### 13.1 技能目录

| 路径 | 必需 | 谁读它 | 说明 |
|---|---|---|---|
| `skills/<目录名>/skill.json` | ✅ | 宿主（发现/校验/界面） | 元数据的**唯一**来源；解析失败 = 这个目录被标红 |
| `skills/<目录名>/index.js`（或清单 `entry` 指的） | ✅ | 两个进程动态 `import` | ESM；`.js`/`.mjs` |
| `skills/<目录名>/` 其他 `.js` / 资源 | 可选 | 技能自己 | 同目录相对 import 允许 |
| `skills/<目录名>/test/`、`README.md` | 可选（强烈建议） | 没人（宿主不读） | 自测与文档；出问题时第一份材料 |
| `skills/.开头/…` | —— | 没人 | **不是技能**（留给上游原件留档，例：`.upstream-original/`） |
| `skills/node_modules/` | 宿主生成 | Node 解析器 | 指向 `vendor/node_modules` 的软链（白名单包，见 §11.3） |

### 13.2 `skill.json` 字段（校验器实际怎么判）

| 字段 | 必需 | 类型/取值 | 校验（`src/extensions.mjs`） |
|---|---|---|---|
| `id` | ✅ | `^[a-z0-9][a-z0-9-]{1,39}$` | 不合法 → **error** |
| `name` | ✅ | 非空字符串 | 空 → **error** |
| `version` | ✅ | 非空字符串 | 空 → **error** |
| `apiVersion` | ✅ | 必须是 `1` | 不等 → **error**（拒绝装载） |
| `entry` | ✅ | `.js`/`.mjs` 相对路径 | 绝对路径/含 `..`/越界/不存在 → **error** |
| `description` | 强建议 | 字符串 | 空 → **warning**（卡片一片空白） |
| `author` / `category` / `icon` | 可选 | 字符串 / emoji | 仅显示 |
| `enabledByDefault` | 可选 | 布尔，默认 `false` | 装了不自动联网/加工具 |
| `session` | 可选 | `required`/`hint`/`none` | 写错 → **warning** 并按 `hint` 处理 |
| `permissions` | 可选 | `{net:[], listen:[]}` | 非对象 → warning；`listen` 非空 → **warning（会开端口）**；整体为空 → warning |
| `settings` | 可选 | 对象（键="设置项"，值=默认值） | 非对象 → **error** |
| `configSchema` | 可选 | 对象 | 非对象 → **error**；`type` 必须是 `boolean/string/number/integer/enum`；`enum` 必须有非空 `values`；缺 `label` → warning |
| `settings` ↔ `configSchema` | —— | 键集必须一致 | schema 有、settings 无 → warning（运行时 `undefined`）；settings 有、schema 无 → **warning（界面上根本不会出现）** |
| `settings.enabled` | 强建议 | 布尔 | 缺 → warning（开关初始状态改取 `enabledByDefault`） |
| `secret: true` 的字段 | —— | 字符串 | 清单里带**非空**默认值 → warning |
| `tools[]` | 可选 | 数组 | 非数组 → **error**；`id` 必须 `^[a-z0-9][a-z0-9_-]{0,39}$`、不可重名；`permission` 只能 `read`/`write`；`parameters` 必须是对象 |
| `prompt.source` | 可选 | `runtime`/`manifest`/`none` | 其他值 → **error**；`runtime` 与 `prompt.sections` 同时存在 → warning |
| `prompt.sections[]` | 可选 | `{id, content}` | 任一为空 → **error** |

### 13.3 插件登记表字段（`src/plugins.mjs`）

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 稳定标识（API/界面用，改了会断） |
| `name` / `icon` | ✅ | 显示名 / emoji |
| `enabledPath` | ✅ | **既有配置键**的路径（不许另造开关） |
| `hot` | ✅ | `true` = 即时生效；`false` = 要重启 |
| `why` | ✅ | **为什么是 hot/cold**（必须给 file:line 级的取证） |
| `what` | ✅ | 一句话：它是什么 |
| `offEffect` | ✅ | **关掉会发生什么**（界面原文显示，不要自己改写） |
| `uiTab` | ✅ | 详细设置在哪一页（`null` = 只有开关） |

### 13.4 十条最容易踩的（都在这份规范里，列出来方便自查）

1. `settings` 有、`configSchema` 没有 → **界面上永远改不了**（静默失效）。
2. `configSchema` 有、`settings` 没有默认值 → 界面空着、运行时 `undefined`。
3. 提示词里写死工具名（或用上游宿主的命名）→ 模型调一个不存在的工具，还说"查不到"。
4. 要判会话却只写了 `session: "hint"` → 猜错会话，动作可能落到别的群。
5. 在 `setup()` 里联网/开端口/设全局代理 → 拖慢或污染宿主自己的请求。
6. 往 stdout 打印 → 直接破坏 MCP 协议帧。
7. 密钥写进清单默认值 / 在日志里回显 → 泄漏。
8. `skill.json` 带 BOM → **解析失败**（表现为"装不上"）；同理任何手写文件都别用会重编码的工具去写
   （见 `docs/0.2.2-project-json-incident.md`）。
9. 备份目录与正式目录**同 id** → **两个都不装载**（fail-closed 并标红）。
10. 以为开关能覆盖装卸 → 工具表与 profile 是启动时定的，**装/卸/升级都要重启**。

## 14. 排障：症状 → 原因 → 怎么办

| 症状 | 先查什么 | 结论 / 怎么办 |
|---|---|---|
| `--extensions` 里技能显示"装不上" | 卡片/输出里的 `errors` | 按错误原文修（id/entry/apiVersion/JSON 解析失败最常见） |
| 技能在列表里，但模型一个工具都调不到 | ① `mcp.enabled` 是否是 true；② 是不是**刚装上没重启** | 总开关关着 ⇒ 技能工具与提示词片段**一起**失效；刚装 ⇒ 重启 |
| 模型说"查不到 / 没有这个功能" | 日志里搜 `mcp__skills__`；看提示词里写的是哪个名字 | 提示词写死了别名 ⇒ 改成 `api.toolName(id)` |
| 开关点了没反应 | 插件是不是**名单类/枚举类**（`access`/`persona`） | 那类没有布尔开关；界面应显示原因而不是给一个假开关 |
| 改了设置但行为没变 | 技能读设置的时机 | `api.config()` 是现读；若技能在 `setup()` 里缓存了一次，就得重启（改成每次调用现读） |
| 技能报"XX 不可用" | `vendor/node_modules/` 里有没有那个依赖（`SKILL_NODE_MODULES` 白名单） | 按 §11.3 放包；或让技能降级到不依赖它的路径 |
| 群聊里动作做错了会话 | 清单的 `session` | 必须是 `required`（宿主会把 `kind`/`peerId` 加进必填入参） |
| 两个同名技能/工具 | `skills/` 下是不是有两个目录用了同 `id` | 删掉/改掉多余那份（两个都不会装载） |
| 装了技能后机器人整体变慢/怪 | 技能是否在 `setup()` 里做 IO、是否设了全局代理/dispatcher | 把 IO 挪进 `execute()`；代理只作用于技能自己的请求 |
| 卸载后配置里还留着 `skills.<id>` | 这是预期的 | 宿主不清残留；手删即可（同名重装会复用它） |
