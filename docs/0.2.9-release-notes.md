# 0.2.9 更新汇总 —— 记忆有了"层"，而机器人开始记得住**关系**

> 面向使用者与后来改这个仓库的人。**只写实际改动与取证方式**，不写"计划中"的东西。
> 逐条过程记录（含被推翻的判断与踩过的坑）在 `docs/0.2.9-per-person-memory-plan.md`。
> 上一版见 `docs/0.2.8-release-notes.md`。

---

## 1. 一句话

**记忆从"一个文件"变成三层（全局 / 群聊 / 个人），并且"记住"这件事不再依赖模型自觉** ——
关键词直写、**情绪倾注**、**承诺**三条确定性通道会在本地判定并必然落盘；
个人档**跟人走**，所以"对某个人的记忆"在他自己的私聊里也真的生效。
控制台多了**「整理记忆」按钮**（把还没计入记忆的消息立刻整理成条目，默认先预演给人看）。

## 2. 记忆：三层 + 七条写入通道

### 2.1 三层布局（`memory-store.mjs`）

| 层 | 文件 | 什么时候注入 |
|---|---|---|
| L1 全局 | `MEMORY.md` | **所有**会话（私聊 + 每个群） |
| L2 群聊 | `memory/groups/<群号>.md`（+ `-slang.md`） | 只在该群 |
| L3 个人 | `memory/people/<QQ>.md` | **跟人走**：他的私聊 + 他在**任何群**发言时（只给他自己那一份） |

- 五档作用域：`global`→L1；`fact`→群里 L2、私聊 L3；`person`→L3（**归属由代码按本轮真实核实过的发言人裁定**）；
  `slang`→L2；`directive`→`memory/directives.md` 且只有管理员私聊能写。
- ★ **写入语义硬约束**：只有本群才知道的事**不许**写 `person` —— 那等于替当事人把它带到别的群（串场），必须写 `fact`。
- 旧布局（`memory/private-<QQ>.md` / `memory/group-<群号>.md`）在 `attach()` 时**只搬不删**地迁移（原件归档到
  `memory/.migrated/`），注入侧另有"旧路径回退读" —— **升级不失忆有两层保证**。
- 篡改检测 / 文件清单 / 体检**递归覆盖** `memory/groups/` 与 `memory/people/` 两个子目录
  （原来只扫根与 `memory/` 一层，漏了就是"改了不告警、不回滚"）。

### 2.2 七条写入通道（**四条不依赖模型**）

| 通道 | 触发 | 依赖模型 | 落点 |
|---|---|---|---|
| 关键词直写 | 「记住 X」「记一下…」「别忘了…」「以后都…」 | ❌ | 会话层 / 个人层 |
| **情绪倾注**（新） | 本地 cue 判定：状态（低落/焦虑/生气/很累/孤单/心情不错）+ 需要（听/静一静/建议/换话题/**留在这里**） | ❌ | 个人层 |
| **承诺**（新） | 本地句式判定：硬话术 / 第一人称+承诺助动词 / 时间+动作 | ❌ | **会话层** |
| 模型标记 | `<<<MEMORY global\|fact\|person\|slang\|directive …>>>` | ✅（漏报率极高） | 按作用域 |
| 管理员手段 | 控制台 / `--memory` | ❌ | 同左（**覆盖前先备份**） |
| 定时整理 | 每小时空闲 + 手动 `--memory --compact` | ❌ | 合并去重 |
| **按需建档**（新） | 控制台「整理记忆」按钮 | ✅（一次调用，**默认预演**） | 按 `#n` 归属 |

### 2.3 情绪倾注与承诺：为什么必须是确定性的

需求原话是「对面向机器人倾注情绪时需要记录」「作出承诺需要记录」。而本项目已**两次实测**证明
"靠模型自觉提议"这条路漏报率接近 100%（本机几十轮 0 次提议；参考项目 58 次运行 0 次调用）。
所以这两件事由桥接**本地判定、零模型调用、命中即必然落盘**。

- **情绪条目写成时间状语**（「他情绪低落的时候想有人听着（细节他没说）」）而不是当下断言 ——
  长期记忆跨重启跨会话，"他现在很难过"一周后就是假话；**不存原文**（倾诉里常混隐私与具体人事）。
- **两条真实性闸门**：不记别人的事（「我朋友最近很累」）、不记那件事（「这游戏崩溃了」）；
  另加两道**被真机语料打出来**的闸门：否定式（「至少**不用**担心…」是松了口气）与需要线索的指向
  （「搓一个**机器人**陪我聊天」——陪他聊的不是眼前这个）。
- **接纳/归属**单独一类：用户点名的例句「没事，你在这里和我们聊天，大家都很高兴，这就是完美的时间线」
  既不是倾诉也不是求助，但它对行为有明确含义 ⇒ 落成「他希望你留在这里、继续和大家聊天」。
  ⚠️ 写这条时抓出一个真缺陷：那句原话末尾的「大家都**开心**了」是个**被拒的第三方情绪线索**，
  第一版据此把整句判成"转述别人的事"，于是**最该记住的一句话恰好被别人的情绪挡住**。
- **承诺双向记录且标明来源**（`（我许的诺）…` / `（对方许的诺）…`），否则「我明天帮你查那个仓库」是一条无主的事实；
  **机器人那一侧的承诺只在消息真的发出去之后才记**（被取代/超时的那一轮用户从没看见那句话）。
- 情绪条目的措辞**不许写成祈使句** —— 否则等于用一次情绪表达绕过"行为指令只有管理员能下"的判据。

### 2.4 个人层的行为统计（`people-stats.mjs`）

累计说过多少次话、首末时间、来过几天、24 小时直方图（→「常在 20-23 点出现」）。
**全部由桥接确定性累加**（不会被编），落在隐藏侧车 `memory/.people.json`，**跨会话按人聚合**
（第一版按"会话+人"分开存，结果私聊里读不到他在群里的统计 —— 那恰好违反个人层"跟人走"的立意）。
渲染侧"数据不足就别装熟"：少于 5 次一个字都不渲染，没到 30 次不说"他常来"。
★ 隐私边界如实写清：**只存计数与小时直方图**（不存内容、话题、词频），有上限（到顶后新面孔不再计入并**只喊一次**日志）。

## 3. 未唤醒的群消息：一个取舍同时造成"看不懂"与"记不住"

**真机事故**（用户报"它没理解我说的其实是前面那句"）：群里一句**没 @ 机器人**的话
（「其实想想，记忆这种碳基生物需要的情感依赖…」）被唤醒判定丢弃 —— **模型从未看见**；
紧接着「@机器人 你说呢」让模型手上只有三个字，只能瞎猜（回复里自己写了"猜错你纠正我"）。

修法分两半（**实测数据决定的**，不是设想）：

1. **上下文**：唤醒时把「机器人上一条发言之后」的最近 ≤6 条消息（单条 ≤150 字）拼成
   【你被叫到之前，群里刚说了这些】（**不是对你说的**）注入，位置紧挨【当前消息】之前。
   数据来自**本地语料库**（它本来就在唤醒判定**之前**入库，只是以前没人用）。
   ★ 代价如实写：这些消息会被送给模型 API（此前只有被唤醒的那几条会）。
2. **记忆**：**没有**直接把情绪判定前移 —— 拿真机语料回放，未唤醒消息里判定命中的 5 条**有 4 条是错的**
   （「舍不得就别走呐」是对**别人**说的挽留、「压力大肥鱼是吧」说的是别人且是玩笑…），
   而个人档**跟人走** ⇒ 记错了他在别的群也会被算上。
   ∴ 改成「**规则先筛 + 判定器再确认**」三档（`memory.affect.prewake`，**默认 `off`**）：
   `off` 一次调用都不发 / `shadow` 判定照跑、**只写日志不落盘** / `judge` 判定通过才写。
   **判不出来一律不记**（与唤醒判定方向相反：那边判不出来要放过）。

## 4. 控制台（`config-ui/`）

- **「整理记忆」按钮**（`BuildMemoryDialog.tsx`）：打开即预演（不调模型、不写盘，显示"会发给模型的原文"）→
  人确认 → 才真跑；报告如实显示采纳/被拒（带原因）/写了哪几份/游标到哪。**不自动轮询、不后台重试**。
- **「未唤醒的倾诉」三选一**（记忆页签）：选中非 `off` 时**就地写明代价**（会送给模型 API、个人档跟人走、
  实测约每 280 条 1 次调用、上限 120 次/小时），并明说"只覆盖本地情绪线索命中的那些"。
- 记忆页签按**三层**改写（徽标按路径前缀判），修正了此前"群聊看不到全局记忆"这句与实现相反的说法。
- 记忆树里保存记忆文件**会把上一版先备份**到 `memory/.backups/`（起因是一次真机事故：
  两份记忆在 11:11 UTC 同时被改，**没有审计、没有备份、没有回滚日志**）。

## 5. 其他修复（都是"不报错但会误导/会丢东西"那一类）

| 症状 | 根因 | 现在的行为 |
|---|---|---|
| 检索到自己说过的话显示 `[mid:?]`，**引用不了** | `await this.onebot.send(...)` 直接丢了返回值，语料库里自己的消息 `message_id` 全是 null | 按 OneBot 11 的形状读 `data.message_id` 入库（拿不到就留 null，**不编**） |
| 「整理记忆」改了什么**事后查不到** | `audit.jsonl` 只有桥接在自己回合结算里写，`applyMemoryItems` 自己不写 | 采纳/被拒各写一行（来源 `build`，**不记原文只记长度**） |
| 文档写着"一批最多 6000 字"，实际能塞 3 万字 | `BUILD_LIMITS.chars` 是**死常量**（只声明、没人用） | 先按条数、再按总字数截批；被截多少如实报 `skipped`/`truncatedBy`，游标只前进到这一批最后一条 |
| 群聊的整理提示词里"对话来自：（没查到名字）" | `index.mjs` 只对私聊查称呼表 | 抽出 `resolveChatLabel()` 并接上 `roster.groupNameOf`（与界面会话列表同一份缓存），查不到就空串**不编** |
| 控制台改记忆**没有后路** | 覆盖是直接写盘 | 覆盖前备份到 `memory/.backups/`，并把路径回报给界面；备份失败**不阻断**写入但如实回 `backupError` |

★ 顺手把判定器的**政策层**抽成 `src/model-gate.mjs`（通路 / 小时预算 / 超时 / 失败方向 / 用量归一），
唤醒判定与情绪闸门共用一份 —— 抄一份必然在这些政策上分叉，而分叉的表现是静默的。

## 7. 刻意**不做**的（免得后来者以为是漏了）

- **好感度 / 情绪强度打分**：不可解释，且必然引出"要不要衰减"（D3 已删除整套好感度；D9 禁止强度浮点）。
- **跨群身份库 / 自动跨群归并**：那要造跨群身份库，而"A 群内容进 B 群"正是个人层跟人走之后要防的串场。
- **由档案驱动外发**：档案只用于"怎么对待这个人"，不用来主动搭话。
- **控制台写入的审计**：`audit.jsonl` 现在覆盖"桥接回合结算"与"按需建档"两处，
  **控制台 / 接口 / `--memory` 命令行的写入仍然没有审计行** —— 别在文档里写成"已审计"。
- **按需建档的界面里"从备份恢复"按钮**：恢复要选哪一份、恢复后快照基线怎么办都是新判据，先保证后路真的存在。
