## 1. 一句话

说话方式从**两份按消息切换**变成**一份所有回合通用**：新增 `src/voice.mjs`（唯一口径），
删掉判定器、`styles/` 目录、`chat.mode.*` 那 9 个配置键与界面上的那张卡片。
融合的方式是给"默认极短"加**一条**开口子（真在干活时允许说清），而不是把两句相反的话都留下。
另外把出厂人设从**三份**收敛成**唯一一份**（`小鲸鱼（完整带情绪）`，见 §4.5）。

## 2. 融合的口径：把一对**相反指令**消解掉

0.3.0beta 的两态各自都"自洽"，但把它们放进**同一份提示词**就出现了这一对：

| 来源 | 那句话 |
|---|---|
| 基座人设（`personas/*.md` 的 `【别变成客服】`） | 「**但对方认真问事实、技术问题时，就认真答**」 |
| 口吻（0.3.0beta 的 `styles/闲聊.md`） | 「**极短。一句话能说完就一句话**」「**别把一句回答扩成一段**」 |

两条都是一般性指令、都指同一件事（"该说多长"），模型只能自己挑一套听 ——
于是两个方向都不稳定。

**这一版的处理不是"保留两句、让模型自己权衡"，而是把它们合成一句**：

- 默认口径仍然是**极短**（口吻那一份原文里的规则一条没删）；
- 另加**唯一**一条新增条款 `WORK_ALLOWANCE`：「**真在干活时，该说清就说清**」——
  拆解步骤、报错原因、多个结果、需要逐条对比的东西该写多长写多长，
  但**口吻不变**（不写「好的，我来帮您」开场、不写总结式收尾）。
- 判据从"这一轮是哪个态"改成"这话是不是在想把事说清" —— 与身份无关，与做什么有关。

**怎么核这件事**（不是看文档，是看提示词）：`mocks/verify-memory-roundtrip.mjs` 第 ⑱ 节里钉着这一组断言
（共 8 条）—— ① 把说话方式那一段剥掉之后，其余部分与基线**逐字**相同；② 剥完的长度在同一量级（±2%）；
③ 说话方式**逐字**在提示词里，而且就是当前 `VOICE_STYLE` 那一份；④ 它**只注入一次**；
⑤ `WORK_ALLOWANCE` 在里面；⑥⑦⑧ **反向**三条 —— 提示词里**不许**出现 `【怎么说话】`、
`【别变成客服】`，也不许出现「但对方认真问事实、技术问题时，就认真答」，
更不许出现双态时代那句「这一轮是**闲聊**」（那两节是被**真正替换**掉了，不是追加在后面）。

## 4. 保留的行为（**别写反**）

这一版删得多，所以把"没删的东西"单列一节：

1. **「先应一声」保留，且默认开启**（长任务超过 8 秒先发一句「我在想」）——
   与升级前的工作态一致。**只**去掉了"闲聊态不发"那条抑制（它依赖已删除的分类器）；
   **静默时段那条抑制仍在**（夜里那声「我在想」正是静默时段要遮的"我在线"信号）。
2. **分条发送没动**：`src/humanize.mjs` 的 `splitReplyForSend` 判据一个字没改
   （只改了一处注释里的措辞：那句规则现在住在 `src/voice.mjs`）；`verify-voice-style.mjs` 里
   仍有「三段分三次发」的端到端断言。
3. **人设仍然按节替换、其余各节逐字保留**：说话方式是通过
   **替换**【怎么说话】【别变成客服】两节注入（编号式 `二、怎么说话` 也认），其余各节**逐字保留**；
   分不出节就走**追加**并在日志里标明退让（这条路与升级前一样，代价也一样：原人设里冲突的句子还在）。
   ★ 但**人设文件本身在这一版换过**（出厂收敛成一份，见下面 §4.5）。
4. **唤醒判定器完全不受影响**：`src/wake-judge.mjs` 的 `createWakeJudge` 一直是独立实例、独立预算
   （`wake.judge.maxPerHour`）。删的只是**同一个文件里**那个 `createModeJudge`。
5. **聊天记录评审台（`chat-review/`）仍在**，只是评审目标从 `styles/闲聊.md` 换成了 `src/voice.mjs`：
   仍然只产出「修改意见」、仍然**不写**那个文件、`/api/apply` 仍然是 404、路由仍是 **13 条**。
   启动参数 `--style` 删掉了；服务端选项 `styleDir` / `styleName` / `chatModePath` 收成单一 `voicePath`；
   `/api/health` 的 `styleFile.path` 现在指向 `src/voice.mjs`。

## 4.5 出厂人设从三份收敛成**唯一一份**（本版第二笔改动）

**改了什么**

| 项 | 0.3.0beta | 0.3.0alpha |
|---|---|---|
| 出厂人设 | 3 份：`小鲸鱼（完整带情绪）`（+ 代码里的 4 个预设 id，含"完整 / 精简 / 软糯"） | **1 份**：`小鲸鱼（完整带情绪）` |
| `personas/` 目录 | 完整带情绪 / 精简 / 软糯 | **只有完整带情绪** |
| `DEFAULT_PERSONA_PRESET` | `mermaid`（旧的"完整版"常量） | `mermaid-emotional`（唯一那份） |
| `personas/小鲸鱼（精简）.md`、`personas/软糯小鲸鱼（情绪）.md` | 在 | **已删除** |
| 界面按钮 | 「恢复默认**两套**」 | 「恢复默认**人设**」 |

**为什么**（使用者 2026-10-02）：「将目前的『小鲸鱼（完整带情绪）』作为唯一默认人设，
后续只用修改这一个人设」。多套出厂人设的代价是真实的：每加一份就要在常量、播种、
`恢复默认`、断言与文档五处各维护一遍；而"想短一点"这个诉求现在由**说话方式**
（`src/voice.mjs`）那一层承担，不必再换一套人设。

**旧预设 id 的去向（升级时最要紧的一条）**：`mermaid` / `mermaid-lite` / `mermaid-soft`
**仍然认得**，但取值**全是那唯一一份**。为什么不是删掉它们：老配置里写着
`persona.preset: "mermaid-lite"` 的人（那种写法只在 `persona.active` 为空时才生效）会走
`resolveActivePersona()` 的 legacy 分支，而 `buildPersona()` / `lintPersona()` 会拿这个 id 去查表 ——
删掉就让他们的配置校验报"预设不存在"。指向同一份文案是**刻意的**：
他们拿到的是这一份人设，而不是一个报错、也不是一段空白。
（`none` 保留：那是"不要人设、只用平台规则"，不是人设变体。）

**用户要改人设时改哪里**：`personas/小鲸鱼（完整带情绪）.md`（运行期读的是这个文件）。
代码里的常量只用于**首次播种**与「恢复默认」，两者有断言盯着逐字一致 ——
改了文件若希望"恢复默认"也给出新内容，得同步常量，否则那条断言会红。

**别的没变**：人设库仍然是**多文件**的（能新建 / 复制 / 改名 / 删除，用来做变体对比），
`persona.active` 的三条回落规则没变，"读不到不许静默退回内置"没变，
改名/删除牵着配置走没变。测试里凡是要"第二套人设"的用例，改成**现建一份侧人设**。

## 5. 行为变化与升级须知

1. ★ **要改口吻，改 `src/voice.mjs` 的 `VOICE_STYLE`**，不再是 `styles/闲聊.md`。
2. ★★ **改完要重启**才生效。0.3.0beta 的风格文件是**每轮现读**；现在它和项目里所有其它源码
   一样是启动时读一次 —— 这是有意的（"说话方式与其它源码同一种存在形式"），
   但**界面上原来那句「风格改了下一轮就生效」现在是错的**，已从 `CONFIG-UI.md` 里删掉。
3. ★★ **你以前改过的 `styles/闲聊.md` 升级后不再生效** —— 那份内容既不会报错、也不会被读，
   表现就是"我改了文件它没反应"。这是这一版**最需要提前说清的一条**。
   要恢复那份改动，把它抄进 `src/voice.mjs` 的 `VOICE_STYLE` 常量正文（注意：常量里**不能**出现
   反引号 / `${` / 反斜杠 —— 硬写会让 `src/voice.mjs` 语法崩掉，整个桥接起不来；
   `src/voice-source.mjs` 的三条守卫会拒绝这种写回）。
4. **老配置里的 `chat` 段被静默忽略**：不报错、不警告、也不影响运行；删掉它也行。
5. **`chat-review/` 的启动命令行**：`--style` 已经不存在了（传了也不会被识别）。
   `/api/health` 里 `styleFile.path` 现在指向包内的 `src/voice.mjs`。

### 6.1 提示词基线为什么涨了一截（5450 → 8806 字）

**实测差额 3356 字**，来源有两笔，分开说：

| 笔 | 贡献 | 怎么核 |
|---|---|---|
| ① 说话方式整段（`VOICE_STYLE`）现在**每一轮**都进提示词 | **+3153** | `node -e "import('./src/voice.mjs').then(m=>console.log(m.VOICE_STYLE.trim().length))"` |
| ② 被替换掉的基座两节 `【怎么说话】` + `【别变成客服】` 不再逐字出现 | **−358**（204 + 154） | 在旧基线里数这两节 |
| ③ 出厂人设从旧的"完整版"常量换成唯一那份（`mermaid-emotional`） | **+约 570** | 两份人设正文长度之差；`PERSONA_PRESETS.mermaid-emotional.length` 与它相减 |
| ④ 其余（双态那句「这一轮是闲聊」不再注入、段间空行等） | **≈ +9** | ①+②+③ 与实测差额的残差 |

①+② = 2795，再加 ③④ ≈ 579，合计 ≈ 3374，与实测 **3356** 差 **约 18 字** ——
这一小截我**没有逐个对上**，如实标注（量级像是段间空行的合并与那句注入的移除）。

★ 好消息是**这件事现在有机器兜底**：§6.2 说的"先剥掉说话方式再逐字比"那一条
会**独立**证明"差额只可能来自说话方式那一段 + 人设正文那一段"—— 因为剥掉之后，
基线里剩下的部分必须与现在**逐字相同**（那条断言现在是绿的）。所以上面这段推导
只是给人看的解释，**不是**门禁的判据。

### 6.2 这条基线在这一版加了**两道**新机制（改文案之前先读这一段）

1. **基线缺失时不再自动生成**：只有包根存在 **`.regenerate-golden`** 标记文件时才允许重建，
   否则判红。理由：一条**能被自己重新生成的基线等于没有基线**（删掉 fixture 再跑一次就"修复"了）。
   要换基线就得显式建这个标记（并在提交信息里说明为什么），换完删掉它。
2. **逐字比对先把"说话方式"那一段剥掉**（`VOICE_STYLE` 从两边删掉换成 `<VOICE>` 占位再逐字比）。
   理由：说话方式是一段会被人**反复改**的文案，而 fixture 是**逐字快照** —— 不剥的话，
   改文案里一个逗号就会让"提示词结构没漂"这条断言变红，而红的原因并不是结构问题。
   剥掉之后另有三条**定向**断言负责：说话方式**逐字**在提示词里（当前那一份）、
   **只注入一次**、以及 `WORK_ALLOWANCE` 在里面。

   **∴ 今后改 `VOICE_STYLE` 的操作纪律**：结构类断言不会红，但"说话方式逐字在提示词里"那条会红，
   并**明确提示**你去建 `.regenerate-golden` 重建基线。看到那条红**不是**结构坏了。

## 7. 已知边界 / 未决

1. **本版没有打包，也还没有提交**（见 §0）。打包按 `RELEASE.md` §1：界面改过要先 `npm run build`、
   `setup.mjs --check`、全量离线测试、组装 + 自校验。
2. **评审台里指向旧文件的文案已经改完了**（0.3.0alpha 收尾时补的一处）：
   `chat-review/public/app.js`、`public/index.html` 里给使用者看的文字原先把产物说成
   「对 `styles/闲聊.md` 的修改意见」，而那个文件在本版已被删除 —— 那种"界面按一个不存在的
   路径说话"正是本项目最忌讳的一类失败。现在它们说的是「对说话方式的修改意见」，
   顶栏那一格也从「风格文件 N 字」改成「说话方式 N 字」；
   `chat-review/server.mjs` 启动时打印的那行标签同理（「风格文件：」→「说话方式：」）。
   ★ 页面文案**不在任何断言的对象里**（套件的三份对账只核对路由与函数接线），
   所以这一处是靠人眼睛发现的 —— 换句话说：**改这类文案不会有门禁替你兜底**。
3. **说话方式改动要重启** —— 这条是这一版有意的取舍（换取"与其它源码同一种形式"），
   但它意味着**不能**再"改一个字、下一轮就见效"。要即时生效只能重启桥接。
4. **追加路径的代价照旧**：如果某套人设分不出「怎么说话」那一节，说话方式只能**追加**在末尾，
   原人设里与它冲突的句子**仍然在提示词里**（靠那段文本的「以本节为准」压住）。
   这一版**没有**改进这条路，只是它现在对所有回合都发生。
5. `chat.mode.*` 的 9 个键在 `config.json` 里留了一段「已下线」说明（`_说明` + `removed: true`）。
   界面上**不必**为它做兼容提示。但要知道：`normalizeConfig` **不会**把这个键带进运行时配置
   （实测 `normalizeConfig({chat:{…}})` 之后 `'chat' in config === false`），
   所以外部脚本 `config.chat.mode.enabled` 这种读法会**抛 `TypeError`**，
   而不是安静地拿到 `undefined` —— 桥接自己不读它，但第三方脚本要自己加保护。
6. `docs/闲聊模式与评审台-转交文档.md` 描述的是 0.3.0beta 的状态，**没有逐处改写**
   （它是历史取证）。文首横幅列出了仍成立与已失效的部分。
