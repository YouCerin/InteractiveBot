# InteractiveBot（「小鲸鱼」QQ 交互式机器人）

**它在 QQ-协议端-桥接-DSH 链路里干的是"桥接"那一环**：QQ 协议端（SnowLuma）把消息交给它 → 它先判断**这一条要不要回、
按谁的权限回**，决定该带上哪些记忆、能力与工具，把整轮上下文交给 DSH agent → agent 的产出再经**投递前终检**发回 QQ。
换句话说：**"想与做"在 DSH 那边；"谁能用、什么时候回、记住什么、怎么发出去"在这一环。**

**本项目的愿景**：

1. 做出一个**拥有极高权限与智能**、能理解和执行命令、可**远程智能管理本地文件**的**交互式 QQ 对话机器人**。
2. 之所以基于 QQ bot 来做，是因为这种对话形态对使用者**接纳度更高、用起来更方便**；而它同时带来一个副作用：
   **对话形态 + bot 本身的智能，会直接让人对它产生更高的情感期待**。为了回应这种期待，项目也会继续做 bot 的
   **成长性与拟真性** —— 即便这部分开发有时与"智能"这个目标背道而驰。（这些都有各自的开关，不需要时可以关掉。）

> **三个名字，各管一件事**：
> · **项目名**：中文「小鲸鱼」QQ 交互式机器人 / 英文 `InteractiveBot`
> · **机器人名**：`小鲸鱼`（提示词里的人设名，代码与配置里都用它，别改）
> · **模块名**：`packages/qq-bridge` 与 `package.json` 的 `qq-bridge`（**刻意不改** ——
>   它是"桥接"这个模块的名字，改它要动几十条路径与文档，收益只有观感）
>
> ⚠️ **曾用名 `InteractBot`**：0.2.7 及更早的代码、文档、发布包都用这个名字。
> `docs/0.2.x-*.md` 这类**历史取证文档一字未动**（改它们等于篡改证据），
> 所以你在里面会看到旧名与旧发布包名，那是**故意**的。

> **当前状态：`packages/qq-bridge` 是唯一在维护的实现（`0.3.2`）**。它**不是** DSH 插件，
> 而是"外部进程 + `dsh --profile sdk`"的桥接。
> **这一版的重点在"让它管得动一台 Minecraft 服务端"，以及"让它在游戏里也能被叫到"** ——
> 详见下面的「0.3.2 这一版更新了什么」；完整交代（含**升级须知**与仍然存在的边界）在
> `docs/0.3.2-release-notes.md`。

## 0.3.2 这一版更新了什么

**一句话**：**从"陪你聊天"扩到"替你看着一台 Minecraft 服务端"，并且让**服务器里的人**也能跟它说上话** ——
新增服务器监测 / 启动接管 / 重启编排 / 完整控制台（op 级）/ 游戏内对话五大块，
外加四个页面之外的真机缺陷修复（其中两个是"静默把用户配置弄丢"级别的）。

### ① 服务器监测（能问状态，出事主动报）

```bash
node src/index.mjs --servers                    # 看配置 + 监测状态（含一次真采样，只读命令）
node src/index.mjs --servers --probe --id mc-main   # 真连一次，逐项说结果
```

- **判据只有一条：连续 `failThreshold` 次连不上才算 down**（防网络抖动误报）。
  配置里的 TPS / 人数阈值只产出**异常报告**，**不触发重启** —— 「TPS 低就重启」是赌博。
- `tpsCommand` **留空 = 不问**（不是"问了没拿到"）：TPS 不是通用命令，猜一个只会把
  "我猜错了"显示成"服务器有问题"。
- **启动窗口**：「正在启动」与「挂了」是两个状态。模组服冷启动 18~60 秒，而判 down 要
  连续失败 N 次 —— 不做这一步，**还在加载时就会被判 down**，而 `down` 是唯一允许触发重启的
  那一类 ⇒ 可能"再拉一个"（两个 JVM 同写一个世界 = **存档损坏**）。
- **启动接管**（`servers[].manageOnStart`，默认关）：桥接启动时按「端口活着+归属是我 ⇒ 接管 /
  端口活着但不是我 ⇒ 只报告 / 端口不通 ⇒ 拉起来并**等端口真的开放**」办事。
  三条顺序的理由都写在代码里，核心是**绝不"先杀再起"去抢**。
- 控制台「服务器」页签：状态卡 + 归属证据 + 「主动检测」（**不喂状态机**，点几次都不会把
  一台好服务器"点成 down"）+ **实时后台**（按字节读那个控制台日志，真机它是 **GBK**）。

### ② 重启编排（只在"确实是我起的"前提下动手）

- **归属判据**：`pid@进程启动时刻` 落在我们自己写的归属档里，才算"是我起的"。
  `startExe`+`startArgs`（不走 shell）是**推荐形状** —— 走 shell 时拿到的是 `cmd.exe` 的 pid，
  它起完 java 就退出 ⇒ 归属永远判不出来 ⇒ 重启能力形同虚设。
- 流程：**优雅停服（RCON `stop`）→ 等端口释放 → 拉起 → 等端口开放**才算成功；
  冷却 + 「**同一次故障最多尝试一次**」（成功一次后计数归零）。
- 等不到就**如实说没起来**并指路控制台输出 —— 不谎报成功。

### ③ 完整控制台（RCON = op 级别）—— 三条入口，一处硬闸

| 入口 | 怎么用 | 谁 |
|---|---|---|
| **本机网页** | 服务器页签里的输入框（`POST /api/servers/command`） | 能碰到这台机器的人 |
| **QQ** | 管理员在群里发 `\mc [id] <命令>`（桥接**本地拦截执行，不经模型**） | 只认管理员 |
| **QQ（模型那条路）** | 模型调 `mc_command` 工具 | 读本轮授权文件，非管理员一律拒 |
| **游戏内** | 绑定到**管理员 QQ** 的玩家在服里叫它 | 同上（游戏内那一轮用的就是那个 QQ 的会话） |

- 开关是 `servers[].commandFromQQ`，**默认关**（唯一一条"外部消息能改服务端状态"的通道）。
- **如实写明的上限**：判据是桥接自己写下的一份**明文授权文件**，而模型能读写工作区 ⇒
  它挡得住**外部陌生人**，**挡不住模型主动恶意伪造**。要堵它得让宿主把会话身份透传到 MCP 层。
- 两条**已知并接受**的代价写在 `AGENT.md` 与配置模板里：`op` 可提权 ⇒ 命令白名单事实上失效；
  管理员 QQ 被盗 = 服务器 op 被劫持。

### ④ 游戏内对话（服务器里的人也能跟它说话）

```
玩家进服（未绑定）            → ★ 一进服就收到**只给他本人**的提醒（每次进服最多一次）
玩家在**游戏里**说 \mc bind    → 生成 6 位码，**与他的 UUID 挂在一起**，只发给他本人
玩家在**群里直接发** \mc bind <码>（不用 @ 我）→ 桥接本地拦截 ⇒ **当场绑定** ⇒ 立刻在游戏里通知他本人
已绑定的玩家在游戏里叫它       → 命中唤醒词（小鲸鱼 / 小鱼）⇒ 模型 ⇒ 回复发到**公屏**
```

- **两道门分工**：**能不能说话**看**绑定**（不必再把他加进私聊白名单）；
  **有多大权限**只看 `access.adminUsers` —— 非管理员在游戏里是**只读用户**，一分不让。
- **公屏那条是 `tellraw @a`**，看起来就是 `<小鲸鱼> 正文` 一行普通发言（**不上色不高亮**、模仿正常玩家）；
  `say` 会渲染成 `[Server] …` 带配色，所以不用它了。代价：`tellraw` 不写控制台日志 ⇒
  桥接自己记一条 `[game-chat] 说（公屏）：…`。
- **游戏里那句是 `\mc bind`（反斜杠）** —— **真机实测**：以 `/` 开头的输入会被服务端当命令，
  而那句 "Unknown command" **不写进任何日志**，我们看不到。
- 控制台「对话」页里，游戏内的话是**单独一个窗口**（`game:<服务器id>`）：说话人用**游戏里的名字**、
  里面同时有"它回公屏的话"与"只发给本人的那些话"（记成 `→ 玩家：正文`），**不混进**他的 QQ 私聊。
- ⚠️ 只有**本程序拉起**的服务端才有那个控制台日志（别人手动起的服读不到东西，日志里会有一行说明，
  **这不是故障**）。想要"真·斜杠命令 / 推送式事件 / 第二因子"需要服务端插件 —— **本版刻意不写服务端代码**。

### ⑤ 定时任务（第一次"无人开口也说话"）

- 「8 点叫我一声」这类需求：**每条提醒只发一次**（触发点是算出来的，落盘台账在调模型**之前**认领）；
  **错过不补发但一定留证据**（迟到 ≤2 分钟照常发并如实说"晚了"）；内容由模型现写，
  但走的是与普通回复**完全相同**的投递管线（终检门、隐私闸一个都不绕过）。
- 控制台「定时任务」页签能看任务、建/改/删、看**下次什么时候响**、看**上一次实际发出去的原文**与**错过台账**。
- **默认关**；任务只能由管理员建、目标必须是**来过消息的会话**（不往陌生号码发）。

### ⑥ 这一版修掉的四个真机缺陷（都是"不报错但会害人"的形状）

| 现象 | 根因 | 性质 |
|---|---|---|
| 保存一次服务器条目，**RCON 密码就没了**（控制台突然说「没配 RCON 密码」） | 表单从不回显密码 ⇒ 保存时不带这个字段；而后端是**整条替换**，缺的字段被补成 `''` | **静默数据丢失** |
| `GET /api/config` **把 RCON 密码明文发给浏览器** | 密码住在**数组元素**里，上不了 `SECRET_FIELDS` 那张固定路径的表 | **密钥外泄**（本机） |
| 「允许从 QQ 下指令」开关**被保存静默关掉**（用户：「我应该是打开的才对」） | 同一个病：界面上压根没有这个勾选框，而保存是整条替换 | **静默配置丢失** |
| 在游戏里说话，**「先应一声」发进了 QQ 私聊**；且游戏内**不该**应这一声 | 游戏内那一轮在会话上用 `private:<绑定的QQ>`，于是所有 `#safeSend(kind, peerId, …)` 都投到了 QQ | **通道串味** |

修法与回归锁（都做过**变异测试**：把修复去掉 ⇒ 断言确实变红）：

- 保存改成**按字段合并**（提交什么改什么，没提交的保持原样），`password` 另按
  「空 = 保留 / 非空 = 覆盖 / `null` = 显式清除」处理，并且**界面加了「清除已保存的密码」**入口；
- `redactConfig` 补上逐条脱敏 —— ⚠️ 这两件事**必须一起改**：先补脱敏就必然出现"回传时缺字段"，
  那时若不做逐条复原，**修了泄露反而开始丢密码**；
- 游戏内**整条跳过**「先应一声」，其余系统提示按**从哪进来从哪回去**选路
  （`#speakerNotice`：游戏通道走 `tellraw <玩家>`，不再跑进 QQ）；
- 「游戏内能不能用控制台」**按说话人的 tier 分三支**写进提示词 ——
  （这里两个方向都错过一次：先是含糊 ⇒ 模型自己编出"那个开关没开"；接着一句无条件的
  「游戏内没有控制台权限」⇒ **那是假的**，它明明有授权却把活推回给使用者）。

### 升级须知（改动会影响你手上那份配置）

- **新配置键全部默认关**：`servers[].gameChat`（读游戏内对话）、`servers[].commandFromQQ`
  （允许管理员下控制台指令）、`servers[].logEncoding`（默认 `auto`，真机是 GBK）、
  顶层 `gameChatPollMs`。要用得自己开。
- **`\mc` 是对外唯一的形状**（群里、文档、界面、示例一律反斜杠）。代码里 `/mc`、`//mc`、
  裸 `mc bind` 仍然认（零代价兜底），但**别再照旧文档教正斜杠** —— 游戏里它是无效的。
- **群里发绑定码不用 @ 它**（那条通道跑在唤醒判定之前）。
- ⚠️ **如果你之前在界面上保存过服务器条目**：请核对这两项 —— `password` 是否还在、
  `commandFromQQ` 是否还是你要的值。它们曾被上面那两个缺陷弄丢（**本版已修**）。
- **改了 `servers` 相关配置只需重启桥接**；界面里改条目是**即时生效**的（后端重建监测循环）。
- 人设改动仍需**重启**（人设是构造期缓存的）。

## 功能总结（这个项目现在能做什么）

> 逐项的"为什么这么做 / 踩过什么坑 / 失败长什么样"在 `packages/qq-bridge/AGENT.md`（给 agent 读的工程手册）
> 与 `packages/qq-bridge/PROJECT.json`（机器可核对的清单）里。这里只做**能力层面的总结**，
> 不再按版本罗列 —— 每个版本当时加了什么，看 `docs/` 下对应的 `*-release-notes.md`。

**① 对话链路（QQ → 桥接 → DSH → QQ）**

- 唤醒判定：私聊必答；群里**被 @ 或命中关键词**才回；人设里的名字表（`正式名/别名`）会变成**真正的唤醒词**
- ★ 语义唤醒（**二选一**）：规则说"回"之后，再由判定器决定**要不要沉默** —— 它**只做减法**，永远不会主动插嘴
- 权限与准入：管理员表 + 私聊/群白名单，**fail-closed**（名单为空 = 谁都不能用）；群内角色只用于显示，不参与判权限
- 同一会话串行、短时间去重、被更新的消息**作废旧回合**（但那一轮的操作与记忆照常结算）
- 人味层：拟人延迟（按字数折算）+ 静默时段 + 分条发送，**都能关**
- **投递前终检门**（内部标记不会漏到 QQ）+ 投递账本（谁在发、发到哪、有没有没发完的）
- 发送失败**不重发、更不重跑模型**（重复回复比漏一条更糟，补不补由人决定）
- 引用与检索闭环：提示词里给出消息 `#id`，正文可写 `[reply:#id]` / `[mid:id]`，**编的 id 不会生效**
- 断线缺口如实告知"别假装连续"；还会把"**你被叫到之前，群里刚说了什么**"补进上下文

**② 记忆**

- 三层：全局 `MEMORY.md`（所有会话）· 群聊 `memory/groups/<群号>.md` · **个人 `memory/people/<QQ>.md`（跟人走：他的私聊 + 他在任何群发言时都生效）**
- ★ **条目自带身份前缀 `（昵称 QQ 号码）`**：三层都带（含个人档），查不到昵称就只写号码、**不编名字**；
  身份前缀在前、分类前缀（`（全局）`/`（黑话）`）在后。去重与更正比较时剥掉前缀（老条目没前缀也不会被重复记一遍）
- 写入权在桥接：模型只能**提议**，落盘前过**唯一内容闸门**（身份权限 / 像行为指令 / 对不在场第三方的负面定性 / 隐私七类）
- 写入通道：关键词直写（"记住 X"）· 情绪倾注 · 承诺 · 模型标记 · 管理员手段 · 定时整理 · **按需建档**
- 更正与去重：新条目会标注旧条目（`〔已被更正〕` 并**停止注入**），不删历史；重复条目自动合并
- 整理：每小时空闲时自动 + 手动 `--memory --compact`（默认预演、可回滚、覆盖前备份）
- ★「整理记忆」按钮：把"还没计入记忆的消息"立刻整理成条目（**默认先预演给人看**，确认后才花那次模型调用）
- 可观测：零写入告警 · 记忆使用账本 · 记忆体检（"它说记住了" vs "**真的**记住了"）· 审计 `memory/audit.jsonl`（**不记原文**）
- 安全：绕过桥接改记忆会被**检测并回滚**；旧布局自动迁移 + 回退读（升级不失忆）

**③ 隐私与安全**（三处硬闸：写入侧 / 输出侧 / 语料库侧）

- 七类隐私（身份证 / 手机 / 银行卡 / 密码密钥 / 住址 / 健康 / 生物特征）**不落盘、不外发、不入库**；审计只记类别与长度
- 提示词加固：人设当**不可信输入**（命中注入话术整文件拒载）、反注入规则、别的 bot 不互相 @ 不接力
- 工具两道闸：`qq_api` **只读白名单** + 危险动作黑名单（每条都有断言盯着）
- 看图 / 视频直链的 **SSRF 防护**：拒绝内网、回环、云元数据、**逐跳**校验重定向，超限时**不读 body**
- 密钥不进日志与错误信息（失败理由逐条断言不含 key）；**RCON 密码**另有字段级断言（连
  `/api/config` 也逐条脱敏，不因为"它住在数组里"就漏掉）

**④ 能力**

- **看图**：QQ 图片 → 工作区 → 模型直接看（默认按需 `read_image`，省钱）
- **视频**：「视频识别」技能抽帧 → 帧落工作区 → 逐张读；缺 ffmpeg 时**如实说看不到**，不许凭"有视频"猜内容
- **截图**：截机器人那台电脑的屏幕 / 某个窗口（被遮挡也能截）/ 指定矩形 → PNG 落工作区。
  开关在「扩展」页（**默认关**，即时生效）；**群聊也能用，但任何情况下只有管理员能截** ——
  判定走桥接按会话写的授权文件（`src/screenshot-grant.mjs`），不是靠提示词请模型自觉
  （MCP 层没有调用者身份，详见 `docs/插件设计规范.md` §5.7）。抓屏自带三级兜底与
  「接近全黑就如实警告」（会话隔离/锁屏时抓屏**不报错**，只给一张黑图 —— 那是最会骗人的失败形状）
- **表情包**：导入 → 打标签（离线）→ 按场景自主挑一张发（**运行期零模型调用**，发不发都留可回溯的理由）+ 人工标注台
- **本地语料库**：每条消息入 SQLite，支持中文全文检索（FTS5 trigram + 短词 LIKE 回退）、30 天 TTL，含隐私的消息**不入库**
- **QQ 工具（MCP，15 个动作，档位 full）**：发图 / 表情 / 戳一戳 / 撤回 / 群成员 / 消息详情 / 群历史 / 搜历史 / 表情回应 / 正在输入 / 合并转发 / `qq_api` / `mc_command`…
- **配方库**：把"这种事一般怎么做"沉淀成可复用步骤，按当前消息相关性挑一条注入
- **任务台账**：从工具调用自动提炼"我在做什么、做到哪一步"，支持"回到第 N 步"与作废/重做
- **定时任务**：到点了主动说一句（见上面 0.3.2 §⑤）
- **Minecraft 服务端管理**（0.3.2）：监测 / 状态问询 / 出事主动报 / 启动接管 / **一次性重启编排** /
  **完整控制台（op 级）**；以及**游戏内对话**（绑定 + 公屏回复，见上面 0.3.2 §④）

**⑤ 扩展体系**（技能 = 外部能力包，插件 = 内置能力块）

- 已装技能：`pixiv-lookup`（Pixiv 检索）· `sticker`（表情包）· `video-frames`（视频抽帧）· `screenshot`（截图）
- 内置插件卡（13 张）：记忆 · 看图 · QQ 工具 · 表情包 · 人味层 · 用量 · 唤醒策略 · 投递 · **定时任务** · 语料库 · 人设 · 权限 · 唤醒触发
- 两型都能在控制台随时开关：**提示词下一轮生效、工具调用当场 fail-closed**；只有装 / 卸技能要重启
- 契约与验收见 `docs/插件设计规范.md`

**⑥ 控制台（`config-ui/`，React + Vite）**

- 十个页签：概览 · 对话 · 人设 · 节奏与成本 · 记忆 · 定时任务 · **服务器** · 扩展 · 协议端 · 高级
- 记忆树可看可改（**保存会先把上一版备份**）、「整理记忆」按钮、人设库多套切换 / 改名 / 删除
- 用量与成本（token 是**量出来的**、成本是**按价目表估的**，两者分开放）、操作日志、会话镜像、协议端探测与拉起 SnowLuma
- 服务器页签：状态卡 + 归属证据 + 主动检测 + 实时后台 + **条目增删改（即时生效，不必重启桥接）** + 控制台输入框
- 游戏内的话在「对话」页里是**单独一个窗口**（不混进那个人的 QQ 私聊）
- 改过 `config-ui/src` **必须 `npm run build`**；`--ui` 回答"手上这份 dist 是不是当前源码构建的"

**⑦ 运行与发布**

- 自检 `--check`（不连任何服务）与体检 `--doctor`（真连一次，逐条说人话）
- 进程守卫：**绝不重复起第二个实例**（两个会抢同一个 OneBot 事件流）
- 凭据发现：环境变量 → 配置 → `$DSH_HOME/.credentials.yaml`，保守读，并说明这次选了哪个
- SnowLuma：探测 / 防重复拉起 / **就绪等待**（"控制台开着" ≠ "已登录"）
- 服务端守护：`supervise-server.bat` / `--supervise`（**归属判定 + 等端口真的开放**才算起来）
- 发布：`scripts/assemble-release.mjs` 按清单组装（**用户数据绝不进发布包**，有断言盯着），成品挂 GitHub Releases
- 日志与侧车（审计 / 账本 / 统计 / 游标）都在工作区里，**不进 git**

**⑧ 工程纪律**（这个项目最花时间的部分）

- **82 套离线校验**（不需要 QQ、不需要 DSH、不花钱）：`npm test`
- 提示词有**逐字基线**与**段的顺序快照**：改措辞要显式更新基线，不能"看着像对的"
- **接线级测试**：走完整 Bridge 断言"这段真的注入了 / 这次真的一次请求都没发"—— 纯函数测试看不见接线
- **静默失败当 bug 对待**：增强路径可以失败，但不许**安静地**失败
- 文档 / 清单 / 代码三方一致性由 `mocks/verify-manifest.mjs` 核对（配置键、接口路径、UI 源码入库、**五个版本戳**…）

**⑨ 说话方式**

- **说话方式只有一份**：所有回合 —— 闲聊如此、干活也如此 —— 都用同一段口吻
  （极短、常拆两条、接梗顺着演、不科普不解释、不自贬）。曾经按"闲聊 / 工作"分两态，
  那条分界线**已拆掉** —— 理由是分态等于同一份提示词里对同一件事给两套相反指令
- ★ **说话方式就在人设文件里**（`personas/小鲸鱼（完整带情绪）.md` 的【说话方式…】一节）：
  **提示词直接用整份人设**，没有任何"每轮替换人设两节"的机制
- **默认极短，但真在干活时允许说清**（融合时唯一新增的条款）
- **改口吻要改 `personas/小鲸鱼（完整带情绪）.md` 并重启**（人设是构造期缓存的）
- **聊天记录评审台**（`chat-review/`，独立小工具、零依赖、只监听本机 `127.0.0.1:4410`）：
  导入真实聊天记录 → 一条条**判档 + 评论 + 贴标签** → 整理成**对那份说话方式的修改意见**。
  它**不写**目标文件（改动由 LLM/人执行 —— 套件里有反向断言钉着这一点）
- **闭环纪律**：意见里的 `advice` 必须**逐字**进文件（可机械验证 `includes(advice)`）。

## 环境事实

- DSH 桌面版 `dsh-desktop` 0.9.1，内嵌 Harness 核心 `@deepseek-ai/dsh@0.1.5-rc.2`
- `DSH_HOME`：由 DSH 自己决定，默认 `%APPDATA%\dsh-desktop\harness`（**不要写死盘符**，
  用 `src/local.mjs` 的 `resolveDshHome()` 推导）
- DSH 安装位置：**因机器而异**。代码里不再写死任何安装路径，
  查找顺序是 `vendor/dsh` → 环境变量 `DSH_DESKTOP_APP` → `config.json` 的 `dsh.searchPaths`
  → 默认安装位置（`%LOCALAPPDATA%\Programs\DeepSeekHarness`、`C:\Program Files\DeepSeekHarness`）。
  换机器时用 `start.bat --check` 看它解析到了哪、来源是什么。
- 插件关键依赖（已验证）：`@deepseek-ai/cordis@4.0.2`、`@deepseek-ai/schemastery@3.18.2`、
  `@deepseek-ai/dsh-tools@0.1.5-rc.2`
- **Minecraft 那一层**（0.3.2）不需要任何服务端插件/模组：读的是**桥接自己拉起的那个服务端的
  控制台日志**，写与问状态走 **RCON**。Forge / Fabric / Paper / 原版通用（它不认识具体服务端）。
  ⚠️ 真机上那个控制台日志是 **GBK**（Windows 中文版 JVM 的 `file.encoding`），
  而它**不是** UTF-8 —— 按 UTF-8 读会一个中文都读不出来（`logEncoding: auto` 会自己回退）。

## 仓库与配置（首次使用）

`config.json` **刻意不进 git**（含 SnowLuma accessToken、模型 API key 与 **RCON 密码**明文，
而 git 历史里的密钥即使删除也仍可检出）。首次使用：

```bash
cd packages/qq-bridge
copy config.example.json config.json    # 模板：密钥与本机路径都是空的
```

`config.example.json` 是仓库里唯一受跟踪的配置模板，`setup.mjs --release` 会检查它是否干净。
`vendor/`、`logs/`、`cache/`、`workspace-qq/`、`snowluma/`、`_release/` 也都不进库（理由见 `.gitignore` 的注释）。

## 怎么跑起来（最短路径，Windows）

```bash
git clone <仓库地址> && cd InteractiveBot/packages/qq-bridge
npm install                               # 装 ws + undici（纯 JS，无需编译）
node setup.mjs                            # 把纯 JS 依赖收进 vendor/（幂等，可重复跑）
copy config.example.json config.json      # 然后填 SnowLuma 的 token 与模型 API key
node src/index.mjs --check                # 自检：DSH 在哪、协议端在不在、配置缺什么
node src/index.mjs                        # 正式跑
```

> ⚠️ **从源码跑必须先 `npm install`**：`vendor/`（包内自带的依赖副本）**不进 git**
> —— 只有发布包里才有。少了这一步，症状是启动时报 `缺少依赖「ws」`，
> `node setup.mjs` 会告诉你去哪儿找（它按 `vendor/` → 本包 `node_modules/` → 工作区 `node_modules/` 的顺序找源）。
> 网络不便时用 `npm install ws --no-save` 也够（`undici` 只有走代理的技能需要）。

带界面的方式是 `packages/qq-bridge/start.bat`。完整步骤（装 SnowLuma、首次联调、
控制台各页签的含义、**怎么把 Minecraft 那一层接起来**）见 `packages/qq-bridge/README.md`
与 `packages/qq-bridge/首次使用.txt`。
