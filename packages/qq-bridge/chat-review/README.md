# 聊天记录评审台

**把「它像不像 AI」从印象变成可数的证据。** 导入真实聊天记录 → 一条条人工打分 →
标记出「违反了哪条规则」→ 生成一段能贴进 `styles/闲聊.md` 的**反例清单**。

它和表情包标注台一样是**独立小工具**：自己的文件夹、自己的进程、零依赖，
只监听 `127.0.0.1`，**不属于控制台**（控制台是"看机器人整体状态"的地方，
而评审是坐下来一次性过几百条的活，两边的形态互相拖累）。

---

## 启动

双击 **`启动评审.bat`**，或：

```bat
node chat-review\server.mjs                 :: 起在 http://127.0.0.1:4410/
node chat-review\server.mjs --port 4411     :: 换端口
node chat-review\server.mjs --open          :: 顺手打开浏览器
node chat-review\server.mjs --style 我的风格 :: 评哪一份风格文件（默认「闲聊」）
node chat-review\server.mjs --no-replace     :: 端口上已有评审台时**不接管**，直接报错
```

关掉那个窗口即停止。它**不需要桥接在跑**（直接读工作区的语料库文件）。

### ★ 启动时会先「接管端口」（不用你手动关旧的那份）

忘了上次那份还开着（窗口被最小化）时，**直接再启动一份就行**：新实例会先把旧的请走，
不会出现"点了一下，窗口自己关了"。

它按**从客气到不客气**三级来，每一级都先确认对方是谁：

1. **请它自己退** —— 向端口上那份发 `POST /api/shutdown`，并**等端口真的空出来**
   （不是"发了请求就当它退了"）。这一步最安全：不需要 PID、不涉及杀进程。
2. 它不退（卡住了）→ 从**进程登记**里找到它，走那条带身份校验的停进程
   （PID + 命令行里的 instanceId 双重比对，专门防 PID 被复用后误杀）。
3. 连登记里都没有（比如是**加这个功能之前的旧版本**）→ **拒绝动手**，并告诉你
   怎么手动关它（`netstat -ano | findstr :4410` → 关窗口），或直接换端口。

⚠️ 两种情况下它**绝不会**动手：端口上跑的**不是评审台**（比如别的东西占了 4410），
或者**认不出那个 PID 是谁**。误杀别的进程比"我自己起不来"严重得多。

> 如果你正好在用另一份（比如 4411 上还有一份），它会提示一句：两份共用同一份评审数据
> （`runtime/chat-review/`），两边同时改会互相覆盖。

## 三步

### ① 导入

两种数据源，选一个：

| 数据源 | 用途 | 说明 |
|---|---|---|
| **语料库** | 评"它最近在这几个群里表现如何" | 下拉里按**机器人发言数**排序（一个机器人不说话的群，评它没意义）。条数最多 500，上下文 0~3 条 |
| **粘贴导入** | 评"别人发我的这份记录" | 支持 QQ「合并转发」的 JSON 与纯文本 `昵称: 内容` |

> ⚠️ 语料库里的消息有 **30 天 TTL**（`--corpus --prune` 会清掉更早的），
> 所以想评更早的记录，要趁早。

**机器人自己的发言怎么认？** 语料库那条路靠 `is_bot` 字段（可靠）；
导入那条路靠昵称，默认认 `小鲸鱼 / 小鱼 / D指导 / deepseek / DeepSeek / 小鲸鱼 bot`。
一份都没认出来时它会**明确告诉你它认哪些名字**，而不是给你一个空批次。

**认不出来的行会怎样？** 原样列在页面上（带行号与原文片段），一条都不会被静默丢掉 ——
评审者对着假数据打的分，比没有数据更糟。

### ② 打分

一条一条过。评的是**「机器人那句话在这个语境下接得怎么样」**，所以卡片上，
上下文在上、它说的话在下（大字）。

| 键 | 作用 |
|---|---|
| `1` / `2` / `3` | 就该这么说 / 还行 / 不该这么说 —— **按下即落盘并跳下一条** |
| `4`~`9`、`0` | 切换前七个标签（多选，点一下即存） |
| `Enter` | 下一条（不改分） |
| `U` | 撤销**本批次最后打的那条** |
| `S` | 跳过这条（不写分） |

- **没有「保存」按钮**：评分是每一条几十秒的小动作，攒着必丢。
- 按下结论后卡片**立刻**换下一条（不等网络往返）；写失败会把这张卡插回来并报错。
- 标签分两组：`bad`（不该这样）与 `good`（这样很好）—— 报告里分开统计。

### ③ 报告 → 生成修订草稿

- 好/还行/该不该这么说的分布、每个标签命中多少次、点开看**证据原文**；
- 「生成修订草稿」→ 得到一段**反例清单**与它的 diff：
  每个被标了 bad 的标签，取最多 2 条**真实原话**，按它挂的规则归类。
- 「应用到 styles/闲聊.md」需要**显式确认**，并且：

  1. 先算 diff 给你看；
  2. 确认后**先把原文件备份**到 `styles/.backups/闲聊.md.<时间戳>.bak`；
  3. 再原子写（追加在文件末尾，原有内容一字不动）；
  4. 回来告诉你备份路径与新的 sha256。

  同一份草稿**不能应用两次**（会让提示词里出现两段一样的反例，白烧 token）。

> ★ 风格文件是**每轮现读**的 —— 应用完**下一轮对话就生效，不需要重启机器人**。

## 为什么产出的是"反例清单"而不是"新规则"

规则该由人写：它涉及取舍（哪句更重要、和现有规则冲不冲突）。
而反例是**纯事实** —— 这段文本只是把真人标过的原话按规则归类列出来，
确定性生成、零模型调用，既不与现有规则打架，也不假装知道判据该怎么改。

「这条规则被违反得最多、建议这么改」那部分**留在报告页给人看**，不进文件。

## 标签是从哪来的

每个标签都挂在 `styles/闲聊.md` 的一**句原文**上（`ruleQuote`）。
这条链子是有意的：标签是"哪条规则没被遵守"的计数器，如果标签与规则是两套东西，
它们一定会漂 —— 文件删了规则、报告还在统计一个不存在的判据。

所以风格文件被改过之后，**打分页顶部会亮一条横幅**告诉你哪几条标签挂了空挡。
它不拦着你用（已评的分照样有效），但你必须知道。

## 数据存在哪

```
<工作区>/runtime/chat-review/
  index.json          批次清单（含条数与建立时间）
  batches/<批次>.json  那一批的条目（回合 + 上下文）
  scores.json         所有评分（+ 评分顺序，撤销靠它）
```

- 只写这三份 + 应用草稿时的 `styles/.backups/` 备份。
- **不动语料库**（它是以只读方式打开的），**不动配置**，**不发消息**。
- 想清空：页面上删批次，或直接删 `runtime/chat-review/` 整个目录。

## 已知边界（如实说）

- 语料库只有 **30 天**，且只包含**本机聊过**的会话；
- 纯文本导入是**兜底**路径：一句正文里如果带冒号（`答案是: 42`），
  它会被当成"昵称: 内容"。要准确就用合并转发 JSON；
- 草稿正文有**行数上限**（60 行）—— 它是要进提示词的，超了会在页面与文本里都说明；
- 税则（`src/chat-review-store.mjs` 的 `TAGS`）是**手写的**：风格文件里加了一条新规则
  之后，标签不会自己长出来，要手动加一个并写上 `ruleQuote`（有测试盯着它必须真的存在）。
