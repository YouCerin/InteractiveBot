# 聊天记录评审台

**把「它像不像 AI」从印象变成证据。** 导入真实聊天记录 → 一条条**判档 + 写一句评论** →
把评论**整理成「点」** → 据此**整篇重写** `styles/闲聊.md`（可按需精简，底线要点一条不许丢）。

它和表情包标注台一样是**独立小工具**：自己的文件夹、自己的进程、零依赖，
只监听 `127.0.0.1`，**不属于控制台**（控制台是"看机器人整体状态"的地方，
而评审是坐下来一次性过几百条的活，两边的形态互相拖累）。

---

## 启动

双击 **`启动评审.bat`**，或：

```bat
node chat-review\server.mjs                 :: 起在 http://127.0.0.1:4410/
node chat-review\server.mjs --port 4411     :: 换端口
node chat-review\server.mjs --open          :: 顺手打开浏览器
node chat-review\server.mjs --style 我的风格 :: 评哪一份风格文件（默认「闲聊」）
node chat-review\server.mjs --no-replace     :: 端口上已有评审台时**不接管**，直接报错
```

关掉那个窗口即停止。它**不需要桥接在跑**（直接读工作区的语料库文件）。

### ★ 启动时会先「接管端口」（不用你手动关旧的那份）

忘了上次那份还开着（窗口被最小化）时，**直接再启动一份就行**：新实例会先把旧的请走，
不会出现"点了一下，窗口自己关了"。

它按**从客气到不客气**三级来，每一级都先确认对方是谁：

1. **请它自己退** —— 向端口上那份发 `POST /api/shutdown`，并**等端口真的空出来**
   （不是"发了请求就当它退了"）。这一步最安全：不需要 PID、不涉及杀进程。
2. 它不退（卡住了）→ 从**进程登记**里找到它，走那条带身份校验的停进程
   （PID + 命令行里的 instanceId 双重比对，专门防 PID 被复用后误杀）。
3. 连登记里都没有（比如是**加这个功能之前的旧版本**）→ **拒绝动手**，并告诉你
   怎么手动关它（`netstat -ano | findstr :4410` → 关窗口），或直接换端口。

⚠️ 两种情况下它**绝不会**动手：端口上跑的**不是评审台**（比如别的东西占了 4410），
或者**认不出那个 PID 是谁**。误杀别的进程比"我自己起不来"严重得多。

> 如果你正好在用另一份（比如 4411 上还有一份），它会提示一句：两份共用同一份评审数据
> （`runtime/chat-review/`），两边同时改会互相覆盖。

## 三步

### ① 导入

两种数据源，选一个：

| 数据源 | 用途 | 说明 |
|---|---|---|
| **语料库** | 评"它最近在这几个群里表现如何" | 下拉里按**机器人发言数**排序（一个机器人不说话的群，评它没意义）。条数最多 500，上下文 0~3 条 |
| **粘贴导入** | 评"别人发我的这份记录" | 支持 QQ「合并转发」的 JSON 与纯文本 `昵称: 内容` |

> ⚠️ 语料库里的消息有 **30 天 TTL**（`--corpus --prune` 会清掉更早的），
> 所以想评更早的记录，要趁早。

**机器人自己的发言怎么认？** 语料库那条路靠 `is_bot` 字段（可靠）；
导入那条路靠昵称，默认认 `小鲸鱼 / 小鱼 / D指导 / deepseek / DeepSeek / 小鲸鱼 bot`。
一份都没认出来时它会**明确告诉你它认哪些名字**，而不是给你一个空批次。

**认不出来的行会怎样？** 原样列在页面上（带行号与原文片段），一条都不会被静默丢掉 ——
评审者对着假数据打的分，比没有数据更糟。

### ② 打分：判档 + **写一句评论**

一条一条过。评的是**「机器人那句话在这个语境下接得怎么样」**，所以卡片上，上下文在上、它说的话在下（大字）。

| 键 | 作用 |
|---|---|
| `1` / `2` / `3` | 对 / 还行 / 不对 —— **按下即落盘并跳下一条** |
| `Enter` | 保存评论并下一条（`Shift+Enter` 换行） |
| `U` | 撤销**本批次最后打的那条** |
| `S` | 跳过这条（不写分） |

- **点按钮（原标签按钮的位置）**：点一下就把"这一类"记在这条上 —— 这是"便捷评论"的那一半。
- ★ **点与评论各自留痕**：点一下**不会**往评论框里自动写字，写评论也**不会**自动选点；
  已选的点显示在评论框上方，可以一个个点掉。
- **评论是素材**：写"哪儿对、哪儿不对"，一句话就够（「问手机就答手机，别交代机箱」）。
- 只判档不写字也行（快速过法），但**整理只用有评论的那些**，页面会如实显示"有 N 条只有判档"。
- **没有「保存」按钮**：评论失焦即存，判档、点一下都立刻落盘。
- 已评过的条目再遇到时，原来那条评论**与它记过的点**都会填回来（重评 = 改，不是重打）。
- ⚠️ 重评时若**没带点**，那条的点会被清空（`POST /api/score` 是**整条替换**，与评论同一语义）——
  页面每次都带上回填的点，所以正常用不会丢。

### ③ 报告 → 整理评论 → 整篇重写

1. **评论清单**：新→旧，可按判档筛选、按文字搜索、**按点筛选**（点排行里点一下就筛），
   每条带被评的那句话与上下文。
2. **「整理评论」**：把这批评论交给模型，让它归纳成若干**「点」**（3~8 条，
   每条一句话、带它依据的那几条评论编号）。这是这个工具**唯一一次调模型**，人点一下才发生。
   ★ 整理出来的点会**并进点表**（同义的并进同一个、`count` 累加）——
   于是**打分页那排按钮会跟着变多、变准**，这就是"点从评论里长出来"。
3. 同时给出一份**完整的新版 `styles/闲聊.md`**（可按需精简：合并重复、删掉被更好说法覆盖的）
   与它的**整文件 diff**。
4. **应用**需要显式确认，并且：

   1. 先**核对锚点** —— 那 10 条底线要点（不越权 / 不外泄记忆 / 不假装成功 / 别的 bot 不接力 /
      接梗不是屈服 / 敬语是台词不是认输 / 不要编 / 低落时不玩梗 / 情色暗示看懂并拒绝 / 优先级条款）
      一条都不许丢；丢了就**拒绝应用**并逐条说清丢了什么（你可以明确选择"仍然应用"）；
   2. **先把原文件备份**到 `styles/.backups/闲聊.md.<时间戳>.bak`；
   3. 再原子写风格文件；
   4. **顺带同步 `src/chat-mode.mjs` 里的出厂默认常量**（否则那两份会开始漂，测试会红）；
   5. 回来告诉你备份路径、新 sha256、`2388 → 2100 字（精简 288）`。

> ★ 风格文件是**每轮现读**的 —— 应用完**下一轮对话就生效，不需要重启机器人**。

## 为什么是「评论 → 点 → 重写」，而不是「标签 → 排行 → 追加」

第一版是**标签制**：我做了一张分类表（太长 / 像客服 / 滥用省略号…），人从里面选，然后按标签排榜。
使用者直接判定：**「标签系统并不合理」**。这个判断是对的，而且差别是根本性的：

- 标签表是**我预先想好的分类**。人只能在我给的格子里打勾 —— **我没想到的问题就永远进不了统计**。
  这是最要命的：排行榜上没有的问题，会被当成"没问题"。
- 评论是**人自己的判断**。而"点"应该是**从评论里长出来的**（使用者原话：
  「从我的评论中整理新的点放上去」），不是我预先设定的。

所以现在的分工是：**人负责判断（评论），模型负责归纳（点），人再负责取舍（改不改、怎么改）**。
工具只做两件确定性的事：把评论原文一字不改地留着、把改写前后的差异摆出来。

## 点是"会长的标签"：为什么它不算走回头路

有人（我）可能觉得"点不就是标签吗"。不是，差别是根本性的：

| | 旧的标签 | 现在的点 |
|---|---|---|
| 从哪来 | **我预先想好的分类** | **从你的评论里归纳出来** |
| 能改吗 | 改不了（在代码里） | 能改标题/摘要、能删、能新建（在 `points.json` 里） |
| 会变多吗 | 不会 —— 我没想到的问题**永远进不了统计** | 会 —— 整理一次就长一批，越用越贴合你 |
| 位置 | 打分卡片上那排按钮 | **同一个位置**（这正是使用者的要求） |
| 作用 | 统计口径 | **让评论更快**（点一下就记下这一类），同时仍是统计口径 |

所以它既保留了标签"点一下就完事"的便利，又不带上标签"分类权在别人手里"的毛病。
点表为空时服务会**幂等播种**（有评论就用本地聚类产出，没有就用 8 个内置种子）；
**你改过或删过之后，再启动也不会把它们补回来**。

## 那 10 条「底线要点」（锚点）是什么、为什么是短词
整篇重写有机会改坏人格文件，所以定了一张必须活下来的要点表（`STYLE_ANCHORS`）。
判据刻意用**短词包含**而不是整句：要求逐字保留整句等于**禁止任何改写**，
而要求"这个要点还在"才既能允许精简、又拦得住"把安全底线顺手删掉"。
每条都给了同义写法（`不泄露记忆` / `不外泄记忆`）。

## 整理失败会怎样

模型不通、超时、输出不合法 —— 一律**如实说失败**，并把两样东西摆在你面前：
**评论原文**与**本地聚类**（把说法相近的评论分组计数，用仓库已有的文本相似度，零调用）。
归纳不出规则，但至少让你看见"哪些评论在说同一件事、说了几遍"。绝不假装整理过。

## 数据存在哪

```
<工作区>/runtime/chat-review/
  index.json                  批次清单（含条数、已评、有评论数）
  batches/<批次>.json          那一批的条目（回合 + 上下文）
  scores.json                 所有评分（判档 + 评论 + 记过的点 + 评分顺序，撤销靠它）
  points.json                 ★ 点表（顶替原标签的评论词汇表，可编辑）
  consolidations/<整理>.json   每次整理的结果（点 + 改写 + diff + 锚点核对 + 是否已应用）
```

- 只写这几类 + 应用改写时的 `styles/.backups/` 备份（以及同步常量时的 `src/.backups/`）。
- **不动语料库**（以只读方式打开），**不动配置**，**不发消息**。
- 想清空：页面上删批次，或直接删 `runtime/chat-review/` 整个目录
  （⚠️ 删点表等于把词汇表清空，下次启动会**重新播种**成初始那 8 个）。
- 每次整理都**单独存一份**（不覆盖旧的）：这样"上次改了什么、有没有应用过"查得到。
- **兼容旧数据**：旧系统的「备注」字段叫 `note`，读的时候当评论用 —— 以前写过的字不会消失。

## 已知边界（如实说）

- 语料库只有 **30 天**，且只包含**本机聊过**的会话；
- 纯文本导入是**兜底**路径：一句正文里如果带冒号（`答案是: 42`），
  它会被当成"昵称: 内容"。要准确就用合并转发 JSON；
- **一次整理要调一次模型**（人点一下才发生）：带评论的评分越多，提示词越长。
  上限是 **150 条评论 / 14000 字**，超了会截断并如实报数（页面上能看到"这次带了 N 条"）；
- 整理出来的点是**模型归纳**的，不是判据 —— 它只是帮你把评论读成几条，
  最终改不改、怎么改仍然是你点确认；
- 锚点核对是**短词包含**，所以它拦的是"底线被删掉"，拦不住"底线被改得含糊"——
  那一条只能靠你看 diff（页面已经把 diff 摆在按钮正上方）。
