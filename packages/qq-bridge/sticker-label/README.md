# 表情包人工标注台（`sticker-label/`）

给表情包**人工贴语义标签**的独立小工具。两个页签：**逐张刷卡标注** + **按标签看图复核**。

> **它不属于控制台后台 UI**（刻意）：控制台是"机器人整体状态"的地方，
> 而这个工具是**一次性、用完就关**的标注台（要全屏看图、要键盘刷）。
> 所以它是一个独立文件夹 + 独立进程 + **零依赖**（只用 Node 内置模块，
> 不走 `config-ui` 的构建，也不碰 `/api/*` 那一套）。

---

## 怎么用

```bash
cd packages/qq-bridge
node sticker-label/server.mjs          # 起在 http://127.0.0.1:4399/
node sticker-label/server.mjs --open   # 顺手打开浏览器
node sticker-label/server.mjs --port 4400
```

或者双击 **`启动标注.bat`**（会用包内的 `vendor\node`，不依赖系统 Node）。

## 页签一：逐张标注

| 操作 | 作用 |
|---|---|
| 点右侧任意标签 | **立刻写回**（没有"保存"按钮），并自动跳下一张 |
| 数字键 `1`-`9` | 前九个常用标签（按你库里实际张数排） |
| `←` `→`（或 `a` `d`） | 上一张 / 下一张 |
| `空格` | 跳过（标成"无合适标签"，见下） |
| `Ctrl+Z` | 撤销上一步（内存里，最多 200 步） |

**"跳过"是什么意思**：把这张标签置空并记成人工 —— 于是自动重打标签
**也不会给它安一个猜的标签**。适合"这张图我判断不出该归哪类，但别让它被乱标"。

### ★ 复核已有标签时，勾上「看全部」

默认只看"**待办**"（没标签的 + 模型不确定的）。但**模型打了个错标签的图不在待办里**
（它已经有标签了）—— 实测：157 张里待办只有 2 张，而模型打的 155 个标签里
错得不少（把「一切都好」的 OK 手势打成「无语」）。

所以要**逐张过一遍**时，勾右下角的「**看全部**」，然后一路 `→` 刷过去，
看到不对就点正确的标签（点完自动跳下一张，`Ctrl+Z` 可撤）。

## 页签二：按标签看图（复核某个标签用得对不对）

逐张页回答不了"**这个标签是不是都打对了**"—— 那需要把同一个标签下的图**摆在一起看**。
所以有了这一页：

```
┌──────────────┬──────────────────────────────────────┐
│ 未打标签 12  │ 笑死（laugh）  共 23 张   [✎ 改这个标签] │
│ ─ 主动情感 ─ │ 轴：被逗乐 · 典型语境：哈哈、笑死、绝了    │
│ 笑死      23 │ ✓ 可被自主补图                         │
│ 抱抱       5 │ ┌────┐┌────┐┌────┐┌────┐┌────┐        │
│ ─ 被逗乐 ─   │ │ 图 ││ 图 ││ 图 ││ 图 ││ 图 │  ← 点一张 │
│ ...          │ └────┘└────┘└────┘└────┘└────┘   就放大  │
└──────────────┴──────────────────────────────────────┘
```

* **左边点标签 → 右边出这标签下的图墙**，张数**实时**（标完一张立刻变）。
* **点任意一张图放大**，浮层里能**直接改成别的标签**（不用切回逐张页）。
  这是复核最主要的动作："这张明显不是笑死，改成无语。"
* **`✎ 改这个标签` / `＋ 新建标签`**：改中文名、轴、典型语境；新建一个标签。
  改完**下一轮对话就生效**（桥接每轮现读词表），**不用重启**。
* `轴` 决定它**能不能被"自主补图"触发**：主动情感/被逗乐/认知反应/表态/状态 → 可以；
  礼节/交付/风险 → 只能由模型主动写 `[sticker:标签]`。
* 标了「慎发」（`risky`）的图右上角有红标。**它是安全闸门：不能改名、不能删**
  （要放行请改配置 `skills.sticker.allowRisky`）。
* 张数**低于 3 张**会变黄 —— 少于 3 张的标签不会出现在提示词里（模型看不到它）。
* 库里引用了、但词表里**已经没有**的标签会单列一区「⚠️ 引用已删标签」——
  这是**兜底**：正常从这一页删标签不会留下这种东西（见下），
  但手改过 `library.json`、或用了旧版本，仍可能出现，所以必须能看见。

## 新建 / 删除标签

**入口在哪**（两个页签都有，任选）：

| 你在哪 | 点哪 |
|---|---|
| 「逐张标注」页 | 右侧「**✎ 管理标签（改名 / 删除）**」—— 会跳到图墙并直接打开编辑表单 |
| 「按标签看图」页 | 选中一个标签 →「**✎ 改这个标签**」；或左列顶部「**＋ 新建标签**」 |

> 逐张页那个入口是后加的：编辑与删除原先只存在于「按标签看图」里，
> 而人常在逐张页干活，于是**完全看不到它们**（实测反馈「没有看见删除、编辑等新功能的入口」）。
> 功能藏起来等于不存在。

**新建**：填名字（≤8 字）、选轴、填**两组线索**（见下）、可选。
id 按名字自动生成（中文名走短哈希），**不用你起**。建完**下一轮对话就能用**。

## ★ 语境轴：三分类决定"该看谁说的话"

每个标签有一个**轴**，而轴决定它**看谁说的话**（这是 0.2.4 的结构性简化）：

| 类别 | 轴 | 看谁说的话 | 该填哪一组 |
|---|---|---|---|
| **主体类** | 状态、交付 | **bot 自己的发言** | 只填 **① 我自己会说** |
| **客体类** | 认知反应、表态、礼节 | **对方那条消息** | 只填 **② 对方会说** |
| **混合类** | 主动情感、社交姿态、攻击性 | 两边都看 | **两组都填** |

> 「礼节」原先归混合类，后来明确改为**客体类**：问候/晚安/道歉这类语义标记，
> 在**对方**说"睡了""我的锅"的时候配一张才自然；bot 自己随口说句"晚安"就贴一张，
> 那是在做装饰。

**为什么要按轴分**（这是用户定的规则，替掉了"每条线索各自判断"）：

上一轮把线索分成 `cues`（bot 自己会说）与 `otherCues`（对方会说）之后，
"这条线索该挂哪边"仍然要**一条条判断** —— 而它其实主要由**轴**决定：
`状态`是"我此刻的状态"（只有我自己的发言里看得出来），
`认知反应`/`表态`是"我对他那句话的反应"（对方说了什么才触发）。
用轴来定这件事，**人不必在每条线索上重复判断，也不会自相矛盾**。

代码里 `AXIS_SIDE` / `axisSide()` 是这条规则的**单一来源**：
判定时按轴**屏蔽**不该看的那一侧（不是靠"那个字段恰好是空的"）。

> ⚠️ `风险`（慎发）与出厂轴 `被逗乐` **不在三分类里** —— 前者是安全闸门
> （本来就不参与自主判定），后者你当前的词表里没有这类标签。
> 对它们工具**一律不动**，不会替你删。

## ★ 两组线索：每组的判据是什么

编辑表单里的两个输入框，含义不同：

| 填在哪 | 匹配谁说的话 | 语义 |
|---|---|---|
| **① 我自己会说** | bot 自己要发的回复 | "我这样回应"（在笑 / 无语 / 抱抱你） |
| **② 对方会说** | 对方发来的那条消息 | "对方处于这个状态"（他累了 / 他在喊冤） |

**为什么必须分开**（一个真实的设计缺陷，被骗了很久才抓出来）：
自主判定原先只匹配 **bot 自己的正文**。而线索里混着两种东西 ——
`累了` 的线索是「好累、困、熬夜」，可这些全是**对方**会说的话：
**一个助手不会在回复里说"我好累、我熬夜了"**。于是那个语境
（对方说"今天加班到现在"）**永远触发不了**，那些图等于白放。

反过来也要小心：bot 那张嘴很爱说套话（确实 / 好的 / 明白了），
如果不分优先级，**套话会盖过真正的信号** —— 所以规则是
「**对方消息里有信号就以它为准**」。

### 怎么填

- 先看这个标签的**轴**（上面那张表）：主体类只填 ①、客体类只填 ②、混合类都填。
- **② 至少要 2 个字**：单字线索在长句里太容易误撞 —— 实测「**早**点休息吧」
  会被当成"打招呼"（`早`），而对方其实是在熬夜。所以单字线索**不参与**对方消息匹配。
- **含糊的词别放 ②**：`6`、`呃` 这类放 ① 就行，放 ② 会到处命中。
- 想清楚"**谁会说**"：`加油` 是 bot 说的（①）；`我好累` 是对方说的（②）。

改完**下一轮对话就生效**，不用重启。

## 删除标签

**入口**（两个页签都有，任选）：

| 你在哪 | 点哪 |
|---|---|
| 「逐张标注」页 | 右侧「**✎ 管理标签（改名 / 删除）**」—— 会跳到图墙并直接打开编辑表单 |
| 「按标签看图」页 | 选中一个标签 →「**✎ 改这个标签**」 |

删除的语义是**两条一起**：

1. **标签本身**从词表里消失；
2. 库里**所有引用它的图** → **恢复成未标注**（`primary` 清空、置信度清 0）。

第 2 条是关键：那些图**不会被选中**（回到"还没打标签"的状态），等着你重新标。
它们会出现在左侧的「**未打标签（待办）**」那一栏里，点进去就能一张张重贴。

> 为什么不只删标签、把图留在"引用已删标签"？那样会留下一批悬在半空的图 ——
> 界面能列出来，但谁也说不清它们算不算有标签、该不该参与选图。
> 恢复成未标注之后语义是明确的：**没标签 = 不会被发出去**。

★ 两种引用是**分开处理**的，这点很重要：

| 它在这张图上的角色 | 删除后的结果 |
|---|---|
| **主标签** | 整条清成未标注（不会被选中） |
| 只是**次要标签** | **只摘掉它**，这张图的主标签**原样保留** |

**标签下还有图时会先拦一次让你确认** —— 不是保护标签，是保护"图上已有的判断"，
因为这一步会清掉你之前（或模型）打的标注。

**删错了怎么办**：`Ctrl+Z` **一步整批撤回** —— 标签会加回词表（id、名字、轴、
典型语境、**以及它原来在词表里的位置**都还原），那些图的标注也一起回来。
不是让你按几十次 Ctrl+Z，是**一次**。

## 它写进去的是什么

写回的形状（`stickers/library.json`）：

```json
"global/7405d3613e866cfa.gif": {
  "primary": "laugh",
  "labels": ["laugh"],
  "primaryConfidence": 1,
  "source": "manual"        ← ★ 关键：人工判断
}
```

★ **`source: "manual"` 是护身符**：控制台上的【重新打标签】按钮与命令行的
重打都会**跳过**它（有断言钉着）。想连它一起重打只能用 `--force` ——
那是一个"把人工成果冲掉"的动作，刻意收窄在命令行。

**改完不用重启桥接**：判定、提示词与词表都是**每轮现读**文件，下一轮对话就生效。

## 页面上的几件事怎么读（逐张页）

| 显示 | 含义 |
|---|---|
| 顶部"库里 N 张｜没标签 X｜低置信度 Y｜我标过 Z" | 全局进度。**低置信度** = 模型自己都不确定（< 0.6），最值得你复核 |
| "当前筛选 M 张" | 右下角那几个勾选框的结果 |
| 标签按钮右边的数字 | 这个标签**当前有几张**。**低于 3 张会变淡** |
| 图下面那行小字 | `id / 体积 / 当前标签 / 置信度 / 来源` |
| 标签按钮的悬停提示 | 该标签的**典型语境**（来自词表，帮你判断这张算不算） |

## 端口被占 / 怎么关掉它

这个工具是**独立进程 + 固定端口（4399）**。端口被占时，新进程连启动都失败
（`EADDRINUSE`），而那时页面上往往什么提示都没有 —— 只能去任务管理器里翻 `node.exe`
（如果是提权启动的，连 `taskkill` 都会被拒）。实测反复卡在这里，所以：

**右上角有两个按钮，直接在页面里管进程**：

| 按钮 | 作用 |
|---|---|
| **重启服务** | 拉起一个新进程（带 `--wait-port`，会等旧进程让出端口）、再关掉旧的。约 1 秒后按 F5 刷新 |
| **✕ 退出** | 关掉本进程、**释放端口**。贴标签是即写即存的，不会丢数据 |

> 为什么"关掉自己"要放在页面上：**进程自己最清楚自己是谁** —— 这是唯一总能杀对进程、
> 且不需要任何权限的办法。
>
> 重启的实现有个坑值得记下来（实测踩过）：新进程**不能立刻绑端口**，
> 因为旧进程不会瞬间释放它 —— 所以重启用 `--wait-port` 拉起，让新进程自己重试几次。
> 另外重启日志写的是 `cache/restart-<时间戳>.log`，**不能复用固定文件名** ——
> 启动壳常把 stdout 重定向到 `cache/label-server.log`，那个文件被占用，
> 写它会让重启直接失败（`EBUSY`）。

## 三个要知道的边界

1. **它只读写 `stickers/library.json` 与 `stickers/labels.json`**：
   不连桥接、不改配置、不发消息、不联网。
   只监听 `127.0.0.1`（图片是本地文件，不该被局域网看到）。
2. **库是共享文件**：如果你一边在这里标注、一边在控制台点【重新打标签】，
   后写的会覆盖先写的。工具不阻止（加锁反而会出现"卡住解不开"的假故障），
   但会**在页面上写明**。建议：别同时干这两件事。
3. **撤销只在内存里**：关掉进程之后就没有撤销栈了。这不是持久化历史。

## 词表去哪了

出厂词表写死在 `src/sticker-labels.mjs`，但从 0.2.4 起它只是**出厂值**：
你在这一页新建/改的标签会写进 **`<工作区>/stickers/labels.json`**，
之后**运行期一律读它**（`src/sticker-vocab.mjs`，缓存按文件签名失效）。

于是：新建一个标签 → 立刻能贴图 → 立刻出现在提示词里 → 立刻能参与选图判定。
**不用改代码、不用跑测试、不用重启。** 想回到出厂词表就点「复位」
（`POST /api/labels {action:'reset'}`；库里的图不动）。

## 为什么不用控制台那套 UI

控制台（`config-ui/`）是 React + Vite 构建出来的后台，它的职责是
"配置 + 观测机器人"。而标注台的需求完全不同：

* 要**整屏看图**（8MB 的动图要看清），控制台的布局是给表单和卡片用的；
* 要**键盘刷**（一张接一张），不该让后台的路由/轮询逻辑掺进来；
* 要**零构建**：`config-ui` 改一行就要 `npm run build`，而这个是"打开就能用"。

所以宁可**多一个文件夹**，也不把两种节奏塞进一个界面。
功能上它有需要的能力（词表校验、库读写）**直接复用宿主的 `src/` 实现** ——
只有一份真值，不重复造。

**代码分工**：HTTP 服务在 `src/sticker-label-server.mjs`（放 `src/` 是为了让测试能
直接 `createLabelServer(...)` 起一个，不 spawn 子进程、不抢端口），
`sticker-label/server.mjs` 只剩"解析命令行 + 监听端口"这点壳。
