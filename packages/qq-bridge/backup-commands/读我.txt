================================================================
  备用命令（backup-commands）—— 界面起不来时才用
================================================================

★ 先说这个**英文目录名**为什么不是中文：实测（Node v24.9.0 / Windows）
  拷贝**中文名目录**时进程会直接崩掉（`cpSync(..., {recursive:true})` →
  Access Violation，退出码 -1073740791），发布组装走到这一项就半途而废。
  目录名保持 ASCII 是为了避开那个缺陷；**目录里的文件名是中文**，没有影响
  （中文文件名一直可以，只有"目录名 + 递归拷贝"这一组合会崩）。

这两个文件在**界面里已经有同样的按钮**：

  · 控制台 → 概览页的「检查配置」   ↔  这里的 检查配置.bat   （后端 /api/check）
  · 控制台 → 状态条上的「体检」     ↔  这里的 体检.bat       （后端 /api/doctor）

那为什么还留着它们？—— 因为它们**不经过界面、也不经过桥接的 HTTP 接口**：

    检查配置.bat   连网络都不碰，只把 config.json 读一遍、把问题列出来
    体检.bat       直接去连一次协议端（SnowLuma），不发消息、不调模型、不花钱

所以**恰恰在"控制台打不开 / 桥接起不来"的时候**，它们是你唯一能拿到诊断的路。
界面正常时请用界面（那边还有更全的「启动前条件门控」，会直接告诉你下一步该做什么）。

----------------------------------------------------------------
怎么用
----------------------------------------------------------------

直接双击即可（它们会自己找到上一级目录里的 start.bat）。
输出会停在那里等你按键，方便你看完。

----------------------------------------------------------------
它们各自会告诉你什么
----------------------------------------------------------------

检查配置.bat
  · config.json 里缺了什么、哪一项互相矛盾
  · 「管理员 QQ 号为空 = 谁都不能用」这类 fail-closed 项有没有踩到
  · 关键词/端口的风险提示
  ★ 它不需要 QQ 在跑，也不需要模型 key 可用

体检.bat
  · DSH 装在哪、找没找到
  · SnowLuma 在不在跑、端口通不通、token 对不对
  · 桥接能不能连上协议端
  ★ 它会"真去连一次"，但**不发任何消息、不调用模型**，所以不花钱

----------------------------------------------------------------
如果这两个也起不来
----------------------------------------------------------------

在包根目录（本目录的上一级）开一个命令行窗口，敲：

    vendor\node\node.exe src\index.mjs --check
    vendor\node\node.exe src\index.mjs --doctor

（`vendor\node\node.exe` 是包内自带的 Node —— 你不需要自己装 Node。）
