# 视频识别（video-frames）— InteractiveBot 版

> ★ **0.2.7 改名**：显示名从「视频抽帧」改成「视频识别」。理由是"抽帧"说的是**手段**
> （把视频切成一堆图），而你要的是**能力**（看懂视频里有什么）；旧名字还容易让人以为它只做切图。
> **id / 目录名 / 工具全名都没改**（仍是 `video-frames`、`mcp__skills__video-frames__frames`），
> 所以 `config.skills['video-frames']` 里你已经设过的开关与路径**照旧有效**。
> 上游那份插件自己的显示名仍叫「视频抽帧」—— 本文提到上游时按上游叫法写。

> 这份文件**只讲差异与怎么用**。上游那份插件本体（`plugin.json` + `index.js` + `frames.js`）
> 逐字留档在仓库根的 `reference/video-frames-1.0.0/`，逐处改法与理由见
> `docs/0.2.7-video-frames-migration.md`。上游**没有** README —— 所以这份同时也是
> 本技能唯一的使用说明。

## 它是干什么的

把一段视频抽成若干张**截图**，存进工作区，再让模型用 `read_image` 逐张去读。
用途是让**只能看图的模型**也能"看"视频（视频本身喂不进模型：本宿主的看图通道是图片，
视频段目前连下载都不做）。

模型看到的工具名：

```
mcp__skills__video-frames__frames      视频识别
```

（`mcp__skills__` 这段前缀是 DSH 的 MCP 客户端加的，改不了；所以技能提示词里的名字
由宿主注入，绝不在代码里写死。）

## 怎么打开它

1. 确认 `skills/video-frames/` 在机器人目录里（发布包自带）；
2. **重启机器人**（装/卸技能才需要重启；之后改设置、开关都不用重启）；
3. 控制台 →「扩展」→ 找到「视频识别」→ 打开开关。

⭐ **本技能默认是关的**（与上游相反，理由见 `skill.json` 的 `_note_switch`：
上游宿主在抽帧不可用时静默退回"只读元信息"，而本宿主不会静默 ——
工具一旦挂上，模型就会看到它、提示词里也会多一段指引，所以默认不打扰）。

## 前置：ffmpeg（这是它唯一的外部依赖）

**没有 ffmpeg 就抽不了帧**，这是设计如此（不是 bug）。本项目的判断是：
不把 ffmpeg 打进包里（体积 + 许可证 + 三平台各一份），而是**如实告诉你缺什么**。

⭐ **最容易误解的一点先说**：**装了 ffmpeg ≠ 它就能用**。
本技能不会去猜你把 ffmpeg 解压到了哪（项目纪律：不写死任何机器专属的绝对路径），
它只查两个地方：**设置里的「ffmpeg 路径」** 和 **系统 PATH**。
两个都没有，它就用不了 —— **这不代表机器上没装**。

缺的时候你会看到（工具调用与控制台卡片上都是这句）：

> 抽帧用不了：设置里**没填 ffmpeg 路径**，系统 PATH 里也没有 ffmpeg。
> ⚠️ 这**不代表机器上没装** —— 装好了的话，把 ffmpeg.exe 的完整路径填进
> 「控制台 → 扩展 → 视频识别 → 设置 → ffmpeg 路径」就行（即刻生效，不用改 PATH、也不用重新下载）。

⚠️ 这句文案 0.2.7 **改过一版**，起因是一次真实误伤：原来写的是「未找到 ffmpeg」，
使用者明明已经装好了（只是没填路径），却以为自己的安装出了问题；更糟的是
**模型照着这句在群里说了「这台机器上没装」**——一句假话。
所以现在这句话必须说清"**我查了什么**"，而不是含糊地说"没找到"。

**这句话出现在哪里、什么时候刷新**（这一格很容易踩空，0.2.7 修过一次）：

| 位置 | 什么时候重新判定 |
|---|---|
| 技能卡片上的黄条 | 技能**装载时**算一次（所以：改设置/装好 ffmpeg 之后，**重启机器人**才会刷成新的；填了路径那条除外——它是同步判存在，走设置保存后列表会重新拉） |
| 工具调用 | **每次调用前**现算一次 —— 缺什么就当场拒绝并把上面这句转述给模型，不会"调了才发现" |
| 「自检」按钮 | 现算，而且会**真的跑一次 `ffmpeg -version`** 核实（"PATH 上有"不等于"跑得起来"） |

> 0.2.7 之前这里还有个真缺陷：`available()` 抄了上游的"首次乐观放行"，而卡片读的是装载时的快照
> —— 结果是**明明没装 ffmpeg，卡片却显示 ✅ 已启用、一句提示都没有**。现在改成**同步扫 PATH**
> （不 spawn 进程），结论是真的。

两种补齐方式，任选一种：

| 方式 | 怎么做 | 适合 |
|---|---|---|
| **填路径** | 「扩展」→ 视频识别 → 点**「设置」**按钮展开 → 把 `ffmpeg.exe` 的完整路径填进「ffmpeg 路径」 | 不想动系统环境变量；**推荐**（把 ffmpeg 解压/下载到任意目录都行，不用 build） |
| 加进 PATH | 把 ffmpeg 解压到某处，把它的 `bin` 目录加进系统 PATH，**重启机器人** | 多个工具都要用 |

> 关于下载包：`ffmpeg-…-full_build`（gyan.dev 那种）**已经是编译好的成品**，
> 解压后直接用 `bin\ffmpeg.exe`、`bin\ffprobe.exe`，**没有"再 build 一次"这一步**。
> 项目自带的那个 `snowluma/native/ffmpeg/ffmpegAddon.win32.x64.node` 是 SnowLuma 的
> Electron 插件、**不是可执行文件**，不能当 ffmpeg 用。

> ⭐ 设置项不藏在别处：技能卡片上有一排按钮（**设置** / 它给模型的工具 / 提示词片段 / 自检），
> 点「设置」才会展开表单 —— 默认是折叠的。

⚠️ 关于 `ffprobe`：它只影响"帧取在哪些时间点"。
填了 ffmpeg 路径时，本技能会**优先在同一个目录里**找 `ffprobe.exe`（官方 zip 解出来两个 exe 是并排放的）；
没有 ffprobe 也能抽，只是时间点会退回"前 1、3、5… 秒"这种固定取值，而不是按时长均匀分布。

⚠️ **本机现状（如实记录）**：写这份适配的机器上 PATH 与仓库里都**没有** ffmpeg
（`snowluma/native/ffmpeg/` 里那个 `ffmpegAddon.win32.x64.node` 是 SnowLuma 的 Electron 插件，
不是可执行文件 —— 项目里三处注释都写了这件事）。所以**真机抽帧这一段没有在本机验证过**，
验证到的是：清单/装载/开关/提示词/路径收束/SSRF 守卫/**抽帧管线（用注入的命令执行器真跑）**
与"没有 ffmpeg 时的如实降级"。装好 ffmpeg 后按下面的自检看一眼就能确认。

## 怎么用（模型视角）

```
mcp__skills__video-frames__frames(source = "inbox/xxx.mp4", count = 4)
```

`source` 只接受两种：

| 来源 | 例子 | 说明 |
|---|---|---|
| 工作区内的**相对路径** | `inbox/a.mp4`、`store/demo.mov` | 相对**工作区**（`workspace-qq/`），不是相对机器人目录 |
| **http(s) 视频直链** | `https://cdn.example.com/v/a.mp4` | 本技能自己下载、自己校验，抽完即删 |

拿到结果后模型必须**自己用 `read_image` 去读那些路径** —— 返回的是路径，不是图片本身
（本宿主的技能工具只能返回文本，见下节）。

`count` 可选，1~12；不填用扩展设置里的值（默认 4）。

## 三个必须知道的边界

### 1. 为什么返回的是"路径"而不是图片

本宿主的技能工具返回值会被 `mcp/mcp-skills-server.mjs` `String()` 掉，只包成
`{content:[{type:'text'}]}` —— **没有图片内容块通道**。所以本技能走的是宿主自己看图功能的
同一条路（`image.mode = 'on-demand'`）：**帧落进工作区 → 给相对路径 → 模型 `read_image` 去读**。
这同时是最省 token 的一条（一张图只在模型真读它的时候才计费）。

> 想要"抽帧后直接把图喂给模型"需要改宿主自己的 MCP 服务器
> （`mcp/mcp-skills-server.mjs` 的 `tools/call` 回帧处），**不在本次适配范围内** ——
> 那是核心改动，不是技能能做的事。

### 2. 只读工作区内的文件，只连公网地址

* **路径**：只接受工作区内的相对路径。绝对路径、`..`、UNC、以及**经符号链接指向工作区外**的路径一律拒绝。
  理由：技能进程**没有沙箱**（宿主不做代码级拦截），而路径是**群友的消息**驱动的 ——
  放行绝对路径就等于给了一条"把机器人能读到的任何文件转成图给模型看"的路。
* **直链**：只允许 http/https，且**内网、回环、CGNAT、链路本地、组播地址一律拒绝** ——
  包括"域名解析结果落在内网"的情况（挡 `127.0.0.1.nip.io` 这类写法），重定向**逐跳**重新校验。
  这条与宿主 `src/images.mjs` 是同一套规则，但**刻意没有**那个
  `security.allowPrivateImageHosts` 逃生口：宿主的 `qq_send_image` 是 adminOnly 的，
  而这个工具对普通用户可用，而 MCP 调用里**没有调用者身份** ——
  照抄那个口子等于给任何群友一个内网探针。
  内网视频请走"放进工作区再给相对路径"那条路。

### 3. QQ 里直接发来的视频：**已经接上了**（0.2.7，方案 A）

群友在群里发一段视频时，现在的链路是：

```
QQ 视频段（SnowLuma 给的是 { type:'video', data:{ file, url } }，url 是带 rkey 的直链）
   → src/text.mjs 把直链**带出来**（videoRefs）
   → src/bridge.mjs 判断"抽帧到底能不能用"（技能开了吗 / 总开关开了吗 / 自检过了吗）
   → src/channel-prompt.mjs 在提示词里如实说：有 N 个视频 + 直链 + 该调哪个工具
   → 模型调 video-frames(source=直链) → 本技能自己下载（自带 SSRF 守卫与上限）
   → 帧落进工作区 → 模型 read_image 逐张读
```

★ **核心不下载视频**，只把直链递出去 —— 真正取视频的是本技能的 `sources.js`
（它已经有 SSRF 守卫、大小上限、超时、临时文件即删、"这不是视频"拒收，且被 123 项断言覆盖）。
核心再实现一份等于多一套要长期维护的下载政策。逐处改动见 `docs/0.2.7-qq-video-inbound.md`。

**要这条链路通，三个条件同时成立**（缺任何一个，提示词里就**不会**出现工具名，而是如实说
"含 N 个视频，但当前看不到画面（原因）"）：

1. 本技能在控制台里**已启用**；
2. 抽帧**自检通过**（装了 ffmpeg / 路径填对了）；
3. QQ 工具总开关（`mcp.enabled`）开着 —— 关着时技能工具根本没挂给模型。

⚠️ 提示词里那段门控是**每轮现算**的（自检是同步扫 PATH，不 spawn），
所以"装好 ffmpeg / 改好路径"之后**下一轮就生效**，不必等重启；
但**桥接代码本身**是启动时加载的，这次接线改动要**重启一次机器人**才生效。

★ 还有两条与"能不能看懂"无关、但你可能遇到的：

* 视频里的**声音**听不到 —— 抽帧只有画面，要文字得先做语音转写；
* 直链**有时效**（rkey 是短期票据）。模型在同一轮里立刻去调通常没问题；
  拖久了会 403，那时工具会**如实报错**（过期了就重新发一次视频）。

另外，**放在工作区里的视频文件**和**对方直接给的 http(s) 直链**这两条路照旧可用 ——
它们不依赖上面那套入站接线。

## 帧存在哪、什么时候清

* 目录：`<工作区>/frames/`，文件名形如 `frame_<来源指纹>_<序号>_<毫秒>ms.jpg`。
  为什么单独一个目录而不复用宿主看图的 `inbox/`：`inbox` 有宿主自己的保留政策
  （72 小时 / 100MB），混进去会让两边互相挤配额。
* 同一个来源**再抽一次**会先把这一来源的旧帧删掉（否则模型会读到两批几乎一样的图）。
* 保留时长由设置决定（默认 24 小时），每次抽帧顺手清理一次；填 `0` = 不清理。
* 直链来源下载的视频副本放在**系统临时目录**，抽完立刻删除（工作区里只留帧）。

## 出问题了怎么查

控制台 →「扩展」→ 视频识别 → **自检**（走技能自己的 `diagnose()`），会把这几格摊开：
开关 / 工作区 / ffmpeg（来源与版本）/ ffprobe / 帧目录现状 / 保留时长 / 抽帧参数 /
下载上限 / 模型看到的工具名 / 上次抽帧结果。

命令行也可以：

```bash
cd packages/qq-bridge
node src/index.mjs --extensions                          # 技能状态、工具全名、清单告警
node mocks/probe-extensions.mjs --enable video-frames    # 看提示词里到底注入了什么
node mocks/verify-video-frames.mjs                       # 本技能的守卫套件（零外网，不需要 ffmpeg）
```

常见症状：

| 症状 | 原因 | 怎么办 |
|---|---|---|
| 扩展列表里看不到「视频识别」 | 目录没放对，或没重启 | 确认 `skills/video-frames/skill.json` 在，然后重启机器人 |
| 卡片上写「未找到 ffmpeg」 | 没装 / 没填路径 / 不在 PATH | 点卡片上的**「设置」**填 ffmpeg.exe 完整路径（**推荐**），或把它加进 PATH 后重启 |
| 卡片上写「设置的 ffmpeg 路径不存在」 | 路径写错 | 改设置（**即刻生效**，不用重启） |
| 卡片显示「已启用」但一调用就说缺 ffmpeg | 桥接比你的改动更早启动（卡片是装载时的快照） | 重启机器人让卡片刷新；或点「自检」看现算结果 |
| 工具报「工作区里没有这个文件」 | `source` 写的是绝对路径或路径不对 | 用**相对工作区**的路径，或改给 http(s) 直链 |
| 工具报「这个地址返回的不是视频」 | 给的其实是网页/接口地址 | 换真正的视频直链 |
| 工具报「抽帧失败（ffmpeg 没有产出可用画面）」 | 文件其实不是视频 / 编码不支持 / 单帧超时太短 | 调大「单帧抽帧超时」，或换来源 |
| 模型说"看到了"但没读图 | 它没调 `read_image` | 提示词片段里已经写了这条；模型偶尔偷懒，重问一次即可 |

## 与上游那份插件的差别（摘要）

| | 上游（QQ Agent） | 这里（InteractiveBot） |
|---|---|---|
| 形态 | **能力提供者**（`providers['video.frames']`），模型看不见 | **工具**（`mcp__skills__video-frames__frames`），模型主动调 |
| 产物 | base64 data URL，宿主直接拼进消息 | JPEG 落在工作区，返回相对路径 + 让模型 `read_image` |
| 触发 | 用户发视频 → 核心自动抽帧 | 模型调用工具（所以"发视频"这条链路还需要核心侧接线，见上） |
| 默认开关 | 开 | **关**（理由见 `skill.json` 的 `_note_switch`） |
| 配置界面 | 上游「设置 → 扩展」 | 控制台 →「扩展」→ 视频识别 |
| 来源 | 由上游核心传本地文件路径 | 工作区相对路径 / http(s) 直链（自带 SSRF 守卫） |
| 帧目录/清理 | 临时文件，用完即删 | 工作区 `frames/`，默认 24 小时清理 |

**上游那条能力导出仍然保留**（`providers['video.frames']` 与 `video.frames.available`），
所以同一份代码在上游宿主里照样能跑 —— 适配的目标是"两个宿主都能跑"，不是"只认 InteractiveBot"。
