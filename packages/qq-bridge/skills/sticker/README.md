# 表情包（`skills/sticker`）

让机器人在合适的时候**从你自己的表情库里挑一张发出去**。

> **一句话定位**：这是一个**技能**（`skill.json` + 入口 + 说明，零依赖、可整目录拷走），
> 但**判定与发送、以及离线导入/打标签脚本都在宿主**（`src/sticker-*.mjs`）。
> 为什么这样拆见文末「这个技能里为什么没有工具」。

---

## 0. 它做什么、不做什么

| | |
|---|---|
| **做** | 从**你导入的**表情库里，按场景（在笑 / 无语 / 安慰 / 收尾…）挑一张发出去 |
| **做** | 模型也可以主动要：回复里写 `[sticker:标签]` |
| **不做** | 不自己去网上抓表情包（库里的每一张都是你导入的） |
| **不做** | 不让模型"看库选图"（它没有图像，只能凭标签名猜 → 必然发错） |
| **不做** | **不在运行期调模型**（判定是纯本地计算，一次 token 都不花） |

**为什么不让模型挑图**：项目里有一条硬规矩 —— 提示词里提到的每一个能力都必须
真实存在（`persona.mjs:20` 记着源项目"人设引用了不存在的工具 ⇒ 模型学会幻觉调用"
的教训）。更实际的理由：模型看不到图，让它挑就是在赌；而本地打分是**可解释、
可复现、可单测**的。

---

## 1. 三步用起来

```bash
cd packages/qq-bridge

# ① 导入（离线、零成本；同一张图只存一份，近似重复会自动跳过）
node src/index.mjs --stickers --import "C:\我的表情包"

# ② 打标签：**两条路，效果一样**（引擎是同一份 src/sticker-tagging.mjs）
#    · 控制台「扩展 → 表情包」卡片上的【重新打标签】按钮（主入口，带进度与停止）
#    · 命令行（离线/界面打不开时的备用入口）
node src/sticker-tag.mjs            # 先预演，看看模型给的标签对不对
node src/sticker-tag.mjs --apply    # 确认没问题再写回库

# ③ 看看现在什么状态（库里有几张能用的图、每类各几张、最近为什么不发）
node src/index.mjs --stickers
```

### 界面上的【重新打标签】按钮

在「扩展」页的表情包卡片上。它做的事是：**把库里所有图重新打一遍标签**（不含人工改过的），
并告诉你进度：

| 它会显示 | 为什么 |
|---|---|
| 点之前："会处理 N 张（库里共 M 张，跳过人工 K 张）" | 这个数就是**预检**（零模型调用）—— 你点之前就该知道要花多少次调用 |
| 二次确认："这将调用模型 **N 次**"＋"人工改过的标签不会被覆盖" | 这是唯一会真花钱的操作，不能点一下就跑 |
| 跑的时候：`已完成/总数`、百分比、当前文件、最近打上的标签 | 长任务没有进度 = 你会以为它卡死了 |
| 【停止】按钮 | 长任务得有刹车；**已打上的照常写回**，不做废 |
| 跑完：新打/重打/失败/跳过人工 + **失败清单**（可展开） | "哪几张失败了"是你一定会问的 |

**命令行与按钮的分工**：按钮是主入口（有进度、能停）；命令行保留给
"界面打不开 / 想抽检准确率（`--sample 30`）/ 想只跑前几张（`--limit 20`）"这类场景。
两者**共用同一份引擎**，所以提示词、判定、跳过规则完全一致。

### 只想补打新导入的图？

* 按钮：**它就是"全部重打"**（含已打好的）。这让行为可预测 —— 不会出现
  "有的图是新标签、有的是旧标签"的混合状态。
* 只想补待定的那些：用命令行 `node src/sticker-tag.mjs --apply`（默认只处理待定的）。

### 文件名先验：**零成本**的第一遍标签

表情包的**原始文件名常常自带语义**（从成套素材导出的尤其如此）：
`蓝色大肥鱼_笑_2026-08-18.gif`、`…_问号_….gif`、`…_加油_….gif` —— 那是打包者
写的描述，比模型猜的准，而且**一次模型调用都不花**。

所以导入时会记下条目里的 `originName`（原始文件名），打标签时**先跑一遍文件名先验**：

```bash
node src/sticker-tag.mjs --from-filename        # 只用文件名（零调用、瞬间完成）
node src/sticker-tag.mjs --apply                # 再用模型处理剩下的
```

实测效果（157 张真实 GIF）：**90 张**靠文件名就定下来了，只剩 67 张需要模型 ——
**省掉约 57% 的模型调用**。

★ 它的标签 `source` 记成 `filename`、置信度 **0.7**（刚过阈值），所以它**只是先验**：
下次模型重打会**覆盖**它（与 `manual` 不同 —— 那是人的判断，不许覆盖）。
按钮不做这件事（按钮的语义是"重打"），文件名先验留在命令行。

### 手工改标签（人工的那份永远优先）

**这是唯一不花钱的打标签方式。** 有两条路：

**① 图形界面（推荐，刷卡式）** —— 独立小工具，不在控制台里：

```bash
cd packages/qq-bridge
node sticker-label/server.mjs --open      # 或双击 sticker-label/启动标注.bat
```

点标签即写回、自动跳下一张、`Ctrl+Z` 撤销。详见 `sticker-label/README.md`。

**② 命令行 + 手改 JSON（没有浏览器时）**

```bash
# ① 看库里有哪条、待定的排在最前面（原始文件名能对上号）
node src/index.mjs --stickers --list            # 全部条目（--pending 只看没标签的，--limit N 限制条数）

# ② 把要改的那条的完整记录原样打出来（可复制）
node src/index.mjs --stickers --show 一切都好   # 关键词可以是原始文件名的一部分、或短 id
```

③ 按打出来的形状改 `stickers/library.json` 里**同名键**的那一条：

```json
"global/4ce14e480d205f52.gif": {
  "primary": "agree",              ← 主标签（必须是词表里的 id，写错会**报错**不会静默）
  "labels": ["agree"],             ← 次要标签，可以留空数组
  "primaryConfidence": 1,
  "source": "manual"               ← ★ 写成 manual：**重打标签会跳过它**
}
```

**三条要知道的：**

* **改完不用重启**：判定与提示词都是**每轮现读库文件**，下一轮对话就生效。
* **`source: "manual"` 是护身符**：模型重打标签时会**跳过**它（实测有断言钉着）。
  想连它一起重打只能用命令行 `--force` —— 刻意收窄，那是一个"把人工成果冲掉"的动作。
* **写错标签名会报错**（不会静默变成一个"没标签"的条目）：词表是封闭的 22 个，
  完整清单见 `--stickers --list` 的最后一行。

> ★ 为什么要有 `--show` 这一步：库里的键是**内容哈希**（`global/7405d3613e866cfa.gif`），
> 直接翻 JSON 根本对不上"哪张是哪张"。`--list` 用条目里存的 `originName`
> （原始文件名）把它对上号，`--show` 再把可复制的完整记录摆出来 —— 手改 JSON
> 最容易错在形状（`labels` 忘改、`source` 写错位置），所以别自己拼。

装到群里：把一个会话的表情放进**它自己的目录**，这样"优先用本群的图"才成立：

```
workspace-qq/stickers/
├── global/                     ← 兜底库（所有会话都能用）
├── group-700000001/            ← 群 700000001 自己的图（优先）
├── private-100000001/         ← 和 100000001 私聊用
├── library.json                ← 清单（哪些图、什么标签）—— 别手改，用脚本
├── usage.json                  ← 配额台账（每日上限、冷却）
└── decisions.jsonl             ← 决策流水：每一次"发/不发 + 原因"
```

### 只想用一份库？导进**全局库**就行

**`--import` 不写 `--scope` 就是全局库**（所有会话共用）—— 这是最省事的用法：

```bash
node src/index.mjs --stickers --import "C:\我的表情包"              # → stickers/global/
node src/index.mjs --stickers --import "C:\群表情" --scope group-700000001   # → stickers/group-700000001/
```

两者的区别只有一个，但很实际：

| | 全局库 | 分会话库 |
|---|---|---|
| 谁能用 | **所有会话**（新群立刻能用） | 只有那个会话 |
| 优先级 | 低（会话自己有图时用会话的） | 高 |

所以"主要用全局库"是**完全正常**的用法；`--stickers` 的状态报告会分别告诉你
全局库和各个会话各有多少张（没有全局库时它会**明说**，并给出上面那条命令）。

### 库是按**会话**存的，不是按标签存的

存储布局是给机器用的：**内容寻址**（文件名 = 内容哈希，同一张图只存一份）+
**按会话分目录**（跨群不借图）。所以直接看目录是读不出来的：

```
workspace-qq/stickers/group-700000001/4ce14e480d205f52.png   ← 这张是什么？
```

想**按标签**看（比如"我这库里`笑死`的表情都有哪些"），导出一份视图：

```bash
node src/index.mjs --stickers --export-tags                 # 预演：只列出会导出什么
node src/index.mjs --stickers --export-tags --apply         # 真导出（默认**复制**，不动源库）
node src/index.mjs --stickers --export-tags --apply --link  # 省磁盘用符号链接（需要系统权限）
node src/index.mjs --stickers --export-tags --apply --out 我的表情整理
```

得到：

```
workspace-qq/stickers-by-tag/
├── laugh/        笑死__4ce14e480d205f52.png
├── confused/     疑惑__57cab8f3266f795c.png
├── task-done/    任务完成__df181ce464315866.png
└── _pending/     8f60130fb0216b98.png        ← 还没打标签的（**不参与选图**）
```

★ 这份目录是**视图，不是库本身**：删掉它不影响发表情；要改图/改标签请改库。
★ 文件名带**中文标签**是刻意的 —— 让人在资源管理器里一眼看出这张图是干什么用的。
★ 默认**复制**而不是符号链接：Windows 上建符号链接需要"开发者模式"或管理员权限，
建不成时脚本会**如实告诉你是回落成复制了**（不静默）。
★ 改了标签或删了图之后**重跑一次导出**（加 `--apply`）：它会先清掉上次导出的过期文件，
再按当前库重写 —— 否则视图里会留着已经不属于任何标签的文件（看到假数据比看不到更糟）。
那份"过期文件"清单会打在报告里；如果有文件被资源管理器/看图软件占用删不掉，
报告会**明说没能删掉哪几个**，而不是假装清干净了。

> ⚠️ 目录名就是 `peerKey`（`group:700000001` 折成 `group-700000001`）。
> 写错了不会报错，只会表现成"图导进去了但一张都选不到"——
> 所以用 `--scope` 让脚本自己算，别手建目录。

## 2. 标签词表（23 个，**封闭**）

标签不是"情绪分类"，而是**这一轮回复在做什么动作** ——
按情绪分（开心/难过/生气）会立刻撞上语义重叠（无语/敷衍/嫌弃/摆烂 互相咬），
最后表现成机器人**随机发错图**。

| 轴 | 标签 |
|---|---|
| 主动情感 | `comfort` 抱抱 · `tired` 累了 · `moved` 被萌到 |
| 被逗乐 | `laugh` 笑死 |
| 认知反应 | `shock` 震惊 · `confused` 疑惑 · `question-mark` 问号 · `deadpan` 无语 |
| 表态 | `agree` 赞同 · `disagree` 反对 · `disgust` 嫌弃 |
| 状态 | `sad` 委屈 · `slack` 摆烂 |
| 社交姿态 | `dismiss` 敷衍 · `gossip` 吃瓜 · `lurk` 暗中观察 · `innocent` 装无辜 |
| 攻击性 | `spite` 挑衅 |
| 混合 | `awkward-smile` 哭笑不得 |
| 礼节 | `greet` 打招呼 · `goodnight` 晚安 |
| 交付 | `task-done` 任务完成 |
| **风险** | `risky` 慎发 ← **不是情绪，是安全闸门**：命中它的图**默认不发**（见下） |

**五条硬规矩：**

1. **封闭**：打标签只能从这 23 个里选。产出不在表里 = 打标签失败（落待定区），
   **绝不允许**自己发明标签 —— 那会让"选图"失去确定性。
2. **不可归类就落待定**：表里**刻意没有"其它"**这个兜底标签。硬塞一个近似标签
   比留在待定区更糟 —— 前者会在某个场景被真的发出去。
3. **标签是内部协议**：只用于选图，**永远不能作为文字发到聊天里**。
4. **功能类只有模型能挑**：`打招呼 / 晚安 / 任务完成` 是"这件事的语义标记"，
   自主判定只看得到词面、判不了"这一轮算不算收工"，所以**系统不会替你挑**。
5. **`risky`（慎发）是安全闸门**：脏话/骂人/擦边/重口/血腥/惊悚/恐怖 →
   打标签时标 `risky: true` → **默认根本不进候选**（不是"进去了但分数低"）。
   发这类图的后果是**账号被处置**，不是"不好看"。要放行只能显式打开
   `skills.sticker.allowRisky`（默认关）。拦下多少张会**如实写进日志**。

### 语义判定用到的三件"防错"机制（都学自同类实现，也都有断言）

| 机制 | 它防什么 | 例子 |
|---|---|---|
| **`exclude`（排除词）** | **语义反转** —— 出现即整条作废，不是扣分 | `被怼得说不出话` 不该拿「挑衅」；`被击中` 不该拿「被萌到」；`笑不出来` 不该拿「笑死」 |
| **压制对 `SUPPRESS_PAIRS`** | 近义标签同时命中、打出自相矛盾的组合 | `哭笑不得` 压住 `被逗乐`；`荒诞反问` 压住 `没听懂`。⚠️ 这张表**保守**：同类实现踩过"压得太宽 → 某个标签永远拿不到"的坑 |
| **单字线索减半计分**（`SINGLE_CHAR_SCORE = 0.5`） | 随处可见的单字压过真正说明问题的双字词 | `摆烂`(2 分) 应当赢过 `怼`(0.5 分) |

**最容易打错的六组对照**（打标签的提示词里也写了）：

```
confused(求解释) ≠ question-mark(荒诞反问) ≠ shock(认知冲击) ≠ deadpan(鄙视)
sad(真委屈) ≠ innocent(刻意装不知道)
slack(放弃挣扎) ≠ tired(疲惫) ≠ dismiss(不想接话)
laugh(被逗乐) ≠ spite(带攻击性) ≠ awkward-smile(又好笑又无奈)

★ 单字线索要小心：「行」会被"就行/银行/运行"命中 ——
  这类裸单字必须出现在 SAFE_SINGLE_CHAR_CUES 白名单里才参与匹配。
★ 句末助词算边界：「太累了」「太绝了」里的「了」不阻断线索命中
  （TAIL_PARTICLES：了/吧/呢/啊/呀/啦/嘛…）—— 但助词**只在右侧**算边界。
```

## 3. 什么时候会发（判定链）

```
模型生成正文
   ↓
① 能力：技能开着？库里有可用图？文件真的在？
② 硬否决：报错 / 道歉 / 权限被拒 / 隐私 / **对方在认真求助** / 正文过长
③ 触发：模型写了 [sticker:标签] → 采纳
        否则**从正文抽态度** → 抽不出就不发（宁可漏发）
④ 打分：最低分不足以确定 → 不发（不为发而发）
⑤ 配额：冷却 / 每 N 轮 / 每日上限 / 同图冷却
   ↓
挂在回复的**最后一条**后面（只有表情没正文时单独发一条）
```

**★ 顺序纪律**：自主补图是**先看正文说了什么，再去选图**，
而不是"想发图然后找个理由"。反过来的话就会出现"模型回了一大段正经技术答案、
末尾贴一张无语脸"。

**★ 发错图的代价**：它是这个功能唯一**无法解释、撤不回、用户当场能看到**的后果。
所以每一层都是否决层 —— 宁可漏发。

### 频率档位

| 档 | 每 N 轮最多 1 次 | 同会话最小间隔 | 每轮上限 | 每群每日上限 |
|---|---|---|---|---|
| `low` | 3 轮 | 120 秒 | 1 | 30 |
| **`medium`（默认）** | **2 轮** | **30 秒** | **1** | **80** |
| `high` | 每轮 | 10 秒 | 2 | 200 |

改：控制台「扩展」页的「表情包」卡片，或者 `config.json` 的
`skills.sticker.frequency`（预设只是默认值，每一项都能单独调）。

## 4. 它没发，为什么？（排查顺序）

```bash
node src/index.mjs --stickers        # 库状态 + 各标签张数 + 最近 12 条决策
```

| 症状 | 先看 | 结论 |
|---|---|---|
| 一张都没发过 | 库状态里"可用 0 张" | 图导进来了但**没打标签** → 跑 `sticker-tag.mjs --apply` |
| 某个标签写了没反应 | 该标签的张数 | 少于 3 张的标签**不会出现在提示词里**（剩余在图少的标签那行） |
| 有时发有时不发 | 决策流水里的原因 | 配额（冷却/每 N 轮/每日上限）、阈值不够、抽不出态度 |
| 只在某些群不发 | 那个群有没有自己的目录 | 没有自己的图时用 `global/`；跨群图**故意不借用** |
| 老发同一类脸 | 各标签张数是否悬殊 | 某个标签占了 30% 以上 → 库的分布太单一 |
| 报错/求助场景从来不发 | 这是**设计** | 硬否决不可配置（与隐私闸门同一个理由） |

`decisions.jsonl` 每一行都记了：`什么时候 / 哪个会话 / 发还是不发 /
如果是发：哪张、多少分、为什么 / 如果不发：被哪一条挡住`。

## 5. 已知边界（如实写出来）

0. **发送上限是宽松的兜底值（默认 50MB ≈ 不拦）**：超过它的图不参与选图。
   实测协议端**不看体积** —— 5.07MB 的 GIF（base64 后 6.76MB）**453ms** 上传成功
   （`snowluma` 日志：`[Highway.Image] uploading 5319636 bytes … fast-upload hit`）。
   ⚠️ 第一版设成 2MB 是**基于猜测**的保守值，结果把 155 张里的 **115 张**滤掉，
   `tired / agree / slack` 等标签**一张都发不出去** —— 比"发大图慢一点"糟得多。
   **别把它调小**；它防的只是误导入的超大文件（整段视频转的 GIF）。
1. **近重复检测只对 PNG 有效**。JPEG/WebP/GIF 拿不到感知哈希（项目没有图像库，
   本机那个 ffmpeg 是 SnowLuma 的 Electron 插件、不是可执行文件），
   所以它们**只按内容哈希去重** —— 导入时会如实告诉你"这 N 张没做近重复检测"。
2. **纯色图之间不会互相去重**：aHash 对纯色会退化成同一个值（实测抓到过），
   而"纯红 vs 纯蓝"的汉明距离是 0 —— 拿它当判据会**误删真图**，所以纯色图
   （指纹全 1 或全 0）被排除在近重复判据之外。
3. **跨群不借图**：`global/` 之外的图只给本会话用。代价是新群在攒够图之前
   可能一次都发不出来 —— 那是刻意的（跨群发错图最难解释）。
4. **打标签要花钱**：一次模型调用/张（用 `wake.judge.apiKey` 那把 key）。
   不想花钱就手改 `library.json` 里的 `primary` 字段，一样有效。
5. **每日上限落盘**（`usage.json`）：重启不会清零 —— 这是刻意的，
   靠重启能绕过的限制等于没有限制。
6. **聊天里收到的表情包不会自动入库**（第一版只做外部导入）：
   所以库里的每一张都是你审过的。

## 6. 这个技能里为什么没有工具

`skill.json` 的 `tools` 是空的、入口也只导出 `setup/available/promptSections`
——**没有决策钩子**。这不是漏了，是边界：

* 技能契约要求"不 import 宿主内部模块、能整目录拷走"（`docs/插件设计规范.md` §12.3）；
* 而"发不发"的判定要碰**配额台账、隐私/投递闸门的顺序、拟人延迟、发送失败冷却**
  —— 那些是宿主的状态机，不是外部能力包该碰的东西；
* 判定还必须是**可离线单测的纯函数**（`src/sticker-decision.mjs` 有 83 项断言），
  把它塞进技能目录等于让"发错图"这条最贵的失败路径离开宿主的测试覆盖面。

所以本项目的答案是：**功能是技能，判定必须在宿主。**

| 层 | 在哪 | 是什么 |
|---|---|---|
| 清单 / 设置 / 说明 | `skills/sticker/`（本目录） | 零依赖、可整目录搬走（**只有三个文件，不含脚本**） |
| 库读写 | `src/sticker-library.mjs` | 内容寻址、去重、标签、用量 |
| 判定 | `src/sticker-decision.mjs` | 四层漏斗、打分、态度抽取 |
| 配额 | `src/sticker-quota.mjs` | 三档、冷却、每日上限（落盘） |
| 离线导入 / 打标签 | `src/sticker-import.mjs`、`src/sticker-tag.mjs` | 命令行脚本（要读写库、要调模型，所以在宿主） |
| 提示词 / 发送 | `src/bridge.mjs`、`src/channel-prompt.mjs` | 每轮现算、挂最后一条 |

> ⚠️ **别把"可整目录搬走"读成"本目录自带全部功能"**：本目录是**清单层**，
> 真正干活的东西在宿主 `src/`。实测踩过：本说明与 `index.js` 原来都写着
> "本目录含离线导入/打标签脚本"，而目录里根本没有 —— 照着文档拷走会得到一个
> **没有脚本的技能**。现在有断言盯着这个说法（`mocks/verify-sticker-skill.mjs` 第 ⑥ 节）。

**验证**：`npm run test:sticker`（库 99 + 判定 123 + 端到端 33 + 打标签 27 + 重打 50 + 词表 81 + 标注台 171 + 删标签 46 = 630 项），
外加技能层 `node mocks/verify-sticker-skill.mjs`（技能可加载 / 默认值不漂移 / 零第三方依赖 / 文档与实体一致 / 发布组装不漏项）。

## 7. 什么时候"生效"（三个不同的时间点，别混）

| 你做了什么 | 什么时候生效 | 为什么 |
|---|---|---|
| 导入 / 打标签 / 改标签 / 改库里的图 | **下一轮对话**，不用重启 | 提示词段与判定都是**每轮现读**（读一次 `library.json`） |
| 改设置（频率、阈值、库目录、开关） | **下一轮对话**，不用重启 | `skills.sticker.*` 每轮现读 |
| **第一次装上这个技能**（或改了 `skills/sticker/index.js`） | ★ **要重启桥接** | 技能模块与插件表是**启动时**加载的（`docs/插件设计规范.md` §4.3 那张表） |

**打标签本身是一个"一次性、手工"的动作**，没有自动触发：

* 导入时**只入库、不打标签**（图进待定区，**不参与选图**）；
* `node src/sticker-tag.mjs` 是**你手动跑的一次性脚本**：它把待定区的图逐张交给
  视觉模型，产出标签写回 `library.json`，然后**退出**；
* 它**不在启动时跑**、**不在每轮对话跑**、**不在后台常驻**。
  这不是偷懒：运行期**一次模型调用都不能加**（`images.mjs:29` 已经说明过理由 ——
  QQ 里大量是表情包，每张都过视觉等于每轮都花 vision token，而且图片会留在会话历史里重复计费）。
  标签只能在导入时算一次、永久复用。

**每条标签的图不必很多**：同一标签下有 3 张左右就够了 —— 超过之后选图精度不再提升，
而且打分相同时是**在最高分那一档里随机挑一张**，所以多出来的图不会浪费（每张都有机会）。
