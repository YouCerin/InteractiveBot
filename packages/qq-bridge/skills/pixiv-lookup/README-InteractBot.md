# pixiv 查图插件（InteractBot 版）— 与上游说明的差异

> 这份文件**只讲差异**。插件的完整介绍、Pixiv 接口细节、Cookie 怎么拿，
> 都在同目录的 `README.md` 与 `安装与使用说明.md` 里 —— 那两份是**为上游宿主（QQ Agent）写的**，
> 我们刻意没有逐句改写（改动清单与理由见 `docs/0.2.2-pixiv-skill-migration.md`）。
> 凡是那两份里提到"技能设置 / 设置 → 安全"的地方，在 InteractBot 里都对应本文的路径。

## 怎么打开它

1. 确认 `skills/pixiv-lookup/` 在机器人目录里（发布包自带）；
2. **重启机器人**（装/卸技能才需要重启；之后开关随时可改）；
3. 打开控制台 → 左侧页签**「扩展」** → 找到「pixiv查图插件」→ 打开开关。

打开之后**不需要重启**：下一轮对话里模型就会拿到这三个工具
（提示词里也会多一段指引），工具名对模型来说是：

```
mcp__skills__pixiv-lookup__search     按关键词搜图
mcp__skills__pixiv-lookup__artwork    按 id 查详情（收藏数/简介/多图）
mcp__skills__pixiv-lookup__ranking    日榜/周榜…
```

（上游那份说明里写的是 `pixiv-lookup__search` 等 —— 那是上游宿主的命名，
在 InteractBot 里前面会多一段 `mcp__skills__`。这是 DSH 的 MCP 客户端加的，改不了，
所以插件的提示词由宿主注入真实工具名。）

## 设置在哪

控制台 →「扩展」→ pixiv查图插件 → **展开设置**。字段与上游说明一致
（Cookie、条数上限、翻页、排序、R-18、群里可用、代理、超时、断路器、本地图片桥…），
密文字段（Cookie）是密码框、**留空即不修改**。

## 发图：要额外打开一个开关

要让机器人**真的把图发进群**（而不是只发链接），需要：

1. 插件设置里的「本地图片桥」保持开启（默认开）——它会在本机开一个只监听
   127.0.0.1 的小端口，把图取回来再给出一条本地直链；
2. 控制台 →「扩展」→ **给扩展用的安全开关** → 打开
   **「允许下载内网/本机图片地址」**（配置键 `security.allowPrivateImageHosts`，默认关）。

不开第 2 步的话，`mcp__qq__qq_send_image` 会明确报：

> 图没发出去：拒绝内网/回环地址 127.0.0.1（这是本机/内网的图片地址，被安全设置挡住了：
> 需要在**控制台 → 扩展 → 给扩展用的安全开关**里打开「允许下载内网/本机图片地址」）

**这条报错不是网络故障**，别反复换图试。

## 出问题了怎么查

控制台 →「扩展」→ pixiv查图插件 → **自检**（走插件自己的 `diagnose()`）。
命令行也可以：

```bash
cd <机器人目录>
node src/index.mjs --extensions          # 技能状态、工具全名、清单告警
node mocks/probe-extensions.mjs --enable pixiv-lookup   # 看提示词里到底注入了什么
```

## 代理（大陆网络必看）

大陆直连 `pixiv.net` 会超时，需要在插件设置里填 `proxy`（推荐 `auto`）。
⚠️ 这条路径依赖 `undici` 这个**可选依赖**：

* 包里带了 → 代理正常工作；
* 包里没带 → 插件会自己报「代理不可用」（**如实降级**，不是坏了别的功能）。
* **怎么提前知道**：控制台自检里有「**代理能力**」一栏，它和「代理」是**两件事** ——
  「代理」说你**配了什么**，「代理能力」说**配了到底能不能用**。故意分两栏，
  是因为实测这两个缺陷会**互相遮蔽**：`proxy` 留空时 `resolveProxySetting` 提前返回，
  根本不会去加载 `undici`，于是"缺依赖"这件事要等你先填了 `proxy` 才会暴露。
  2026-09-27 的排查就是卡在这里（界面只说"代理：未配置"，日志里一个字都没有）。

补装：在机器人目录（`packages/qq-bridge`）执行 `npm install undici`，
再跑一次 `node setup.mjs`，然后重启机器人。
