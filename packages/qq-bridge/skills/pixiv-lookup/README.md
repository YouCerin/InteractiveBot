# pixiv查图插件（pixiv-lookup）

给 QQ Agent 用的 Pixiv（P站）搜图插件。装上之后，群里有人问「帮我找 XX 的图」「P站上有没有 XX 的插画」，
机器人就能自己用工具去 Pixiv 搜，把 **作品标题、作者、标签、链接** 报出来 ——
并且（v1.1.0 起）还能把图**真的发到群里**。

> **v1.1.0 修了什么**：以前只能发链接、发不出图（`图片下载失败：域名解析到内网/本机地址，已阻止`）。
> 原因是 `i.pximg.net` 有防盗链 + 大陆要代理 + 宿主的图片下载通道带 SSRF 保护（Clash fake-ip
> 会把所有域名解析成 `198.18.x.x`，被当成内网）。
> 现在插件内置一个只监听 `127.0.0.1` 的**本地图片桥**，自己带 Referer、走插件代理把图取回来，
> 再给宿主一条本地直链。宿主侧只需打开一次「允许下载内网/本机图片地址」。
> 细节见 `安装与使用说明.md` 的 **4.4 节**。

---

## 一、它能做什么

| 工具名（模型看到的） | 干什么 | 典型触发话术 |
| --- | --- | --- |
| `pixiv-lookup__search` | 按关键词搜插画/漫画，返回 id + 标题 + 作者 + 标签 + 尺寸页数 + 链接 + **发图直链** | 「帮我找初音ミク的图」「有没有原神的插画」「P站上XX的图」 |
| `pixiv-lookup__artwork` | 按 id 查详情：收藏数、点赞数、浏览数、标签、简介、缩略图/大图/**多图原图地址**、**发图直链/原图直链** | 「这张的详细数据」「把原图地址发我」「100412238 这作品什么水平」 |
| `pixiv-lookup__ranking` | 取 Pixiv 榜单：日榜/周榜/月榜/新人/原创/男性向/女性向（含 **发图直链**） | 「今天P站有什么好图」「最近的热门插画」 |

搜到的结果会让机器人用这样的形式报出来：

> 《リゾートメイドに挑戦する綾華ちゃん》 — torino
> https://www.pixiv.net/artworks/100540913

要发图时，模型把结果里的 `发图直链`（`http://127.0.0.1:端口/i/xxxx`）交给 `send_image` 即可。

## 二、设置项（界面：设置 → 扩展 → pixiv查图插件）

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| **启用** | 关 | 打开后模型才会拿到这三个工具 |
| **Pixiv Cookie** | 空 | 🔒 **密码框，填完默认显示为 ******、不再回显**。填了才能查 R-18 内容和更完整的结果 |
| **每次返回条数上限** | 10 | 1~50。模型请求的条数会被夹到这个范围内 |
| **最大翻页数** | 2 | 模型最多能翻到第几页 |
| **默认排序** | `popular_d` | 按热度；可改成 `date_d`（按最新）等 |
| **允许查询 R-18 内容** | 关 | 群聊里建议保持关闭 |
| **允许在群里使用** | 开 | 关掉后只在私聊可用 |
| **代理地址** | 空 | **中国大陆必填，推荐填 `auto`**：插件自动找本机代理（Electron 会话代理 → Windows 系统代理 → 扫常见端口）。也可填死地址，如 `http://127.0.0.1:7890`（Clash）/ `http://127.0.0.1:10809`（v2ray）。**只作用于本插件自己的请求，绝不影响 QQ Agent 主程序**（含模型 API）。之所以推荐 `auto`：Clash/mihomo 这类客户端常把混合端口设成每次启动随机，写死端口过两天就失效 |
| **单次请求超时（毫秒）** | 20000 | 走代理慢就调到 40000 |
| **多次查询失败时强制终止** | **开** | 连续失败到阈值就停止一切查询，并明确要求模型别再调工具、直接用中文回话。见第四节 |
| **连续失败几次后终止** | 3 | 只统计"上游不行"类失败；404/参数错/搜到 0 条不计入 |
| **终止后冷却多少秒** | 60 | 冷却期内不再发请求；冷却结束自动放行一次试探 |
| **本地图片桥** | **开** | v1.1.0 新增。关掉 = 只发链接不发图 |
| **图片桥端口** | 18717 | 0 = 自动分配；端口被占用会自动改用随机端口 |
| **图片直链有效期（秒）** | 1800 | 30~86400；过期后模型需重新查询 |
| **桥单张图片上限（MB）** | 8 | 1~64；「原图」常超这个大小，日常发的大图 0.3~2MB |

> **宿主侧还要打开一个开关**（只做一次）：**设置 → 安全 → 允许下载内网/本机图片地址**
> （`security.allowPrivateImageHosts`）。不开的话，宿主的 SSRF 保护会挡掉图片桥的 `127.0.0.1` 直链，
> `send_image` 就会报 `图片下载失败：禁止访问内网/本机地址`。

### 上限是怎么被夹住的

想少发点图，就把「每次返回条数上限」调小 —— 这是**硬上限**：

```
模型传 limit=999  →  先夹到 maxResults（比如 10）→  再过滤 R-18  →  最终条数 ≤ 10
模型传 limit=4    →  允许调小，返回 4 条
```

## 三、Cookie 怎么填（可选，但建议填）

**为什么要填**：不填也能搜，但 R-18 标签/榜单查不了、结果页数偏少。
**怎么拿**：

1. 电脑浏览器登录 <https://www.pixiv.net/>
2. 按 `F12` → `Application`（应用）/ `存储` → 左侧 `Cookies` → 点 `https://www.pixiv.net`
3. 找 `PHPSESSID` 那一行，把它的值复制出来
4. 粘贴进插件的 **Pixiv Cookie** 框，格式就是：

   ```
   PHPSESSID=12345678_abcdefghijklmnopqrstuvwxyz
   ```

   也可以把浏览器里整行 Cookie 全部复制过来（含 `p_ab_id` 等），插件会自己清洗。

**⚠️ 安全须知（请务必看完）**

- 这条 Cookie **等于你的 Pixiv 登录凭证**，谁拿到谁就能以你的身份操作。**不要截图、不要发给别人。**
- 界面与 API 层面它都是密文：输入框是密码框、保存后只回显 `******`。
  但**它是以明文存在 `data\config.json` 里的** —— 请保管好这个文件，别把整个 data 目录打包发人。
- 想清除已填的 Cookie：目前界面上**清不掉**（上游对密文字段的约定是「空值/****** = 不修改」）。
  取消办法：关掉插件开关即可停止使用；或打开 `data\config.json`，把
  `skills` → `pixiv-lookup` 里的 `"cookie"` 值改成 `""`，然后重启 QQ Agent。

## 四、连续失败强制终止（断路器）

**为什么需要它**：Pixiv 连不上时，每次查询都要等满 `timeoutMs`（默认 20 秒）。
模型拿到"超时"结果后很常见的反应是**换个关键词再试**，试 3 次就是 1 分钟，
而且它经常把一整轮的 12~20 次工具预算全耗在重试上 —— 群里最后**一条回复都没有**。
用户看到的是"机器人卡死后装死"。

**打开后（默认打开）的行为**：

```
第 1 次失败 → 正常报错，提示配代理
第 2 次失败 → 正常报错
第 3 次失败 → 达到阈值：返回里附带「⛔ 插件已强制停止后续查询」+
              「不要再调用任何 pixiv 工具，立刻用中文把情况告诉对方」
第 4 次起   → 冷却期内**一个请求都不发**（不再等超时），直接返回终止说明
冷却结束后  → 自动放行一次试探，成功就完全恢复正常
```

**关键设计**：

- **是真的不发请求**：冷却期内被拦下的调用耗时是 0 毫秒，不是"快速失败"
- **跨工具**：search / artwork / ranking 共用一道闸 —— 因为它们共享同一条网络通道
- **只统计"上游不行"**：超时、DNS、连接被拒、403、429、5xx、风控页、业务报错。
  **不计入**：作品 404、id 不合法、关键词为空、R-18 被闸门拒、搜到 0 条 ——
  这些换个参数就能成，不能因为一次输入错误把整个插件封掉
- **任意一次成功即清零**：上游恢复了就立刻回到正常状态
- **冷却期有下限（≥5 秒）**：防止被误设成 0 而变成"永久封死"

**想关掉**：把「多次查询失败时强制终止」关掉即可，行为退回"每次失败都照实报错"。

## 五、发图：本地图片桥（v1.1.0 的核心）

### 为什么需要它

老版本只把 `i.pximg.net` 的原始地址交给模型去 `send_image`，这条路**三道坎**：

| 坎 | 实测表现 |
| --- | --- |
| 防盗链 | 不带 `Referer: https://www.pixiv.net/` → **403**（548 字节错误页）；带了才是正常 jpeg（实测 1.07MB） |
| 要代理 | 宿主的图片下载通道不认系统代理（Node fetch 不会自动走 Clash 系统代理），大陆直连 pximg → 等满 20 秒超时 |
| SSRF 保护 | 宿主默认拒绝"内网/本机"地址；Clash/mihomo 开 **fake-ip** 时 DNS 把**所有**域名解析成 `198.18.0.0/15` → 全被判成内网 → **连百度图床、QQ 表情包都发不出去**，报 `图片下载失败：域名解析到内网/本机地址，已阻止` |

### 怎么做的

`image-bridge.js` 在 `127.0.0.1` 上开一个小 HTTP 服务：

```
模型拿到「发图直链」 → 交给宿主 send_image → 宿主来下这条本地直链
   → 插件当场带 Referer、走插件代理去 pximg 取图 → 字节回给宿主 → 发到群里
```

安全约束（都在代码里，且有自测钉住）：

- **只监听 `127.0.0.1`**：外网/局域网都连不上
- **直链 = 本进程内存里随机生成的 18 字节 id**（144 位），只对应一张 pximg 图，有有效期（默认 30 分钟）
- 取图时**再校验一次** `*.pximg.net` 白名单 → 永远不可能变成通用 URL 代理
- 取图带 `Referer`，Accept **不索要 webp/avif**（图站按 Accept 做内容协商，回 webp 会让本机视觉接口 400）
- 同一张图在有效期内有内存缓存（"先 preview 再正式发"只去 Pixiv 取一次）
- 单张大小上限（默认 8MB）、总缓存上限（64MB）、响应 `Cache-Control: no-store`
- 插件被停用/重载时 `dispose()` 立即关掉端口

### 直链为什么是"发图大图"而不是缩略图

搜索/榜单接口只给 250×250 的方形缩略图。Pixiv 的路径规则是公开的，插件按规则换算：
去掉 `/c/<尺寸>_<质量>/` 前缀、把 `_square1200`/`_custom1200` 换成 `_master1200`，
得到长边 1200 的 master1200 —— **不需要额外调一次接口**。

### 验收

```powershell
$env:ELECTRON_RUN_AS_NODE='1'
Set-Location 'D:\QQ-Agent-爆改版0.4'
& '.\node_modules\electron\dist\electron.exe' '.\skills\pixiv-lookup\verify-image-bridge.mjs'
```

12 项：插件经代理取图 → 开关关着时宿主会挡（复现故障）→ 开关打开后宿主下到真 JPEG
→ **直接调用宿主 `send_image` 工具**确认图片数据交给了发送器 → 对照组：裸链必定失败。

## 六、自测（不联网也能跑）

本插件带一套 **151 项**的自测，用真实的 Pixiv 响应形状（fixtures）验证解析、R-18 过滤、条数上限夹取、
Cookie 不回显、断路器（含"冷却期真的不发请求"和"冷却后自动半开"）、
**图片桥（29 项：换算/白名单/直链/缓存/编造 id 404/端到端下到字节）**、
**代理隔离**、各种网络错误的报错文案。

在插件目录里双击 **`selftest.bat`**，或者在 PowerShell 里：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "selftest.ps1"
```

看到 `=== 结果：151 项通过，0 项失败 ===` 和 `[PASS]` 就是好的（退出码 0）。

## 七、出问题了怎么查

插件导出了一个 `diagnose()` 排障函数，会打印开关 / Cookie 状态 / 代理 / 上限 /
**断路器状态** / **图片桥状态** / 最近一次请求。
在 QQ Agent 目录下这样跑：

```powershell
$env:ELECTRON_RUN_AS_NODE='1'
Set-Location 'D:\QQ-Agent-爆改版0.4'
& '.\node_modules\electron\dist\electron.exe' '.\skills\pixiv-lookup\verify-in-agent.mjs' --diagnose
```

（或直接看 `安装与使用说明.md` 第七节「验证是否运行」里的完整说明。）

| 现象 | 原因 / 怎么办 |
| --- | --- |
| 报「请求 Pixiv 超时」 | 没开代理或代理端口不对。填 **代理地址**；大陆直连 pixiv.net 必然超时 |
| 报「已完成终止」「插件已强制停止后续查询」 | 断路器动作了：连续失败已达阈值。**这是正常的保护行为**，先解决网络/代理，等冷却（默认 60 秒）过去自动恢复；不想用它就把「多次查询失败时强制终止」关掉 |
| 报「Pixiv 返回 403」 | 触发风控。填一次完整 Cookie（含 PHPSESSID）；或换个代理出口 |
| 报「返回的是网页而不是数据」 | 被风控页/登录页接管了，同上 |
| 报「Pixiv 限流 429」 | 查太快了。等几十秒，或把每次返回条数上限调小 |
| 搜不到东西 | Pixiv 标签以**日文/英文**为主，中文命中率低。换个日文/英文说法再试一次 |
| 明明有结果却返回 0 条 | 被 R-18 过滤了。需要的话打开「允许查询 R-18 内容」 |
| 模型不知道有这个工具 | 插件开关没开，或该分类被关了（工具分类是 `media`） |
| `图片下载失败：域名解析到内网/本机地址，已阻止`<br>`图片下载失败：禁止访问内网/本机地址` | 宿主把图片地址判成内网。发「发图直链」时出现 = 宿主的「允许下载内网/本机图片地址」没开；发别的网图时出现 = 代理 fake-ip 把 DNS 变成了 `198.18.x.x`。打开那个开关并重启 |
| `图片下载失败：HTTP 403` / `请求超时：i.pximg.net` | 模型用了 pximg **裸链**（没用发图直链）。提示词里已写死规则；必要时在群里纠正一句 |
| `图片下载失败：HTTP 404` | 直链过期（默认 30 分钟）或插件重载过 → 重新查一次 |
| `图片桥取图失败：…` | 插件侧取图失败（代理挂了 / 节点抽风 / 作品被删），看后半句原因 |

## 八、技术说明（给改代码的人）

- **类型**：LLM 型技能（放在 `skills/`，通过 `registerTool` 把工具交给模型），不是确定性型插件。
- **自包含**：只用 Node 内置模块（`node:path` / `node:url` / `node:http` / `node:crypto`），
  不 import 宿主的任何 `src/`，整个目录可以原样拷走。
- **`available()` 只判开关，必须同步**：上游在 `isActive()` 里同步调用它。
  如果这里因为「网络不通」返回不可用，上游会把整个技能连同工具一起摘掉，
  用户看到的是「功能凭空消失、没有任何解释」。所以网络问题一律留到 `execute()`
  里返回**写明原因和怎么办**的中文报错。
- **出网只有一个出口** `httpJson()`：统一超时 / 代理 / 错误分类。
  测试脚本用导出的 `__setTransport()` 换成假实现。
- **不信任模型参数**：条数、页码、id 数量、ids 格式都在服务端二次夹紧。
- **Cookie 卫生**：进请求头前会去掉控制字符（防头注入）、剥掉 `Cookie:` 前缀与包裹引号；
  日志/报错/`diagnose()` 只输出「有没有、长度多少、含不含 PHPSESSID」，**绝不回显原文**。
- **图片桥（`image-bridge.js`）不改宿主的任何东西**
  它只做一件事：把"插件自己能取到的图"变成"宿主能下载的本地地址"。
  宿主侧唯一的依赖是 `security.allowPrivateImageHosts = true`（宿主的既有开关，
  语义就是"我信任本机图源"）。这样插件仍然是一个可以原样拷走的目录，
  不需要给 QQ Agent 打补丁 —— 这一点是刻意保持的。
  桥的取图函数由 `index.js` 注入（`fetchImage`），所以自测里可以完全离线地验证 HTTP 行为。
- **代理只作用于自己的请求（血泪教训）**
  早期版本在 `ensureProxy()` 里做了 `undici.setGlobalDispatcher(new ProxyAgent(proxy))`
  和 `process.env.HTTPS_PROXY = proxy` —— 这是**进程级**的，等于把宿主 QQ Agent 的
  **所有**出网请求（包括调模型 API）都改道到我们填的代理上。用户填了个死代理，
  整个机器人直接不可用（`connect ECONNREFUSED <代理IP>:443`），而且因为改的是全局状态，
  把设置里的代理清掉也要**重启**才恢复。
  现在：代理以 `dispatcher` 参数**逐请求**传给 undici 的 fetch，一个字节的全局状态都不动；
  不写任何 `*_PROXY` 环境变量；没填代理时连 undici 都不 import。
  这条由 8 项断言 + `verify-proxy-isolation.mjs` 钉住（后者在填死代理的情况下，
  真实验证宿主侧对模型 API 域名的请求仍然正常）。
- **有代理时必须换用 undici 自己的 fetch**：`dispatcher` 是 undici 的参数，
  Node 内置的 `globalThis.fetch` 不认它 —— 传了会被静默忽略，变成"以为走代理、其实直连"，
  报错还长得很像网络问题。所以有代理时用 `undici.fetch`，没有时用内置 fetch。
- **断路器是进程级状态**（故意如此）：`breaker` 是模块级变量，跨工具、跨轮次共享 ——
  否则"连续失败"根本统计不出来。代价是它同时作用于所有会话（这符合真实故障场景：
  代理挂了是所有群一起挂）。因此专门导出了 `__resetBreaker()` 供测试重置。
- **失败分两类**：`httpJson()` 的返回值上有 `userError` 标记区分
  「请求本身的问题」（404、作品不存在）与「上游现在不行」（超时/403/429/5xx/风控页）。
  只有后者进断路器计数 —— 这是防止"一次输入错误把插件封死"的关键。

### 用到的 Pixiv 接口

| 用途 | 接口 |
| --- | --- |
| 搜索 | `GET https://www.pixiv.net/ajax/search/artworks/{关键词}?word=&order=&mode=&s_mode=&type=all` |
| 详情 | `GET https://www.pixiv.net/ajax/illust/{id}` |
| 多图 | `GET https://www.pixiv.net/ajax/illust/{id}/pages` |
| 榜单 | `GET https://www.pixiv.net/ranking.php?format=json&mode=&content=` |

返回形状 `{ error, message, body }`，搜索列表在 `body.illustManga.data`。
这些是 Pixiv 的**非官方 Web 接口**，Pixiv 改版可能需要跟着调。

> **图床防盗链**：`i.pximg.net` 的图片只有在请求头带 `Referer: https://www.pixiv.net/` 时才能下载。
> 所以插件返回的 `缩略图/大图/原图` **不是「点开就能看」的普通链接**，也**不能**直接喂给 `send_image`。
> 要发图，用 `发图直链`（本地图片桥给的 `http://127.0.0.1:端口/i/xxxx`）。
